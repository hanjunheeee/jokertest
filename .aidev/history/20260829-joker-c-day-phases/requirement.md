# joker-C · 낮 페이즈 분리 (토론 → 투표)

## 배경

DAY 단일 구간이라 토론 중에도 투표가 들어간다. 토론 페이즈와 투표 페이즈를 분리한다.

## 요구

1. DAY를 DAY_DISCUSSION → DAY_VOTE 두 하위 페이즈로 나눈다. 토론 중에는 투표 제출을 거부하고, 투표 페이즈에는 채팅을 허용하되 투표 제출을 받는다.
2. 페이즈 전환은 우선 타이머 없는 트리거(전원 준비 또는 호스트 진행 등)로 구현한다 — 타이머 연결은 이후 슬라이스(S1-2)에서. 전환 트리거 방식은 계획 단계에서 1안을 제시하고 승인받는다.
3. 재투표(joker-A의 5번 규칙)는 DAY_VOTE 내부의 반복으로 동작해야 한다.
4. 전원 기권(유효 투표 0)이면 처형 없이 밤으로 진행한다 (동점 규칙과 별개 케이스).
5. 처형 발생 직후 즉시 승리 조건을 재평가한다 — 원칙: 승리 재평가는 "사망 이벤트 직후 항상" (밤 사망·처형·이후 끊김 사망까지 동일 원칙, S3와 공유).

## 성공 조건

- 토론 중 투표 제출이 거부된다 (6.3)
- 투표 페이즈 진입 후 투표가 정상 집계되고, A의 재투표 규칙이 그대로 동작한다
- 전원 기권 시 처형 없이 밤으로 넘어간다
- 광대 처형 직후 밤 진입 전에 시민 승리가 판정된다

## 성공 조건에 넣지 말 것 (범위 밖 — 수정 금지)

- 시간 기반 자동 전환 (타이머)
- 밤 페이즈

## 자잘한 규칙

- 변경 범위: backend/game-core/gameSession.js의 DAY 페이즈 전이, backend/socket 이벤트, 프론트 낮 UI 상태
- joker-A merge 후에 돌린다 (재투표 규칙 의존)

## 구현 메모 (재개용 — 직전 시도가 gameSession.test.js 재읽기로 중단)

gameSession.test.js를 통으로 재읽지 말 것. 접점은 두 가지뿐: ① DAY 진입 헬퍼를 '토론→ready 전원 제출→투표' 경유로 전진시키면 기존 테스트 대부분이 통과한다 — 헬퍼부터 고쳐라 ② 신규 테스트 6종(토론 거부·준비 전이·재투표·전원 기권·광대 처형 승리·스냅샷)은 파일 끝에 추가하라. 실패하는 기존 테스트만 grep으로 좁혀 겨냥 수정. 백엔드 본체(gameSession.js·socket)는 완성돼 있다 — 남은 것은 테스트와 프론트(파서·스토어·훅·패널) 순서다.
