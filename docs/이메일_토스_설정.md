# 이메일·토스 설정

- 값은 전부 `backend/.env`에만 넣기 (깃에 안 올라감). 이름 목록은 `backend/.env.example`.
- 값 넣은 뒤엔 백엔드 다시 켜기.

## 1. 이메일 (Gmail로 보내기)

비밀번호 재설정 메일·가입 인증번호·소셜 계정 안내 메일이 이걸로 나감.

1. 구글 계정 → 보안 → **2단계 인증** 켜기 (앱 비밀번호는 2단계 인증이 켜져 있어야 보임)
2. 구글 계정 → 보안 → **앱 비밀번호** → 이름 아무거나(예: 가면무도회) → 16자리 받기
3. `backend/.env`에 아래 줄 넣기

```
MAIL_SMTP_HOST=smtp.gmail.com
MAIL_SMTP_PORT=465
MAIL_SMTP_USER=보내는 Gmail 주소
MAIL_SMTP_PASS=앱 비밀번호 16자리
PASSWORD_RESET_MAIL_FROM=가면무도회 <보내는 Gmail 주소>
PASSWORD_RESET_APP_URL=http://localhost:5173
SIGNUP_EMAIL_HMAC_SECRET=길고 무작위인 글자
```

- `PASSWORD_RESET_APP_URL`은 앱 주소(`http://localhost:5173`)나 화면 주소(`…/password-reset`) 둘 다 됨. 링크는 `…/password-reset?token=…` 한 번만 붙음.
- 모바일 화면으로 링크를 열고 싶으면 모바일 주소(`http://localhost:5174`)로 바꾸기.
- 보내는 사람 주소는 `MAIL_SMTP_USER`와 같게 (다르면 Gmail이 바꿔 버림).
- Gmail 하루 보내기 한도 있음(개인 계정 약 500통) → 사람 많아지면 아래 Resend로.

### 확인

```
cd backend
node --env-file=.env scripts/send-test-mail.js 내메일주소
```

- `결과: 보냄`이면 끝. `실패`면 앱 비밀번호·2단계 인증·주소 오타 확인.
- 화면에서: 로그인 화면 → 비밀번호 찾기 → 이메일 입력 → 메일의 링크 열기 → 새 비밀번호.

### 대안: Resend (도메인 있을 때)

- `MAIL_SMTP_HOST`를 비우면 이 방법으로 보냄.
- resend.com 가입 → Domains에서 도메인 인증(DNS 몇 줄) → API Keys에서 키 받기.
- 도메인 인증 전엔 보내는 사람이 `onboarding@resend.dev`만 되고 가입한 본인 메일로만 감.

```
MAIL_SMTP_HOST=
PASSWORD_RESET_MAIL_GATEWAY_URL=https://api.resend.com/emails
PASSWORD_RESET_MAIL_GATEWAY_TOKEN=Resend API 키
PASSWORD_RESET_MAIL_FROM=가면무도회 <no-reply@내도메인>
```

## 2. 토스 결제 (다이아 충전)

- 토스 개발자센터(developers.tosspayments.com) 로그인 → API 키 → **API 개별 연동 키**의 시험 키 두 개.
- 결제위젯 키(`test_gck_`·`test_gsk_`)는 안 됨. `test_ck_`·`test_sk_`로 시작하는 것만.

```
TOSS_TEST_CLIENT_KEY=test_ck_로 시작하는 클라이언트 키
TOSS_TEST_SECRET_KEY=test_sk_로 시작하는 시크릿 키
```

- `TOSS_TEST_SECURITY_KEY`(보안 키)는 웹훅 확인용이라 지금 코드는 안 읽음. 넣어 둬도 됨.
- 키가 없거나 모양이 틀리면 충전 버튼이 "설정 대기"로 바뀌고 주문이 안 만들어짐.

### 시험 키·운영 키 고르는 규칙 (`backend/utils/adapters/toss.js`)

| 환경 | 운영 키(`TOSS_LIVE_*`) | 쓰는 키 |
|---|---|---|
| 개발·시험 (`NODE_ENV`≠production) | 넣어도 무시 | 시험 키(`TOSS_TEST_*`, `test_ck_`·`test_sk_`)만 — 실수로 실제 결제 막기 |
| 운영 (`NODE_ENV=production`) | 하나라도 넣음 | 운영 키(`live_ck_`·`live_sk_`)만, 모양 틀리거나 하나 빠지면 503 (시험 키로 안 내려감) |
| 운영 | 비움 | 시험 키로 돎 + 켤 때 `[STARTUP] 경고` (결제해도 돈이 안 들어옴) |

- 클라이언트 키·비밀 키는 같은 묶음끼리만 (시험 클라이언트 + 운영 비밀 같은 섞기 안 됨)
- 화면(`frontend/src/domains/store/constants/currencyPurchase.js`의 `CLIENT_KEY`, 모바일도 같은 코드): 개발 화면(`npm run dev`)은 `test_ck_`만, 빌드한 화면은 `live_ck_`도 받음 (어느 키 줄지는 서버가 정함)

### 로컬 확인 순서

1. Docker DB 켜기 (`docker start jokertest-db-1`)
2. 시험 상품 넣기 (임시 가격, 운영 상품 아님, 여러 번 돌려도 같음)
   ```
   cd backend
   node --env-file=.env scripts/seed-test-currency-products.js
   ```
3. 백엔드·데스크톱 화면 켜기 → 로그인 → 상점 → 인게임 재화
4. 다이아 상품 고르고 "충전" → 토스 시험 결제창 ("실제 결제가 안되는 테스트입니다" 표시)
5. 결제창에서 카드 고르고 약관 동의 → 결제 → `/store?topup=success…`로 돌아옴 → "충전이 완료되었습니다." → 위 다이아 숫자 늘어남
6. 결제창 닫기 → "결제가 취소되었거나…" 안내, 다이아 그대로
7. 다이아로 금화 상품 "골드 구매" → 금화 늘고 다이아 줄어듦 (다이아 모자라면 "충전하러 가기")

- 결제 뒤 새로고침·창을 닫아도 다음에 상점 들어오면 진행 중 주문을 찾아 마저 지급함.
- 같은 주문은 두 번 지급 안 됨 (서버가 주문·결제 키·장부로 막음).

## 3. 운영 전환 때 바꿀 것

- 토스: 전자결제 계약 뒤 운영 키(`live_ck_`·`live_sk_`) 받음 → 운영 서버 env에 `TOSS_LIVE_CLIENT_KEY`·`TOSS_LIVE_SECRET_KEY` 넣기 (코드는 이미 받음, 위 "시험 키·운영 키 고르는 규칙"). 켤 때 `[STARTUP] 경고 — 운영인데 토스 시험 키…`가 안 뜨는지 확인. docker compose로 띄우면 backend `environment`에 이 이름들을 넘겨야 컨테이너까지 감.
- 상품: 시드 스크립트 쓰지 말고 운영자가 `economy_currency_products` 표에 진짜 가격으로 넣기 (`scripts/seed-test-currency-products.js`는 운영에선 안 돌게 막혀 있음).
- 메일: `PASSWORD_RESET_APP_URL`을 진짜 화면 주소(https)로. 메일 양 많으면 Resend 등 도메인 메일로.
- `JWT_SECRET`·`SIGNUP_EMAIL_HMAC_SECRET`은 운영용 새 값으로.
