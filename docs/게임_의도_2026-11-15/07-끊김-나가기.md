# 끊김·다시 들어오기·나가기·탈락 — 의도와 지금 동작

판 도중·대기방에서 연결이 끊기거나 스스로 나갈 때 서버가 얼마나 기다려 주고, 다시 붙으면 무엇을 돌려주고, 못 돌아오면 어떻게 탈락시키는지 적은 글임.

- 기준: 브랜치 release/2026-11-10 작업 폴더 코드, 운영 규칙(`NODE_ENV=production`)
- 소켓(브라우저와 서버를 잇는 실시간 연결) 사건 이름은 그대로 쓰고 괄호에 뜻
- 승패 규칙 자체 → 05, 판 끝난 뒤 어디로 가나 → 06에서 다룸

## 1. 흐름

### 1-1. 판 도중 산 사람의 연결이 끊김
1. 소켓이 끊기면 `disconnect` 처리기 셋이 따로 돎: 판·접속 상태·대기방 — `backend/socket/socket.js:90-102`
2. 판 쪽: 지금 그 계정의 진짜 소켓일 때만 처리(옛 탭이 늦게 끊긴 것은 무시) — `backend/socket/gameSession/handlers/leave.js:99-100`, `connection/ownership.js:81-100`
3. 산 사람이고 진행 중 단계(ROLE_REVEAL·DAY·NIGHT·TRIBUNAL)면 끊김 유예(grace, 바로 탈락시키지 않고 기다려 줌) 시작 — `handlers/leave.js:108-116`, `game-core/queries/live.js:55-69`, `game-core/queries/constants.js:5`
   - 내 역할 밤 차례 중이면 그 차례 마감 시각까지 타이머 — `connection/grace.js:37-59`
   - 그 밖엔 타이머 없음. 큰 단계(ROLE_REVEAL→DAY→TRIBUNAL→NIGHT)가 바뀌는 순간 만료 — `grace.js:64-71`, 부르는 곳 `phase/day.js:186,255`, `phase/night/turn.js:190`
   - 밤에 다른 역할 차례 중 끊긴 사람도 자기 역할 차례 마감 때 만료됨 — `phase/night/turn.js:121-130` (→ Q07-2)
4. 판 사람 전원에게 `session_player_connection_changed`(누가 끊김·다시 붙음, `isConnected:false`) 한 번 — `handlers/leave.js:112`, `connection/presenceNotice.js:19-29`
5. 밤 연출을 기다리던 사람이면 기다림 명단에서 뺌(상한까지 안 기다리게) — `handlers/leave.js:89-94`
6. 판은 그대로 진행. 끊긴 사람은 계속 "산 사람·투표할 사람"으로 셈 — `game-core/phase/day/ballots.js:5-11`
   - 토론 "준비"를 못 누르니 토론은 시간 끝까지 감 — `game-core/departure/leave.js:158-163`
   - 낮 투표·재판·밤 차례는 마감 때 안 낸 사람을 기권으로 채움 — `phase/day.js:115-120`, `phase/tribunal.js:78-82`, `phase/night/turn.js:132-138`
   - 끊기기 전에 낸 표·밤 행동은 그대로 남음 (지우는 곳은 탈락 처리뿐)
7. 화면: PC 카드에 "연결 끊김" 배지 — `frontend/src/domains/game/ingame/components/board/InGamePlayerStatusOverlay.jsx:13-16`. 모바일은 채팅 줄에 "○○님의 연결이 끊겼습니다"도 남김 — `frontend-mobile/src/domains/game/ingame/utils/talk/playerNotices.js:9-12,36-39`

### 1-2. 끊긴 사람이 다시 붙음
1. 화면은 끊겨도 판을 안 지움, 다시 붙으면 스냅샷(판 전체 모습)으로 복귀 — `frontend/.../hooks/sessionEvents/useSessionConnection.js:3`, 결정 FE-001 `docs/버그수정_결정_2026-11-09.md:106`
2. 서버는 새 소켓이 붙자마자 판 채널(판 사람끼리 받는 방송 통로)에 다시 넣고 유예를 풂 — `socket.js:119`, `connection/routing.js:16-98` (유예 풂 `:46`)
   - 어느 화면에서 붙었는지는 안 봄: 로비 화면으로 붙어도 유예가 풀림 (→ Q07-3, Q07-4)
3. 화면이 `get_session_snapshot`(내 판 상태 묻기) 보냄 → 서버가 또 유예 풂, 채널 밖이면 `SESSION_ROUTING_PENDING`(잠깐 뒤 다시) — `handlers/snapshot.js:89,103-113`, 화면 다시 묻기 250ms·최대 20번·5초 — `frontend/.../hooks/snapshotSync/attempt.js:178-179`, `request.js:10-11`
4. 판 사람들에게 `isConnected:true` (끊김 알린 사람만) — `presenceNotice.js:32-37`

### 1-3. 기다림이 끝남 (탈락)
1. 만료 때 다시 확인: 그사이 붙었거나 이미 죽음·기권·판 끝이면 아무것도 안 함 — `grace.js:82-95`
2. 아니면 "나가기"와 같은 길로 탈락 처리(이유 `DISCONNECT_GRACE_EXPIRED`) — `grace.js:94`, `departure/apply.js:20-91`
   - 죽음 처리(사망 원인 DISCONNECT)·밤 행동 지움·기권 명단·떠난 명단 — `game-core/departure/eliminate.js:10-41`
   - 직업은 공개 안 함: 방송엔 uuid·생존만 — `eliminate.js:53-62`
   - 바로 승패 확인 → 05에서 다룸 (`eliminate.js:33-38`)
3. 방송: `player_eliminated`(탈락, 승부 났으면 전원 정체 칸 덧붙임) → `session_participation_changed`(빠진 사람·방장·참여 번호) → 각자에게 `session_self_progress`(내 제출 상태) — `apply.js:43-71`
4. 막혀 있던 단계 풀기: 남은 산 사람이 다 준비·다 냈으면 바로 다음 단계·판정 — `apply.js:94-137`
5. 빠진 사람은 다시 붙어도 못 돌아옴: 스냅샷이 `FORFEITED_FROM_SESSION` + "연결이 끊겨 이 게임에서 제외되었습니다. 다시 참여할 수 없습니다." — `handlers/snapshot.js:31-40`. 화면은 판을 지우고 /multiplay로 감(글은 안 띄움) — `request.js:21-27,37-41`, `pages/InGamePage.jsx:166-169`

### 1-4. 스스로 "게임 나가기"
1. 확인 창 "게임에서 나가시겠습니까?" — `frontend/.../utils/exitConfirm.js:5`
2. `leave_game_session`(판 나가기) 보냄, 8초 안 답 없으면 "결과 모름" 뒤 스냅샷으로 확인 — `hooks/exit/leave.js:50-74`, `constants/ingameExit.js:5`, `hooks/exit/outcome.js:86-155`
3. 서버: 진행 중 판이면 1-3의 2~4와 같은 처리(이유 `PLAYER_LEFT`), 그 자리에서 바로 — `handlers/leave.js:42-62`
   - 산 사람은 끊김 사망, 죽은 사람은 기권 명단에만 — `game-core/departure/leave.js:102-110`
   - 내 표 지우고 나를 찍은 표는 기권으로, 나를 고른 밤 행동은 빈 값으로 — `leave.js:28-52`
   - 재판 피고였으면 재판 취소(처형 없이) 바로 밤 — `leave.js:55-76`
   - 판 기록에서 풀려 바로 다른 방에 들어갈 수 있음 — `leave.js:117`, `queries/live.js:19-27`
4. 판 채널에서 떼고 대기방 흔적 정리 — `handlers/leave.js:56-61`
5. 끝난 판(결과 화면)에서 나가기는 나만 빼고, 마지막 사람이면 판 지움 → 06에서 다룸 — `handlers/leave.js:65-85`

### 1-5. 대기방에서 끊김·나가기
1. 끊기면 줄(매칭 대기)에서 빼고, 하던 입장 시도 되돌림 — `matchmaking/room/reconnect.js:81-96`
2. 방에 있으면 15초 뒤 빼기 예약 — `reconnect.js:99-110`, `room/leave.js:31-54`, `matchmaking/core/constants.js:12`
3. 15초 안에 `get_current_room`(지금 방 묻기)을 하면 예약 취소 — `reconnect.js:114-151`
4. 빼면 `player_left_room`(방에서 나감), 방장이었으면 `host_changed`(방장 바뀜, 먼저 들어온 사람) — `room/leave.js:88-93,124-150`
5. 마지막 사람이면 방 지움 — `room/leave.js:83-86`
6. `leave_room`(방 나가기)은 15초 없이 바로 같은 처리 — `matchmaking/registerEvents.js:94`
7. 판 시작은 참가자 전원 소켓이 있어야 됨, 하나라도 없으면 "일부 참가자와의 연결을 확인할 수 없습니다" — `room/startLaunch.js:65-80`

### 1-6. 같은 계정으로 다른 창·다른 기기
1. 계정당 소켓 하나: 새 소켓을 목록에 먼저 넣고 옛 소켓에 `force_disconnect`(강제 끊김) 보낸 뒤 끊음 — `connection/presence.js:35-48`
2. 같은 브라우저 다른 창이면 `REPLACED_BY_SAME_SESSION` → 옛 창은 알림만(로그아웃 안 함), 다른 기기면 `REPLACED_BY_OTHER_LOGIN` → 알림 뒤 로그아웃·/login — `connection/replace.js:7-18`, `frontend/src/shared/hooks/useSocket.js:64-71`
3. 옛 소켓 끊김은 판에서 무시(새 소켓이 주인) → 유예 안 걸림 — `ownership.js:81-89`
4. 새 창이 /ingame을 열면 판 번호 없이 스냅샷을 물어 그대로 이어짐 — `e2e/tests/mobile/talk-reconnect.spec.js:68-78`
5. 서버 여러 대면 순번(connseq)이 큰 쪽만 남기고 다른 서버의 옛 탭도 끊음 — `replace.js:50-93`

### 1-7. 관리자 끊기·정지
1. 관리자 끊기: 모든 서버의 그 계정 소켓에 `force_disconnect` + 끊기, 정지·비활성이면 그다음 세션 내림 — `backend/services/ops/disconnect.js:54-76`
2. 정지는 끊기를 안 불러도 5초 주기 검사로 끊김 — `connection/sessionCheck.js:8`, `e2e/tests/ingame/c-chat/admin-disconnect.spec.js:152-156`
3. 판 쪽은 보통 끊김과 똑같음: 유예 → 단계 경계에서 탈락. 정지된 사람은 다시 못 들어와 결국 탈락 — `admin-disconnect.spec.js:143-150`
4. 정지 없는 관리자 끊기는 세션을 안 내려 다시 로그인되고, 다시 붙는 순간 유예가 풀림 → 판에서 안 죽음 (→ Q07-3)

### 1-8. 서버가 꺼짐·서버 여러 대
1. 끌 때: draining 표시 → 새 연결 막기 → `server_shutdown`("서버 점검·업데이트로 잠시 연결이 끊깁니다. 잠시 뒤 자동으로 다시 연결돼요.") → 1.5초 뒤 소켓 닫음 — `backend/utils/processLifecycle.js:5-9,35-60`
2. 판은 메모리에만 있어 다시 켜면 사라짐. 끌 때 판을 저장·끝내는 단계 없음 — `processLifecycle.js:46-55`, `docs/배포_설정.md:63` (→ Q07-7)
3. 다시 붙은 화면이 스냅샷을 물으면 "판 없음"(`SESSION_NOT_FOUND`) → 판 지우고 /multiplay — `handlers/snapshot.js:22-28,76-79`
4. 점검 시각이 되면 이 서버 진행 중 판을 승패 없이 끝냄(전적 `MAINTENANCE`, 진 사람 없음) + `game_ended`(판 끝남) — `departure/maintenanceAbort.js:11-38`
5. 서버 여러 대: 접속 때 그 사람 판이 있는 서버가 따로 있으면 `WRONG_NODE`로 거절 → 화면이 그 서버로 다시 붙음 — `connection/nodeRouting.js:36-56`
6. 판 서버가 죽었으면 위치 기록을 지우고 받음 → 판은 사라짐(설계로 고정) — `nodeRouting.js:43-44`, `docs/노드_여러개_계획_2026-11-09.md:55`
7. 배포는 서버 하나씩 드레인(새 손님 안 받기)하고 판·방 0개 될 때까지 기다린 뒤 바꿈 — `docs/배포_설정.md:250-262`

### 1-9. 판 끝난 뒤 끊긴 사람 정리
- 판 끝 60초 뒤 연결 없는 사람만 끝난 판에서 뺌, 다 빠지면 판 끝 정리 → 06에서 다룸 — `departure/end.js:40-75`, `core/constants.js:77`

- 대기방 화면이 다시 붙을 때 15초 안에 `get_current_room`을 꼭 묻는지 (서버 다시 넣기 `reconnect.js:15-78`는 빼기 예약을 안 풂, 묻기 쪽만 풂)
- 다른 기기에서 밀려난 옛 기기의 로그아웃이 새 기기 세션까지 건드리는지 (`useSocket.js:57-60` logout 안쪽은 안 봄)
- 판 시작 바로 그 순간(소켓 찾은 뒤 `activeGameId` 적기 전) 끊긴 사람은 유예가 안 걸릴 수 있는지 (`startLaunch.js:65-80,117-122`, 짐작)
- 단계 경계에서 탈락 방송과 단계 바뀜 방송의 순서가 화면에 맞는지 (결정 known 1-13 `docs/버그수정_결정_2026-11-09.md:20`)
- 모바일 전용 나가기·사망 후 선택 화면(`frontend-mobile/.../DeadChoiceOverlay.jsx`)은 PC 훅을 쓰는 것만 보고 속은 안 봄
- 서버 2개 시험(`e2e/tests/multinode/**`) 내용은 이름만 봄
- 일부러 안 고친 시험 중 `dead-joker-tribunal:100`은 죽은 광대 채팅 줄 문제라 이 구간 밖 → 채팅 구간 글에서 다룸 (`docs/점검_실패목록_2026-11-10.md:450`)
- 옛 문서(`git show HEAD:docs/architecture-ingame-api-report.md`)는 "판 중 나가기 = 판 중단(ABORTED)", "판 중 추방은 끊김 사망 규칙"이라 말함. 지금은 나가기도 판 계속(시험 `leave-game.spec.js:181,211`), 판 중 추방은 없앰 → 옛 문서가 낡은 것으로 봄
