# 게임 의도 조사 — 글 양식

이 폴더는 "실제 게임이 어떤 의도로 돌아가는지"를 구간별로 적은 것임. 버그를 고치기 전에 **무엇이 맞는 동작인지** 기준을 세우려는 것.

## 하는 일
- 맡은 구간의 코드를 읽고 **의도(이렇게 돌아가야 함)** 와 **지금 동작(코드가 실제로 하는 것)** 을 나눠 적음.
- 읽기만 함. 코드·시험·설정을 고치지 않음. 서버·DB·Redis·브라우저를 띄우지 않음. 시험 묶음을 돌리지 않음(순수 함수를 `node -e`로 한두 번 불러 보는 것은 됨).
- 자기 파일 하나만 씀: `docs/게임_의도_2026-11-15/<맡은 이름>.md`. 임시 스크립트는 저장소 밖 임시 폴더에.
- git으로 바꾸는 명령(add·commit·stash·reset·checkout) 금지. `git show`·`git log`로 읽는 것은 됨.

## 의도를 어디서 읽나 (믿는 순서)
1. 사용자가 정한 것: 한 판은 5~10명. 랜덤 매칭(자동 매칭)을 잠가 둔 것은 일부러임. 개발 환경 전용 규칙(적은 인원으로 시작 등)은 곧 지울 예정이라 "의도"로 치지 않음 — 운영 규칙(`NODE_ENV=production`)이 기준.
2. 결정 문서: `docs/버그수정_결정_2026-11-09.md`, `docs/점검_실패목록_2026-11-10.md`(끝 칸 "사용자가 고를 것"), `docs/known-issues.md`(읽기만).
3. 옛 요구·설계 문서: 작업 폴더에서는 지워졌지만 git에 남아 있음 — `git ls-tree -r --name-only HEAD docs/` 로 찾고 `git show HEAD:<경로>` 로 읽음(`docs/requirements`, `docs/design`, `docs/qa` 등). 오래된 것이라 코드와 다르면 "옛 문서는 이렇게 말함"으로만 적음.
4. 코드 주석(파일 머리·함수 위), 화면에 뜨는 문구, 오류 글.
5. 시험의 이름과 기대값(`backend/tests`, `frontend/tests`, `e2e/tests`) — "이렇게 돼야 한다"가 적혀 있음.
6. 위 어디에도 없으면 **짐작**이라고 적음.

## 글 모양
```
# <구간 이름> — 의도와 지금 동작

(맨 앞 한 문장: 이 글이 무엇을 말하는지)

## 1. 흐름
사람이 무엇을 하면 → 서버가 무엇을 하고 → 누구 화면에 무엇이 보이는지, 차례대로 번호. 단계마다 근거 `파일:줄`.
소켓 사건(주고받는 알림) 이름은 그대로 쓰고 괄호에 뜻.

## 2. 규칙 표
| 규칙 | 값 (시간·인원·횟수) | 근거 (파일:줄) | 의도를 읽은 곳 |

## 3. 갈림길
경우마다 어떻게 되는지: 동점, 아무도 안 고름, 시간 끝, 한 사람만 남음, 방장이 나감 … 구간에 맞는 것 전부.
| 경우 | 의도 | 지금 동작 | 근거 |

## 4. 의도가 갈리는 곳 (사용자가 고름)
코드·주석·시험·옛 문서·화면(PC와 모바일)이 서로 다르게 말하거나, 의도가 어디에도 안 적힌 곳.
항목마다: 무엇이 갈리나 / 어디(파일:줄) / 플레이하는 사람이 겪는 모습 / 고를 수 있는 안 2~3개(추천 하나, 까닭 한 줄).

## 5. 버그로 보이는 곳
의도는 분명한데 코드가 다르게 도는 곳. 항목마다: 겪는 모습 / 왜 그런지(파일:줄) / 다시 겪는 차례(짐작이면 "짐작") / 얼마나 큰가(판이 멈춤 · 잘못된 결과 · 보기만 이상함).
고치지 않음. 확실하지 않으면 4번에 넣음.

## 6. 확인 못 한 것
```

## 규칙
- 쉬운 우리말, 개조식(~함/~음/~기), 짧게. "~합니다·~해요" 금지. 개발 용어는 지우지 않고 처음 한 번 뒤 괄호에 우리말. 규칙 전체: `~/.claude/skills/easy-doc/SKILL.md`.
- 코드를 옮겨 적지 않음. `파일:줄`로 가리킴. 줄 번호는 지금 작업 폴더 기준.
- 사실과 짐작을 섞지 않음. 직접 읽은 것만 사실로 적음.
- 다른 구간 것은 깊이 안 들어감: "→ <그 구간 파일>에서 다룸" 한 줄.
- 비밀값·`.env` 값·개인 정보·사용자 폴더 경로 금지(이 저장소는 공개임).
- 5번·4번은 번호를 붙임: 파일 이름 앞 숫자를 써서 `B03-1`, `Q03-1`처럼 (B=버그로 보임, Q=사용자가 고름).

## 보고 (짧게)
통과/막힘 + 글 줄 수, 4번·5번 항목 수와 제목 한 줄씩, 확인 못 한 것.
