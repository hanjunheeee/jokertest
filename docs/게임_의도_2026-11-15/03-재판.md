# 재판 — 의도와 지금 동작

낮 투표로 피고가 정해진 뒤부터 유죄·무죄 판정을 거쳐 밤 또는 판 끝으로 넘어가기까지, 의도와 지금 코드 동작을 나눠 적은 글.

- 범위: 피고가 정해진 순간 ~ `tribunal_vote_resolved`(재판 결과 알림) 방송과 다음 단계 타이머까지.
- 낮 투표 자체 → 02에서 다룸. 밤 → 04에서 다룸. 승패 판정 규칙·결과 화면 → 05에서 다룸 (여기선 "재판 끝에 승패를 확인함" 한 줄만).
- 끊김 유예(다시 붙기 기다리는 시간) 자체 → 나가기·끊김 구간 파일에서 다룸.

## 1. 흐름

1. 낮 투표 판정에서 최다 득표 1명 → 판 단계가 `TRIBUNAL`로 바뀌고 재판 상태(피고·날짜·빈 표 묶음)가 생김. `backend/game-core/phase/day/resolve.js:124-133`
2. 서버가 재판 마감 타이머를 먼저 걸고, 마감 시각(`tribunalDeadline`)을 실은 `day_vote_resolved`(낮 투표 결과 알림)를 전원에게 보냄. `backend/socket/gameSession/phase/day.js:157-168`, 타이머 `backend/socket/gameSession/phase/tribunal.js:29-56`
3. 화면에 재판 연출 창이 뜸: 피고 카드 + 유죄·무죄 버튼 먼저, 약 1초 뒤 옆에 "최후의 반론" 채팅이 열림. 아래 판 화면은 잠김, Esc로 안 닫힘.
   - PC `frontend/src/domains/game/ingame/components/tribunalPresentation/InGameTribunalPresentationOverlay.jsx:61-96`, 1초 = `constants/tribunalPresentation/ingameTribunalPresentationLayout.js:51`
   - 모바일 `frontend-mobile/src/domains/game/ingame/components/overlays/tribunal/TribunalGate.jsx`
4. 피고는 "당신은 피고인입니다. 투표할 수 없습니다.", 죽은 사람은 "사망한 참가자는 투표할 수 없습니다." 안내만 보임. `frontend/src/domains/game/ingame/utils/resolveInGameTribunalPresentationNotice.js:9-19`, 문구 `constants/actions/ingameActionPanel.js:66-68`
5. 투표할 수 있는 사람(산 사람 중 피고 뺀 전원)이 유죄·무죄를 누름 → `cast_tribunal_vote`(재판 표 보내기) → 서버가 한 사람 한 표로 적음, 바꾸기 없음. `backend/game-core/phase/tribunal/vote.js:18-70`
   - 낸 사람 화면엔 "투표가 완료되었습니다.", 서버는 그 사람에게만 진행 상태(낸 수/필요 수)를 보냄. `backend/socket/gameSession/handlers/tribunal.js:92-100`, `backend/game-core/snapshot/progress.js:39-48`
6. 같은 시간에 채팅: 산 사람(피고 포함)은 낮 채널, 죽은 사람은 죽은 사람 채널로만 씀. 따로 "피고만 말하는 시간"은 없음. `backend/game-core/chat/rules.js:38-50`
7. 판정은 셋 중 하나로 시작됨
   - 재판 마감: 안 낸 산 사람을 기권(`ABSTAIN`)으로 채운 뒤 판정. 실패하면 1초 간격 최대 5번 다시. `backend/socket/gameSession/phase/tribunal.js:68-98`, `core/constants.js:73-74`
   - 누가 나간 뒤 남은 사람이 다 냄: 바로 판정. `backend/socket/gameSession/departure/autoResolve.js:52-81`, `departure/apply.js:123-125`, `handlers/tribunal.js:102`
   - `resolve_tribunal_vote`(재판 판정 요청): 판에 있는 누구나 보낼 수 있고, 전원이 냈을 때만 통과. `backend/socket/gameSession/handlers/tribunal.js:109-165`, `backend/game-core/phase/tribunal/resolve.js:41-45`
8. 판정 준비(prepare): 표 세서 결과만 정함 → 확정(commit): 그사이 표·피고·날짜가 안 바뀌었는지 다시 보고 확정. `backend/game-core/phase/tribunal/resolve.js:13-69`, `:72-112`
9. 유죄면 피고 죽음(죽은 이유 `EXECUTION`), 재판 결과 기록, MVP 점수 쌓음. `resolve.js:115-124`
10. 재판 끝에 승패를 확인함 → 05. 승부 나면 판 끝(`ENDED`), 아니면 같은 날짜 그대로 밤(`NIGHT`)으로. `resolve.js:130-138`, 밤 시작 `backend/game-core/core/rules/terminal.js:40-45`
11. `tribunal_vote_resolved` 방송: 피고·결과·유죄/무죄 수·처형된 사람·처형된 사람 직업(`executedRole`). 판 끝이면 승패 칸도 붙음. `resolve.js:142-159`, `handlers/tribunal.js:137-162`
12. 화면: 유죄면 추방 영상 → "[닉네임]님이 가면무도회에서 추방당하셨습니다." 문구 → 밤 안내. 무죄면 문구 없이 밤. `frontend/src/domains/game/ingame/hooks/useInGameTribunalExpulsionPresentation.js:91-111`, 문구 `constants/ingameTribunalExpulsionPresentation.js:56-62`, 상태 반영 `store/applyTribunalResolved.js:31-164`
13. 다음 단계 타이머 맞춤: 재판 타이머 끔, 밤 차례 시작(→ 04). 단계가 바뀌며 끊김 유예도 끝냄. `backend/socket/gameSession/phase/day.js:252-277`

## 4. 의도가 갈리는 곳 (사용자가 고름)

### Q03-1. 전원이 다 냈는데 마감까지 기다림
- 무엇이 갈리나: 나간 사람이 없으면 전원이 투표해도 판정이 안 되고 마감(15~120초)까지 기다림. 나간 사람이 한 명이라도 있으면 다 내는 순간 바로 판정.
- 어디: `backend/socket/gameSession/handlers/tribunal.js:102`, `departure/autoResolve.js:16-25`, `departure/marks.js:12-13`. PC 운영 화면엔 판정 버튼 없음 `frontend/.../InGameTribunalPresentationGate.jsx:21-22`. 시험은 개발 버튼으로 "타이머를 안 기다리고 판정됨"을 기대 `e2e/tests/ingame/a-day/tribunal.spec.js:97`
- 겪는 모습: 다 눌렀는데 남은 시간 동안 연출 창에 갇혀 기다림. 같은 상황인데 누가 나갔던 판만 빨리 끝남.
- 안:
  - (추천) 전원이 내면 바로 판정: 기다릴 까닭이 없고, 나간 사람 있을 때와 같아짐.
  - 늘 마감까지 기다림: 최후의 반론 시간을 보장. 이때는 나간 사람 있을 때 바로 판정도 빼야 앞뒤가 맞음.

### Q03-2. 처형된 사람 직업·유죄/무죄 수를 화면에 보여 줄지
- 무엇이 갈리나: 서버는 `executedRole`·`counts`를 보내고 옛 문서도 "역할을 공개"라 적었지만, PC·모바일 화면 어디에도 안 씀.
- 어디: 서버 `backend/game-core/phase/tribunal/resolve.js:154-157`, 옛 문서 `git show HEAD:docs/architecture-ingame-api-report.md` 재판 절, 화면 `frontend/src/domains/game/ingame/hooks/useInGameTribunalExpulsionPresentation.js:91-111`(닉네임만 씀), `store/applyTribunalResolved.js`(직업 안 읽음)
- 겪는 모습: "[닉네임]님이 추방당하셨습니다."만 보이고 그 사람이 광대였는지, 몇 대 몇이었는지 모름.
- 안:
  - (추천) 직업은 숨김 유지, 서버 방송에서도 빼기: 추리 게임이라 처형 직업 비공개가 긴장감 유지, 화면에 안 쓰는 값이 개발자 도구로 새는 것도 막음.
  - 직업 공개: 추방 문구에 직업을 붙임 (옛 문서 의도).
  - 수만 공개: "유죄 3 : 무죄 2" 표시, 직업은 숨김.

### Q03-3. 재판 동안 말하는 사람
- 무엇이 갈리나: 창 이름은 "최후의 반론"이지만 산 사람 누구나 같은 낮 채널로 씀. 피고만 말하는 토막은 없음.
- 어디: `backend/game-core/chat/rules.js:49`, `frontend/.../InGameTribunalPresentationChatPanel.jsx:1,24`, 미리보기 문구 `tribunalPresentationPreviewFixture.js:21`
- 겪는 모습: 피고 변론이 다른 사람 말에 묻힐 수 있음.
- 안:
  - (추천) 지금처럼 모두 말함: 미리보기 문구 "각자 의견을 말해 주세요."와 맞고, 토막을 늘리면 시간이 길어짐.

### Q03-4. 모바일 재판 창의 "재판 판정" 버튼

## 5. 버그로 보이는 곳

### B03-1. 모바일에서 피고를 판 명단에서 못 찾으면 재판 창이 안 뜸
- 겪는 모습: 모바일 화면에 재판 창이 안 떠서 유죄·무죄를 못 누름 → 마감 때 기권 처리. 채팅방도 재판 중엔 가려져 채팅도 못 할 수 있음(짐작).
- 왜: 모바일 문지기는 피고를 못 찾으면 아무것도 안 그림 `frontend-mobile/src/domains/game/ingame/components/overlays/tribunal/TribunalGate.jsx:37-41`. PC는 같은 경우 기본 그림으로 띄우게 고침 `frontend/.../InGameTribunalPresentationGate.jsx:45-57`, 결정 `docs/버그수정_결정_2026-11-09.md:123` "안 띄우면 채팅이 둘 다 사라짐".
- 다시 겪는 차례: 짐작 — 다시 붙은 직후 등 판 명단이 아직 안 채워진 순간에 재판이 시작되면.
- 얼마나 큰가: 잘못된 결과 (그 사람 표가 기권으로 빠짐).

## 6. 확인 못 한 것

- 재판 창이 덮은 동안 남은 시간(타이머 바)이 화면에 실제로 보이는지: 타이머 값은 받음(`frontend/src/domains/game/ingame/utils/timebar/phaseDeadline.js:22`), 창 아래에 가려지는지는 화면을 안 띄워 못 봄. 결정 `:114`의 "tribunalDeadline 화면에 안 씀(보류)"는 뒤에 바뀐 듯(`phase/day.js:155` 주석 2026-11-09) — 지금 화면 상태 확인 못 함.
- 마감 판정이 5번 다 실패하면 재판이 멈춘 채 남음(`phase/tribunal.js:92-94`, 로그만 남김). 실제로 5번 연속 실패할 길이 있는지는 못 찾음.
- e2e 시험 일부가 3명 판(`tribunal.spec.js:279`)으로 돌아 개발 전용 인원 규칙에 기댐. 운영(5~10명)에서 같은 결과인지는 시험으로 확인 못 함.
- 재판 중 끊긴 사람의 유예가 재판 안에서 끝나는 경우(유예 시간 vs 재판 시간) 순서 → 나가기·끊김 구간 파일에 맡김.
- 화면·서버 시험은 돌리지 않음(읽기만). `node -e` 실행도 안 함 — 표 세기 규칙은 시험 이름·기대값과 코드로만 확인.
