# 버그로 보이는 것 — 다시 확인한 결과

구간 글 01~09가 "버그로 보인다"고 적은 12개와, 판이 멈추거나 사람이 갇히는 의도 갈림 7개를 코드에서 다시 따라가 봤음 — 뒤집힌 것은 없고, 4개는 "일부만 맞음"(겪는 차례가 코드로 안 만들어지거나 짐작 일부가 틀림)임.

- 줄 번호는 지금 작업 폴더(브랜치 release/2026-11-10) 기준. 경로 앞 `be/` = `backend/`, `fe/` = `frontend/src/`, `mo/` = `frontend-mobile/src/`.
- 확인 방법: 코드 읽기 + 시험 기대값 읽기 + 결정 문서(`docs/버그수정_결정_2026-11-09.md`)·점검 실패 목록(`docs/점검_실패목록_2026-11-10.md`)·알려진 문제(`docs/known-issues.md`) 찾기. 서버·브라우저·시험 묶음은 안 돌림. 순수 함수 하나(B07-1)만 `node`로 불러 봄.
- 판정 뜻: **맞음** = 코드로 그 길이 닿음 / **일부만 맞음** = 코드 빈틈은 맞지만 겪는 차례나 짐작 일부가 다름 / **틀림** = 막는 곳이 따로 있음 / **확인 못 함** = 띄워 봐야 앎.
- 판정 개수: 맞음 15 · 일부만 맞음 4 · 틀림 0 · 확인 못 함 0 (단 Q04-7은 "멈추는 장치"만 맞음, 멈추는 길은 확인 못 함).

## 항목마다

이 장은 항목마다 구간 글 말 → 내가 본 것 → 시험·문서 → 판정 → 다시 겪는 차례 → 고칠 곳 순서로 적음.

### B06-1 파티를 떠난 사람도 방장 새 방에 끌려 들어감
- 구간 글이 말한 것: "로비로"로 끝난 판에서 빠진 사람도 자동 입장 명단에 남아, 방장 새 방에 "준비 안 함"으로 들어감.
- 내가 본 것:
  - 자동 입장 명단은 방장·기권(판 중 나감)만 뺌. 떠난 명단(detachedUuids)은 안 봄 — `be/game-core/queries/ended.js:16-22`, `queries/participation.js:6-15`.
  - "로비로"는 떠난 명단에 넣고 내 판 기록만 지움, 판의 사람 목록(players)엔 그대로 — `be/game-core/core/registry/write.js:50-54`.
  - 자동 입장은 방·처리 중·줄·연결만 봄 — `be/socket/matchmaking/join/join.js:72-81`. 입장 앞 검사의 "게임 중" 거절도 끝난 판은 안 막음 — `be/game-core/queries/live.js:23-26`, `join/guards.js:17-28`.
  - 로비 화면엔 `room_joined`(방 들어감 알림) 듣는 곳이 없음. 멀티 화면만 들어서 대기방으로 옮김 — `fe/domains/game/mode/socket/rooms.js:19,35`, `mode/hooks/usePublicRooms.js:28-34`.
  - 시작은 전원 준비여야 함 — `be/socket/matchmaking/room/start.js:165-167`.
  - 기다림 화면 "방 나가기"는 `leave_room`만 보내 끝난 판에 묶인 채 남음 — `fe/domains/game/matching/hooks/useMatchingPage.js:120-126`.
- 시험·문서: 서버 시험은 "자동 입장 **뒤** 로비로" 차례만 봄(`be/tests/socket/matchmaking.partyRejoin.test.js:164`). e2e `e2e/tests/result/nav.spec.js:31-37`은 "방 나가기 → 목록"까지만 보고 그 뒤 방장 새 방은 안 봄. 결정 문서 `:23`은 "자동 입장 자리는 로비로 누르면 빠져야 함"이라 의도와 반대. 알려진 문제 목록엔 없음.
- 판정: **맞음**. 막는 검사를 다른 곳에서 못 찾음.
- 다시 겪는 차례 (5명 판):
  1. 판 끝 → B "로비로" → 확인 → 로비.
  2. 방장 A "대기방으로" → 서버가 B를 A 방에 넣음.
  3. A "시작" → "아직 준비하지 않은 참가자가 있습니다." / B 로비에서 방 만들기 → "이미 참여 중인 방이 있습니다."
  4. B가 멀티 화면에 있었으면 화면이 A 방으로 끌려감.
- 얼마나 큰가: 판이 멈춤(방장이 B를 강퇴할 때까지) + B 갇힘(B는 방에 있는 줄 모름, 창 닫고 15초 지나야 풀림).
- 고칠 곳 후보: `be/game-core/queries/ended.js:18-21` 떠난 명단도 건너뛰기 (같은 묶음 `getEndedPlayerUuids` `:55-58`도).

### Q06-4 결과 화면에 머무는 사람이 새 방에 박힘
- 구간 글이 말한 것: 결과 화면 사람도 자동 입장되지만 화면은 모르고, 방장은 시작을 못 함.
- 내가 본 것:
  - 자동 입장은 어느 화면에 있는지 안 봄, 연결만 있으면 넣음 — `be/socket/matchmaking/join/join.js:72-91`.
  - 결과 화면(인게임 사건 묶음)은 `party_matching_room_ready`(파티 방 준비됨)를 적어 두기만 함 — `fe/domains/game/ingame/hooks/sessionEvents/roomHandlers.js:62-65`. `room_joined`는 결과 화면에서 안 들음.
  - 결과 화면엔 시간 제한·자동 이동 없음 — 서버·화면 둘 다 못 찾음(구간 글과 같음).
- 시험·문서: 이 경우를 보는 시험 못 찾음. 결정·알려진 문제에 없음.
- 판정: **맞음**. 결과 영상을 오래 보는 사람이 있으면 흔히 생김(짐작: 방장이 먼저 누르는 일이 잦음).
- 다시 겪는 차례: 판 끝 → C는 결과 화면 그대로 → 방장 "대기방으로" → 나머지 "대기방으로"·준비 → 방장 "시작" → 준비 안 한 사람 있음으로 거절. C가 "대기방으로"를 누르면 풀림.
- 얼마나 큰가: 판이 멈춤 (C가 누르거나 강퇴될 때까지).
- 고칠 곳 후보: `fe/domains/game/ingame/hooks/sessionEvents/roomHandlers.js:62-65` 결과 화면에 "새 방 생김" 띠, 또는 `be/socket/matchmaking/join/join.js:72-81`에서 "대기방으로"를 누른 사람만 넣기.

### Q06-2 방장이 판 끝 뒤 먼저 떠나면 헛기다림
- 구간 글이 말한 것: 끝난 판에선 방장이 안 넘어가 아무도 파티 방을 못 만들고, 기다리던 사람은 3분 뒤 목록.
- 내가 본 것:
  - 끝난 판 빼기는 방장 칸(hostUuid)을 안 건드림 — `be/game-core/core/registry/write.js:47-65`.
  - 파티 문맥은 "방장이 아직 끝난 판에 묶여 있음"일 때만 — `be/game-core/queries/ended.js:11-15`. 방장이 빠지면 알림·우편함·자동 입장 다 안 함 — `be/socket/matchmaking/join/party.js:62-65`, `join/join.js:69-70`.
  - 참가자가 만든 방은 개인 방(BE-005) — 결정 문서 해당 줄.
  - 기다림은 2.5초마다 묻고 3분(180000ms)이면 끝 — `fe/domains/game/matching/constants/roomTiming.js:17-20`, `hooks/room/partyRejoinPoll.js:41`. "방장 나감"을 알려 주는 답은 없음 — `party.js:42-58`.
- 시험·문서: 이 경우를 보는 시험 못 찾음. 결정·알려진 문제에 없음.
- 판정: **맞음**.
- 다시 겪는 차례: 판 끝 → 참가자 넷 "대기방으로"(기다림 화면) → 방장 "로비로"(또는 새로고침, Q06-1) → 넷 다 "방장이 새 방을 만드는 중입니다"를 3분 봄 → 알림 → 목록.
- 얼마나 큰가: 3분 헛기다림. "방 나가기"로 빠질 수는 있어 갇힘은 아님.
- 고칠 곳 후보: `be/game-core/core/registry/write.js:52-54` 끝난 판에서 방장이 빠지면 남은 사람에게 넘기기, 또는 `be/socket/matchmaking/join/party.js:42-58`가 "방장 없음"을 답하기.

### Q05-2·Q06-1 결과 화면에서 새로고침·잠깐 끊기면 바로 빠짐
- 구간 글이 말한 것: 결정 BE-020 이유("60초면 다시 붙을 시간 넉넉")와 달리, 결과 화면에서 끊기면 바로 끝난 판에서 뺌. 05 글은 "파티 방 찾기도 안 될 수 있음(짐작)"까지 적음.
- 내가 본 것:
  - 끝난 판 끊김 = 그 자리에서 빼고 마지막이면 판 끝 마무리 — `be/socket/gameSession/handlers/leave.js:130-138`. 유예 없음.
  - 60초 정리는 판 끝 순간 연결 없던 사람만 — `be/socket/gameSession/departure/end.js:38-75`.
  - 방장이면 파티 문맥이 없어짐 → Q06-2와 같음 — `be/game-core/queries/ended.js:11-15`.
  - **짐작과 다른 점**: 다음 방 우편함 자격(`canLookupPartyRoom`)은 판의 사람 목록만 보고 떠난 명단은 안 봄 — `be/game-core/queries/ended.js:38-46`. 판 id를 알면(기다림 화면은 판 id를 저장소에 적어 둠) 우편함은 그대로 읽힘. 판 id 없이 물으면 못 찾음(`ended.js:27-35`). 그리고 자동 입장은 이 사람도 그대로 끌어들임(B06-1과 같은 원인).
