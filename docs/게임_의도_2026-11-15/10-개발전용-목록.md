# 개발 환경에서만 다르게 도는 것 — 목록과 지우면 걸리는 것

(맨 앞 한 문장) 운영(`NODE_ENV=production`)과 다르게 도는 곳 40개를 6묶음으로 나눠 적고, 지우면 걸리는 시험 수를 셈 — **가장 크게 걸리는 것은 "적은 인원 판"(브라우저 시험 약 357개·백엔드 시험 파일 약 32개)과 "/e2e 시험 손잡이"(브라우저 시험 약 1,300개)**이고, 지울지 말지는 5번에서 사용자가 고름.

- 읽기만 한 조사. 줄 번호는 지금 작업 폴더(release/2026-11-10) 기준.
- 시험 수는 grep·간단한 글 읽기 스크립트로 센 **어림값**. 시험을 돌려 본 숫자 아님.
- 브라우저 시험 수는 `e2e/시험목록_2026-11-10.json`(2,546개, 프로젝트별: desktop 1,822 · mobile 329 · mobile-safari 329 · admin 30 · admin-phone 5 · serial 30 · admin-phone-serial 1) 기준. 같은 파일을 mobile·mobile-safari가 두 번 돌리므로 같은 시험이 두 번 셈됨.
- "운영 판정" 한 곳: `backend/config/nodeEnv.js:8` (`NODE_ENV === "production"`일 때만 운영). 빈 값·값 없음은 개발로 침(`nodeEnv.js:11-15`), 오타는 시작 거부.

### 빈틈 (사실 + 짐작 표시)
1. **`NODE_ENV=development`라고 정확히 적으면 아무것도 안 막음.** 운영 서버의 `.env.production`에 루트 `.env.example`(값 `development`, `.env.example:46`)을 그대로 베끼면 compose가 그 값을 넘김(`docker-compose.yml:68`의 `${NODE_ENV:-production}`은 "비었을 때만" production). 그러면 2명 판·정원 4·쿠키 https 끔·500 스택 응답·Origin 없는 소켓 허용·관리자 Access 끄기 가능이 한꺼번에 켜짐. "운영 주소(https FRONTEND_URL)인데 개발" 같은 거부는 없음.
2. **Docker·pm2 없이 `node index.js`/`npm start`로 켜면** `NODE_ENV`가 비어 개발로 뜸(`nodeEnv.js:11-15`, `index.js:37`은 경고만). 배포 문서 길(docker·pm2)만 따르면 안 생김.
3. **씨앗 스크립트는 `NODE_ENV`만 봄.** 로컬(개발)에서 `DATABASE_URL`을 운영 DB로 두고 돌리면 tester 계정·시험 상품이 운영 DB에 들어감. 부하 시험은 로컬 DB인지 따로 봄(`loadtest/run.js:240`)인데 씨앗 두 개는 그런 검사 없음.
4. **개발 판이 운영 판으로 기록됨**(바1). 개발 서버를 운영 DB에 붙이면 전적·역할 통계에 섞임. 통계 제외 표의 `development`는 쓰이지 않는 값.
5. **화면 `?outcome=` 미리보기는 운영 빌드에서도 열림**(마7). 가짜 판 결과가 누구 화면에나 뜰 수 있음 — 서버 값은 안 바뀜(화면만, 짐작).
6. **`__…ForTests` 함수 53개는 운영 코드에 늘 있음**(나8). 밖에서 부르는 길(경로·소켓 사건)은 찾지 못함 → 지금은 위험 없음으로 봄(짐작: 다른 구간 에이전트가 경로 쪽을 볼 것).
7. 시작 거부 목록(`E2E_ONLY_KEYS`)에 `GAME_DEV_MIN_PLAYERS`·`ADMIN_ACCESS_MODE`·`ADMIN_ACCESS_CERTS_URL`·`DEV_TESTER_PASSWORD`는 없음. 운영에서 무시되므로 해는 없지만, 빈틈 1과 겹치면 바로 살아남.

### Q10-1 게임 규칙 개발 편의((가) 묶음)를 어디까지 지울지
- 안 A — **전부 지움**: 어디서나 5~10명. 3번 표대로 백엔드 약 32파일 + e2e 357개를 5명 판으로 고침. 규칙이 하나라 헷갈림 없음, 대신 고칠 양 가장 많고 e2e가 무거워짐.
- 안 B — **개발 서버에선 지우고, 시험 손잡이 켤 때만 남김**: 판정을 `isProduction` 대신 "시험 훅 켜짐(`E2E_HOOKS=1`) 또는 `NODE_ENV=test`"로 옮김. 손으로 띄운 개발 서버는 운영 규칙, 시험만 작은 판. 운영에선 훅 값이 있으면 시작 거부라 새는 길이 없음. 고칠 시험은 판정 자체를 보는 몇 파일뿐(어림 10파일 안쪽).
- 안 C — 그대로 둠, 4번 빈틈 1만 막음(운영 주소인데 개발이면 거부 등).
- **추천: 안 B.** 까닭: "개발 환경은 필요 없음"이라는 뜻(개발 서버 = 운영 규칙)은 지키면서, 브라우저 시험 357개·백엔드 32파일을 지금 다시 짜지 않아도 됨. 나중에 안 A로 가는 것도 막지 않음.

## 6. 확인 못 한 것
- 시험 수는 모두 정적 어림. 특히 e2e "작은 판 357개"는 시험 구간 안의 `bots: N` 글자로 셈 — 감싸개 함수가 봇 수를 위치 인자로 받거나(`citizenTable(table, user, settings, bots)`), 도우미 파일(`tests/ingame/b-night/_night/table.js`, `tests/mobile/_talk.js`, `tests/ingame/c-chat/_lib.js`) 안에서 인원을 정하는 경우는 덜 셌거나 더 셌을 수 있음.
- 백엔드 32파일 안에서 실제로 깨지는 `test(` 수는 못 셈(파일 안 시험 합 1,298개 중 일부).
- 시험을 `NODE_ENV=production`으로 실제로 돌려 보지 않음(규칙상 시험 묶음 안 돌림).
- 화면이 방 정원 선택지로 4를 보여 주는지(화면 쪽 정원 표)는 깊이 안 봄 → 방 만들기 구간 글에서 다룰 일.
- `__…ForTests` 53개를 밖에서 부를 길이 정말 없는지는 이름으로만 찾음(경로·소켓 사건 목록 전수 대조는 안 함).
- 운영 서버의 실제 `.env.production` 내용은 안 봄(규칙상 `.env` 값 안 읽음) — 빈틈 1이 지금 운영에 해당하는지 모름.
- `docs/CI_CD.md`가 말하는 CI 설정은 저장소에 `.github/workflows`가 없어 대조 못 함.
