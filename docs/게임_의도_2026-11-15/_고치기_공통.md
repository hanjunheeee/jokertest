# 고치기 공통 규칙 (고치는 에이전트 모두 읽음)

이 글은 `고치기_계획.md`의 단위를 맡은 에이전트가 똑같이 지킬 것을 적음.

## 먼저 읽을 것
1. `docs/게임_의도_2026-11-15/고치기_계획.md` — **1장의 내 단위 글 전부**(끝난 모습·바꿀 파일·주고받는 것·"시험 단계가 꼭 넣을 케이스"), 2장에 내 단위 설계가 있으면 그것, 3-2장(겹치기 쉬운 파일을 누가 맡나), 3-3장의 내 줄.
2. `docs/게임_의도_2026-11-15/결정.md` — 내 단위가 온 결정 줄(사용자 뜻). 맨 아래 "반장이 임시로 정한 것" 표도. **결정이 정답임.** 계획 글과 결정이 다르면 결정을 따르고 보고에 적음.
3. 스킬(꼭): `~/.claude/skills/impact-check/SKILL.md`(고치기 전에 그 파일을 바꾸면 어디가 영향받는지 먼저 찾음), `~/.claude/skills/comment/SKILL.md`(주석 말투), 화면을 고치면 `~/.claude/skills/ui-check/SKILL.md`, 버그를 고치는 단위면 `~/.claude/skills/bug-fix/SKILL.md`(원인부터 확인), 글을 쓰면 `~/.claude/skills/easy-doc/SKILL.md`.

## 하는 일
- 내 단위의 **코드만** 고침. 3-3장 내 줄의 "맡는 파일"과 1장 내 단위 글의 "바꿀 파일" 밖은 고치지 않음. 새 파일은 계획에 적힌 것만.
- 고치기 전에 바꿀 함수·값·소켓 사건을 **누가 쓰는지 grep으로 찾음**(서버·PC `frontend/src`·모바일 `frontend-mobile/src`·e2e 도우미). 내 범위 밖 파일이 같이 바뀌어야 하면 **고치지 말고 보고의 "범위 밖에서 같이 바뀌어야 하는 것"에 파일:줄과 무엇을 바꿔야 하는지 적음**(다른 에이전트가 그 파일을 고치는 중일 수 있음).
- 모바일은 PC 코드를 같이 씀(`@` → `frontend/src`). PC 파일을 고치면 모바일이 그 파일을 쓰는지, 모바일에 베껴 둔 사본이 있는지 확인.
- 서버가 여러 대(Node 여러 개)일 때도 맞게 도는지 생각함(`backend/cluster/**`·`backend/socket/matchmaking/cluster/**`가 같은 값을 다루는지).
- DB를 새로 부르는 코드는 사람마다·요청마다 부르지 않게(계획 2장 설계대로).

## 시험
- **시험 묶음을 돌리지 않음. 시험 파일을 새로 쓰지 않음.** (사용자 규칙: 시험은 고치기가 다 끝난 뒤 따로 만들고 한 번에 돌림.) 옛 시험은 전부 지워져 있음.
- 끝난 뒤 가벼운 확인만: 고친 파일에 `npx eslint <파일>`(그 폴더에 eslint 설정이 있을 때), 서버 파일은 `node -e "require('./경로')"`로 불러 보기(DB·서버에 안 붙는 것만), 화면은 `frontend`·`frontend-mobile`에서 `npx vite build`(오래 걸리면 한 번만). 순수 함수는 `node -e`로 한두 번 불러 결과를 봐도 됨.
- 남아 있는 시험 도우미(`backend/tests/helpers/**`, `e2e/helpers/**`, `e2e/tests/**/_*.js`)가 내가 바꾼 것을 쓰면 계획에 내 몫으로 적힌 것만 고치고, 나머지는 보고에 적음.
- `frontend/tests/domains/game/ingame/store/participantDeparture.test.js`는 사용자가 고치는 중 — 읽기만, 절대 안 고침.

## 주석
- 사용자 말투: 개조식 명사형 끝맺음(~함/~음/~기), 쉬운 우리말(영어 용어·어려운 말 금지, 코드 이름은 그대로), **이유만** 짧게. 파일 머리 주석 2줄은 내용이 바뀌면 같이 고침. 지운 코드를 주석으로 남기지 않음. 낡게 된 주석은 고침.

## 절대 하지 않는 것
- git으로 바꾸는 명령(add·commit·stash·reset·checkout·restore·rm) — 커밋은 반장이 함. `git diff`·`git log`·`git show`·`git status`는 됨.
- 있는 마이그레이션 고치기(새 번호만), `.env`·`.env.*` 값 읽기·고치기(`.env.example`은 계획에 있을 때만), `.claude/**`·`docs/known-issues.md`·`e2e/.tmp-check` 건드리기, `npm install`, 서버·브라우저 띄우기, DB에 붙기(`joker_realgame`은 어떤 경우에도 금지), Docker 켜고 끄기, 포트 4000 서버 건드리기, 파일 영구 삭제(계획이 "지움"이라 한 추적되는 코드 파일은 작업 폴더에서 지워도 됨 — git 기록에 남음. 영상·그림 같은 자료 파일은 지우지 않음).
- 공개 저장소임: 비밀값·개인 정보·사용자 폴더 경로를 코드·주석·글에 넣지 않음.

## 보고 (짧게, 한국어 개조식)
- **통과 / 문제 있음 / 막힘** 한 줄.
- 바꾼 파일 목록(새로 만든 것·지운 것 따로), 파일마다 무엇을 바꿨는지 한 줄.
- 결정 줄마다 "했음/못 함"(못 했으면 까닭).
- 가벼운 확인 결과(돌린 명령과 끝난 모양).
- **범위 밖에서 같이 바뀌어야 하는 것**(파일:줄, 무엇을) — 없으면 "없음".
- 서버↔화면이 주고받는 것 중 바꾼 것(사건 이름·값) — 다른 단위가 맞춰야 함.
- 계획·결정과 다르게 한 것과 까닭, 확인 못 한 것.
