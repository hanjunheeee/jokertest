# 게임 의도 한눈에 — 가면무도회 살인사건

이 글은 구간 글 10개를 한 장으로 묶어, 한 판이 어떤 의도로 도는지와 주인이 정할 것(58묶음)을 한 번에 보게 함.

- 기준: 운영 규칙(`NODE_ENV=production`, 실제 서비스 설정). 한 판 5~10명. 개발 전용 규칙(2명 판 등)은 곧 지울 것이라 의도로 안 침.
- 새 사실 없음. 구간 글에 있는 것만 줄여 옮김. 구간 글이 "짐작"이라 한 것은 "짐작"을 그대로 붙임.
- 코드를 직접 다시 읽은 곳은 6장(구간 글끼리 말이 다른 곳)뿐.

## 2. 한 판의 흐름

이 장은 대기방에서 다음 판까지 한 바퀴를 단계별로 보여 줌.

```
대기방 → 시작 → 역할 확인(10초) → 낮(토론 → 투표) ─┬─ 최다 1명 → 재판 ─┬─ 승패 남 → 판 끝
                                                    │                   └─ 아니면 → 밤
                                                    └─ 동점·전원 기권 ──────────→ 밤
밤 → 승패 남 → 판 끝 / 아니면 → 다음 날 낮 (되풀이)
판 끝 → 결과 화면 → "대기방으로"(다음 판 방) 또는 "로비로"
```

### 2-1. 대기방 → `01-대기방.md`
- 방장이 방 만듦: 정원 5~10(기본 10), 광대 1~2(기본 1), 토론 30~150초(기본 60), 투표 30·60·90초(기본 60), 재판 15~120초(안 정하면 투표 시간), 밤 행동 30~120초(화면 기본 90).
- 들어오는 길 셋: 6자리 방 코드(1분 20번 제한), 공개 방 목록, 친구 초대(3분 유효).
- 전원(방장 포함) "준비". 방장이 설정을 바꾸면 전원 준비 풀림.
- 방장 넘기기는 방장이 나갈 때만(먼저 들어온 사람에게). 같은 방 강퇴 3번이면 그 방 못 들어옴.
- 대기방 채팅 없음. 자동 매칭은 일부러 잠금.

### 2-2. 시작 → `01-대기방.md`, `02-판시작-낮.md`
- 시작 조건: 5명 이상 · 광대 수보다 많음 · 직업 구성이 지금 인원과 맞음 · 전원 준비 · 초대로 들어오는 중인 사람 없음.
- 안 맞으면 방장 화면에 "게임을 시작할 수 없습니다" 창 + 이유.
- 통과하면 사람 목록을 고르게 섞어 직업을 나눔 → 섞인 순서 = 자리 순서. 색 10가지는 겹치지 않게.
- 참가자 한 명이라도 연결이 없으면 시작 취소. 시작되면 원래 대기방은 지워짐.

### 2-3. 역할 확인 (0일째) → `02-판시작-낮.md`
- 내 직업 창이 뜸. 광대는 동료 광대를 앎. 다른 사람 직업은 안 보임.
- 10초 고정. "확인"을 눌러도 안 기다림 → 10초 뒤 무조건 첫 낮.
- 채팅 못 씀. 이모티콘은 됨(Q02-3).

### 2-4. 낮: 토론 → 투표 → `02-판시작-낮.md`
- 낮이 되면 날짜 +1(첫 낮 = 1일째). 토론(기본 60초) → 투표(기본 60초).
- 토론: 산 사람 채팅(150자, 0.5초 간격). 산 사람 전원이 "준비"를 누르면 남은 토론 시간 버리고 바로 투표.
- 투표: 산 사람 한 표. 나 자신 못 찍음. 기권 됨. 판정 전까지 바꾸기 됨. 마감 때 안 낸 사람은 기권.
- 판정: 최다 1명 → 재판 / 최다 동점 → 밤 / 진짜 표 0개 → 밤. 재투표 없음.
- 누가 누굴 찍었는지는 안 알림(수만).

### 2-5. 재판 → `03-재판.md`
- 피고 한 명. 산 사람 중 피고 뺀 전원이 유죄·무죄 한 번(바꾸기 없음).
- 시간 15~120초(안 정하면 낮 투표 시간). 같은 시간에 "최후의 반론" 채팅(모두 말함).
- 유죄 수 > 무죄 수면 처형. 동점·0:0은 무죄. 기권은 안 셈.
- 끝나면 승패 확인 → 안 나면 같은 날 밤. 하루 재판 최대 1번.
- 피고가 나가면 재판 취소, 처형 없이 밤.

### 2-6. 밤 → `04-밤-직업.md`
- 차례: 광대 → 의사 → 경비원 → 마녀사냥꾼. 판에 없는 직업·첫 밤 마녀사냥꾼은 건너뜀.
- 차례 길이: 방 설정 값(없으면 30초). 그 직업 산 사람이 다 내면 바로 닫음. 그 직업이 다 죽었으면 차례 길이의 20~60% 뒤 닫음(다 죽은 걸 숨기려고).
- 밤 채팅: 같은 직업끼리(시민끼리도). 죽은 사람은 언제나 죽은 사람끼리.
- 밤에 죽는 사람 최대 1명(광대 암살). 의사가 그 사람을 지키면 0명.
- 끝나면 승패 확인 → 안 나면 다음 날 낮(토론부터).

**직업 표**

| 직업 (화면 이름) | 밤에 하는 일 | 몇 명부터 나옴 (자동 구성) |
|---|---|---|
| 광대 | 산 사람 한 명 암살 (광대끼리는 못 고름) | 5명부터, 1~2명 (방장이 정함) |
| 의사 (주치의) | 한 명 보호, 광대가 노린 사람이면 살림 (나 자신도 됨) | 6명부터 1명 |
| 경비원 | 한 명 조사 → 그 사람 정확한 직업을 나만 받음 (나 자신 못 고름) | 8명부터 1명 |
| 마녀사냥꾼 | 죽은 사람 한 명 직업 확인 (둘째 밤부터) | 10명부터 1명 |
| 시민 (귀족) | 밤 행동 없음, 같은 직업 채팅만 | 나머지 전부 |

- 인원 기준은 정원이 아니라 실제 시작 인원.
- 직접 구성: 광대·의사·경비원·마녀사냥꾼 각 0~2명(광대는 1 이상), 남는 자리는 시민(0명도 됨).
- 같은 직업 여럿: 광대는 최다표(동률이면 아무도 안 죽음), 나머지는 고른 사람이 다 같아야 결과가 남.
- 같은 사람 연속 지목 막지 않음(의사 매일 자기 보호 됨, Q04-5).

### 2-7. 판 끝 → `05-승패-결과.md`
- 승패 확인 때: 밤 확정 · 재판 확정(무죄 포함) · 산 사람이 나가거나 끊김으로 탈락한 직후. 낮 투표 뒤엔 없음.

**승패 조건** (산 사람만 셈)

| 결과 | 조건 |
|---|---|
| 시민 승 | 산 광대 0명 |
| 광대 승 | 산 광대 수 ≥ 산 나머지 수 (같아도 승) |
| 무승부 | 없음 |
| 무효 판 | 점검 시각에 강제로 끝낸 판만 (승자 없음, 업적 없음) |

- 판 끝 뒤 전원 직업·생사 공개, MVP 1명(이긴 팀만, 산 채로 떠난 사람 뺌).
- 전적 저장: 실패하면 1초·5초·30초·그 뒤 60초마다 다시. 그 뒤 업적 보상(골드·다이아·테두리).
- 판마다 재화 보상은 없음(업적만). 짐작: 의도.
- 산 채로 떠난 사람은 편이 이겨도 패. 죽은 뒤 떠나면 편 결과 그대로.

### 2-8. 결과 화면 → `05-승패-결과.md`, `06-판끝-대기방-로비.md`
- 승패 영상(막히거나 20초 넘으면 "건너뛰기") → 결과판: 내 승패·이긴 진영·전원 이름과 직업·MVP.
- 보상 숫자는 결과 화면에 안 나옴(업적 보상은 로비 알림·상점 잔액으로).
- 머무는 시간 제한 없음. 모바일만 1.5초 뒤 광고 창(5초 뒤 닫기), 판마다 한 번.
- 단추 둘: "대기방으로" · "로비로". 결과가 없으면 "로비로 돌아가기" 하나.

### 2-9. 대기방·로비로 → `06-판끝-대기방-로비.md`
- 판 끝 뒤 "같은 방"은 없음. 방장이 새 방(파티 방)을 만들고 끝난 판 사람을 서버가 끌어다 넣는 구조.
- 방장 "대기방으로": 새 방(새 코드) 만들고 끝난 판 사람 자동 입장.
- 참가자 "대기방으로": "방장이 새 방을 만드는 중입니다" 화면에서 2.5초마다 물음, 최대 3분.
- "로비로": "게임에서 나가시겠습니까?" 확인 → 끝난 판에서 빠짐 → 로비.
- 새 방 설정: "다음 게임 설정 유지"를 켰을 때만 옛 설정, 아니면 기본값(공개·10명·광대 1).
- 새 방도 일반 대기방 규칙 그대로(5명 이상이어야 시작).

## 3. 끊김·나가기 한 쪽 요약

이 장은 어디서 끊기거나 나가면 어떻게 되는지 한 표로 보여 줌. 자세한 것 → `07-끊김-나가기.md`, 결과 화면 쪽 → `06`.

| 어디서 | 잠깐 끊김·새로고침 | 못 돌아옴 | 스스로 나가기 |
|---|---|---|---|
| 대기방 | 15초 안에 다시 붙으면 그대로 | 15초 뒤 방에서 빠짐, 방장이면 먼저 들어온 사람에게 넘김 | 바로 빠짐 |
| 판 중 — 산 사람 | 큰 단계(역할 확인→낮→재판→밤)가 바뀌기 전에 붙으면 그대로. 내 밤 차례 중이면 그 차례 마감까지 | 단계가 바뀔 때 탈락 = 죽음(끊김). 직업 공개 안 함. 다시 못 들어옴 | 그 자리에서 죽음 처리, 판은 계속 |
| 판 중 — 죽은 사람 | 유예(기다려 주기) 없음, 판 끝까지 참여 중으로 남음 | 같음 (판 끝까지 새 방 못 들어감, Q07-5) | 기권 명단에만, 판 계속 |
| 결과 화면 | 끊기는 순간 끝난 판에서 바로 빠짐 → 다시 열면 "게임 결과를 확인할 수 없습니다" (Q05-2·Q06-1) | 같음 | "로비로" → 빠짐 → 로비 |
| 판 끝 순간 이미 끊겨 있던 사람 | 60초 안에 붙으면 결과 화면 | 60초 뒤 정리 | — |

- 끊긴 산 사람은 계속 "산 사람·투표할 사람"으로 셈 → 마감 때 기권으로 채움. 끊기기 전에 낸 표는 남음.
- 서버가 조용한 끊김을 알아채는 데 약 45초.
- 같은 계정 다른 기기: 새 기기로 이어짐, 옛 기기는 로그아웃.
- 판 중 방장이 나감: 아직 참여 중인 다음 사람(자리 순서, 죽은 사람도 됨)에게 넘김. 짐작: 적힌 곳 없음. 끝난 판에선 안 넘김(Q06-2).
- 서버 재시작: 판이 메모리에만 있어 사라짐, 전적 없음(Q07-7). 점검 시각: 판을 승패 없이 끝내고 기록함.
- 사람이 줄어도 최소 인원 규칙으로 판을 깨지 않음. 승패 규칙으로만 끝남.
- 판 중 나간 사람은 다음 판 파티 방에 안 부름(Q06-7).
- 벌은 패 기록과 MVP 후보 빠짐뿐. 정지·감점 없음.

## 4. 버그로 보이는 것

이 장은 구간 글 5번에 나온 "의도는 분명한데 코드가 다르게 도는 곳" 12개를 큰 것부터 보여 줌.

- 다시 확인한 결과는 → `00-버그-다시확인.md` (다른 에이전트가 따로 씀).

| 번호 | 겪는 모습 | 얼마나 큰가 | 어느 글 |
|---|---|---|---|
| B06-1 | "로비로"로 떠난 사람도 방장 새 방에 자동으로 끌려 들어감 → 방장은 강퇴 전까지 시작 못 함, 그 사람은 방 만들기가 막힘 | 다음 판이 멈춤 | 06 |
| B03-1 | 모바일에서 피고를 판 명단에서 못 찾으면 재판 창이 안 떠 유죄·무죄를 못 누름 → 기권 처리 (다시 겪는 차례는 짐작) | 잘못된 결과 | 03 |

### (가) 먼저 정할 것

**가1. 판 도중 로비로 가면 판 화면으로 되돌릴지** — Q06-5 · Q07-4 · Q09-1

- 안: 만들기(추천, 세 글 모두) / 안 만들기(시험을 "로비에 남음"으로 고침) / 06만: 되돌리진 않고 "진행 중인 게임으로 돌아가기" 띠만.

- 07: 이것을 만들면 가5(Q07-3)·가6(Q07-5)도 같이 풀림.

**가2. 결과 화면에서 끊기면 바로 빠지나, 60초 기다리나** — Q05-2 · Q06-1
- 정할 것: 결과 화면 사람의 끊김·새로고침을 바로 정리할지.
- 지금: 60초는 "판 끝 순간 이미 끊겨 있던 사람"만. 결과 화면에서 끊기면 바로 빠짐 → 결과 사라짐, 파티 자격도 잃음(방장이면 파티 전체가 깨짐). 결정 BE-020의 까닭("새로고침해도 결과 보게")과 다름. 시험·안내 글은 "새로고침하면 못 봄"을 정답으로 둠.

**가3. 방장이 판 끝 뒤 먼저 떠나면 파티를 어떻게 하나** — Q06-2

- 안: 남은 사람 중 다음 사람에게 방장 넘기고 알림(추천) / 기다리는 사람에게 바로 "방장이 나갔습니다" 알리고 목록으로 / 지금대로.

### 7-2. 지우면 걸리는 시험 (큰 것)
- 적은 인원 판((가) 묶음): 브라우저 시험(e2e) 약 357개(48파일) + 백엔드 시험 파일 약 32개. 백엔드는 정원 4 쓰는 15파일, 광대 0명 7파일, 개발 인원 값 9파일, 자동 매칭 5파일도 같이.
- `/e2e` 시험 손잡이((나) 묶음): 브라우저 시험 약 1,300~1,600개 → 지우면 시험 묶음 절반 이상이 못 돎.
- `__…ForTests` 덮어쓰기 함수 53개: 백엔드 시험 97파일이 씀 → 사실상 못 지움.
- 백엔드 시험은 기본으로 개발 규칙 위에서 돎 → (가)를 지우면 기본 규칙이 바뀌어 위 32파일이 깨짐.

### 7-4. 운영이 개발 규칙으로 뜨는 빈틈
1. `NODE_ENV=development`라고 정확히 적으면 아무것도 안 막음. 운영 환경값 파일(`.env.production`)에 예시 파일 값을 그대로 베끼면 2명 판·정원 4·쿠키 https 끔·오류 스택 응답·Origin 없는 소켓·관리자 문 끄기가 한꺼번에 켜짐.
2. Docker·pm2(서버 띄우는 도구) 없이 `node index.js`/`npm start`로 켜면 `NODE_ENV`가 비어 개발로 뜸(경고만).
3. 씨앗 스크립트는 `NODE_ENV`만 봄 → 로컬에서 운영 DB 주소로 돌리면 시험 계정·상품이 운영 DB에 들어감.
4. 개발 판이 운영 판으로 기록됨 → 개발 서버를 운영 DB에 붙이면 전적·통계에 섞임.
5. 화면 `?outcome=` 미리보기가 운영 빌드에서도 열림(서버 값은 안 바뀜, 짐작).
6. `__…ForTests` 함수 53개가 운영 코드에 늘 있음. 밖에서 부를 길은 못 찾음 → 지금은 위험 없음(짐작).
7. 시작 거부 목록에 개발 인원 값·관리자 문 끄기 값·시험 계정 비번 이름이 없음. 운영에서 무시돼 해는 없지만 빈틈 1과 겹치면 살아남.

## 8. 확인 못 한 것 (중요한 것만)

이 장은 구간 글들이 "확인 못 함"으로 남긴 것 중 고를 때 걸리는 것만 모음.

- 모든 구간 글이 서버·브라우저·시험을 안 돌림. "겪는 모습"·"다시 겪는 차례"는 코드를 읽어 만든 것(01~10 전부).
- 판정 다시 해 보기 5번이 실제로 다 실패할 길이 있는지 못 찾음 (02·03·04 → 가10).
- 서버 여러 대일 때 판 방송과 판 상태 답의 도착 순서 (08 → B08-1·가12), 끝난 판에 묶인 사람의 위치 기록 (06).
- 운영 서버의 실제 `.env.production` 내용 안 봄 → 빈틈 1이 지금 운영에 해당하는지 모름 (10).
- 브라우저 시험 일부가 3명 판으로 돌아 개발 규칙에 기댐 → 운영(5~10명)에서 같은 결과인지 모름 (03·10).
- 판 시작 바로 그 순간 끊긴 사람은 유예가 안 걸릴 수 있음, 짐작 (07).
- 대기방 화면이 다시 붙을 때 15초 안에 지금 방을 꼭 다시 묻는지 (07).
- 새 판 시작이 옛 끝난 판을 지울 때 남는 것이 채팅 보관 기간 말고 해가 있는지 (05·06 → B05-1).
- 재판 창이 덮은 동안 남은 시간 막대가 화면에 실제로 보이는지 (03).
- 밤에 죽을 예정인 사람이 밤이 끝날 때까지 같은 직업 채팅을 쓸 수 있음, 의도 기록 없음 (04).
- 밤 사망 원인 `UNKNOWN_NIGHT`는 지금 코드로는 나올 길이 없어 보임, 남겨 둔 칸인지 안 물어봄 (04).
- "판 깨지게 한 사람만 패" 규칙은 지금 쓰이는 길이 없어 보임, 짐작 (05).
- 투표 공개 설정이 판 화면(프런트 인게임)에서 따로 쓰이는지 서버만 확인함 (01 → 다1).
- 모바일 실기기(iOS 사파리·안드로이드 크롬)의 키보드·화면 끄기·다른 앱 다녀오기 (09 → 나23).
