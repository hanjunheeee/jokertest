# A11b 비번 찾기·바꾸기·이메일 바꾸기·탈퇴·마이페이지 — 시험 케이스 목록

이 글은 비밀번호 찾기(재설정)·아이디 찾기·비밀번호 바꾸기·이메일 바꾸기·회원 탈퇴·마이페이지(전적·닉네임·프로필 수정)·로비 톱니 장식(버그 1)에서 시험할 것을 겉으로 보이는 결과로 적은 목록임 (목표 백 240 · 화 175 · 모 6 · 브 간단 105 + 어려움 10, 합 536 — A11 칸의 절반).

- 번호: A11-B(백)·F(화)·M(모)·E(브 간단)·H(브 어려움)-501~999 (A11a가 001~499를 씀)
  - 백: 순수 501~550 · 요청 601~818 · DB 851~874 · 흐름(소켓) 901~904
  - 화: 화면 상태 501~590 · 화면 부품 701~785
- 종류: 순수 / 흐름 / 요청 / DB / 화면 상태 / 화면 부품 / 브
  - 요청 = 서버 앱에 HTTP 요청을 보내고 상태·본문·쿠키·메일 상자를 봄. 이 영역은 거의 다 진짜 시험 DB(`F01_TEST_DATABASE_URL`)를 씀 → 파일은 `backend/tests/db/*.integration.test.js`
  - 메일은 시험용 메모리 발송기(mail adapter(메일 보내는 통로))가 받은 것을 봄, 브는 메일 상자 파일(`e2e/helpers/mail.js`)을 봄
- 인원: 판을 차리는 줄만 괄호로 적음 (5~10명). 판을 안 쓰는 줄은 적지 않음
- 표 돌리기는 번호 범위 한 줄 + "값" 목록 (값 하나 = 케이스 하나)
- [버그 1] = 받은 버그 다시 생기는지 잡는 케이스, [지금 동작] = 출처 없어 지금 동작을 임시 정답으로 씀, [#n] = `비밀번호_점검.md` 6장 케이스 n번
- 경로·오류 코드 이름은 지금 코드(브랜치 `fix/scenario-2026-11-16`, 커밋 `f0b94266`)에서 찾음. 기대값은 아래 출처에서만 가져옴
  - 재설정: `POST /auth/password-reset/request`·`GET /auth/password-reset/verify?token=`·`POST /auth/password-reset/confirm` (`backend/routes/auth.routes.js`)
  - 아이디 찾기: `POST /auth/find-id`
  - 내 계정: `PATCH /user/me/password`·`PATCH /user/me/nickname`·`GET /user/me/profile`·`GET /user/me/account`·`POST /user/me/withdraw`·`POST /user/me/email/code`·`POST /user/me/email/verify` (`backend/routes/user.routes.js`)
  - 화면 주소: `/password-reset/request`·`/password-reset`·`/find-id`·`/mypage`·`/account`·`/lobby` (PC·모바일 같음)
- 시험 값에 진짜 메일 주소·비번·토큰을 안 씀: 주소는 `…@example.com`, 토큰은 시험이 받은 링크에서 꺼냄, DB 해시는 `(해시값)`으로 적음
- 브 "보임"은 `expectReadable`(보임·화면 안·안 가려짐·글자 대비 4.5 이상, 그림 단추는 3 이상 — `e2e/helpers/visible.js`, 시험_계획 3-6)로 봄
- 브 `@realtime` = 손잡이(`/e2e` 시간 건너뛰기) 안 쓰고 진짜 시간으로 기다림
- 소셜 전용 계정 = `users.has_local_password = false`인 계정. 시험이 만드는 법은 소셜 가입 흉내(A11a 도우미) 또는 시험 DB에서 칸을 바꿈
- A11a 몫(여기서 안 다룸): 가입·로그인·로그인 잠금·세션·refresh·소셜 로그인·Discord 연결. A14 몫: 관리자 비번(점검 #41~44). A12 몫: 꾸미기 창·착용 창 안의 아이템 장착 규칙

## 결정과 조사 글이 다른 곳

이 목록은 출처끼리 말이 다른 곳과 어느 쪽을 따랐는지 적음.
