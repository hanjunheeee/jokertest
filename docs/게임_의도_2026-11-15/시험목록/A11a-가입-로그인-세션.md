# A11a 가입·로그인·세션·소셜 — 시험 케이스 목록

이 글은 회원 영역 앞쪽(이메일 가입·인증번호·약관·로그인·잠금·세션과 토큰·로그아웃·구글·디스코드 소셜 로그인과 가입·디스코드 계정 연결 서버 흐름·로그인 기록)에서 시험할 것을 겉으로 보이는 결과로 적은 목록임 (목표 백 240 · 화 175 · 모 6 · 브 간단 105 + 어려움 10, 합 536).

- 번호: A11-B(백)·F(화)·M(모)·E(브 간단)·H(브 어려움)-세 자리, **001~499만 씀**(501~999는 A11b 몫). 백은 순수 001~050 · 요청(DB 없이) 101~130 · DB 201~360, 화는 상태 001~095 · 부품 201~280.
- 종류: 순수 / 요청 / DB / 화면 상태 / 화면 부품 / 브
- 인원: 이 영역은 판을 차리지 않음 → 인원 칸 없음. 사람 수는 브 어려움 줄에만 "(사람 N)"으로 적음.
- 표 돌리기는 번호 범위 한 줄 + "값" 목록 (값 하나 = 케이스 하나)
- [지금 동작] = 출처가 없어 지금 동작을 임시 정답으로 씀. 사용자가 정할 것(비밀번호_점검 5장 P-Q1~Q8)에 걸린 케이스는 번호 없이 "결정 대기" 표에만 둠(시험으로 안 잠금).
- 돈·보안이 걸린 곳이라 경계값(하나 모자람·딱 맞음·하나 넘음)을 꼭 넣음: 비번 7·8·64·65자, 72·75바이트, 닉네임 1·2·8·9자, 만 14세 생일 전날·당일, 틀림 4·5번째, 잠금 1초 남음·1초 지남, 인증번호 9분 59초·10분·10분 1초, 다시 보내기 59·60초, 요청 한도 N−1·N·N+1, refresh 봐주는 30초 안·밖.
- 예시 값은 전부 가짜: 메일 `…@example.com`, 비번 `pass1234` 꼴, 토큰·해시는 `(해시값)`. 진짜 키·비밀값·`.env` 값은 안 적음.
- 바깥으로 나가는 것은 가짜로: 메일은 시험 메일함(`MAIL_TEST_OUTBOX_DIR`, 브는 `e2e/helpers/mail.js`) 또는 메모리 발송기, 구글·디스코드는 가짜 제공자 서버(브 `e2e/tests/auth/fakeOAuth.js`, 백도 같은 꼴을 `fetchablePort.js` 포트로 띄움 — `GOOGLE_`·`DISCORD_OAUTH_BASE_URL`).
- 시간: 백은 서비스에 시각 넣기(`now`) 또는 DB 끝 시각 칸 옮기기로 경계를 봄. 브는 끝 시각 칸을 DB로 옮기는 것이 기본이고, "다시 보내기 60초"만 진짜로 기다림(`@realtime` 간단 1 + 어려움 1).
- "보임"은 `expectReadable`(보임·화면 안·안 가려짐·글자 대비 4.5 이상, 시험_계획 3-6)로 봄. PC 알림(`window.alert`)은 브라우저 창이라 글만 봄.
- 사건·칸 이름은 지금 코드(커밋 `f0b94266`)에서 찾음. 기대값은 아래 출처에서만 가져옴.

## 결정과 조사 글이 다른 곳

이 목록은 출처끼리 말이 다른 곳과 어느 쪽을 따랐는지 적음.

1. 결정 BE-009 둘째 줄 "없는 이메일 문구 '가입되지 않은 이메일입니다.' 그대로" ↔ 보안 점검(같은 날 뒤)·결정「보안 로그인 문구」 "없는 이메일·틀린 비번 같은 문구". → 나중 결정인 보안 쪽을 따름 (B-로그인 "없는 이메일과 틀린 비번이 똑같음", E 로그인 실패).
2. 옛요구 D-02 "최소 연령 제한 미지정, 임의 추가 안 함" ↔ 회원기능「약관」 "만 14세 미만 거절". → 나중에 정한 회원기능을 따름.
3. F-31 2-1 "확인 응답 `{ok, signupProof, expiresInSec}`" ↔ 지금 코드는 `expiresInSec`을 안 줌. → 시험은 `signupProof`만 봄(증명 10분은 가입 쪽 거절로 봄). 반장이 확인하면 좋음.
4. F-31 2-1 "이미 가입된 이메일: 메일은 보내지 않거나 '이미 가입됨' 안내 메일" → 둘 중 하나라 시험은 "같은 응답"만 잠그고 메일은 지금 코드대로 0통을 봄(B-이미 가입한 이메일, E-이미 가입한 이메일로 인증번호). 안내 메일로 바꾸면 그 줄만 고침.
5. F-03약속 "access 쿠키 Max-Age 30일" ↔ 지금 쿠키는 "남은 유지 시간"(회전해도 안 늘어남). F-03약속 R-IMPL #2 (2) "쿠키 수명이 절대 30일을 넘으면 안 됨"과 맞는 쪽(남은 시간)을 따름.
6. 결정 BE「소셜 로그인 정지」 "화면 문구표에 두 코드 없음(프론트 추가 필요)" → 지금은 표에 있음. 고친 뒤 모습으로 씀(F-소셜 실패 code → 문구).
7. 보안「입력·메일」 주소 전체 254자 ↔ 가입 칸은 코드가 100자로 자름. 100자 경계는 출처가 없어 넣지 않음(254자 경계는 A15 입력 검사 몫).
