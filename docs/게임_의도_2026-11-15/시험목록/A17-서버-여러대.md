# A17 서버 여러 대 — 시험 케이스 목록

이 글은 서버 프로그램(Node(서버 프로그램 하나))이 여러 개일 때 시험할 것을 겉으로 보이는 결과로 적은 목록임 (목표 백 170 · 화 0 · 모 0 · 브 간단 20 + 어려움 40, 합 230).

- 번호: A17-B(백)·E(브 간단)·H(브 어려움)-세 자리. 백은 흐름(메모리 Redis) 001~080 · Redis 101~190.
- 종류
  - 흐름 = 진짜 Redis 대신 메모리 받침(`backend/cluster/testing/memoryCluster.js`, Redis 자리 흉내)으로 n1·n2 두 Node를 한 프로세스에 띄움. `npm test`에서 돎. 도우미 `backend/tests/socket/multinode/setup.js`·`roomJoinSetup.js`·`backend/tests/cluster/helpers/slice2.js`
  - Redis = 진짜 시험 Redis(6380) + Node 2개(`backend/tests/cluster/helpers/redisNodes.js`), 죽음·멈춤은 `redisProxy.js`(Redis 앞 중계로 끊기·멈추기). `npm run test:with-redis`, `REDIS_URL_TEST` 없으면 건너뜀
  - Redis·DB = 위 + 시험 DB도 씀. `F01_TEST_DATABASE_URL`도 없으면 건너뜀
  - 브 = `E2E_NODES=2`(서버 2개 + 앞단 4100) 브라우저 시험, 폴더 `e2e/tests/multinode/`(모바일은 `multinode/mobile/`)
- 인원: 판을 차리면 몇 명 판인지(5~10)를 줄마다 괄호로 적음. 판 없는 케이스는 적지 않음.
- 표 돌리기는 번호 범위 한 줄 + 값 목록 (값 하나 = 케이스 하나).
- [버그 n] = 받은 버그가 서버 2대에서도 다시 안 생기는지, [지금 동작] = 출처 없어 지금 동작을 임시 정답으로 씀, [결정 대기] = 정해지기 전엔 시험 코드 안 씀.
- 사건(event, 서버와 화면이 주고받는 알림)·키·함수 이름은 지금 코드(커밋 `648f52fb`, `backend/cluster/**`·`backend/socket/matchmaking/cluster/**`)에서 찾음. 기대값은 아래 출처에서만 가져옴.
- 브 "보임"은 `expectReadable`(보임·화면 안·안 가려짐·글자 대비 4.5 이상 확인 도우미, 시험_계획 3-6)로 봄.
- 브 `@realtime` = 손잡이(`/e2e` 시간 건너뛰기) 안 쓰고 진짜 시간으로 기다림. `@serial` = Node를 끄거나 Redis를 멈춰 다른 시험과 같이 못 돎(작업자 1).
- 브 어려움 도우미: 사람·봇을 정한 Node에 붙이기는 `e2e/tests/multinode/_mn.js`(`onNode.person`·`botsOn`·`moveBot`), Node 끄기는 `e2e/helpers/servers.js` `triggerShutdown`.

## 결정과 조사 글이 다른 곳

이 목록은 출처끼리 말이 다른 곳과 어느 쪽을 따랐는지 적음.

1. 설계 2-6은 탈주 막힘을 Redis 키(`desertlock:<사람>`·`desertcount:<사람>:<날짜>`)에 둔다고 적음 ↔ 지금 코드(`backend/services/game/desertion.js`)는 Node마다 메모리 표 + 버스 알림 `desertion.blocked` + Redis 살아날 때 DB 다시 읽기. 겉 결과(다른 Node도 막힘)는 같아서 케이스는 결과만 봄, 키 이름은 안 봄.
2. 설계 2-1 [안] "Redis 멈춰 코드 못 잡으면 새 코드 + 문구" ↔ 지금 코드에 없음 → 사용자 결정(2026-11-16 오전 둘째 10번)으로 지금 코드(같은 코드)를 따름 (B-133).
3. MN-008 "끊김 뒤 15초 안 재접속" ↔ 결정「끊김 1분」 60초. 60초를 따름 (B-145, H-011·012).
4. MN-010 "판 끝 → 다음 방 → 참가자 자동 입장", MN-011 "다음 방 묻기 `ROOM_ON_OTHER_NODE`" ↔ 결정「같은 방」 "누른 사람만", `get_party_matching_room` 없어짐. 새 길(`return_to_room`)로 바꿔 씀 (B-039, E-009).
5. 노드계획 4-2 `startedcode` 30분 표시 ↔ 결정「다음 판까지」 "판 끝 뒤엔 새 사람도 코드로 입장". 판 끝에 표시를 지우는 쪽을 따름 (B-037).
6. 노드계획 3장 "목표 Node 죽음 → '방을 찾을 수 없습니다'"는 목록에서 고른 방만. 사람이 친 코드는 "방 없음"으로 답함(MN-110) → 둘을 나눠 씀 (B-017·018).
7. 결정 "대기방에서 기다림 — 추방 3번이면 못 들어옴(안내 문구 없음)" ↔ 지금 코드엔 추방 횟수 문구가 있음. A17은 문구를 안 보고 "못 들어옴"만 봄 (B-025).
