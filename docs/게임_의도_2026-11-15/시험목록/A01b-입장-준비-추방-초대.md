# A01b 대기방 입장·준비·추방·방장·초대 — 시험 케이스 목록

이 글은 대기방에 들어오는 길 셋(방 코드·공개 목록·친구 초대), 못 들어오는 때, 준비, 한 번 누르면 바로 내보내는 추방, 방장 넘김·방 삭제·나가기·끊김 15초를 겉으로 보이는 결과로 적은 목록임 (목표 백 200 · 화 230 · 모 6 · 브 간단 140 + 어려움 15, 합 591).

- A01을 둘로 나눈 뒤쪽. 방 만들기·설정·시작 조건은 A01a(번호 001~499), 이 글은 501~999.
- 번호: A01-B(백)·F(화)·M(모)·E(브 간단)·H(브 어려움)-세 자리. 백은 순수 501~530 · 흐름 531~690 · DB 701~710, 화는 상태 501~603 · 부품 604~730.
- 종류: 순수 / 흐름 / 요청 / DB / 화면 상태 / 화면 부품 / 브
- 인원: 대기방은 "(정원 n · 지금 m명)"으로 적음. 대기방은 판이 아니라 5명 밑도 있음(혼자 있는 방 등). 판을 차리는 줄만 "(판 n명)".
- 표 돌리기는 번호 범위 한 줄 + "값" 칸에 값 목록 (값 하나 = 케이스 하나)
- [버그 7] = 받은 버그 다시 생기는지 잡는 케이스, [지금 동작] = 출처 없어 지금 동작을 임시 정답으로 씀
- 사건(event, 서버와 화면이 주고받는 알림) 이름·칸 이름·`data-testid`는 지금 코드(커밋 `648f52fb`)에서 찾음. 기대값은 아래 출처에서만 가져옴.
- 브 "보임"은 `expectReadable`(보임·화면 안·안 가려짐·글자 대비 4.5 이상 확인 도우미, `e2e/helpers/visible.js`, 시험_계획 3-6)로 봄. 입장 실패 글은 지금 브라우저 알림 창(`alert`, dialog)으로 뜸 → 브라우저 쪽은 dialog 글을 읽음(대비는 브라우저 기본 창이라 안 봄).
- 브 "모바일"이라 적은 줄은 같은 이름의 `e2e/tests/mobile/` 파일로 감.
- 판 끝 뒤 돌아온 방(남겨 둔 방장 자리·"대기방으로"·추방 3번 기록 옮김)은 A08 몫, 로비·방 목록 화면에 들어올 때 대기방 자리 정리(뒤로 가기·새 탭)는 A10 몫 → 여기선 안 넣음.
