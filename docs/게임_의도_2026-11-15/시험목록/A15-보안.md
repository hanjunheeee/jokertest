# A15 보안 — 시험 케이스 목록

이 글은 보안·요청 제한·입력 검사 영역에서 "이 요청은 거절돼야 함·이 값은 안 실려야 함"을 겉으로 보이는 결과로 적은 목록임 (목표 백 200 · 브 간단 80 + 어려움 10, 합 290).

- 공개 저장소라 뚫는 방법은 자세히 안 적음. 키·토큰·비밀값·개인 정보 글자도 안 적음. 시험 값은 시험이 그 자리에서 만듦.
- 번호: A15-B(백)·E(브 간단)·H(브 어려움)-세 자리. 백은 순수 001~045 · 요청·흐름·DB 101~255, 결정 대기는 901~ (개수에 안 셈).
- 종류: 순수 / 흐름 / 요청 / DB / 브
  - 계획 2-5는 백 "순수 60 · 요청 140"이었으나, 판 전체 훑기(흐름)와 로그인 없이 막히는 길 표가 커서 순수 45 · 요청·흐름·DB 155로 나눔 (합 200 같음).
- 인원: 판을 차리면 몇 명 판인지 (5~10)를 줄마다 괄호로 적음.
- 표 돌리기는 번호 범위 한 줄 + "값" 목록 (값 하나 = 케이스 하나).
- [지금 동작] = 출처 없어 지금 동작을 임시 정답으로 씀, [결정 대기] = 정해지기 전엔 시험 코드 안 씀.
- 받은 버그 9개(시험_계획 2-6)에 A15 줄은 없음.
- 사건(event, 서버와 화면이 주고받는 알림) 이름·경로·오류 코드 이름은 지금 코드(커밋 `f0b94266`)에서 찾음. 기대값은 아래 출처에서만 가져옴.
- 브 "보임"은 `expectReadable`(보임·화면 안·안 가려짐·글자 대비 4.5 이상 확인 도우미, `e2e/helpers/visible.js`)로 봄.
- 브 `@realtime` = 손잡이(`/e2e` 시간 건너뛰기) 안 쓰고 진짜 시간으로 기다림.
- 브 요청 수 제한 케이스는 기본 제한 값 서버를 따로 띄움: 브라우저 시험 서버는 ip 제한을 크게 올려 둠(`e2e/helpers/backendEnv.js` `RAISED_IP_LIMITS`) → `e2e/tests/security/_sec.js` `startSec(n, { defaultIpLimits: true })`.
- 겹치지 않게
  - 서버 여러 대에서 요청 제한 합쳐 세기 → A17, 관리자 권한·관리자 CSRF(남의 사이트가 몰래 보내는 요청) → A14, 비밀번호 흐름 자체(잠금 5번·재설정 링크 한 번만·비번 규칙) → A11
  - 같은 방 안 손님의 `NOT_HOST`·코드 입장 21번째 경계 → A01, 소켓 접속 거절 다섯 가지(쿠키 없음·서명 틀림·만료·세션 끝·정지) → A10, 판 단계마다 남의 직업 안 샘 → A02·A04·A05 (여기는 판 하나 처음부터 끝까지 한 번에 훑기)
  - 운영에서 시험 손잡이가 켜지는 쪽(시작 거부·`createE2eRouter` 404) → A18, 여기는 운영 값 서버에 요청을 보내 확인
  - 채팅 길이·나쁜 글자·금지어 가림·채팅 XSS → A06

## 코드에서 찾은 이름 (어디를 볼지만)

- 앞단: 보안 헤더 `middlewares/securityHeaders.middleware.js`, 본문 앞단 `bodyGuard.middleware.js`(`hasForbiddenKey`·`BODY_LIMIT` 100kb·`MAX_DEPTH` 32), 오류 응답 `errorHandler.middleware.js`, CORS(다른 주소 요청 허용) `config/frontendOrigins.js`
