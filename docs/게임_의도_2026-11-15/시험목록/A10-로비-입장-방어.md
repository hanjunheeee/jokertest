# A10 로비 입장 방어 — 시험 케이스 목록

이 글은 로비·게임 모드·방 목록·게임 설정 화면에 들어올 때 서버가 그 사람의 남은 자리를 정리하는지(산 사람 판 중이면 판으로 되돌림), 중복 접속(버그 4)·밀린 옛 창·소켓 연결 검사를 겉으로 보이는 결과로 적은 목록임 (목표 백 160 · 화 60 · 모 8 · 브 간단 60 + 어려움 30, 합 318).

- 번호: A10-B(백)·F(화)·M(모)·E(브 간단)·H(브 어려움)-세 자리. 백은 순수 001~010 · 흐름 101~230 · DB 301~320, 화는 상태 001~038 · 부품 201~222.
- 종류: 순수 / 흐름 / 요청 / DB / Redis / 화면 상태 / 화면 부품 / 브
- 인원: 판·방을 차리면 몇 명인지 줄마다 괄호로 적음. 판은 5~10명만. 대기방은 정원 5~10 방에 지금 앉은 사람 수.
- 표 돌리기는 번호 범위 한 줄 + 값 목록 (값 하나 = 케이스 하나)
- [버그 4] = 받은 버그 다시 생기는지 잡는 케이스, [지금 동작] = 출처 없어 지금 동작을 임시 정답으로 씀
- 사건(event, 서버와 화면이 주고받는 알림) 이름·답 모양은 지금 코드(커밋 `648f52fb`)에서 찾음. 기대값은 아래 출처에서만 가져옴.
  - 로비 입장 사건 `enter_lobby`(보내는 값 없음), 답 `{ ok, redirect:'INGAME'|null, gameId, cleared }` — `cleared`(정리한 것) 칸은 `liveGame`(진행 중 판에서 풀림)·`endedGame`(끝난 판에서 빠짐)·`pending`(처리 중 입장 되돌림)·`room`(대기방 자리 빠짐), 밀린 옛 창이면 `{ ok:false, code:'NOT_CURRENT_SOCKET' }` (`backend/socket/matchmaking/room/lobbyEntry.js`)
  - 화면 쪽은 훅 `useLobbyEntryCleanup`(`frontend/src/domains/game/shared/hooks/useLobbyEntryCleanup.js`, 모바일도 같은 파일을 씀)
- 보내는 화면: `/lobby`·`/gameMode`·`/multiplay`(방 목록)·`/game-setup`. 안 보내는 화면: `/game-matching`(대기방)·`/ingame`(판)·`/gameresult`(결과)·`/roomInvite`(코드 입력).
- 브 "보임"은 `expectReadable`(보임·화면 안·안 가려짐·글자 대비 4.5 이상 확인 도우미, `e2e/helpers/visible.js`, 시험_계획 3-6)로 봄.
- 브 `@realtime` = 손잡이(`/e2e` 시간 건너뛰기) 안 쓰고 진짜 시간으로 기다림 (60초 끊김 규칙을 보는 케이스).
- 서버 여러 대(다른 Node에 판·방이 있을 때 로비 입장 정리)는 A17 몫 — 여기선 안 다룸.
