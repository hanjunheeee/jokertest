# A14 관리자 — 시험 케이스 목록

이 글은 관리자 페이지(로그인·권한·회원·제재·신고·금지어·점검 요청·공지·쿠폰·문의·재화·판 골드 값·기록·통계)에서 시험할 것을 겉으로 보이는 결과로 적은 목록임 (목표 백 280 · 화 110 · 모 0 · 브 간단 90 + 어려움 10 = 490).

- 번호: A14-B(백)·F(화)·E(브 간단)·H(브 어려움)-세 자리. 모바일 앱(`frontend-mobile`)엔 관리자 코드가 없어 M 없음 (관결 :19·관설 4-2 "frontend-mobile엔 관리자 코드 안 넣음"). 휴대폰 크기 관리자 화면은 브 `admin-phone`으로 봄
- 종류: 순수 / 요청 / DB / 흐름 / 화면 상태 / 화면 부품 / 브
- 백 종류 나눔: 순수 30 · 요청 77 · DB 173 — 계획 2-5(순수 30·요청 100·DB 150)와 다름. 까닭: 관리자 세션이 DB 표(`admin_sessions`)라 로그인이 필요한 케이스는 전부 DB 붙는 시험이 됨. 요청(DB 없음)은 "로그인 전에 막히는 것"만 남음
- 인원: 판을 차리면 "(N명 판)". 백 판 도우미·브 `table.setup` 모두 5명 이상
- 표 돌리기는 번호 범위 한 줄 + 값 목록 (값 하나 = 케이스 하나)
- [지금 동작] = 출처 없어 지금 동작을 임시 정답으로 씀, [결정 대기] = 사용자 결정이 없어 시험 코드 안 씀
- 받은 버그 9개(계획 2-6) 중 A14 몫은 없음
- 보안이 걸린 곳은 **되는 사람·안 되는 사람 둘 다** 적음: 관리자 세션 있음(됨) / 없음 / 플레이어 토큰(role=ADMIN 포함) / Access 표 없음 / 쓰기 확인값(CSRF, 남의 사이트가 몰래 보내는 요청 막기) 없음
- 이 글에 관리자 비밀번호·OTP 비밀·키·개인 정보는 안 적음. 시험 값은 시험이 그때 만듦 (`adminTestApp`·`createAdmin`)
