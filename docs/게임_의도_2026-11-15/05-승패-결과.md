# 승패·결과 — 의도와 지금 동작

이 글은 승패가 정해지는 조건과 때, 판이 끝난 순간부터 서버가 하는 일(공개·MVP·DB 저장·업적 보상·메모리 정리), 결과 화면에 보이는 것과 결과 화면이 닫히는 조건까지를 적음.

## 1. 흐름

1. 판을 바꾸는 일이 확정됨: 밤 판정 확정, 재판 판정 확정, 산 사람의 이탈(나가기·추방·끊김 유예 끝)
   - 밤: `backend/game-core/phase/night/commit.js:90-98` (암살 사망 → MVP 점수 → 죽은 사람 밤 행동 지움)
   - 재판: `backend/game-core/phase/tribunal/resolve.js:114-124` (유죄면 처형 → MVP 점수)
   - 이탈: `backend/game-core/departure/leave.js:102-106` → `departure/eliminate.js:22-30` (산 사람이면 죽은 이유 DISCONNECT로 사망, 기권·떠난 명단에 넣음)
   - 안쪽 규칙은 → 03-재판.md, 04-밤-직업.md, 07-끊김-나가기.md에서 다룸
2. 바로 그 자리에서 승패 확인(`evaluateWinCondition`)
   - 밤 `commit.js:101`, 재판 `resolve.js:130`, 이탈 `eliminate.js:33`
   - 산 사람만 셈: 산 광대 0명이면 시민 승, 산 광대 ≥ 산 나머지면 광대 승, 아니면 계속 (`core/rules/terminal.js:12-26`)
3. 승패가 나면 판 닫기(`finalizeGameSession`): 단계 `ENDED`, `winResult = { winner }`, 끝난 시각 기록 (`terminal.js:29-36`)
   - 승패 안 나면 밤 → 낮(`commit.js:109`), 재판 → 밤(`resolve.js:137`), 이탈 → 판 계속
4. 그 뒤 판 바꾸는 요청은 전부 `GAME_ALREADY_ENDED`(이미 끝난 판)로 거절 (`terminal.js:6-9`, 시험 `backend/tests/game-core/result/gameSession.winCondition.test.js:90`)
5. socket 쪽: 판을 끝낸 방송에 "종료 필드"를 덧붙임 (`backend/socket/gameSession/departure/end.js:24-36`)
   - 종료 필드 = 단계·생존 목록(`{uuid, isAlive}`) + 공개 승패 `winResult` (`backend/game-core/result/winReveal.js:7-16`)
   - 공개 승패 = `winner` + 전원 공개 `reveals`(uuid·닉네임·직업·팀·생사·죽은 이유) + `mvp: { uuid }` (`winReveal.js:20-35`)
   - 방송 사건(주고받는 알림)은 판을 끝낸 길마다 다름
     - 밤으로 끝남: `night_result_applied`(밤 결과 반영) (`phase/night/finalize.js:116`, `:47`)
     - 재판으로 끝남: `tribunal_vote_resolved`(재판 결과) (`handlers/tribunal.js:141`, `:161`), 이탈 뒤 바로 판정·재판 마감도 같은 사건 (`departure/autoResolve.js:72-77`)
     - 이탈로 끝남: `player_eliminated`(탈락 알림) (`departure/apply.js:43-60`)
   - 다시 들어온 사람은 스냅샷(판 전체 모습)에 같은 `winResult`를 받음 (`game-core/snapshot/session.js:130`)
6. 같은 자리에서 전적 저장 시작(안 기다림) + 60초 뒤 끊긴 사람 정리 예약 (`end.js:33-34`, 이탈 길은 `apply.js:80-86`)
7. 전적 저장(`services/game/record/persist.js:12-40`)
   - 기록은 처음 한 번만 만들고 얼림, 같은 판은 한 번만 (`persist.js:16-18`, `:36`)
   - DB 한 트랜잭션(묶어서 한 번에 쓰기): `game_results` 판 한 줄 → `game_result_players` 사람별 줄 → `user_stats` 판 수·생존·처형·많이 한 직업 더하기 (`backend/repositories/game/result.js:57-91`)
   - 실패하면 1초 → 5초 → 30초 → 그 뒤 60초마다 다시 (`services/game/record/constants.js:8-11`), 제약 위반·값 검사 실패는 그만둠 (`persist.js:51-58`, `:74-77`)
8. 저장 성공 뒤 (`persist.js:116-134`)
   - 참가자 전원에게 `account_cache_invalidated`(계정 캐시 버려라, `{gameId, scopes:['profile']}`)
   - 업적 평가: 전원 진행 값 한 번에 읽고 사람마다 평가 (`services/game/achievementHooks.js:40-52`)
   - 기준 넘은 업적마다 한 트랜잭션: 지급 기록 → 골드·다이아·테두리 보상 → 알림 행 (`services/achievement/grant.js:51-81`)
   - 새로 받으면 그 사람에게 `achievement_granted`(업적 받음) + 알림 방송 (`grant.js:10-29`, `services/achievement/evaluate.js:50-54`)
   - 평가 끝나면 다시 `account_cache_invalidated`(`['economy','achievements']`)
   - 점검으로 끝난 판은 업적 평가 안 함 (`persist.js:35-36`, `:128`)
9. 화면(PC·모바일 같은 코드): 승패를 받으면 `/gameresult`로 한 번 이동 (`frontend/src/domains/game/ingame/hooks/useInGameResultNavigation.js:19-33`)
   - 재판 추방 영상·밤 성공 영상이 도는 동안은 미룸 (PC `frontend/src/domains/game/ingame/pages/InGamePage.jsx:125-130`, 모바일 `frontend-mobile/src/domains/game/ingame/hooks/overlays/useOverlayLayer.js:80-82`)
10. 결과 화면: 승리/패배 영상(소리 없음) → 결과판 (`frontend/src/domains/game/result/page/GameResultPage.jsx:71-80`)
    - 영상이 막히거나 20초 지나면 "건너뛰기" (`result/components/GameResultIntroVideo.jsx:45-48`, `constants/gameResultIntro.js:5`)
    - 결과판: 내 승패 띠, 이긴 진영 띠("시민 진영 승리"/"광대 진영 승리"), 참가자 전원 이름·직업, MVP 한 명, 남의 줄엔 신고 버튼 (`result/utils/buildGameResultViewModel.js:25-61`, `constants/gameResultLabels.js:5-30`)
    - 승패는 "내 팀 = 이긴 팀"이면 승리 (`buildGameResultViewModel.js:49`)
    - 보상·재화·전적 숫자는 결과 화면에 안 나옴 (결과 폴더 어디에도 없음), 업적 보상은 로비 알림·상점 잔액으로 보임 (e2e `e2e/tests/result/achievement-stats.spec.js:71`, `:96`)
    - 모바일만: 결과가 다 뜬 뒤 1.5초 뒤 판마다 한 번 광고 창 (`frontend-mobile/src/shared/ads/useInterstitialAd.js:1`, `interstitialRule.js:8`)
11. 결과 화면이 닫히는 조건 (서버 쪽 시간 제한 없음)
    - "로비로": `leave_game_session`(판 나가기) → 끝난 판에서 나만 빠짐 (`backend/socket/gameSession/handlers/leave.js:65-85`) → 로비로
    - "대기방으로": 판 나가기를 안 보냄 → 그 뒤는 → 06에서 다룸
    - 새로고침·탭 닫기·끊김: 서버가 끊긴 순간 끝난 판에서 바로 뺌 (`leave.js:130-138`) → 다시 열면 "게임 결과를 확인할 수 없습니다" (`constants/gameResultUnavailable.js:19-20`, e2e `e2e/tests/result/nav.spec.js:48`)
    - `game_ended`(판 끝남) 알림이 지금 판 것으로 오면 판·방 비우고 멀티 화면으로 (`frontend/src/domains/game/ingame/utils/sessionEnd.js:5-10`) — 실제로 받는 건 점검 강제 종료 때뿐(아래 12)
12. 메모리에서 판 지우는 때 (`backend/game-core/core/registry/write.js:47-64`)
    - 끝난 판은 사람이 하나씩 빠지고 "떠난 명단 수 ≥ 참가자 수"가 되면 판째 지움
    - 판 끝 순간 연결 없던 사람(죽은 뒤 끊김·유예 중 판 끝)은 60초 뒤 자동으로 뺌 (`end.js:40-75`, `socket/gameSession/core/constants.js:77`)
    - 판째 지울 때 socket 마무리(`finalizeGameSessionEnd`, `end.js:83-138`): 채팅 증거 보관 끝 표시 → 전적 저장(이미 했으면 건너뜀) → 타이머 전부 끔 → 대기방 상태 정리 → `game_ended {gameId, reason}` → 판 채널에서 소켓 뗌
    - 받을 사람은 "아직 판에 묶인 사람 − 마지막에 나간 사람"이라 보통 아무도 없음 (`socket/gameSession/delivery/eligibility.js:62-76`), 점검 강제 종료 때만 전원이 받음 (`departure/maintenanceAbort.js:11-22`)
    - 판 채팅 증거: 이 끝 표시부터 10분 보관, 끝 표시가 없으면 마지막 채팅 뒤 3시간 (`backend/services/ops/chatBuffer.js:11-22`)

### B05-1. 새 판 시작으로 옛 끝난 판이 지워지면 판 끝 마무리가 안 돎
- 겪는 모습: 같은 파티가 결과 화면에서 "대기방으로"(판 나가기 안 보냄) → 새 판을 시작하면 옛 판 채팅 증거가 10분이 아니라 마지막 채팅 뒤 3시간까지 메모리에 남음. 옛 판 채널에서 소켓도 안 뗌
- 왜: 새 판 등록이 옛 끝난 판에서 사람을 빼다 판째 지워도(`backend/game-core/setup/commit.js:174-177` → `core/registry/write.js:57-63`) socket 마무리 `finalizeGameSessionEnd`(`socket/gameSession/departure/end.js:83-138`)를 부르는 곳이 없음 → `chatBuffer.markGameEnded`(`end.js:88`)가 안 불림 → `chatBuffer.js:20-21`의 3시간 규칙으로만 지워짐. 의도는 "판 끝 뒤 10분까지"(`chatBuffer.js:3`)
- 다시 겪는 차례: 5명 판 → 끝 → 전원 "대기방으로" → 방장이 새 방 → 같은 5명으로 새 판 시작 → 옛 판 id로 채팅 보관 확인(짐작: 판 시작 전에 60초 정리가 먼저 돌면 그쪽은 연결된 사람을 안 빼서 똑같음)
- 얼마나 큰가: 보기만 이상함 (메모리·보관 기간, 게임 진행·전적은 이미 저장돼 영향 없음)
