## 2. 5명 판 차리기와 직업 고정

이 장은 층마다 5명 이상 판을 만들고 직업을 정해 두는 법을 보여 줌. **직업은 늘 정해 줌** — 무작위로 두면 돌릴 때마다 결과가 바뀜.

### 2-1. 백 (메모리 판)

| 하고 싶은 것 | 부르는 법 |
|---|---|
| 5명 판 (광대 1) | `const s = gf.startGame({ id: 'a05-1', n: 5 })` — `randomFn`이 기본 `() => 0`이라 직업이 늘 같음 |
| 직업 직접 구성 | `gf.startGame({ id: 'a05-2', n: 6, roleCounts: { JOKER: 1, DOCTOR: 1 } })` |
| 그 직업 사람 찾기 | `gf.firstOf(s, 'JOKER')`, `gf.byRole(s, 'DOCTOR')`, `gf.nonJokers(s)` |
| 첫 낮·투표·재판·밤으로 | `gf.toDay(s)` → `gf.toVote(s)` → `gf.toTribunal(s, uuid)` / `gf.toNight(s)` |
| 밤 한 번 판정 | `gf.resolveNightDirect(s, { [jokerUuid]: targetUuid })` |
| 바로 쓰는 판 | `commitSessionAtDay({ id, playerCount: 5 })`, `nightSessionWithDoctor({ id, playerCount: 6 })`, `commitFullRoleSessionAtNight({ id })`(10명, 직업별 uuid) — `tests/helpers/gameSession.testUtils.js` |
| 순서를 정한 무작위 | `sequenceRandom([0.1, 0.9, …])` (나누기 순서를 볼 때) |

- **판 id는 시험마다 다르게** (`gf.startGame`의 uuid가 `<id>-번호`라 같은 id면 "이미 다른 판에 속함"으로 터짐). 아니면 시험마다 `gf.resetCore()`
- 4명 이하로 부르면 `PLAYER_COUNT_OUT_OF_RANGE`로 바로 멈춤 (거절을 보는 시험만 일부러 씀)

### 2-2. 백 (대기방 → 시작)

```js
process.env.DATABASE_URL = 'mysql://blocked:blocked@127.0.0.1:1/blocked_test_db' // 맨 위, 모델이 DB에 안 붙게
const matchmaking = require('../../socket/matchmaking')

```

- 로비 입장 정리(`enter_lobby`)·대기방으로(`return_to_room`)는 `__testables`에 없음 → `registerMatchmakingHandlers(io, fakeSocket)` 뒤 `fakeSocket.trigger('enter_lobby', payload, cb)`로 부름

### 2-3. 화면·모바일

- 판 없이 **스토어(화면이 들고 있는 판 값)에 서버 알림 값을 넣어** 봄: 5명 명단·내 직업을 값으로 직접 줌 (견본의 `PLAYERS`처럼)
- 직업 이름은 `광대·의사·경비원·마녀사냥꾼·시민` 그대로 (`e2e/helpers/ui.js` `ROLE_LABELS`와 같음)

### 2-4. 브라우저

| 하고 싶은 것 | 부르는 법 |
|---|---|
| 5명 판 (사람 1 + 봇 4) | `const t = await table.setup({ humans: [user] })` — `bots`를 안 주면 5명이 되게 채움 |
| 인원 바꾸기 | `table.setup({ humans: [user], bots: 6 })` (7명), 5명 밑이면 차리기 전에 오류 |
| 직업 고정 | `roles: ({ humans, bots }) => ({ [humans[0].account.uuid]: 'DOCTOR', [bots[0].account.uuid]: 'JOKER' })` |
| 직업 직접 구성 | `settings: customRoleSettings({ JOKER: 1, DOCTOR: 1, GUARD: 1 })` (`helpers/game.js`) |
| 직업이 꼭 맞아야 할 때 | 밤 도우미 `require('./_night').setup(table, { humans, bots, humanRoles, botRoles })` — 서버 역할을 읽어 다시 맞춤 |
| 판 끝까지 (결과 화면) | `playToResult({ user, table, kind: 'citizenWin' })` (`tests/room/roomHelpers`) — `jokerWin`·`jokerLose`·`citizenWin`, 사람 수 제한은 함수 머리 주석 |
| 사람이 방장인 판 | `hostGame({ host, guests, botList })` — 합 5명 밑이면 오류 |

- 정한 직업은 `const s = await t.state()`로 꼭 한 번 확인 (서버 예약이 가끔 못 맞음)

## 3. 시간 — 가짜 시계와 진짜 기다림

이 장은 시간 규칙(5초·10초·60초·180초)을 어떻게 다루는지 적음. 규칙: **확인하려는 규칙의 시간은 건너뛰지 않음.**

### 3-1. 백 가짜 시계

- `const c = gf.fakeClock()` → `{ nowFn, setTimeoutFn, clearTimeoutFn, advance(ms), now() }`
- 단계 타이머에 넣는 이름 (`require('../../socket/gameSession').__testables`)

| 단계 | 부르는 법 |
|---|---|
| 낮 토론·투표 | `startDayPhaseTimer(io, s, { nowFn, setTimeoutFn, clearTimeoutFn, discussionDurationMs, voteDurationMs, settleDelayMs })` |
| 재판 | `startTribunalTimer(io, s, { …, durationMs, settleDelayMs })` |
| 밤 차례 | `startNightTurnSequence(io, s, { …, turnDurationMs, settleDelayMs, randomFn })` |
| 역할 확인 10초 | `ensureRoleRevealTimer(io, s, { …, durationMs })` |
| 끊김 60초 | `beginDisconnectGrace(io, s, uuid, { …, graceMs })` |

- "다 내면 5초" 판정은 표를 낸 뒤 서버가 스스로 당김 → 시험은 `c.advance(4_999)`(아직) / `c.advance(1)`(판정)로 경계를 봄 (견본 `a03-sample-day-settle.test.js`)
- 메모리 시험에서 낮 표를 보내면 참여 기록을 DB에 씀 → `T.__setRecordVoteParticipationForTests(async () => {})`·`T.__setEvaluateAchievementsForTests(async () => {})`로 바꿔 끼우고 끝에 `null`로 되돌림 (안 하면 표 답이 `VOTE_PERSIST_FAILED`)
- 다음 단계 타이머는 진짜 시계로 걸릴 수 있음 → `t.after`에서 `stopDayPhaseTimer`·`stopTribunalTimer`·`stopNightTurnSequence` 부르기
- 화면·모바일: `mock.timers.enable({ apis: ['setTimeout'] })` (`domSetup.mjs`가 창의 setTimeout도 같이 따르게 함)

### 3-2. 브라우저 손잡이 (`/e2e`, 시험 백엔드에만 있음)

이 표는 브라우저 시험이 부를 수 있는 손잡이와, 써도 되는 때를 보여 줌. 손잡이는 `E2E_HOOKS=1`이고 운영이 아닐 때만 붙음.

| 손잡이 | 부르는 법 | 하는 일 | 써도 되는 때 |
|---|---|---|---|
| 역할 미리 정하기 | `table.setup({ roles })` / `e2e.setRoles({ uuid: 'JOKER' })` | 다음 판 직업 | 늘 |
| 판·방 보기 | `t.state()`, `e2e.gameOf(uuid)`, `e2e.roomOf(uuid)` | 단계·생존·직업·방 코드 | 늘 |
| 단계 바로 끝내기 | `t.advance()`, `t.advanceUntil('NIGHT')` | 지금 단계 마감 타이머를 바로 돌림 | 앞 단계 빨리 가기만. **"다 내면 5초" 케이스에선 금지** (그 5초도 건너뜀) |
| 끊김 60초 바로 끝내기 | `t.expireGraces()` | 끊긴 사람 탈락·탈주 기록 | 60초 규칙 자체를 안 볼 때 |
| 결과 화면 180초 바로 닫기 (새) | `t.closeResults()` / `e2e.closeResults(gameId)` | 결과 화면 닫힘 알림 → 로비, 방장 자리 끝, 아무도 안 온 방 지움 | 180초 규칙 자체를 안 볼 때 |

| 시간 | 진짜로 기다리는 케이스 (`@realtime`) |
|---|---|
| 역할 확인 10초 | 10초 전엔 낮 아님, 확인 눌러도 안 당겨짐 |
| 토론·투표·재판·밤 마감 | 방 설정 최소값(30·30·15·30초)으로 두고 진짜로 |
| 다 내면 5초 | 그 규칙을 보는 케이스 전부 (손잡이 안 씀) |
| 끊김 60초 | 59초 돌아오면 이어서·61초면 탈락 |
| 결과 화면 180초 | 남은 시간·180초 뒤 로비 (견본-2) |
| 방 다시 붙기 15초 | 늘 진짜로 |

- 허용 폭 ±1.5초. 더 늘려서 덮지 않음
- 시험 하나 제한 2분(`playwright.config.js`) → 넘는 시험은 **그 시험 안에서** `test.setTimeout(300_000)` (설정은 안 바꿈)
- 고정 쉬기(`sleep`) 대신 `expect(...).toHaveText`·`expect.poll`로 기다림 (진짜 시간 규칙 확인만 예외)

## 5. 도우미가 지금 규칙으로 판을 끝까지 몰고 가나 — 조심할 것

이 장은 지금 규칙 때문에 도우미를 잘못 쓰면 판이 안 끝나는 곳을 적음.

- **기권이 많으면 재판 없음**: 낮 투표는 최다 득표가 기권보다 많아야 재판. 사람(브라우저)은 안 내면 기권으로 셈
  - 봇 표로 처형하는 도우미(`_talk.js` `executeBot`·`getExecuted`, `c-chat` `executeByBots`, `playToResult`)는 시작 전에 `t.assertBotsCanExecute(uuid)`로 셈을 보고, 모자라면 바로 오류
  - 직접 셀 땐 `await t.botVoteMargin(uuid)` → `{ votes, abstain, enough }` (예: 사람 2·봇 3, 봇 하나 처형 → 2 ≤ 3 → 밤으로 감)
- **봇 계획 `'skip'` = 안 냄**: 그 단계는 마감까지 감 → `t.advance()`로 넘기거나, 다 내게 해서 5초 판정
- **모두 기권·밤에 아무도 안 죽임**이면 판이 끝나지 않음 → `toEnd`·`advanceToEnd`·`finishGame`은 봇이 누군가를 죽이게 계획을 줘야 끝남
- **밤 영상 없음**: 밤엔 아무 화면에도 연출 없음. 낮이 되면 모두에게 낮 시작 연출 (죽은 사람 있음 = 영상 + 글 / 의사가 살림 = 글 창 / 없음 = 없음)
- **의사가 살렸을 때 글 창은 "확인"을 눌러야 닫힘**, 창 이름이 "단계 전환 안내"와 같음 → `[data-ingame-dawn-report]`로 구별. 기록 도우미 `recordUi(page, { autoConfirmDawn: true })`면 같이 누름
- **마녀사냥꾼 봇**: `night: 'random'`이면 죽은 사람 중에서 고르고 없으면 건너뛰기를 냄 (산 사람을 고르면 늘 거절이라 차례가 마감까지 끌렸음)
- **판 끝 뒤**: "대기방으로" = `return_to_room`(누른 사람만), 결과 화면 180초 뒤 로비. 로비·게임 모드·방 목록·게임 설정 화면을 열면 `enter_lobby`로 그 사람 대기방 자리·끝난 판이 정리됨 → 시험 도중 `ui.gotoLobby`를 부르면 방에서 빠짐
- **a-day `toDay`**: 첫날 "낮이 되었습니다"만 닫음. 둘째 날부터는 그 앞에 낮 시작 연출 창이 먼저 뜰 수 있음
- **부하 봇**(`backend/scripts/loadtest`): 지금 규칙으로 판이 끝까지 감 (다 내면 5초, 동률이면 밤, 판 끝 뒤 `leave_game_session` → 다음 판 새 방)

## 7. 쓰면서 알게 된 것 (2026-11-16, 시험 4,700개쯤 쓴 뒤)

이 장은 시험을 쓰는 동안 여러 에이전트가 똑같이 걸려 넘어진 곳을 모음 — 새로 쓰는 사람은 이것부터 읽음.

### 7-1. 돌릴 때

- Git Bash의 `timeout`은 이 PC에서 node를 못 끔
  - 오래 걸릴 수 있는 실행은 감시 실행기로: 시간·메모리를 넘으면 프로세스 나무(자식의 자식까지)째 끔
  - 예: `node ../tools/시험도구/guard-run.cjs --ms=60000 --mb=1500 -- node --experimental-test-module-mocks --test tests/a03-day-vote/x.test.js`
  - 끊으면 종료 코드 124, 안 끊으면 자식의 종료 코드 그대로
- DB 시험은 늘 `--test-timeout=60000 --test-force-exit`
  - 2분 넘게 아무 줄도 안 나오면 끊고 원인을 찾음 (잠금을 쥔 채 멈추면 다른 사람이 전부 기다림)
- Redis와 시험 DB를 같이 쓰는 시험은 잠금을 늘 `redis` 먼저, 그다음 `testdb`
  - 거꾸로 잡으면 서로 기다리다 멈춤
  - Redis 시험은 `REDIS_URL_TEST=redis://127.0.0.1:6380`을 줘야 돎 (없으면 건너뜀으로 나옴)
- 이름에 `integration`이 없는데 시험 DB를 쓰는 파일이 있음: `backend/tests/flow/a13-*`(7개), `backend/tests/flow/a11b-session-revoke-socket.test.js`
  - 전체를 돌릴 땐 DB 묶음에 넣음
- 임시 파일은 scratchpad 아래 내 이름 폴더에만 (여럿이 같은 이름 파일을 덮어쓴 일이 있었음)
  - 폴더에서 `sed -i … *.test.js`처럼 남의 파일까지 건드리는 명령을 안 씀

### 7-2. 가짜 시계

- node 가짜 시계(`t.mock.timers`)는 한 번에 넘긴 시간의 **끝 시각**으로 타이머를 부름
  - 시각 경계(59.999초·60초)는 잘게 넘기거나 `gameFixtures.fakeClock`으로 전역 `setTimeout`·`Date.now`를 바꿔 씀
- 가짜 시계를 켠 채 시험 뒤 정리가 돌면 서버 닫기가 안 끝나 프로세스가 멈춤
  - 가짜 시계 풀기(`t.after(() => t.mock.timers.reset())`)를 서버·세상 차리기보다 **먼저** 검
- 가짜 시계를 켠 동안 `waitFor`를 쓰면 멈춤
  - 화면에서 창이 닫힌 뒤 가짜 시계를 더 넘기면 0ms 예약이 끝없이 다시 걸려 메모리가 불어남
  - 필요한 시각까지만 넘기고 `mock.timers.reset()` 뒤 진짜 시계로 기다림
- 시험 DB의 시각 칸(DATETIME)은 소수 초를 반올림함
  - 1초 경계 시험은 시각을 초 단위(0밀리초)로 맞춰 넣음

### 7-3. 백엔드 흐름

- `gf.socketWorld`는 부를 때마다 접속 목록을 갈아 끼움
  - 판·방 두 개를 한 번에 다루려면 목록을 합쳐 다시 넣음 (본보기 `backend/tests/flow/a04-world.js`의 `setupWorlds`, `a08-world.js`, `a10-world.js`)
- 결과 화면에서 나간 직후엔 판 채널 떼기가 아직 안 끝나 있음 → 다음 동작 전에 `await gf.flush()`
- 메모리 흐름 시험에서 "[탈주] 막힘 기록 못 읽음" 줄이 찍히면 탈주 저장소를 가짜로 끼움 (`__setRepositoryForTests`, `findDesertionsForWarmup`도 넣기)
- 공용 `assertNoForbiddenPrivateData`는 값이 `null`인 `role` 칸(`phase_settle_started`)과 밤 결과 방송의 `deathReveals.*.source`도 샌 것으로 잡음
  - 그 칸은 값이 맞는지 먼저 확인하고 빼고 검사
- `.env.test`로 돌리면 판 출처가 "시험"이 아님
  - 업적·통계를 보는 시험은 `NODE_ENV=test`나 `GAME_SOURCE_OVERRIDE`를 직접 넣고 끝에 되돌림
- 지갑 모델은 `db.sequelize.models.EconomyWallet`로 꺼냄 (`db`에 안 올라가 있음)
  - 판 골드 지급을 가짜로 바꾸는 손잡이는 `services/game/record/persist.js`에 있음
- `fixedRandom`(무작위 고정)을 켠 채 빈 포트를 고르면 늘 같은 포트라 부딪힘
- `getSessionById`는 없는 판이면 `undefined`를 돌려줌
- 직업은 늘 정해 줌 (무작위로 두면 결과가 그때그때 바뀜)

### 7-4. 화면(PC) 시험

- 비교(`assert.equal`·`deepEqual`)에 화면 요소(DOM 노드)·React 요소·스토어 통째를 넣지 않음
  - 틀렸을 때 차이 글을 만들다 메모리가 터져 node가 죽음
  - `assert.ok(a === b)`나 글자·숫자·참거짓만 비교
- 판 화면 전체를 그리려면 네 가지가 필요함
  - 데이터 라우터(`createMemoryRouter` — 나가기 훅이 `useBlocker`를 씀)
  - `ResizeObserver` 흉내 (채팅 칸·스크롤바가 씀)
  - `MotionGlobalConfig.skipAnimations = true` (창 움직임이 안 끝나 메모리가 바닥남)
  - 가짜 `fetch` (판 보드가 이모티콘 목록을 HTTP로 받음 — 안 막으면 진짜 요청이 나감)
- 판 화면과 RTL `waitFor`를 같이 쓰면 안 끝남 → 작은 대기 함수를 따로 씀
- 가짜 소켓은 `timeout().emitWithAck`·`emitWithAck`를 흉내 내야 함 (대기방 훅이 그렇게 부름)
  - 방 확인(`get_current_room`)에 늘 같은 방으로 답하면 방을 지운 뒤에도 화면이 방을 다시 넣음
- jsdom(가짜 브라우저)은 그림을 안 그리고 `inert`·Enter 키 누름도 안 지킴
  - 색 대비·가려짐·진짜 키보드는 브라우저 시험 몫
- 시험 파일은 `.test.js`로 (목록에 `.test.jsx`로 적힌 줄이 있어도 — `npm test`가 `tests/**/*.test.js`만 돌림)
