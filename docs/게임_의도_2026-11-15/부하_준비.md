## 1. 꼭 지킬 것 (도구가 막아 줌)

이 장은 부하가 사용자의 개발 서버·개발 DB에 닿지 않게 도구에 넣은 막기를 적음.

| 막는 것 | 어떻게 | 전에는 |
|---|---|---|
| 4000번 포트(사용자 개발 서버) | 로컬 대상이 4000번이면 바로 멈춤. 기본 대상도 4100으로 바꿈 | 기본 대상이 4000번이었음 |
| 개발 DB `joker`·`joker_realgame` | DB 이름을 보고 멈춤. `--allow-db`로 이름을 줘도 안 풀림 | 호스트(localhost)만 봐서 개발 DB에 시험 계정을 만들 수 있었음 |
| 모르는 DB | 시험 DB 이름(`joker_e2e`·`joker_loadtest`)만 통과. 다른 시험 DB는 `--allow-db <이름>`을 줘야 함 | 아무 로컬 DB나 통과 |
| `backend/.env`(개발 값) 읽기 | `--db-env ../e2e/.env.e2e`를 주면 그 파일의 DB 주소·내부 열쇠 2개만 읽고 `backend/.env`는 안 읽음 | 늘 `backend/.env`를 읽음 |
| 엉뚱한 DB에 붙음 | 붙은 뒤 `SELECT DATABASE()`(지금 붙은 DB 이름 묻기)로 한 번 더 확인 | 없음 |

- Docker(컨테이너 실행기)는 켜고 끄지 않음. `jokertest-db-1`(DB)·`mmc-redis-test`(시험 Redis, 6380)는 사용자가 켜 둔 것을 씀
- Redis(서버끼리 잇는 저장소)는 `E2E_REDIS_URL=redis://127.0.0.1:6380`을 꼭 줌 → 도구가 컨테이너를 만들거나 켜지 않고 살아 있는지만 물음

## 2. 돌리는 순서 (명령 그대로)

이 장은 저장소 맨 위 폴더에서 Git Bash로 차례대로 치는 명령을 적음. 서버 틀은 브라우저 시험 틀(`e2e/scripts/start-backend.js`)을 씀 — 결정 글 "시험 새로 만들기" 7번.

**먼저 볼 것**: 다른 에이전트가 시험·고치기를 돌리는 중이면 숫자가 틀어짐. 조용할 때 검.

### 2-0. 준비 (한 번)

```bash
# (가) 부하 도구 자가 점검 — 서버·DB 없이 5초, 26개 통과가 나와야 함
cd backend && node --test scripts/loadtest/selfcheck.js scripts/loadtest/selfcheck-bot.js; cd ..

# (나) 시험 DB(joker_e2e)에 새 마이그레이션(DB 표 바꾸기) 올리기 — 0035·0036이 들어온 뒤에
cd e2e && npm run db:setup; cd ..
#   → "[e2e] 시험 DB joker_e2e 준비 끝 (마이그레이션 N개 중 이번에 M개 적용 …)"

# (다) 포트가 비었는지 — 아무 줄도 안 나와야 함 (4000번은 사용자 것이라 보지도 끄지도 않음)
netstat -ano | grep LISTENING | grep -E ":(4100|4101|4102) "

# (라) 결과 둘 곳 + CPU 감시 (뒤에서 끝없이 돎, 30초마다 재고 90% 넘으면 "PC 부담 높음" 줄)
mkdir -p tools/시험도구/.run/load
powershell -NoProfile -File tools/시험도구/cpu-watch.ps1 > tools/시험도구/.run/load/cpu.txt 2>&1 &
```

- 결과 폴더 `tools/시험도구/.run/`은 git에 안 올라감
- 서버를 켜는 명령은 시험 DB 마이그레이션을 스스로 한 번 더 확인함 → (나)를 빼먹어도 올라감

## 3. 통과 기준

이 장은 무엇이 나오면 통과이고 무엇이 나오면 실패인지 적음. 결과 화면의 줄 이름 그대로 적음.

### 3-1. 잘 작동하는지 (꼭 지켜야 통과)

| 볼 줄 | 통과 | 지난번(11/10, 서버 2대) |
|---|---|---|
| `접속` | 사용자 수와 같음 (C-1 250/250, C-2 300/300) | 250/250 · 300/300 |
| `판` | 시작 = 끝까지 = 판 수, 실패 0 | 50/50 · 30/30 |
| `오류` | **0** | 0 |
| `끊김` | 0 | 0 |
| 서버 옮기기 | `사건별`의 `socket:node_move` 횟수만 있고, `오류`에 `socket:node_move_timeout` 없음 | 110번 · 144번 성공, 실패 0 |
| 서버 로그 | 오류 줄 0 (6장 명령) | 오류·경고 0 |
| 맨 끝 `[부하] 판정` 줄 | `통과` (위 접속·판·오류·끊김을 도구가 한 번에 봄) | 그땐 없던 줄 |

- `규칙 거절`은 0이 아니어도 됨. 다만 3-3의 "이상한 거절"이 있으면 들여다봄

### 3-2. DB를 여러 번 부르지 않는지

`--db-digest`를 주면 결과에 두 가지가 나옴.
- `DB 질의` 줄: MySQL 전체 셈(`Questions`, 받은 문장 수). 같은 MySQL의 다른 DB 일도 섞임
- `DB 문장 모양별` 표: 시험 DB(`joker_e2e`) 것만. 같은 모양 문장이 판 하나당 몇 번 불렸는지. **이쪽을 기준으로 봄**

| # | 볼 것 | 통과 | 근거 |
|---|---|---|---|
| 1 | `DB 문장 모양별`의 "판당 초당" | **1.6 이하** | 지난번(11/9 줄인 뒤) 0.4~0.8 → 그 2배 |
| 2 | A-1(1판)과 A-3(20판)의 "판 하나당" | 차이 30% 안 | 판이 많아진다고 판 하나가 부르는 수가 늘면 안 됨 |
| 3 | A-2(10명)와 A-1(5명)의 "판당 초당" | 10명이 5명의 2.5배 안 | 사람 수만큼 느는 것(입장·투표 기록)만 2배 |
| 4 | 표에서 `game_settings`를 읽는 문장 | 판마다 안 불림 (0이거나 서버 켤 때 한 번) | 설계: 판 시작·결과 화면에서 0번 (`고치기_계획.md` 5-3) |
| 5 | 표에서 `game_desertions`를 읽는 문장 | 판마다 안 불림 | 설계: 탈주 대기 검사는 메모리·Redis, 봇은 탈주를 안 함 |
| 6 | 판 골드 지급 | 거래 시작(`START TRANSACTION`)이 판 하나당 사람 수만큼 늘지 않음 | 설계: 판 하나에 거래 하나 |
| 7 | 표 맨 위 줄들 | "판 하나당"이 인원 × 낮 횟수보다 훨씬 큰 문장이 없음 | 사람마다·줄마다 따로 묻는 문장(N+1)이 다시 생긴 표시 |

- 1번의 1.6·2번의 30%·3번의 2.5배는 이 글이 추천하는 선임(7장 1번). 지난번엔 "판 하나당 몇 번"을 적어 두지 않아 A-1 숫자가 오늘 기준이 됨
- 넘으면: 표에서 횟수가 큰 문장부터 어느 코드가 부르는지 찾음 → 서버 코드 문제로 적음 (도구에서 덮지 않음)

| `submit_night_action:TARGET_NOT_DEAD` | 마녀사냥꾼이 산 사람을 고름 | 지난번 57번. 지금은 봇이 죽은 사람만 골라 거의 없어야 함 |
| `http:login:401`·`423`·`429` | 계정이 서버 DB에 없음·잠김·로그인 요청 수 제한 | **이상** — 6장 |
| `…:DESERTION_COOLDOWN` | 탈주 대기에 걸림 | **이상** — 봇은 탈주를 안 함. 앞 실행이 시간 넘김으로 끝났는지 봄 |
| `start_game:PARTICIPANT_UNAVAILABLE`·`…:STALE_SOCKET`이 많음 | 참가자 소켓을 못 찾음 | **이상** — 서버 2대 옮기기 쪽 |

## 4. 도구가 무엇을 오류로 세나

이 장은 "오류 0"이 무엇을 뜻하는지 적음. 오늘 세는 법을 넓혀서, 전에는 조용히 지나가던 실패도 오류로 잡힘.

| 오류 이름 | 뜻 | 전에는 |
|---|---|---|
| `<사건>:timeout` | 10초 안에 답이 없음 | 같음 |
| `<사건>:INTERNAL_ERROR`·`DELIVERY_ERROR` | 서버 안에서 실패 | 같음 |
| `<사건>:VOTE_PERSIST_FAILED` | 낮 표 참여 기록을 DB에 못 씀 | 규칙 거절로 셈 |
| `<사건>:NODE_UNAVAILABLE`·`CLUSTER_UNAVAILABLE` | 방 있는 서버가 죽음·Redis를 못 씀 | 규칙 거절로 셈 |
| `game:create_failed`·`join_failed`·`start_failed` | 판을 못 차림 | 결과 글만 찍고 오류·실패 판에 안 셈 |
| `game:not_finished` | 판이 15분 안에 안 끝남·판이 서버에서 사라짐 | 실패 판에만 셈 |
| `setup:bot_not_ready` | 로그인·소켓 접속을 못 한 사용자 | 안 셈 → 판 수만 조용히 줄었음 |
| `http:login:5xx`·`network`, `socket:connect_error`·`node_move_timeout` | 로그인·접속·서버 옮기기 실패 | 같음 |

- 봇은 규칙을 어기는 요청을 일부러 보내지 않음 → 판 차리기 거절은 전부 문제로 봄
- 실패한 판 뒤에는 3초 쉼 (전엔 안 쉬고 방 만들기를 퍼부어 소켓 사건 수 제한에 걸려 끊겼음 — 11/9 70판 기록)

## 5. 봇이 하는 일과 오늘 정한 것 대조

이 장은 부하 봇(가짜 사용자)이 보내는 사건이 지금 서버와 맞는지 코드로 대조한 결과를 적음. 서버 코드는 작업 폴더의 지금 파일 기준(오늘 고친 것 포함).

| 봇이 하는 일 | 보내는 사건 | 지금 서버 | 맞음 |
|---|---|---|---|
| 로그인 | `POST /auth/login` | 답 `data.user.uuid` + `accessToken` 쿠키. 맞는 비번이라 잠금(5번 틀림)에 안 걸림 | 맞음 |
| 방 만들기 | `create_room` (코드 방·정원 5~10·광대 1·시간 30초) | 정원 5~10·광대 1~2·토론 30~150·투표 30~90·밤 30~120만 받음. 답 방 값에 `title`이 더해짐(봇은 `roomId`·`roomCode`·`settingsVersion`만 씀) | 맞음 |
| 코드 입장 | `join_room_by_code` | 답은 `room_joined`·`room_join_failed` 알림. 1분 20번 제한(봇은 판마다 1번) | 맞음 |
| 준비·시작 | `set_ready`·`start_game` | 5명 이상·전원 준비여야 시작 | 맞음 |
| 판 상태 묻기 | `get_session_snapshot` (1초마다) | `phase`·`dayPhase`·`nightTurnRole`·`tribunal`·`self`·`players` 그대로 | 맞음 |
| 낮 토론 | `submit_game_chat_message` → `ready_for_day_vote` | 전원 준비면 바로 투표 | 맞음 |
| 낮 투표 | `cast_day_vote` (나·죽은 사람·동료 광대 빼고) | 다 내면 5초 뒤 서버가 판정. "낮 집계" 사건 없음(봇도 안 보냄). 끝난 판이면 `GAME_ALREADY_ENDED` | 맞음 |
| 재판 | `cast_tribunal_vote` (피고는 안 냄) | 다 내면 5초 뒤 판정. 결과 값 `DEFENDANT_DISCONNECTED`·`DEFENDANT_DIED`, 알림에 `executedRole`·`counts` 없음 — 봇은 결과 값을 안 읽음 | 맞음 |

| 판 끝 | `leave_game_session` | 결과 화면에서 나가기 = 그 사람만 정리. 다음 판은 새 방 | 맞음 |
| 이모티콘 | 안 보냄 | 낮에만 됨(그 밖 `INVALID_PHASE`) | 해당 없음 |
| 판 끝 뒤 "대기방으로" | 안 보냄 (`return_to_room`) | 누른 사람만 같은 방으로 | 안 탐 (7장 3번) |
| 결과 화면 180초·끊김 60초 | 안 기다림 (봇은 판 끝을 보면 1초 안에 나감, 스스로 안 끊김) | - | 해당 없음 |

- 봇이 보내는 사건 13개가 서버에 전부 등록돼 있는지는 자가 점검이 서버 파일을 읽어 확인함(8장)

## 6. 실패했을 때 볼 곳

| 보이는 것 | 먼저 볼 곳 |
|---|---|
| `[부하] 중단: 4000번은…` / `개발 DB(…)엔…` | 막기에 걸림(1장). `--target`·`--db-env`를 다시 봄 |
| `접속 0/…`, `http:login:401` | 서버와 도구가 다른 DB를 봄. 서버를 2-1·2-2 명령으로 켰는지, `--db-env ../e2e/.env.e2e`를 줬는지 |
| `http:login:429` | 로그인 요청 수 제한. 서버를 브라우저 시험 틀로 안 켠 것(틀은 제한을 풀어 둠) |
| `socket:connect_error` | 서버가 안 떴거나 포트가 다름. `curl -s http://127.0.0.1:4100/health` |
| `시작 실패`·`입장 실패`·`방 만들기 실패` | 결과 줄 뒤의 코드 + 서버 로그 |
| `끝까지 못 감: TIMEOUT` | 판이 15분 안에 안 끝남. 서버 로그에서 그 시각 단계 넘기기 오류를 찾음. 이 사용자들은 탈주로 적혀 다음 실행에서 `DESERTION_COOLDOWN`이 날 수 있음 → 서버를 다시 켬 |
| `끝까지 못 감: VANISHED` | 판이 서버에서 사라짐 = 서버가 죽었다 다시 켜짐. 로그의 "백엔드 꺼짐" 줄 |
| `DB 문장 모양별` 표가 안 나옴 | docker 안 DB를 못 읽음(경고 한 줄이 찍힘). `DB 질의` 줄만으로 보고, 그동안 다른 DB 일을 멈춤 |

**서버 로그** (`e2e/.runtime/`, git에 안 올라감)

```bash
# 서버 1대: backend.log / 서버 2대: backend-e2e-n1.log · backend-e2e-n2.log
# 마지막으로 켠 뒤의 오류 줄 수 (0이어야 함)
for f in e2e/.runtime/backend*.log; do
  echo "$f: $(awk '/백엔드 켬/{buf=""} {buf=buf $0 "\n"} END{printf "%s", buf}' "$f" | grep -ciE "error|에러|unhandled")"
done
```

- 오류 줄이 있으면 그 줄 앞뒤를 읽고 서버 코드 문제로 적음 (`시험에서_나온_코드_문제.md`)
- 판 하나가 이상하면 `/internal/live`(지금 상황 요약)가 판 번호·단계를 줌: `--out` JSON에는 없고, 도구가 5초마다 읽기만 함

### 부록 2. DB 셈을 손으로 읽을 때

```bash
cd backend
# 서버 전체 셈 값 한 번 (JSON)
node scripts/loadtest/dbcount.js status --db-env ../e2e/.env.e2e --out 앞.json
# 문장 모양별 셈 한 번 (시험 DB 것만)
node scripts/loadtest/dbcount.js digest --schema joker_e2e --out 앞d.json
# 앞뒤 차이
node scripts/loadtest/dbcount.js diff 앞.json 뒤.json --games 20
node scripts/loadtest/dbcount.js diff 앞d.json 뒤d.json --games 20 --top 30
```

- `status`는 `SHOW GLOBAL STATUS`(MySQL 전체 셈 값 보기) — 권한이 필요 없음
- `digest`는 `performance_schema`(MySQL이 문장마다 세어 둔 표)를 DB 이름으로 걸러 읽음. 시험 DB 계정엔 권한이 없어 docker 안에서 읽기 문장 하나만 돌림
- `run.js --db-digest`는 판을 돌리기 바로 앞·뒤에 이 둘을 읽어 계정 만들기·로그인·계정 지우기가 숫자에 안 섞이게 함
