# 고치기 계획

이 글은 `결정.md`에서 "고침·새로 만듦"으로 정한 줄을 18개 작업 단위로 묶고, 4차 묶음으로 차례를 정한 계획임. 고치기는 코드만 고치고, 시험은 고치기가 다 끝난 뒤 따로 새로 만들어 한 번에 돌림.

- 기준: 브랜치 release/2026-11-10 작업 폴더 코드. 코드는 읽기만 했고 아무것도 안 고침.
- 경로는 열어 보고 있는 것만 적음. 새로 만들 파일은 "(새)"를 붙임.
- [사실] = 코드·문서에서 직접 봄, [짐작] = 코드로 미루어 생각함, [임시] = `결정.md` 맨 아래 "반장이 임시로 정한 것"(아침에 확인).
- 옛 시험은 전부 지움(다른 에이전트가 하는 중). 시험 파일만 지우고 도우미는 남김(`준비_시험환경.md` 2장). 사용자가 고치는 중인 `frontend/tests/domains/game/ingame/store/participantDeparture.test.js` 하나만 남고 건드리지 않음.
- 빼는 것: "각자 고르는 선택지"(다른 브랜치) → 7장.

## 1. 작업 단위

이 장은 단위마다 끝난 모습, 온 결정 줄, 바꿀 파일, 주고받는 값, 나중에 시험 단계가 꼭 넣을 케이스, 크기·위험, 고친 뒤 가벼운 확인을 적음.

- 줄임: 서버 = `backend/`, PC = `frontend/src/`, 모바일 = `frontend-mobile/src/`.
- 모바일 화면은 PC 훅·스토어(store, 화면이 들고 있는 판 상태)·상수를 `@` 길로 그대로 씀 [사실, `버그8` 글]. PC 쪽 파일 하나를 고치면 모바일도 같이 바뀌는 곳이 많음.
- 고치는 단위는 **코드만 고침**. 시험 묶음은 안 돌림.
- 고친 뒤 가벼운 확인(공통)
  - 서버: 고친 파일 `cd backend && npx eslint <파일들>` + 고친 모듈 한 번 불러 보기 `node -e "require('./<파일>')"`.
  - PC·모바일: `npx eslint <파일들>` + `npm run build`(그 폴더).
  - 관리자 화면은 PC 폴더(`frontend/src/admin`) 안이라 PC 빌드로 같이 확인 [짐작: 빌드 설정이 관리자 입구도 묶는지 첫 빌드 때 확인].

### 단위 1. 같은 직업끼리 보이기 (시민 빼고)

- 끝난 모습: 광대·의사·경비원·마녀사냥꾼은 같은 직업 동료를 역할 확인 창과 카드에서 봄. 시민은 아무도 안 봄.
- 결정 줄: "역할 확인 — 누가 누구 직업을 보나", "역할 확인 — 시민끼리 보이나".
- 바꿀 파일
  - 서버: `backend/game-core/setup/startPayload.js` (`buildViewerRoleFields`의 광대만 `allies` 붙이는 줄 → 시민 뺀 네 직업). 스냅샷(snapshot, 판 전체 모습 다시 받기)도 같은 함수를 써서 `backend/game-core/snapshot/session.js`는 따라옴 [사실 :108].
  - PC: `frontend/src/domains/game/ingame/utils/buildPlayerSessionSourceFromGameState.js`(:55-62 광대 아니면 `allies` 거절하는 검사), `utils/snapshot/self.js`(:9-20, :57), `utils/roleReveal.js`(:54-67), `utils/actionTargets.js`(동료 고르기 막음은 광대만, 이름 뒤 "동료 JOKER" 글자를 직업 이름으로), `components/roleReveal/InGameRoleRevealOverlay.jsx`.
  - 모바일: `frontend-mobile/src/domains/game/ingame/components/overlays/RoleRevealOverlay.jsx`.
- 주고받는 값: `game_started`·스냅샷의 `state.self.allies`가 의사·경비원·마녀사냥꾼에게도 붙음(같은 직업 다른 사람 uuid 목록). 이름은 그대로.
- 시험 단계가 꼭 넣을 케이스
  - 의사 2명 판: 의사 A의 시작 알림·스냅샷 `allies`에 의사 B만 있음.
  - 경비원 2명·마녀사냥꾼 2명도 같음.
  - 시민은 시민이 여럿이어도 `allies` 칸이 없음.
  - 직업이 1명이면 `allies`가 빈 목록.
  - 광대는 지금처럼 동료 광대.
  - 남의 직업이 새지 않음: 다른 직업 사람 uuid가 `allies`에 안 섞임.
  - 화면: 의사 A의 역할 확인 창에 "동료" 줄로 의사 B가 보임, 시민 화면엔 동료 줄 없음.
  - 화면: 의사 A가 밤에 동료 의사 B를 고를 수 있음(광대만 동료 지목 막힘).
  - 새로고침(스냅샷) 뒤에도 동료 표시가 그대로.
- 크기·위험: 보통. 위험 = `actionTargets.js`가 동료를 "고를 수 없음"으로 만들어 의사가 동료 의사를 못 지키게 될 수 있음 → 서버 규칙대로 광대만 막음(서버 `TARGET_IS_ALLY`는 광대만 [사실, `04-밤-직업.md` 2-1]).

### 단위 2. 시민 밤 채팅 삭제

- 끝난 모습: 밤 직업 채팅은 광대·의사·경비원·마녀사냥꾼만. 시민은 밤 채팅 칸이 닫힘. 죽은 사람 채팅·죽은 광대 읽기는 그대로.
- 결정 줄: "밤 채팅".
- 바꿀 파일
  - 서버: `backend/game-core/chat/messages.js`(`prepareJokerChatMessage` :64-93 — 시민이면 `NOT_ELIGIBLE`), `backend/game-core/chat/rules.js`(:54-70 채널 받는 사람).
  - PC: `frontend/src/domains/game/ingame/utils/selfAlive.js`(`NIGHT_CHAT_ROLES` :33에서 `CITIZEN` 뺌).
  - 모바일: `frontend-mobile/src/domains/game/ingame/utils/talk/buildTalkFeed.js`(`ROLE_CHANNELS` :5).
- 주고받는 값: 사건 이름 그대로(`submit_joker_chat_message`). 시민이 보내면 거절 코드만 생김.
- 시험 단계가 꼭 넣을 케이스
  - 밤에 산 시민이 직업 채팅을 보내면 거절, 아무에게도 안 감.
  - 밤에 산 의사가 보내면 같은 직업 산 사람만 받음.
  - 죽은 광대는 광대 채팅을 읽기만, 보내면 거절(지금 그대로).
  - 죽은 사람 채팅은 시민이었어도 낮·밤 언제나 됨.
  - 화면: 밤에 산 시민은 채팅 입력칸이 닫히고 "밤 · 같은 직업끼리" 띠가 없음.
  - 화면: 밤에 산 경비원은 입력칸이 열림.
- 크기·위험: 작음. 위험 = 모바일 채팅 줄 만들기가 채널 목록에 시민이 있다고 보고 짜였을 수 있음.

### 단위 3. 재판 표시 남음(버그 8) + 기권이 많으면 재판 없음(버그 9)

- 끝난 모습
  - 둘째 날 재판에서도 유죄·무죄 단추가 뜸. 서버가 표를 거절하면 까닭 글이 재판 창에 보임.
  - 낮 투표에서 최다 득표가 기권 수보다 많아야 재판. 같거나 적으면 재판 없이 밤. 결과 문구도 따로.
- 결정 줄: "재판 — 둘째 날 유죄·무죄를 못 누름 (버그 8)", "낮 투표 — 기권이 더 많을 때 (버그 9)".
- 바꿀 파일
  - 서버: `backend/game-core/phase/day/ballots.js`(`tallyDayVoteOutcome` :24-74, 새 결과 값).
  - PC: `frontend/src/domains/game/ingame/store/ingame/voteActions.js`(:44-58 재판 들어갈 때 `hasSubmittedTribunalVote` 지우기), `utils/store/selfActed.js`(:5 새 낮 지우기 목록), `store/ingame/phaseActions.js`(:102), `hooks/useInGameTribunalVoteSubmit.js`(:139-151), `components/tribunalPresentation/InGameTribunalPresentationGate.jsx`(:72-79 거절 글), `utils/dayVoteResolve.js`(:8 결과 값 표), `components/vote/InGameVoteStatusContent.jsx`, `constants/store/sessionSnapshot.js`.
  - 모바일: `frontend-mobile/src/domains/game/ingame/components/overlays/tribunal/TribunalGate.jsx`(:50-55 거절 글), `components/actions/VoteStatusContent.jsx`.
- 주고받는 값: `day_vote_resolved.outcome`에 새 값 하나(예 `ABSTAIN_MAJORITY`, 다음 단계 `NIGHT`). 기존 `TRIBUNAL`·`TIE`·`ABSTAINED` 그대로.
- 시험 단계가 꼭 넣을 케이스
  - 1일 재판에서 유죄를 누른 사람이 2일 재판에서 유죄·무죄 단추를 봄(새로고침 없이).
  - 2일 재판에서 그 사람 표가 서버에 들어가 기권으로 안 셈.
  - 새 낮이 되면 지난 재판 "표 냈음" 표시가 지워짐.
  - 서버가 재판 표를 거절하면(예 이미 판정) 재판 창에 까닭 글이 보임(PC·모바일).
  - 7명 중 1표 6기권 → 재판 없이 밤, 결과 문구가 "기권이 많아" 쪽.
  - 3표(한 사람) 3기권 → 같음이라 재판 없이 밤.
  - 4표(한 사람) 3기권 → 재판.
  - 동점은 지금처럼 밤, 전원 기권은 지금처럼 밤.
  - 투표 현황 창(PC·모바일)이 새 결과 값을 알아보고 문구를 띄움.
- 크기·위험: 보통. 위험 = `voteActions.js`·`phaseActions.js`는 단위 11(밤 영상)도 고침 → 1차에 이 단위, 2차에 단위 11. 사용자 파일 `participantDeparture.test.js`가 같은 스토어를 봄(5장 시험 단계에서 돌려 보기만, [임시] 11).

## 2. 큰 단위 설계 안

이 장은 설계가 필요한 7개에 안·추천·까닭을 적음. 새로 DB를 부르는 곳마다 "요청마다·사람마다 DB를 부르지 않게" 한 줄을 붙임(지난번 부하 문제가 DB 여러 번 부르기였음).

### 2-1. 판 끝 뒤 같은 방으로 (단위 16)

지금 [사실]
- 판이 시작되면 대기방을 지움(`startLaunch.js:107 disposeRoom`), "시작된 방" 표시만 30분 남김(`startedMarks.js`).
- 판은 방 코드·방 id·설정 원본·방장을 들고 있음(`game-core/setup/create.js:36`, `startPayload.js:94-101`). 설정 원본엔 역할 구성(`roleCompositionMode`·`roleCounts`)도 있음(`validations/room/updateSettings.js:45-46`).
- 같은 방 id의 판이 있으면 새 판을 못 넣음(`game-core/setup/commit.js:158`). 끝난 판도 장부에 남아 있는 동안은 같음.
- 추방 횟수는 방 객체에 묶임(`room/kickLimit.js:8`, WeakMap(방이 사라지면 같이 사라지는 표)).
- 서버 여러 대면 대기방 코드는 Redis `roomcode` 키로 잡고, 방이 지워지면 놓음(`cluster/roomDirectory.js:25-52,108-111`).

안 A — 방을 지우지 않고 "게임 중" 상태로 장부에 둠
- 좋은 점: 방 id·코드·추방 횟수·Redis 키가 그대로 남음.
- 걸리는 점: 방 장부(`gameRooms`)를 읽는 파일이 32개 [사실, grep]. 목록·입장·설정·추방·시작·드레인(새 손님 안 받기) 수 세기 모두 "게임 중 방 빼기"를 넣어야 함.

안 B (추천) — 판 시작 때 방 정보를 판에 옮겨 담고, 판 끝 때 같은 코드로 다시 만듦
- 판 시작: 방 코드·설정·추방 횟수를 판에 옮겨 담음. 방은 지금처럼 지움. Redis 코드 키는 놓지 않고 판 Node가 계속 잡아 둠(수명 6시간, 3시간마다 다시 씀 — 지금 방 키 규칙과 같음).
- 판 끝(승부 나서 종료 칸 붙는 순간, `departure/end.js withTerminalFields`): 같은 Node에 빈 대기방을 만듦.
  - 방 id는 새로 뽑음 → `commit.js`의 "같은 방 판" 검사와 안 부딪힘.
  - 코드·설정·추방 횟수는 그대로. "시작된 방" 표시는 지움.
  - 방장 칸 = 비움, `reservedHostUuid` = 판이 끝날 때의 판 방장(`session.hostUuid`, [임시] 8).
  - 180초 동안 정원에서 방장 자리 1칸을 남겨 둠([임시] 3). 남은 자리 셈은 입장 다시 보기(`join/joinRecheck.js`)에 넣음.
  - 공개 방이면 첫 사람이 들어온 뒤부터 목록에 보임([임시] 13).
- "대기방으로": `return_to_room { gameId }` 하나. 서버가 끝난 판 사람인지 보고 → 방에 넣고(보통 입장과 같은 확정 함수) → 끝난 판 묶임에서 뺌. 준비 안 됨으로 들어감.
- 방장 정하기: 남겨 둔 방장이 들어오면 그 사람이 방장. 남겨 둔 방장이 "로비로"·로비 입장·180초 지남 → 방에 먼저 들어온 사람이 방장(`room/leave.js:88-93`과 같은 규칙). 그동안 방장이 없으면 설정 바꾸기·추방·시작 단추는 아무에게도 안 보임.
- 180초 (판 끝 시각부터 하나의 시계, [임시] 4)
  - 결과 화면에 남은 사람 → `game_result_closed` 보내고 끝난 판에서 뺌 → 화면은 `/lobby`.
  - 방에 아무도 없으면 방 지움. 있으면 유지.
  - 방장 자리 남겨 두기 끝.
  - 지금 60초 정리(`ENDED_SWEEP_DELAY_MS`, 판 끝 순간 끊긴 사람)는 이 180초에 합침 [안].
- 결과 화면 새로고침·끊김: 지금처럼 바로 판에서 빠짐(결정 "맞음"). BE-020 글만 고침.
- DB: 이 흐름은 메모리·Redis만 씀. 새로 DB를 부르지 않음.
- 까닭: 안 A보다 고칠 곳이 좁음. "판 중엔 방 없음 + 이미 시작된 방" 동작이 그대로. 사람에겐 같은 코드·같은 설정이라 결정과 맞음.

서버 여러 대 길잡이
- 판과 다시 만든 방은 같은 Node. 사람 소켓은 위치 기록(`socket/connection/locationSync.js`)으로 그 Node에 붙어 있어 `return_to_room`도 그 Node가 받음.
- 로비로 갔다가 코드로 다시 오는 사람은 지금의 "다른 Node 방이면 그 Node로 옮겨 붙기" 길(`cluster/roomRouting.js`)을 그대로 탐.
- 판 동안 코드 키를 잡아 두므로 다른 Node가 같은 코드를 못 뽑음. Redis가 멈춰 있어 판 끝 때 코드를 못 잡으면 새 코드로 만들고 결과 화면에 "방 코드가 바뀌었습니다" 한 줄 [안].
- 드레인 중인 Node: 방을 다시 만들면 드레인이 최대 180초 늘어남 → 드레인 중이면 방을 안 만들고 결과 화면에 "서버 점검 준비 중이라 대기방으로 돌아갈 수 없습니다" + "로비로"만 [안, 배포 때만 생김].

없어지는 것: 자동 입장(`join/join.js autoJoinPartyToRoom`), 다음 방 우편함(`join/party.js`), 기다림 화면(`partyRejoin*`), 스스로 옮김 표시(`partyOrigin.js`), 끝난 판 방장만 파티 방 만들기(`game-core/queries/ended.js getEndedPartyContext`). B06-1·B06-2·B06-4·Q06-2·Q06-4가 같이 사라짐 [짐작: 원인 코드가 없어짐].

### 2-2. 로비 입장 방어 (단위 17)

안 A (추천) — 화면이 들어올 때 소켓(서버와 이은 실시간 줄) 사건 `enter_lobby`를 보냄
- 판·대기방 상태는 서버 Node 메모리에만 있음. 소켓은 그 사람 판·방이 있는 Node에 붙어 있음(`socket/connection/nodeRouting.js:33-56`). 그래서 소켓 사건이면 그 Node가 바로 정리할 수 있음.
- 서버 차례
  1. 진행 중 판에 산 채로 있음 → 아무것도 안 지우고 `{ redirect: 'INGAME', gameId }`. 끊김 기다림은 지금처럼 다시 붙어서 풀림.
  2. 진행 중 판에 죽은 채 있음 → 판에서 풀기(죽은 사람 나가기와 같은 처리: 기권 명단만, 편 결과·골드 그대로).
  3. 끝난 판에 묶임 → 끝난 판에서 뺌(남겨 둔 방장이면 방장 넘김, 2-1).
  4. 대기방 자리 → `leave_room`과 같은 처리(15초 유예 없이).
  5. 입장 중 표시·초대 입장 처리 중·매칭 줄 → 되돌림.
  - 몇 번을 불러도 같은 결과(이미 없으면 그냥 ok).
- 보내는 곳: 로비(`/lobby`), 방 목록(`/multiplay`), 게임 모드, 게임 설정 화면. 안 보내는 곳: 대기방(`/game-matching`), 판(`/ingame`), 결과(`/gameresult`), 초대 받기 화면.
- 화면은 답이 `INGAME`이면 `/ingame`으로 감. 답이 늦거나 연결이 없으면 화면은 그대로(다음 연결 때 다시 보냄).
- DB: 메모리만 봄. 로비 입장마다 DB를 부르지 않음(정리할 것이 없으면 아무것도 안 씀).

안 B — 로비 HTTP 요청(프로필 읽기 등)에 붙임
- HTTP는 앞단이 아무 Node로 보낼 수 있어 판이 있는 Node 메모리를 못 만짐(서버 여러 대면 틀림). 서버끼리 묻기(RPC)가 새로 필요.

추천 까닭: 안 A가 서버 여러 대에서도 맞고, 이미 있는 처리(나가기·`leave_room`·끝난 판 빼기)를 한곳에서 부르기만 하면 됨.

로비가 아닌 화면으로 바로 들어오는 길: 주소창에 `/multiplay`·`/game-setup`을 쳐도 같은 훅이 돌아 같이 정리됨. `/game-matching`을 직접 치면 지금처럼 `get_current_room`으로 방 확인(정리 안 함).

### 2-3. 다 누르면 5초 뒤 판정 (단위 15)

- DB: 안 부름(메모리 타이머).
- 까닭: 마감 시각 하나만 당기면 타이머·스냅샷·기권 채우기를 다 다시 씀. 새 판정 길이 없어 "5번 실패 멈춤"(Q04-7) 같은 위험이 안 늘어남. 화면이 스스로 세는 안은 남의 진행 수를 화면이 몰라(나4) 안 됨.

### 2-4. 밤 영상 정리 (단위 11)

- 서버 밤 턴 닫기: 지금 "결과 확정 → 성공 사건 개별 전달 → 턴 끝 방송 → 연출 대기"(`turn.js:145-173`) → "결과 확정 → 턴 끝 방송 → 다음 턴". 성공 계약·수신 기록·연출 대기·다 봄 신호 모두 지움.
- 경비원 조사 당한 사람 알림·마녀사냥꾼 확인 대상 알림은 성공 사건이 없어지며 같이 없어짐.
- 결과 글은 지금 있는 밤 끝 개인 결과(`finalize.js:26-42 night_action_result`)로 줌. 새로 만들 것 없음 [사실: 개인 결과 만들기 `prepare.js:62-96`].
- 낮 시작 연출: `night_result_applied`에 `doctorSaved`만 더함. 화면이 받으면
  - 희생자 있음(`deathReveals[].source === 'JOKER'`) → 모두에게 암살 영상(지금 KILL 영상 재사용) + "지난밤 [닉네임]님이 살해당했습니다".
  - `doctorSaved` → "지난밤 의사가 공격받은 사람을 살려냈습니다".
  - 둘 다 아님 → 지금처럼 "낮이 되었습니다"만.
  - 차례: 낮 시작 연출 → "낮이 되었습니다" 창. 판이 끝났으면 낮 시작 연출 → 결과 화면([임시] 9).
  - 새로고침·늦게 붙은 사람에게는 다시 안 틀어 줌 [안]. 모바일은 채팅 알림 줄(`playerNotices.js`)이 남음.
- `doctorSaved`는 광대가 노린 사람을 의사가 지켜 암살이 막혔을 때만 참(지금 광대에게 주는 암살 실패 조건 `assassinationBlocked`와 같음 [사실 `prepare.js:62,81-83`]).
- DB: 안 부름. 지금 연출 대기·수신 기록(메모리)이 없어져 서버 일이 줄어듦.

### 2-5. 판마다 골드 (단위 10)

- 값 저장: 새 표 `game_settings`(4장)에 `GAME_GOLD_REWARD = 1`.
- **DB 덜 부르기**
  - 값은 서버 켤 때 한 번 읽어 메모리에 둠. 관리자가 바꾸면 `services/ops/reloadSync.js`의 "다시 읽기"로 모든 Node가 한 번 다시 읽음(점검·금지어가 쓰는 길과 같음 [사실], 60초 안전망도 Node마다 한 번이지 요청마다가 아님). 판 시작·결과 화면은 메모리 값만 봄.
  - 지급은 판 끝 전적 저장(`services/game/record/persist.js`) 뒤 **판 하나에 한 번**, 판 사람 전원(5~10명)을 한 거래 안에서 한꺼번에 씀(장부 여러 줄 + 지갑 여러 줄). 사람마다 따로 거래를 열지 않음. 지금 `grantReward`는 한 사람 한 거래라 여러 사람용 함수를 하나 더함.
  - 지급 뒤 잔액 캐시 무효화 신호도 판에 한 번.
- 판 시작 때 그 판 지급 값을 판에 적어 둠 → 판 중에 관리자가 바꿔도 그 판은 시작 때 값.
- 받는 사람: 판의 사람 중 "산 채로 떠나지 않은 사람" 전원. 산 채로 떠남 판단은 전적 기록이 이미 씀(`game-core/result/record.js:23-27`).
- 두 번 안 주기: 참조 id `game-reward:<gameId>`, 장부 (사람, 참조 id) 유일 제약 [사실 `models/economy/economy.model.js:75`]. 장부 사유 칸은 글자라 표 바꾸기 필요 없음.
- 안 주는 판: 점검 강제 종료 판(`session.abortReason`, 지금 업적도 안 줌 [사실 `persist.js:35-36`], [임시] 12). 서버 재시작으로 사라진 판은 기록 자체가 없음.
- 값이 0이면 지급·표시 둘 다 안 함.
- 결과판: 판 끝 칸에 사람마다 `goldReward`. 결과판 내 결과 자리에 "+1골드"(모두 같은 값이라 내 것 하나) [안].
- 관리자: 값 보기·바꾸기(0~100 정수 [안]), 바꿀 때 감사 기록(`admin_audit_logs`).

### 2-6. 탈주 대기 시간·끊김 60초·죽은 사람 풀기 (단위 12·13)

탈주 기록 (단위 12)
- 표 `game_desertions`: 한 판에 한 줄(사람·판 유일). 칸: 사람, 판, 이유(산 채로 나감 / 60초 못 돌아옴), 탈주 시각, 막힘 끝 시각.
- 몇 번째인지: 같은 사람의 "오늘(한국 시간 0시부터) 탈주 수 + 1". 1번째 5분, 2번째 30분, 3번째 이상 24시간([임시] 5).
- 막힘 끝 = 탈주 시각 + 대기 시간. 자정이 지나도 남음. 다음 날 처음 탈주는 다시 1번째.
- **DB 덜 부르기**
  - 입장 검사(방 만들기·입장·초대 수락·매칭)는 DB를 안 부름. 사람별 "막힘 끝" 표를 서버 한 대면 메모리, 여러 대면 Redis 키(`desertlock:<사람>`, 수명 = 남은 시간)로 봄.
  - 오늘 몇 번째인지도 메모리/Redis 숫자(`desertcount:<사람>:<한국 날짜>`, 수명 = 자정까지)로 셈.
  - DB는 탈주가 생길 때 한 줄 쓰기 한 번(드문 일).
  - 서버 한 대가 다시 켜질 때만 "막힘 끝 > 지금"인 줄을 한 번 읽어 메모리를 채움(켤 때 한 번).
  - 관리자 회원 상세는 관리자가 볼 때만 DB를 읽음.
- 기록 실패(DB 안 됨)면 로그만, 막힘은 메모리/Redis에 이미 걸려 있어 그대로 막음.

끊김 60초 (단위 13)
- 끊기면 늘 60초 타이머 하나. 단계가 바뀌어도 유지(지금의 단계 경계 만료·내 밤 차례 마감 만료 지움).
- 60초 안에 다시 붙으면(지금처럼 `connection/routing.js:46`) 타이머 끔.
- 그동안 투표·밤 차례는 마감 때 기권·건너뜀(지금 그대로).
- 60초 지나면 지금 탈락 길(`departure/apply.js`, 이유 `DISCONNECT_GRACE_EXPIRED`) + 탈주 기록.
- 끊긴 피고: 재판 그대로 진행, 재판 중 탈락하면 그때 지금 "피고 나감" 규칙으로 취소([임시] 10).
- DB: 끊김·다시 붙음은 DB를 안 부름. 탈락 때 탈주 기록 한 줄만.

죽은 사람 풀기 (단위 13·17, [임시] 2)
- 죽은 사람이 끊기면 "매칭을 막지 않음"만 함(`queries/live.js isMatchmakingBlocked`에서 죽은 사람 빼기). 판 자리는 남겨 관전 중 새로고침이면 그대로 판을 봄.
- 다른 방에서 새 판을 시작하면 그때 옛 판에서 풀림(`setup/commit.js`). 로비 입장(단위 17)·나가기는 바로 풀림.

## 5. 고친 뒤 차례 (시험·부하·브라우저)

이 장은 고치기가 끝난 뒤 시험을 새로 만들고 한 번에 돌리는 차례를 적음. 옛 시험은 다 지워져 "깨질 시험"은 셀 것이 없음.

### 5-1. 차례

1. **고치기 4묶음** — 1차 → 2차 → 3차 → 4차. 단위마다 코드만 고치고 가벼운 확인(eslint·불러 보기·빌드)만. 시험 묶음은 안 돌림.
2. **시험 새로 만들기** — 고치기가 다 끝난 뒤 따로 한 단계. 정답은 `결정.md`. 1장 단위마다 "시험 단계가 꼭 넣을 케이스"를 빠짐없이 넣음. 운영 규칙(5~10명)으로만 판을 차림.
3. **한 번 돌림** — 아래 5-2 명령을 다 돌림(Docker 켜짐, DB·Redis 씀).
4. **실패 모아 고침** — 실패를 한 목록에 모은 뒤 한꺼번에 고치고, 고친 곳에 걸친 시험만 다시 돌림.
5. **부하** — 5-3. 목적: DB를 여러 번 부르는 문제가 다시 생기지 않았는지.
6. **브라우저 한 번** — `cd e2e && npm run db:setup`(처음 한 번) → `npx playwright test`. 서버 2개 전용은 `E2E_NODES=2 npx playwright test`.
7. **나온 버그만 다시** — 그 뒤 버그가 나오면 버그 목록과 그 코드에 걸친 시험만 다시 돌림.

### 5-2. 한 번 돌릴 명령

| 묶음 | 폴더 | 명령 |
|---|---|---|
| 서버 단위 | `backend` | `npm test` |
| 서버 진짜 DB | `backend` | `npm run test:db:setup`(한 번) → `npm run test:with-db` |
| 서버 진짜 Redis(서버 여러 대) | `backend` | `npm run test:with-redis` |
| 화면 PC·관리자 | `frontend` | `npm test` |
| 화면 모바일 | `frontend-mobile` | `npm test` |

- 사용자 파일 `participantDeparture.test.js`는 화면 `npm test`에 같이 돎. 깨지면 고치지 않고 보고([임시] 11).
- DB·Redis가 있어야 확인되는 케이스: 단위 8(마이그레이션), 10(지급·관리자 값·다른 Node 다시 읽기), 12(탈주 기록·켤 때 읽기·Redis 막힘 표), 16(서버 두 대 방 다시 만들기·코드 잡아 두기), 17(서버 두 대 로비 정리). 이 케이스는 `test:with-db`·`test:with-redis`·브라우저 서버 2개에서 확인.

### 5-3. 부하에서 볼 것

- 명령(서버 1대, `준비_시험환경.md` 1-5): 서버 하나 켜 둔 뒤 `node scripts/loadtest/run.js --target <주소> --games <N> --players 5`(5명)·`--players 10`(10명).
- 볼 숫자: **판 하나당 DB 질의 수**. 부하 앞뒤로 MySQL `SHOW GLOBAL STATUS LIKE 'Questions'`를 읽어 판 수로 나눔. 지난 기록과 견줌.
- 새로 DB를 부르는 곳이 설계대로인지 하나씩
  - 판마다 골드: 판 하나에 거래 하나(사람 수만큼 따로 아님).
  - `game_settings` 읽기: 판 시작·결과 화면에서 0번(메모리 값), 관리자가 바꿀 때만 Node마다 한 번.
  - 탈주 대기 검사: 방 만들기·입장마다 0번(메모리·Redis), 탈주가 생길 때 쓰기 한 번.
  - 로비 입장 정리: 0번(메모리만).
- 부하 봇(`backend/scripts/loadtest/bot.js`)이 판 중 나가기를 하면 탈주 막힘에 걸려 다음 판에 못 들어갈 수 있음 → 부하는 나가기 없는 판으로 [짐작: 봇이 나가기를 하는지 첫 실행 때 확인].
