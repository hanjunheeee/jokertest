# 고치기 계획

이 글은 `결정.md`에서 "고침·새로 만듦"으로 정한 줄을 같이 고칠 것끼리 17개 작업 단위로 묶고, 4차 묶음(같은 파일을 두 단위가 동시에 안 고치게)으로 차례를 정한 계획임.

- 기준: 브랜치 release/2026-11-10 작업 폴더 코드. 코드는 읽기만 했고 아무것도 안 고침. 서버·DB·브라우저·시험 묶음은 안 띄움.
- 경로는 열어 보고 있는 것만 적음. 새로 만들 파일은 "(새)"를 붙임.
- [사실] = 코드·시험에서 직접 봄, [짐작] = 코드로 미루어 생각함.
- 빼는 것: "각자 고르는 선택지"(다른 브랜치), 개발 환경 지우기 → 7장.

## 1. 작업 단위

이 장은 단위마다 끝난 모습, 온 결정 줄, 바꿀 파일, 주고받는 값, 같이 고칠 시험, 크기·위험, 확인법을 적음.

- 줄임: 서버 = `backend/`, PC = `frontend/src/`, 모바일 = `frontend-mobile/src/`.
- 모바일 화면은 PC 훅·스토어(store, 화면이 들고 있는 판 상태)·상수를 `@` 길로 그대로 씀 [사실, `00-버그-다시확인.md`·`버그8` 글]. 그래서 PC 쪽 파일 하나를 고치면 모바일도 같이 바뀌는 곳이 많음.
- 단위 시험 돌리기(공통): 서버 `cd backend && npm test -- <파일>`, PC `cd frontend && node --experimental-test-module-mocks --test <파일>`, 모바일 `cd frontend-mobile && node --test <파일>`. 전체 묶음은 다 만든 뒤 한 번(5장).

### 단위 1. 같은 직업끼리 보이기 (시민 빼고)

- 끝난 모습: 광대·의사·경비원·마녀사냥꾼은 같은 직업 동료를 역할 확인 창과 카드에서 봄. 시민은 아무도 안 봄.
- 결정 줄: "역할 확인 — 누가 누구 직업을 보나", "역할 확인 — 시민끼리 보이나".
- 바꿀 파일
  - 서버: `backend/game-core/setup/startPayload.js` (`buildViewerRoleFields`의 광대만 `allies` 붙이는 줄 → 시민 뺀 네 직업). 스냅샷(snapshot, 판 전체 모습 다시 받기)도 같은 함수를 씀 → `backend/game-core/snapshot/session.js`는 그대로 따라옴 [사실 :108].
  - PC: `frontend/src/domains/game/ingame/utils/buildPlayerSessionSourceFromGameState.js` (광대 아닌데 `allies` 오면 버리는 검사 :55-62), `utils/snapshot/self.js` (:9-20, :57), `utils/roleReveal.js` (:54-67), `utils/actionTargets.js` (동료면 고르기 막음 — 광대만 막게, 이름 뒤 "동료 JOKER" 글자를 직업 이름으로), `components/roleReveal/InGameRoleRevealOverlay.jsx`.
  - 모바일: `frontend-mobile/src/domains/game/ingame/components/overlays/RoleRevealOverlay.jsx`.
- 주고받는 값: `game_started`·스냅샷의 `state.self.allies`가 의사·경비원·마녀사냥꾼에게도 붙음(같은 직업 다른 사람 uuid 목록). 이름은 그대로.
- 같이 고칠 시험: "광대 아닌데 allies면 거절"을 고정한 시험 — `frontend/tests/domains/game/ingame/utils/buildPlayerSessionSourceFromGameState.test.js`, `getInGameRoleRevealInfo.test.js`, `store/applySessionSnapshot.test.js`, `utils/buildNightActionTargets.test.js`, 서버 `backend/tests/game-core/setup/gameSession.session.test.js`, `backend/tests/socket/gameSession.test.js` 등. `allies` 든 시험 42개(14파일) 중 실제로 깨질 것 약 20~25개 [짐작].

### 단위 3. 재판 표시 남음(버그 8) + 기권이 많으면 재판 없음(버그 9)

## 2. 큰 단위 설계 안

이 장은 설계가 필요한 7개에 안 1~2개·추천·까닭을 적음.

### 2-1. 판 끝 뒤 같은 방으로 (단위 16)

지금 [사실]
- 판이 시작되면 대기방을 지움(`startLaunch.js:107 disposeRoom`), "시작된 방" 표시만 30분 남김(`startedMarks.js`).
- 판은 방 코드·방 id·설정 원본·방장을 들고 있음(`game-core/setup/create.js:36`, `startPayload.js:94-101`).
- 같은 방 id의 판이 있으면 새 판을 못 넣음(`game-core/setup/commit.js:158`). 끝난 판도 장부에 남아 있는 동안은 같음.
- 추방 횟수는 방 객체에 묶임(`room/kickLimit.js:8`, WeakMap(방이 사라지면 같이 사라지는 표)).
- 서버 여러 대면 대기방 코드는 Redis `roomcode` 키로 잡고, 방이 지워지면 놓음(`cluster/roomDirectory.js:25-52,108-111`).

안 A — 방을 지우지 않고 "게임 중" 상태로 장부에 둠
- 판 동안 방 객체를 `status: 'IN_GAME'`으로 남기고, 판이 끝나면 `WAITING`으로 돌림.
- 좋은 점: 방 id·코드·추방 횟수·Redis 키가 그대로 남음.
- 걸리는 점: 방 장부(`gameRooms`)를 읽는 파일이 32개 [사실, grep]. 목록·입장·설정·추방·시작·드레인(새 손님 안 받기) 수 세기 모두 "게임 중 방 빼기"를 넣어야 함. "판 중엔 방이 없음"에 기대는 시험·검사(`describeVanishedRoom`)도 바뀜.

안 B (추천) — 판 시작 때 방 정보를 판에 옮겨 담고, 판 끝 때 같은 코드로 다시 만듦
- 판 시작: 방 코드·설정(공개/코드·정원·광대 수·역할 구성·시간)·판 끝 때 쓸 방장·추방 횟수를 판에 옮겨 담음. 방은 지금처럼 지움. Redis 코드 키는 놓지 않고 판 Node가 계속 잡아 둠(수명 6시간, 3시간마다 다시 씀 — 지금 방 키 규칙과 같음).
- 판 끝(승부 나서 종료 칸 붙는 순간, `departure/end.js withTerminalFields`): 같은 Node에 빈 대기방을 만듦.
  - 방 id는 새로 뽑음 → `commit.js`의 "같은 방 판" 검사와 안 부딪힘.
  - 코드·설정·추방 횟수는 그대로. "시작된 방" 표시는 지움.
  - 방장 칸 = 비움, `reservedHostUuid` = 판 끝 때 판 방장(`session.hostUuid`).
  - 정원 안에서 방장 자리 1칸은 180초 동안 남겨 둠(6장 물음 3).
- "대기방으로": `return_to_room { gameId }` 하나. 서버가 끝난 판 사람인지 보고 → 방에 넣고(보통 입장과 같은 확정 함수) → 끝난 판 묶임에서 뺌. 준비 안 됨으로 들어감.
- 방장 정하기: 남겨 둔 방장이 들어오면 그 사람이 방장. 남겨 둔 방장이 "로비로"·로비 입장·180초 지남 → 방에 먼저 들어온 사람이 방장(`room/leave.js:88-93`과 같은 규칙). 그동안 방장이 없으면 설정 바꾸기·추방·시작 단추는 아무에게도 안 보임.
- 180초 (판 끝 시각부터 하나의 시계):
  - 결과 화면에 남은 사람 → `game_result_closed` 보내고 끝난 판에서 뺌 → 화면은 `/lobby`.
  - 방에 아무도 없으면 방 지움. 있으면 유지.
  - 방장 자리 남겨 두기 끝.
  - 지금 60초 정리(`ENDED_SWEEP_DELAY_MS`, 판 끝 순간 끊긴 사람)는 이 180초에 합침 [안].
- 결과 화면 새로고침·끊김: 지금처럼 바로 판에서 빠짐(결정 "맞음"). BE-020 글만 고침.
- 까닭: 안 A보다 고칠 곳이 좁음(방 장부를 읽는 32파일을 안 건드림). "판 중엔 방 없음 + 이미 시작된 방" 동작이 그대로라 시험이 덜 깨짐. 방 id만 바뀌고 사람에겐 같은 코드·같은 설정이라 결정과 맞음.

서버 여러 대 길잡이
- 판과 다시 만든 방은 같은 Node. 사람 소켓은 위치 기록(`socket/connection/locationSync.js`)으로 그 Node에 붙어 있어 `return_to_room`도 그 Node가 받음.
- 로비로 갔다가 코드로 다시 오는 사람은 지금의 "다른 Node 방이면 그 Node로 옮겨 붙기" 길(`cluster/roomRouting.js`)을 그대로 탐.
- 판 동안 코드 키를 잡아 두므로 다른 Node가 같은 코드를 못 뽑음. Redis가 멈춰 있어 판 끝 때 코드를 못 잡으면 새 코드로 만들고 결과 화면에 "방 코드가 바뀌었습니다" 한 줄 [안].
- 드레인 중인 Node: 지금은 끝난 판 방장 방 만들기를 드레인 중에도 받음(`join/create.js:46-48`). 안 B에선 방을 다시 만들면 드레인이 최대 180초 늘어남 → 드레인 중이면 방을 안 만들고 결과 화면에 "서버 점검 준비 중이라 대기방으로 돌아갈 수 없습니다" + "로비로"만 [안, 배포 때만 생김].

없어지는 것: 자동 입장(`join/join.js autoJoinPartyToRoom`), 다음 방 우편함(`join/party.js`), 기다림 화면(`partyRejoin*`), 스스로 옮김 표시(`partyOrigin.js`), 끝난 판 방장만 파티 방 만들기(`game-core/queries/ended.js getEndedPartyContext`). B06-1·B06-2·B06-4·Q06-2·Q06-4가 같이 사라짐 [짐작: 원인 코드가 없어짐].

### 2-2. 로비 입장 방어 (단위 17)

안 A (추천) — 화면이 들어올 때 소켓(서버와 이은 실시간 줄) 사건 `enter_lobby`를 보냄
- 판·대기방 상태는 서버 Node 메모리에만 있음. 소켓은 그 사람 판·방이 있는 Node에 붙어 있음(`socket/connection/nodeRouting.js:33-56`). 그래서 소켓 사건이면 그 Node가 바로 정리할 수 있음.
- 서버 차례
  1. 진행 중 판에 산 채로 있음 → 아무것도 안 지우고 `{ redirect: 'INGAME', gameId }`. 끊김 유예는 지금처럼 다시 붙어서 풀림.
  2. 진행 중 판에 죽은 채 있음 → 판에서 풀기(죽은 사람 나가기와 같은 처리: 기권 명단만, 편 결과·골드 그대로).
  3. 끝난 판에 묶임 → 끝난 판에서 뺌(남겨 둔 방장이면 방장 넘김, 2-1).
  4. 대기방 자리 → `leave_room`과 같은 처리(15초 유예 없이).
  5. 입장 중 표시·초대 입장 처리 중·매칭 줄 → 되돌림.
  - 몇 번을 불러도 같은 결과(이미 없으면 그냥 ok).
- 보내는 곳: 로비(`/lobby`), 방 목록(`/multiplay`), 게임 모드, 게임 설정 화면. 안 보내는 곳: 대기방(`/game-matching`), 판(`/ingame`), 결과(`/gameresult`), 초대 받기 화면.
- 화면은 답이 `INGAME`이면 `/ingame`으로 감. 답이 늦거나 연결이 없으면 화면은 그대로(다음 연결 때 다시 보냄).

안 B — 로비 HTTP 요청(프로필 읽기 등)에 붙임
- HTTP는 앞단이 아무 Node로 보낼 수 있어 판이 있는 Node 메모리를 못 만짐(서버 여러 대면 틀림). 서버끼리 묻기(RPC)가 새로 필요.

추천 까닭: 안 A가 서버 여러 대에서도 맞고, 이미 있는 처리(나가기·`leave_room`·끝난 판 빼기)를 한곳에서 부르기만 하면 됨.

로비가 아닌 화면으로 바로 들어오는 길: 주소창에 `/multiplay`·`/game-setup`을 쳐도 같은 훅이 돌아 같이 정리됨. `/game-matching`을 직접 치면 지금처럼 `get_current_room`으로 방 확인(정리 안 함).

### 2-3. 다 누르면 5초 뒤 판정 (단위 15)

- 서버 새 파일 `phase/settle.js`가 판마다 "당긴 마감" 하나를 들고 있음.
  - 걸리는 때: 표·밤 행동을 받은 뒤, 나가기·탈락 반영 뒤(`departure/apply.js`) "다 찼나"를 봄.
    - 낮 투표: 산 사람 전원 표 있음(기권 포함, `game-core/phase/day/ballots.js getDayVoterUuids`).
    - 재판: 투표할 사람 전원 표 있음(`game-core/phase/tribunal/ballots.js`).
    - 밤: 그 직업 산 사람 전원 고름(`gameSessionCore.isRoleTurnComplete`).
  - 다 찼고 남은 시간 > 5초 → 마감을 지금+5초로 당김(낮 `session.dayPhaseDeadline`, 재판 `session.tribunalDeadline`, 밤 `run.deadline`·`session.nightTurnDeadline`), 단계 타이머를 다시 검, `phase_settle_started` 방송.
  - 남은 시간 ≤ 5초 → 아무것도 안 함(원래 마감).
  - 한 단계에 한 번만 당김. 5초 안에 표를 바꿔도 다시 안 늘림 [안].
  - 마감이 되면 지금 마감 길 그대로(안 낸 사람 기권 채우기 → 판정, 밤은 턴 닫기). 그래서 판정 코드는 새로 안 만듦.
- 5초 안 바꾸기: 낮 표는 지금도 판정 전까지 바꾸기 됨, 밤 행동은 차례 안에서 덮어쓰기 됨 [사실 `04` 글 1-5] → 서버 고칠 것 없음. 바꿔도 "다 찼음"은 그대로라 마감 유지.
- 나간 사람 때문에 다 찬 경우: 지금은 바로 판정(`departure/autoResolve.js`). 같은 규칙으로 5초 [안, 6장 물음 7].
- 화면: `phase_settle_started`를 받으면 그 단계 마감 시각을 바꾸고 타이머 줄에 "5초 뒤 마감". 새로고침이면 스냅샷 마감 시각이 이미 당겨져 있음(글은 "남은 5초 이하"면 같은 문구) [안].
- 안 B(안 씀): 화면이 표 수를 보고 스스로 5초를 셈 — 남의 진행 수를 화면이 모름(나4) → 안 됨.
- 까닭: 마감 시각 하나만 당기면 타이머·스냅샷·기권 채우기를 다 다시 씀. 새 판정 길이 없어 "5번 실패 멈춤"(Q04-7) 같은 위험이 안 늘어남.

### 2-4. 밤 영상 정리 (단위 11)

- 서버 밤 턴 닫기: 지금 "결과 확정 → 성공 사건 개별 전달 → 턴 끝 방송 → 연출 대기"(`turn.js:145-173`) → "결과 확정 → 턴 끝 방송 → 다음 턴"으로 줄임. 성공 계약·수신 기록·연출 대기·다 봄 신호 모두 지움.
- 경비원 조사 당한 사람 알림·마녀사냥꾼 확인 대상 알림은 성공 사건이 없어지며 같이 없어짐.
- 결과 글은 지금 있는 밤 끝 개인 결과(`finalize.js:26-42 night_action_result`)로 줌 — 경비원 "○○님의 직업은 의사입니다", 마녀사냥꾼 확인, 광대 암살 실패. 새로 만들 것 없음 [사실: 개인 결과 만들기 `prepare.js:62-96`].
- 낮 시작 연출: `night_result_applied`에 `doctorSaved`만 더함. 화면이 받으면
  - 희생자 있음(`deathReveals[].source === 'JOKER'`) → 모두에게 암살 영상(지금 KILL 영상 재사용) + "지난밤 [닉네임]님이 살해당했습니다".
  - `doctorSaved` → "지난밤 의사가 공격받은 사람을 살려냈습니다".
  - 둘 다 아님 → 지금처럼 "낮이 되었습니다"만.
  - 차례: 낮 시작 연출 → "낮이 되었습니다" 창. 판이 끝났으면 낮 시작 연출 → 결과 화면(6장 물음 9).
  - 새로고침·늦게 붙은 사람에게는 다시 안 틀어 줌 [안] — 모바일은 채팅 알림 줄(`playerNotices.js`)이 남음.
- `doctorSaved`는 광대가 노린 사람을 의사가 지켜 암살이 막혔을 때만 참(지금 광대에게 주는 암살 실패 조건 `assassinationBlocked`와 같음 [사실 `prepare.js:62,81-83`]). 광대 둘이 서로 다른 사람을 골라 아무도 안 죽은 경우는 거짓.

### 2-5. 판마다 골드 (단위 10)

- 값 저장: 새 표 `game_settings`(4장)에 `GAME_GOLD_REWARD = 1`. 서버는 값을 읽어 잠깐 저장하고, 관리자가 바꾸면 `services/ops/reloadSync.js`의 "다시 읽기"로 모든 Node가 다시 읽음(점검·금지어가 쓰는 길과 같음 [사실]).
- 판 시작 때 그 판 지급 값을 판에 적어 둠 → 판 중에 관리자가 바꿔도 그 판은 시작 때 값(결과판 숫자와 실제 지급이 같게).
- 받는 사람: 판의 사람 중 "산 채로 떠나지 않은 사람" 전원. 산 채로 떠남 판단은 전적 기록이 이미 씀(`game-core/result/record.js:23-27`) → 같은 판단을 씀.
- 지급: 전적 저장(`services/game/record/persist.js`)이 끝난 뒤 사람마다 `grantReward({ amount, reason: 'GAME_REWARD', referenceEventId: 'game-reward:<gameId>' })`. 장부의 (사람, 참조 id) 유일 제약으로 두 번 안 줌. 실패는 사람마다 따로 기록(업적 평가와 같은 모양).
- 안 주는 판: 점검 강제 종료 판(`session.abortReason`, 지금 업적도 안 줌 [사실 persist.js:35-36]) [안, 6장 물음 12]. 서버 재시작으로 사라진 판은 기록 자체가 없음.
- 값이 0이면 지급·표시 둘 다 안 함.
- 결과판: 판 끝 칸에 사람마다 `goldReward`. 결과판 내 줄에 "+1골드"(모두 같은 값이라 내 것 하나만 크게) [안].
- 관리자: 값 보기·바꾸기(0~100 정수 [안]), 바꿀 때 감사 기록(`admin_audit_logs`).
- 안 B(안 씀): 환경값으로 둠 — 관리자 페이지에서 못 바꿔 결정과 다름.

### 2-6. 탈주 대기 시간·끊김 60초·죽은 사람 풀기 (단위 12·13)

탈주 기록 (단위 12)
- 표 `game_desertions`: 한 판에 한 줄(사람·판 유일). 칸: 사람, 판, 이유(산 채로 나감 / 60초 못 돌아옴), 탈주 시각, 막힘 끝 시각.
- 몇 번째인지: 같은 사람의 "오늘(한국 시간 0시부터) 탈주 줄 수 + 1". 1번째 5분, 2번째 30분, 3번째 이상 24시간 [안: 4번째 이후 6장 물음 5].
- 막힘 끝 = 탈주 시각 + 대기 시간. 자정이 지나도 남음(③번째 1일). 다음 날 처음 탈주는 다시 1번째.
- 검사: 방 만들기·코드 입장·공개 방 입장·초대 수락·자동 매칭 앞에서 "막힘 끝 > 지금"이면 거절 + 남은 시간. 이 Node 메모리에 사람별 막힘 끝을 바로 적어 두어 DB 저장이 늦어도 곧바로 막힘. 다른 Node는 DB를 읽음(사람별 시각 목차로 빠름).
- 기록 실패(DB 안 됨)면 로그만, 판은 계속.

끊김 60초 (단위 13)
- 끊기면 늘 60초 타이머 하나. 단계가 바뀌어도 유지(지금의 단계 경계 만료·내 밤 차례 마감 만료 지움).
- 60초 안에 다시 붙으면(지금처럼 `connection/routing.js:46`) 타이머 끔.
- 그동안 투표·밤 차례는 마감 때 기권·건너뜀(지금 그대로).
- 60초 지나면 지금 탈락 길(`departure/apply.js`, 이유 `DISCONNECT_GRACE_EXPIRED`) + 탈주 기록.

죽은 사람 풀기 (단위 13·17)
- 추천: 죽은 사람이 끊기면 "매칭을 막지 않음"만 함(`queries/live.js isMatchmakingBlocked`에서 죽은 사람 빼기). 판 자리는 남겨 관전 중 새로고침이면 그대로 판을 봄. 다른 방에 들어가 새 판을 시작하면 그때 옛 판에서 풀림(`setup/commit.js`). 로비 입장(단위 17)·나가기는 바로 풀림.
- 까닭: 결정의 "끊기면 바로 풀림"을 글자대로 하면 죽은 뒤 새로고침만 해도 관전에서 쫓겨남(6장 물음 2).

## 5. 시험 영향

이 장은 깨질 시험을 폴더·단위별로 어림하고 센 방법을 적음.

### 5-1. 센 방법

- 시험 파일(`*.test.js`·`*.spec.js`)을 `test(`·`it(` 줄로 시험 하나씩 나누고, 그 안에 고칠 코드의 이름·문구가 있는 시험만 셈(저장소 밖 임시 폴더의 작은 node 글로 돌림).
- 찾은 글자 예: 밤 연출 `night_action_success|night_presentation_wait|acknowledge_night_action_success|NightSuccess|presentationWait`, 단추 `resolve_day_vote|resolve_tribunal_vote|resolve_night|handleResolve*|낮 집계|재판 판정|밤 종료`, MVP `mvp`(대소문자 무시), 동료 `allies`, 파티 `partyRejoin|party_matching_room|partyOrigin|nextRoomSettings|대기방으로`, 설정 `lights-out|soul-betting|lightsOut|soulBetting|불이 꺼진|영혼의 베팅`, 유예 `grace|유예|DISCONNECT_GRACE`.
- 글자가 걸린 시험 = "볼 시험". 그중 실제로 깨질 것은 코드를 따라가 어림함(짐작).

### 5-4. 돌리는 차례

- 단위마다: 그 단위가 고친 시험 파일만 (1장 "확인").
- 묶음이 끝날 때마다: 서버 `cd backend && npm test`(DB 없는 것), PC `cd frontend && npm test`, 모바일 `cd frontend-mobile && npm test`.
- 다 끝난 뒤 한 번: DB 시험 `cd backend && npm run test:with-db`, e2e `cd e2e && npm test`. 실패는 모아 기록한 뒤 한 번에 고침.
- e2e는 개발 규칙(적은 인원 판, `/e2e` 손잡이)에 기댐 → 이번엔 그 규칙을 그대로 둠. 시간에 기대는 새 규칙(5초·60초·180초)은 `/e2e` 손잡이로 시험이 줄이거나 넘길 수 있게만 함.
- 사용자가 쓰는 것은 건드리지 않음: `frontend/tests/domains/game/ingame/store/participantDeparture.test.js`, `docs/known-issues.md`, `.claude/launch.json`, `e2e/.tmp-check`.

## 6. 사용자에게 물어볼 것

이 장은 고치기 전에 정해야 하는 것만 번호로 적음. 안마다 ★가 추천.

1. **"투표 공개 여부" 칸** — 불 꺼진 무도회·영혼의 베팅처럼 판에서 안 쓰임(결정 줄 "물어볼 것").
   - ★ 같이 지움(단위 7에 넣음) — 켜도 판이 같아 헷갈림.
   - 남겨 두고 나중에 기능 만듦.
2. **죽은 사람이 끊기면 판에서 바로 풀까** — 결정 글자대로면 관전 중 새로고침만 해도 판에서 빠짐.
   - ★ 끊기면 "다른 방 입장·방 만들기는 됨"만 하고 판 자리는 남김. 나가기·로비 입장·새 판 시작 때 풂(2-6).
   - 끊기면 바로 풂(새로고침이면 관전 끝).
3. **남겨 둔 방장 자리와 정원** — 판 끝 뒤 방은 코드로 남이 들어올 수 있음. 정원이 차면 원래 방장이 못 들어옴.
   - ★ 180초 동안 방장 자리 1칸을 정원에서 남겨 둠.
   - 안 남김(먼저 온 사람 순서).
4. **180초는 하나의 시계로** — 결과 화면 닫힘·방장 자리 남겨 두기·빈 방 지우기를 모두 판 끝 시각부터 180초로.
   - ★ 하나로(대기방으로 간 사람은 결과 화면 타이머와 상관없음).
   - 따로(예: 방장 자리는 방에 첫 사람이 들어온 뒤 180초).
5. **4번째 탈주부터** — 정한 것은 1·2·3번째뿐.
   - ★ 4번째부터도 1일.
   - 늘려 감(예 3일).
6. **탈주 대기 중 자동 매칭(빠른 매칭)도 막나** — 정한 것은 방 입장·방 만들기·초대 수락.
   - ★ 막음(같은 "판 참여"라서).
   - 안 막음.
7. **나간 사람 때문에 표가 다 찬 경우** — 지금은 바로 판정.
   - ★ 이것도 5초 뒤(규칙 하나로).
   - 지금처럼 바로.
8. **"원래 방장"은 누구** — 판 중 방장이 나가 방장이 넘어간 경우.
   - ★ 판 끝 때 방장(넘겨받은 사람).
   - 판 시작 때 방장(이미 탈주했으면 자리 없음).
9. **밤 암살로 판이 끝날 때** — 지금은 KILL 영상이 결과 화면 이동을 미룸.
   - ★ 낮 연출(암살 영상 + 문구) 뒤 결과 화면.
   - 연출 없이 바로 결과 화면.
10. **끊긴 사람이 재판 피고가 될 때** — 결정은 "재판 취소하고 밤"을 그대로 두라 했는데, 60초 기다림이면 재판 들어가는 순간엔 아직 안 빠짐.
    - ★ 60초 안이면 재판을 그대로 함(투표대로 처형·무죄), 재판 중 60초가 지나면 그때 취소하고 밤.
    - 끊긴 피고는 재판 들어갈 때 바로 취소(지금과 같은 모습, 60초 규칙에 예외 하나).
11. **사용자 시험 파일과 겹침** — `frontend/tests/domains/game/ingame/store/participantDeparture.test.js`(지금 고치는 중)는 단위 3·11이 고치는 스토어(`voteActions.js`·`phaseActions.js`)를 같이 봄.
    - ★ 그 파일은 안 건드리고 돌려 보기만, 깨지면 알려 드림.
    - 같이 고쳐도 됨.
12. **점검 강제 종료 판의 골드** — 결정은 "판 끝까지 있던 사람".
    - ★ 안 줌(판이 무효, 업적도 지금 안 줌).
    - 줌.
13. **판 끝 뒤 공개 방이 사람 0명으로 목록에 뜸** — 방장이 아직 안 온 빈 방.
    - ★ 첫 사람이 들어온 뒤부터 목록에 보임(코드로는 바로 들어옴).
    - 바로 목록에 보임.
