# 버그 4·7 — 중복 접속 때 방이 남음 / 추방이 안 됨

- 버그 7 가장 그럴듯한 원인: PC 추방 창의 "추방·취소" 확인 칸과 실패·빈 목록 글에 글자색이 없어 기본 검정 글자가 거의 검은 창 틀 위에 그려짐 → 줄 단추가 "확인 중"으로만 바뀌고 멈춘 듯 보임.
- 버그 4 가장 그럴듯한 원인: 새 창·새 기기 소켓이 옛 소켓을 밀어내면 서버가 15초 유예 없이 방 자리를 새 소켓에 넘김 → 새 접속은 로비로 가고 로비는 "내 방"을 안 물음 → 방장이 로비에 있는 채로 방이 계속 남음.

이 글은 읽기만 한 조사. 서버·브라우저를 띄우지 않았고 시험도 안 돌림. "사실"은 코드에서 본 것, "짐작"은 코드로 미룬 것.

### 후보마다

#### K1. PC 확인 칸·결과 글이 안 보임 (그럴듯함, 가장 강함)
- 사실

  - 실패 글, 결과 모름 글, "결과 확인" 단추, 다시 확인 중 글, "추방할 수 있는 참가자가 없습니다." 글도 `className` 없음 — 같은 파일 `:70-95`.
  - 화면 기본 글자색 `--color-text-body: #000000`, `body`·`p`에 그 색 — `frontend/src/app/index.css:32,52-55,64-66`. 창 틀·안쪽 칸에 글자색 없음 — `SettingKickPlayerModalShell.jsx:33-82`.
  - Tailwind(화면 꾸미기 도구) 4 기본값: 단추는 배경·테두리 없음, 글자색은 물려받음 (`frontend/package.json:41`).
  - 창 틀 그림 `frontend/public/frame/투표현황창 프레임.webp` 안쪽 평균 밝기 약 20/255(거의 검정) — 이번에 그림 픽셀을 재서 확인.
  - 모바일은 같은 칸을 붉은 배경·밝은 글자·그림 단추로 꾸밈 — `frontend-mobile/src/domains/game/matching/components/kick/KickStatus.jsx:70-124`.
  - 이 확인 칸은 2026-09-18(pluto 자동 구현 `cb01b1a7`)부터 꾸밈 없이 그대로.
  - 시험 `e2e/tests/room/kick.spec.js:22-27,61-69`은 `data-testid`로 찾고 `toBeVisible`만 봄 → 글자색이 배경과 같아도 통과.
- 짐작
  - 방장이 줄의 "추방"을 누르면 줄 단추 글이 "확인 중"으로만 바뀌고, 위에 생긴 검정 "추방·취소"는 안 보여 못 누름 → "추방이 안 됨".
  - 혼자 있는 방에서 창을 열면 빈 안내 글도 안 보여 빈 창만 보임.
  - 서버가 거절해도 실패 글이 안 보여 아무 일 없는 것처럼 보임.
- 다시 겪는 차례(가장 짧게, 코드로 읽은 차례): PC로 방 만들기 → 다른 사람 입장 → "참가자 추방" → 줄의 "추방" → 줄이 "확인 중"으로 바뀌고 그 뒤 할 것이 안 보임.
- 판정 까닭: 들은 모습과 가장 잘 맞고, 판 끝 여부와 상관없이 늘 생김. 화면을 띄워 눈으로 보지는 않음.
- 새 규칙: 상관없음, 따로 고쳐야 함.

#### K2. 추방 단추가 꺼짐 (그럴듯함)
- 사실
  - 단추는 방장이면 보이고, 방 확인 상태가 `verified`(서버 확인 끝)일 때만 켜짐 — `useMatchingRoomKick.js:21-22`, `useRoom.js:46`, `MatchingHostActionButtons.jsx:55-61`.
  - 꺼지는 길: 소켓이 없거나 끊김·오프라인·계정 바뀜이면 `waiting_socket` — `useRoomCheck.js:22-26,90-98,207-218`. 방 확인 5초 응답 없음·거절이면 `failed`(다시 물을지 확인 창 한 번, 그 뒤 5초마다 조용히 다시) — `useRoomCheck.js:69-84,164-168`, `constants/roomTiming.js:7,15`.
  - 같은 계정이 다른 탭·기기로 붙으면 서버가 옛 소켓을 끊음 — `backend/socket/connection/presence.js:35-48`. 옛 창은 다시 붙지 않음(서버가 끊은 연결) → 옛 창 대기방은 계속 `waiting_socket` → 추방 단추 꺼짐, 설정 단추는 사라짐(`useSettingsEdit.js:21`).
  - 꺼진 까닭은 `title`(마우스 올리면 뜨는 글) "방 정보를 서버에서 확인하는 중입니다"뿐 — PC `MatchingHostActionButtons.jsx:61`, 모바일 `frontend-mobile/src/domains/game/matching/components/layout/HostActions.jsx:38`. 폰은 마우스가 없어 이 글이 안 보임.
- 짐작: 버그 4·7이 같이 알려진 것으로 보아, 시험한 사람이 같은 계정을 두 창에 띄운 상태였을 수 있음. 그러면 옛 창에서 단추가 흐리게 꺼져 "활성화 안 됨"이 그대로 맞음.
- 다시 겪는 차례: PC 방 만들기 → 같은 브라우저 새 탭으로 사이트 열기 → 옛 탭에 "같은 브라우저의 다른 창에서 접속해…" 알림 → 옛 탭 "참가자 추방" 흐림.
- 판정 까닭: "활성화 안 됨"이라는 말과 맞지만, 단추가 꺼지려면 연결이 끊긴 상태여야 함. 보통 방에서는 곧 `verified`가 됨.
- 새 규칙: 밀린 옛 창이 죽는 건 그대로라 안 풀림. 꺼진 까닭을 보이는 글로 주는 것은 따로 고칠 것.

#### K3. 서버 거절이 안 보이거나 뭉뚱그려짐 (그럴듯함)

#### K5. 판 끝 뒤 돌아온 대기방 (아님)

### 후보마다

#### D1. 밀려난 옛 소켓 자리를 새 소켓이 이어받고 방이 남음 (맞음)
- 사실
  - 같은 계정 새 소켓이 붙으면 접속 목록에 새 소켓을 먼저 넣고, 옛 소켓에 표시(`forcedLogout`) 남긴 뒤 `force_disconnect`(강제 끊김)·끊기 — `presence.js:35-48`.
  - 옛 소켓 끊김 처리: 밀린 소켓이고 새 소켓이 목록에 있으면 15초 빼기 예약을 안 걺 — `reconnect.js:105-108` (의도된 동작 BE-031, 시험 `socket.connectionFixes.test.js:195`).
  - 새 소켓은 접속 때 그 방 채널에 다시 붙고 지금 방 표시도 넘겨받음 — `presence.js:58`, `reconnect.js:15-78`.
  - 로그인·새 탭은 모두 `/lobby`로 감 — `frontend/src/domains/auth/hooks/login/useLoginSubmit.js:67`, `useLoginPage.js:56`.
  - 로비·멀티 화면은 `get_current_room`(지금 방 묻기)을 안 보냄. 이것을 보내는 곳은 대기방 확인·결과 화면·방 만들기 응답 못 받음·초대 수락뿐 — `matching/hooks/room/useRoomCheck.js:121`, `result/hooks/useGameResultReturnToMatching.js:124`, `setup/hooks/createRoomRequest.js:38`, `lobby/socket/gameInvite.socket.js:35`.
  - 로비에서 방 만들기 → "이미 참여 중인 방이 있습니다." — `join/create.js:33-36`. 코드·공개 방 입장도 같음 — `join/joinChecks.js:38-41`. 화면은 이 거절(`ALREADY_IN_ROOM`)을 따로 다루지 않아 알림만 뜨고 그 방으로 안 데려감(화면 코드에 `ALREADY_IN_ROOM` 없음).
  - 대기방은 오래 비어 있어도 지우는 타이머 없음. 지워지는 때는 나가기·추방·방 지우기·끊김 15초뿐 — `room/leave.js:58-95`, `room/host.js:192-244`.
- 짐작(겪는 모습)
  - 새 창(로비)은 방을 모르고, 방 만들기·입장이 막힘.
  - 공개 방이면 목록에 "○○의 방" 1명이 계속 뜸. 남이 들어와도 시작할 방장이 로비에 있어 판이 안 열림.
  - 옛 창(같은 브라우저)은 알림만 뜨고 대기방 화면이 끊긴 채 남음 — `frontend/src/shared/hooks/useSocket.js:64-71`. 다른 기기면 옛 기기는 로그아웃 — 같은 곳.
  - 방이 사라지는 때: 새 접속도 닫은 뒤 15초, 또는 주소창에 `/game-matching`을 직접 열어 "뒤로".
- 다시 겪는 차례(가장 짧게): 탭 A에서 방 만들기 → 같은 브라우저 탭 B로 사이트 열기(로비) → 탭 B에서 방 만들기 → "이미 참여 중인 방이 있습니다."
- 앞 창을 열어 둔 채일 때만 이 길. 닫았으면 D3.
- 새 규칙: 로비 입장 때 그 사람을 대기방에서 정리하면 풀림(로그인·새 탭 모두 로비로 오므로). 로비가 아닌 주소(`/multiplay`·`/game-setup` 등)를 바로 열면 안 풀림.

#### D2. 다른 기기 로그인에서 옛 소켓이 먼저 끊기는 경우 (아님, 경주)
- 사실
  - 새 로그인은 그 사람 옛 세션을 모두 끊음 — `services/auth/account/session.js:10-12`.
  - 이 Node 안에서 끊은 세션은 옛 소켓을 바로 다시 검사하지 않음, 5초 주기 검사 때 끊음 — `sessionCheck.js:8,133-136,154-157`. 이때 `forcedLogout` 표시가 없음 → 15초 유예가 걸림 — `reconnect.js:98-110`.
  - 새 소켓이 다시 붙어도 유예는 안 꺼짐(유예를 끄는 건 `get_current_room`뿐 — `reconnect.js:141,147-148`) → 15초 뒤 빠짐 → 방장 혼자면 방 지워짐 — `leave.js:41-46,83-86`.
- 짐작: 새 기기 소켓이 5초 주기 검사보다 먼저 붙으면 D1(방 남음), 늦으면 D2(15초 뒤 사라짐). 같은 일을 해도 때마다 결과가 다를 수 있음.

#### D3. 앞 창을 닫고 15초 안에 다시 접속 (아님)
- 사실: 닫힘은 보통 끊김이라 15초 유예 → 새 소켓이 채널에 다시 붙어도 유예는 안 꺼짐 → 15초 뒤 빠짐 — `reconnect.js:15-78`, `leave.js:31-54`.
- 판정 까닭: 방이 남지 않음. 다만 15초 안에 로비에서 방 만들기를 누르면 그 15초 동안은 "이미 참여 중인 방"으로 막힘.

#### D4. 뒤로 가기·주소로 로비 이동 (그럴듯함, 다른 길)
- 사실: `leave_room`(방 나가기)은 대기방 앱 안 "뒤로" 단추와 방 만들기 응답이 늦게 온 때만 보냄 — `useMatchingPage.js:121-126`, `setup/hooks/useCreateRoom.js:28-32`. 브라우저 뒤로 가기나 주소로 로비에 가면 안 보냄.
- 짐작: 중복 접속이 아니어도 D1과 똑같은 모습(로비에 있는데 방이 남음)이 생김. 사용자가 "다시 접속"을 이렇게 했을 수도 있음.
- 새 규칙: 로비 입장 정리로 풀림.

#### D5. Node 여러 개 (짐작)
- 사실: 접속 때 그 사람 방이 다른 Node에 있으면 그 Node로 다시 붙게 함 — `nodeRouting.js:33-56`. 그래서 보통 같은 Node에서 D1과 같이 됨.
- 사실: 다른 Node에서 밀어낼 때는 접속 목록에서 먼저 빼고 끊음 — `replace.js:40-46`. 그러면 `reconnect.js:107-108`의 "새 소켓이 목록에 있음"이 거짓이라 15초 유예가 걸림.
- 짐작: Node 사이로 밀린 경우는 15초 뒤 방이 사라짐. Redis(서버끼리 공유 저장소)가 죽어 있으면 두 Node에 따로 붙어 옛 소켓이 안 밀리고 방이 남을 수 있음(실행 안 해 봄).

### 고칠 곳 후보
- 새 규칙 "로비 입장 때 대기방·끝난 판 정리"를 서버 사건으로 만들고 로비 화면이 들어올 때 보냄 (PC·모바일 로비). D1·D4가 같이 풀림.
- 아니면 더해서: 로비 들어올 때 `get_current_room`을 물어 방이 있으면 대기방으로 보내기 (`07-끊김-나가기.md`의 Q07-4 "판으로 되돌리기"와 같은 자리).
- 방 만들기·입장 거절 `ALREADY_IN_ROOM` 때 화면이 "그 방으로 가기 / 나가기"를 고르게 함 — `join/create.js:33-36`, `join/joinChecks.js:38-41`, 화면 `setup/hooks/createRoomRequest.js:78-81`.
- 서버 쪽 막기(짐작 안): 밀려난 자리를 이어받은 새 소켓이 일정 시간 안에 `get_current_room`을 안 하면 빼기 — `reconnect.js:105-108`. BE-031 의도와 부딪혀 사용자가 고를 것.
