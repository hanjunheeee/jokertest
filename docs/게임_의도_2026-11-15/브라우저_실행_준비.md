# 브라우저 시험 한 번 돌리기 준비

이 글은 부하가 끝난 뒤 브라우저 시험 3,078개(서버 1대 3,007 + 서버 2대 전용 71)를 **명령 한 줄로, 단계마다 한 번씩, CPU를 보면서** 돌리는 순서·시간·멈추는 조건·결과 모으는 법을 적음.

- 기준: 브랜치 `fix/scenario-2026-11-16`, 2026-11-16 오후, `--list`(돌리지 않고 세기)로 셈
- 이 글을 쓰는 동안 브라우저 시험·서버는 안 띄움 (부하 시험이 4100~4102 포트와 시험 DB를 쓰는 중)
- 사용자 말: "브라우저 테스트는 수정·부하 이후 한 번만 시행(CPU 사용량 체크하면서). 나중에 버그가 나오면 버그 리스트만 다시."

## 한눈에

이 표는 돌리는 사람이 칠 명령과 걸리는 시간을 보여 줌. 저장소 맨 위 폴더에서 Git Bash로 침.

| 할 일 | 명령 | 시간 어림 |
|---|---|---|
| 전부 (0~4단계 + 끝 확인) | `bash tools/시험도구/br/once.sh all` | 4.5~8.5시간 (어림 6시간) → **밤새** |
| 옆 창에서 CPU 보기 | `powershell -NoProfile -File tools/시험도구/cpu-watch.ps1` | 끝날 때까지 |
| 옆 창에서 진행 보기 | `tail -f tools/시험도구/.run/br-once/$(date +%Y%m%d)/timeline.txt` | |
| (고르면) 실패만 한 번 더 | `bash tools/시험도구/br/once.sh rerun` | 실패 100개면 30~60분 |
| 결과 표 다시 뽑기 | `node tools/시험도구/br/summary.js --merge tools/시험도구/.run/br-once/<날짜>` | 몇 초 |

- `once.sh`는 e2e 잠금(`with-lock.sh e2e`)을 스스로 잡음 → 부하가 잠금을 쥐고 있으면 풀릴 때까지 기다렸다 시작함
- 밤을 넘기면 날짜 폴더가 바뀜 → 나중에 따로 부르는 명령(`rerun` 등)은 `BR_OUT=tools/시험도구/.run/br-once/<시작한 날짜>`를 앞에 붙임
- 멈춘 단계부터 다시: `BR_OUT=… bash tools/시험도구/br/once.sh rest serial mn mnserial after` (이미 결과가 있는 단계는 저절로 건너뜀 — "한 번만")

- 단계 사이마다 다시 확인: 포트 비었나, 디스크 20GB 넘나, DB 컨테이너 떠 있나 (서버 2대면 시험 Redis도)

### 1단계 견본이 먼저인 까닭

- 암살 영상이 안 돌면(영상 파일·코덱·화면 빌드 문제) 영상 쓰는 시험 약 40개가 한꺼번에 실패함 → 3개로 먼저 봄
- 사파리(WebKit) 것이 같이 있음: 윈도우 WebKit이 영상을 트는지 여기서 드러남
- 같은 로그에서 "바깥 막기" 경고를 찾음
  - `[e2e] 바깥 막기: 크로미움 주소 규칙을 확인 못 함 …`이 있으면: 모든 창에 가로채기로 막는 중 → 여전히 막힘, 창 캐시만 꺼져 조금 느림 → 계속 가고 결과에 적음
  - 없으면: 주소 규칙이 먹음 (정상)

### "한 번만" 원칙과 다시 돌리기

- 설정 파일은 `retries: 1`(실패하면 한 번 더) → 그대로 돌리면 흔들림이 통과로 가려지고 실패마다 시간이 두 배
- **추천: 본 실행은 `--retries=0`** (once.sh가 넣음)
- 흔들림을 가리려면 다 끝난 뒤 **실패한 시험만** 한 번 더: `bash tools/시험도구/br/once.sh rerun`
  - 실패한 시험 목록(`<단계>.list`)만 `--test-list`(목록에 적힌 시험만 돌리기)로, 작업자 3, CPU 80% 밑에서
  - 옛 `run-phase.sh`는 실패한 **파일 전체**를 다시 돌려 통과한 시험도 또 돎 → 새 도구는 시험 단위
  - 이것이 "버그 리스트만 다시"와 같은 모양 → 나중에 버그를 고친 뒤에도 같은 방법

## 3. 작업자 수와 CPU

이 장은 동시에 몇 개를 돌릴지와 CPU가 높을 때 어떻게 할지 적음.

- 이 PC: 8코어 16스레드, 메모리 40GB, 디스크 남은 약 90GB
- 설정 기본 작업자(동시에 도는 시험 수) 6, README에 8까지 확인됨
- **시작 6, 최대 8** (8 넘으면 포트 칸이 겹침 — 7장 4번)
- 어림 [짐작]: 작업자 6이면 CPU 평균 70~90%, 화면 빌드·어려움 판(사람 5명 창)에서 100% 순간 있음
  - 지난 기록(2026-11-10, 작업자 5, 다른 에이전트 일과 겹침): desktop 평균 78%·최고 100%, mobile 61%·99%, safari 79%·97%
  - 이번 시험이 더 무거움: 판 쓰는 것 69%(옛 판은 2~4명, 이번은 5명 이상), 어려움 15%, 진짜 시간 11%
  - 서버(백엔드)는 Node 하나라 코어 하나만 씀 → CPU가 100%면 서버 답이 늦어 `ECONNRESET`·시간 초과가 남 (지난번 흔들림 원인)
- once.sh가 하는 것
  - 단계 시작 전 CPU 85% 넘으면 10분까지 기다림 (다른 일이 끝나길)
  - 30초마다 CPU·남은 메모리를 `cpu-<단계>.txt`에 적음, 단계 끝에 평균·최고·95% 넘은 표본 수를 timeline에 적음
  - 앞 단계에서 **95% 넘은 표본이 1/3 넘거나 남은 메모리 3GB 밑이 한 번이라도** 있으면 다음 단계 작업자 −2 (3 밑으로는 안 감)
- 사람이 보는 기준 (`cpu-watch.ps1` 창)
  - "PC 부담 높음"이 10분 넘게 이어져도 **도는 단계는 끊지 않음** (끊으면 결과 JSON이 반쪽) → 다음 단계에서 저절로 줄어듦
  - 남은 메모리 3GB 밑이 이어지면 그때만 Ctrl+C → `BR_WORKERS=4 BR_FORCE=1 BR_OUT=… bash tools/시험도구/br/once.sh <그 단계> …`
  - 돌리는 동안 다른 무거운 일(개발 서버 빌드·다른 시험·부하) 안 돌림

## 5. 결과 모으기

이 장은 결과가 어디에 쌓이고 실패를 어떻게 뽑는지 적음.

### 5-1. 결과 폴더 (`tools/시험도구/.run/br-once/<날짜>/`, git에 안 올라감)

| 파일 | 무엇 |
|---|---|
| `timeline.txt` | 단계 시작·끝·걸린 분·CPU 요약·멈춘 까닭 |
| `<단계>.log` | 그 단계 화면 출력 (시험마다 한 줄, `list` 출력) |
| `<단계>.json` | 결과 JSON (숫자는 늘 여기서 셈 — 셸 종료값은 안 믿음) |
| `<단계>.counts` | 전체·통과·실패·건너뜀·흔들림·끊김 한 줄 |
| `<단계>.failed.tsv` | 실패: 번호·프로젝트·파일:줄·상태·오류 첫 줄·기록물 |
| `<단계>.list` | 실패한 시험 목록 (`--test-list` 모양, 다시 돌릴 때 씀) |
| `<단계>-art/` | 실패 사진·trace(실행 기록)·오류 맥락 (`E2E_OUTPUT_DIR`) |
| `cpu-<단계>.txt` | 30초마다 `시각 CPU% 남은메모리GB` |
| `summary-table.txt` · `failed-all.tsv` | 단계 전부 묶은 표 · 실패 전부 (`--merge`가 만듦) |

- 보고서 html은 안 만듦 (`--reporter=list,json`) → `e2e/reports/`를 안 덮고 기록물이 두 벌로 안 쌓임
- 실패 기록물은 `e2e/test-results`가 아니라 결과 폴더에 둠 → 다음 단계 시작 정리(6시간 넘은 것 지움)에 안 지워짐

## 6. 끝난 뒤 정리

이 장은 다 돌린 뒤 볼 것과 지울 것을 적음. `once.sh after`가 보고만 하고, 끄기·지우기는 안 함.

| 볼 것 | 정상 | 남았으면 |
|---|---|---|
| 시험 포트 4100~4209·5273~5275 | 없음 | Playwright가 서버를 끄는 중일 수 있음 → 1분 뒤 다시 봄 |
| 시험 서버 프로세스 (`start-backend`·`serve-front`·`lb-proxy`) | 없음 | 적힌 번호만 `taskkill //PID <번호> //T //F` (4000번 개발 서버는 안 건드림) |
| 시험 Redis | `running paused=false` | `paused=true`면 사용자에게 알리고 `docker unpause mmc-redis-test` |
| 시험 계정 | 단계마다 `[e2e] 이번 실행 계정 N개 지움` | "지우기 실패" 경고 → 다음 실행 시작 정리가 6시간 넘은 것을 지움 (따로 안 해도 됨) |
| 결과 폴더 크기 | 몇 GB 안 | 보고서 끝나면 사용자 확인 뒤 날짜 폴더를 휴지통으로 |
| 서버 로그 `e2e/.runtime/` | 작음 (질의 로그 꺼짐) | 그대로 둠 |

- 기록물 크기 어림 [짐작]: 실패 하나에 trace 2~20MB → 실패 100~300개면 0.5~6GB, 1,000개면 약 20GB
  - 영상은 꺼짐(`video: 'off'`), 사진은 실패 때만 → 통과한 시험은 거의 안 남음
  - 그래서 디스크 20GB 밑이면 단계 앞에서 멈춤

## 7. 미리 보이는 위험

이 장은 코드·설정을 읽어 찾은 위험을 심한 것부터 적음. 시험·도우미 코드는 안 고침 (보고만).

1. **잠금이 2시간 뒤 빼앗김** — `tools/시험도구/with-lock.sh:12`가 2시간 넘은 잠금을 죽은 것으로 보고 치움
   - 6시간 도는 브라우저 실행 중 다른 에이전트가 `with-lock.sh e2e`를 부르면 같은 포트로 겹침
   - once.sh는 5분마다 잠금 폴더 시각을 새로 함(`touch -c`) → 안 빼앗김. 옛 `all.sh`엔 이것이 없음
   - 지금 부하도 같은 잠금을 쥐고 있음(15:16부터) → 부하가 2시간 넘게 가면 다른 사람이 잠금을 가져갈 수 있음
2. **앞 프로젝트에 실패가 하나라도 있으면 serial이 통째로 건너뜀** — `e2e/playwright.config.js:113`·`139` (`dependencies`)
   - 그래서 `npx playwright test` 한 번으로 돌리지 않음, 단계마다 `--no-deps`
   - `--project=serial`만 주고 `--no-deps`를 빼면 3,005개가 돎 (확인함)
3. **다시 돌리기 1번이 켜져 있음** — `e2e/playwright.config.js:47` `retries: 1` → 흔들림이 가려지고 시간이 늘어남 → `--retries=0`
4. **`--list`가 보고서를 덮음** — `e2e/playwright.config.js:49~53`의 html·json 보고가 세기 때에도 돎 → `e2e/reports/results.json`·`reports/html`이 빈 결과로 바뀜
   - README 35줄 명령(`npx playwright test --list …`)이 그대로 이렇게 함 → 셀 때는 `--reporter=list`를 붙임
5. **긴 실행에서 앞 단계 기록물이 지워짐** — `e2e/helpers/global-setup.js:30~44`가 실행 시작마다 `e2e/test-results` 아래 6시간 넘은 폴더를 지움 → once.sh는 기록물을 결과 폴더에 둠
6. **작업자 9개 넘으면 포트가 겹침**
   - 소셜 시험 `e2e/tests/auth/_a11a-kit.js:230~233`: 작업자 번호를 8로 나눈 나머지 → 9번째가 1번째와 같은 포트
   - `e2e/helpers/servers.js:79~80` 4150 + 작업자 번호 → 10번째부터 4160번대(충전 시험)와 겹침
   - 충전 시험 `e2e/tests/store/a12-topup.spec.js:139~141` 4160·4200 + 작업자 번호 → 작업자 8이면 4207까지 씀
   - once.sh는 8에서 자름
7. **서버 2대 단계가 Docker를 켤 수 있음** — `e2e/helpers/redis.js:52~56` → `backend/scripts/setup-test-redis.js:20~25`가 시험 Redis가 꺼져 있으면 `docker start`·`docker run`을 부름
   - once.sh는 시작 전 상태를 보고 안 떠 있으면 멈춤 (켜지 않음)
   - `E2E_REDIS_URL`을 주면 Docker를 안 건드리지만, 그러면 A17 Redis 멈춤 시험이 일부러 실패함(`e2e/tests/multinode/_a17-kit.js:227`) → 주지 않음
8. **Redis가 멈춘 채 남을 수 있음** — `e2e/tests/multinode/_a17-kit.js:224~234` 시험 도중 프로세스가 죽으면 `unpause`를 못 함 → `after`가 상태를 보고 알림
9. **화면 빌드를 단계마다 다시 함** — `e2e/scripts/serve-front.js:212` `E2E_FRONT_REBUILD=0`이 없으면 부를 때마다 화면 셋을 같이 빌드 (1~3분, CPU 100%)
   - once.sh는 늘 `=0` (화면 코드가 빌드본보다 새로우면 그래도 다시 빌드 — 91~98줄)
   - **돌리는 동안 화면 코드를 고치면** 다음 단계부터 다른 화면으로 돎 → 돌리는 동안 코드 안 고침
10. **사파리(WebKit)만 느리고 다르게 걸림** — `e2e/playwright.config.js:97~103`에 크로미움 막기 값이 없어 창마다 가로채기 → 캐시 꺼짐
    - 지난번 같은 수에 mobile 11분 · safari 18분
    - 영상 재생(윈도우 WebKit 코덱)은 1단계 견본으로 먼저 봄
11. **서버 2대로 전부 돌리면 3,007개가 또 돎** — 서버 2대 목록의 multinode 밖 3,007개는 서버 1대와 똑같음 → `multinode/` 거르기를 꼭 씀
12. **서버 하나가 모든 작업자를 받음** — `e2e/scripts/start-backend.js:107~108` Node 하나 → CPU 100%일 때 `ECONNRESET`(지난번 흔들림 3개의 원인)
13. **백엔드 켜기 시간 제한 2분 안에 시험 DB 준비가 들어 있음** — `e2e/playwright.config.js:150`, `start-backend.js:103` (마이그레이션 확인) → PC가 바쁘면 켜기 실패 가능, 그때는 그 단계만 다시
14. README 낡은 줄 (고치지 않음, 나중에 고를 것)
    - 21줄 "서버 로그 SQL까지 다 있음" → 지금은 `DB_LOG_QUERIES=1`일 때만 (`backend/models/index.js:26~27`)
    - 39줄 `br/all.sh` 안내 → 실패 파일 전체를 다시 돌리는 옛 방식
