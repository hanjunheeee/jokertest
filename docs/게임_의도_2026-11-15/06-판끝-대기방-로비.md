# 판 끝 뒤 대기방·로비 — 의도와 지금 동작

판이 끝난 뒤 사람마다 어디로 가는지(결과 화면 단추·자동 입장·끊김·새로고침·다음 판 방)를 서버·PC 화면·모바일 화면 코드로 적은 글. 승패 판정·결과 저장·결과 화면 값은 → `05`에서 다룸, 판 도중 끊김·다시 들어오기 규칙 자체는 → `07`에서 다룸.

줄 번호는 지금 작업 폴더(브랜치 release/2026-11-10) 기준. 경로 앞 `be/` = `backend/`, `fe/` = `frontend/src/`, `mo/` = `frontend-mobile/src/`.

먼저 알아 둘 큰 틀 세 가지:
- 판이 시작되면 원래 대기방은 지워짐. 판 끝 뒤 "같은 방"은 없고, **방장이 새 방을 만들고 남은 사람을 그 방에 넣는 구조**(파티 방, party room = 끝난 판 사람들이 다시 모이는 다음 방)임.
- 판이 끝나도 서버는 끝난 판(phase `ENDED`)을 바로 안 지움. 사람마다 "끝난 판에 묶임"이 남아 있고, 나가기·끊김으로 한 명씩 풀림. 다 풀려야 판이 지워짐.
- 결과 화면 "대기방으로"는 끝난 판 나가기(`leave_game_session`)를 **안 보냄**. "로비로"만 보냄. 그래서 "대기방으로"를 고른 사람은 다음 판 시작 때까지 끝난 판에 묶인 채로 있음.

## 1. 흐름

### 1-1. 판 끝 순간
1. 서버가 승패를 정하면 종료 칸(winResult 등)을 그 단계 방송에 실어 보냄: `night_result_applied`(밤 결과), `tribunal_vote_resolved`(재판 결과), `player_eliminated`(나감·끊김 탈락) — `be/socket/gameSession/departure/end.js:24-36`, `be/socket/gameSession/departure/apply.js:80-86`. 값의 뜻은 → `05`.
2. 이때 서버는 판을 지우지 않음. 전적 저장을 시작하고, "판 끝 순간 연결 없던 사람" 정리를 60초 뒤로 예약함 — `end.js:33-34`, `end.js:40-53`, `be/socket/gameSession/core/constants.js:76-77`.
3. 판 끝 알림 `game_ended`(판 끝남)는 승부가 났을 때 보내지 않음. 마지막 사람이 끝난 판에서 빠져 판이 지워질 때만 보내고, 그때 받을 사람은 거의 없음(빠지는 본인은 뺌) — `end.js:83-138`(보내기 `:118`), `be/socket/gameSession/delivery/eligibility.js:62-76`.
4. 화면(PC·모바일 같음): 인게임 store(화면 상태 저장소)의 `state.phase === "ENDED"`이고 `state.winResult`가 있으면 `/gameresult`로 한 번 옮김(뒤로 가기 기록 덮어씀) — `fe/domains/game/ingame/hooks/useInGameResultNavigation.js:19-34`. 재판 추방·밤 성공 연출 중이거나 다시 묶는 중이면 미룸 — `fe/domains/game/ingame/pages/InGamePage.jsx:126-130`, `mo/domains/game/ingame/hooks/overlays/useOverlayLayer.js:80-82`.
5. 판 끝 순간 받을 사람: 판에 참여 중인 사람만(산 사람·죽고 관전 중인 사람). 판 중에 나간 사람(기권 명단)은 안 받음 — `eligibility.js:11-27`.

### 1-2. 결과 화면
1. 승패 영상 → 결과판 → 단추 줄. 단추는 영상이 끝난 뒤 나타남 — `fe/domains/game/result/page/GameResultPage.jsx:62-80`, `:92-123`.
2. 결과 값은 화면 store에 받아 둔 `winResult`만 씀 — `fe/domains/game/result/hooks/useGameResultData.js:9-16`. 새로고침 직후엔 스냅샷(판 전체 모습 다시 받기)을 최대 6초 기다림 — `GameResultPage.jsx:45-59`, `fe/domains/game/result/constants/gameResultUnavailable.js:5`.
3. 단추와 글자 — `fe/domains/game/result/constants/gameResultLabels.js:14-19`:
   - 결과가 있으면 "대기방으로"(누르는 중엔 "이동 중..")·"로비로" 두 개.
   - 결과가 없으면 안내 "게임 결과를 확인할 수 없습니다" + "로비로 돌아가기" 하나 — `GameResultPage.jsx:84-91`, `:114-121`, `gameResultUnavailable.js:19-21`.
4. 다시 하기(같은 사람·같은 방 즉시 재시작) 단추는 없음. "대기방으로"가 그 역할.

### 1-3. "대기방으로" — 방장
1. 화면이 `get_current_room`(지금 내 방 묻기)을 보냄. 이미 방이 있으면 그 방으로 감 — `fe/domains/game/result/hooks/useGameResultReturnToMatching.js:124-129`.
2. 없으면 `create_room`(방 만들기) 보냄. 설정은 방장이 판 중 설정 탭에서 "다음 게임 설정 유지"를 켰으면 그 값, 아니면 기본값 — `useGameResultReturnToMatching.js:54-65`, `:132-138`, `fe/domains/game/setup/utils/resolveNextGameCreateRoomPayload.js:9-33`.
3. 서버: 끝난 판 방장이면 Node(서버 한 대)가 비우는 중이어도 여기서 만듦 — `be/socket/matchmaking/join/create.js:46-48`. 새 방 id·새 방 코드·방 이름 "닉네임의 방"·준비 전부 풀림 — `create.js:156-168`, `:173-180`. 옛 방 코드는 끝난 판이 잡고 있어 다시 못 씀 — `be/socket/matchmaking/join/guards.js:191-194`.
4. 서버가 답한 뒤 `party_matching_room_ready`(파티 방 준비됨)를 판 채널 + 계정 채널로 보내고, 우편함(다음 방 기록)에 30분 넣음 — `be/socket/matchmaking/join/party.js:64-85`, `be/socket/matchmaking/core/constants.js:9`.
5. 이어서 끝난 판 사람들을 한 명씩 자동 입장시킴(서버가 끌어다 넣음). 넣는 사람에게 `room_joined`, 방에 `player_joined_room` — `be/socket/matchmaking/join/join.js:68-96`, `be/socket/matchmaking/join/joinCommit.js:46`, `:62`.
6. 화면: 판 정보 지우고(`clearGame`) 방 넣고(`setRoom`) `/game-matching` — `useGameResultReturnToMatching.js:114-118`. 서버가 거절하면 알림 창만 띄우고 결과 화면 그대로 — `:136-137`.

### 1-4. "대기방으로" — 참가자(방장 아님)
1. 이미 방이 있으면(방장이 먼저 만들어 자동 입장됨) 그 방으로 바로 감 — `useGameResultReturnToMatching.js:124-129`.
2. 없으면 끝난 판 id를 세션 저장소(sessionStorage, 탭 하나 동안 남는 저장소)에 적고 `/game-matching`에 "방장 방 기다림" 표시(`awaitRoomAfterGameResult`)를 달고 감 — `:140-151`, `fe/domains/game/shared/utils/partyMatchingRejoin.js:16-23`.
3. 대기방 화면: 빈 자리 + "방장이 새 방을 만드는 중입니다. 잠시만 기다려 주세요." + 파티 인원 0명 — `fe/domains/game/matching/hooks/useMatchingPage.js:22-31`, `:131-138`, `fe/domains/game/matching/constants/gameMatchingAssets.js:21`.
4. 2.5초마다 `get_current_room` + `get_party_matching_room`(다음 방 묻기), `party_matching_room_ready` 받으면 `join_room_by_code`(코드로 들어가기) — `fe/domains/game/matching/hooks/room/partyRejoinRun.js:40-80`, `partyRejoinPoll.js:37-64`, `fe/domains/game/matching/constants/roomTiming.js:17-20`.
5. 3분 넘거나 다시 해도 안 될 거절(방 없음·가득 참·이미 시작·코드 다름·판 끝남)이면 알림 뒤 `/multiplay` — `partyRejoinRun.js:13-19`, `partyRejoinPoll.js:27-44`, `useMatchingPage.js:53-57`, `fe/domains/game/matching/constants/roomMessages.js:29-30`.
6. 들어가고 방 확인까지 끝나면 기다림 표시를 끔(새로고침해도 다시 안 기다림) — `useMatchingPage.js:73-81`.
7. `leave_game_session`은 안 보냄(일부러) — `useGameResultReturnToMatching.js:1-3`, `docs/버그수정_결정_2026-11-09.md:133`.

### 1-5. "로비로"
1. 확인 창 "게임에서 나가시겠습니까?" — `fe/domains/game/ingame/utils/exitConfirm.js:5`, `fe/domains/game/ingame/hooks/useInGameExit.js:121-128`.
2. 확인 → `leave_game_session {gameId}`, 답을 8초 기다림 — `fe/domains/game/ingame/hooks/exit/leave.js:50-73`, `fe/domains/game/ingame/constants/ingameExit.js:5`.
3. 서버(끝난 판): 판에 없어도 성공으로 답함. 이 사람을 "떠난 명단"(detachedUuids)에 넣고 내 판 기록을 지움 — `be/socket/gameSession/handlers/leave.js:65-85`, `be/game-core/core/registry/write.js:47-65`.
4. 서버: 자동 입장으로 들어가 있던 대기방 자리도 뺌. 단 본인이 스스로 만든·들어간 자리는 안 뺌 — `be/socket/matchmaking/room/sessionCleanup.js:30-93`(가르는 곳 `:31`), `be/socket/matchmaking/join/partyOrigin.js:125-133`, `docs/버그수정_결정_2026-11-09.md:23`.
5. 마지막 사람이면 판을 장부에서 지우고 판 끝 마무리(타이머·채널 정리·`game_ended`) — `handlers/leave.js:79-83`, `end.js:83-138`.
6. 화면: 답이 성공이면 판·방 지우고 `/lobby` — `fe/domains/game/ingame/utils/sessionEnd.js:22-28`, `GameResultPage.jsx:42`. 판 중 나가기는 `/multiplay` — `useInGameExit.js:21`, `docs/버그수정_결정_2026-11-09.md:170`.

### 1-6. 아무것도 안 누름 · 창 닫기 · 새로고침
1. 결과 화면엔 시간 제한·자동 이동이 없음(서버·화면 둘 다 찾지 못함). 연결된 채 있으면 끝난 판에 계속 묶임.
2. 끝난 판에서 소켓(연결)이 끊기면 그 자리에서 바로 끝난 판에서 뺌, 마지막이면 판 끝 마무리 — `handlers/leave.js:130-138`, 끊김 연결은 `be/socket/socket.js:90-102`.
3. 판 끝 순간 이미 끊겨 있던 사람(죽은 뒤 끊김·끊김 유예 중)만 60초 기다렸다 정리, 그 안에 다시 붙으면 결과 화면 — `end.js:38-75`.
4. 새로고침: 옛 소켓 끊김이 먼저 처리돼 끝난 판에서 바로 빠짐 → 새 화면의 스냅샷이 "참가자 아님" → "게임 결과를 확인할 수 없습니다" — `be/game-core/snapshot/session.js:136-158`, 시험 `e2e/tests/result/nav.spec.js:48-53`.

### 1-7. 다음 판
1. 새 방은 일반 대기방과 같음: 준비·시작 규칙 그대로, 운영은 5명 이상 — `be/socket/matchmaking/room/start.js:153-170`, `be/socket/matchmaking/core/config.js:7`, `:44-48`.
2. 새 판이 등록될 때 그 판 사람들의 끝난 판 묶음이 풀림 — `be/game-core/setup/commit.js:161-177`.
3. 결과 화면에 아직 남은 사람은 옛 끝난 판에 그대로 묶여 있음.

## 4. 의도가 갈리는 곳 (사용자가 고름)

### Q06-1. 결과 화면에서 끊기면 바로 빠지나, 60초 기다리나
- 갈리는 것: 결정 문서 BE-020 이유 칸은 "바로 빼면 새로고침 중이던 사람이 결과 화면을 못 봄, 60초면 다시 붙을 시간 넉넉"이라 함. 코드 주석도 "그 안에 다시 붙으면 결과 화면 그대로 봄". 실제 60초는 "판 끝 순간 이미 끊겨 있던 사람"에만 걸리고, 결과 화면에서 끊기면 바로 뺌. 브라우저 시험은 "새로고침하면 결과 없음 안내"를 기대함.
- 어디: `docs/버그수정_결정_2026-11-09.md:46`, `be/socket/gameSession/core/constants.js:76`, `end.js:38-39` / `handlers/leave.js:130-138` / `e2e/tests/result/nav.spec.js:48-60`, `gameResultUnavailable.js:20-21`.

## 5. 버그로 보이는 곳

### B06-1. 파티를 떠난 사람도 방장 새 방에 자동으로 끌려 들어감
- 겪는 모습: 참가자 B가 결과 화면에서 "로비로"를 눌러 로비에 있음(또는 기다림 화면에서 "방 나가기"·3분 기다림 끝으로 멀티 화면에 있음). 그 뒤 방장 A가 "대기방으로" → 서버가 B를 A 방 명단에 넣음(준비 안 함). B가 로비에 있으면 화면은 아무것도 모르고, 방 만들기·코드 입장은 "이미 참여 중인 방이 있습니다."로 막힘. B가 멀티 화면에 있으면 화면이 A 방으로 끌려감. A는 B를 강퇴하기 전까지 시작을 못 함.
- 왜:
  - 자동 입장 명단은 끝난 판 사람 중 방장·기권(판 중 나감)만 뺌. 끝난 판에서 "로비로"로 빠진 사람(떠난 명단)은 안 뺌 — `be/game-core/queries/ended.js:16-22`, 빠질 때 명단만 바뀜 `write.js:52-54`.

  - "방 나가기"·기다림 끝은 `leave_room`만 보내거나 아무것도 안 보내 끝난 판에 묶인 채 남음 — `useMatchingPage.js:120-126`, `useMatchingPage.js:53-57`.

- 얼마나 큰가: 다음 판이 멈춤(방장이 강퇴할 때까지 시작 못 함) + 남의 화면이 원치 않게 대기방으로 끌려감. 같은 Node에 연결된 사람만 겪음(`membership.js:71-78`).
