# 버그 8 — 둘째 날 재판에서 한 사람이 유죄·무죄를 못 누름

가장 그럴듯한 원인: 첫날 재판에서 표를 낸 사람 화면에 "재판 표 냈음" 표시(`hasSubmittedTribunalVote`)가 지워지지 않고 둘째 날 재판까지 남아, 유죄·무죄 단추 대신 "투표가 완료되었습니다."가 뜨고 서버엔 표가 안 들어가 마감까지 기다림.

- 범위: 읽기만 한 조사. 코드·시험은 안 고침.
- 줄 번호는 지금 작업 폴더(브랜치 release/2026-11-10) 기준. 경로 앞 `be/` = `backend/`, `fe/` = `frontend/src/domains/game/ingame/`, `mo/` = `frontend-mobile/src/domains/game/ingame/`.
- 모바일 화면도 같은 스토어(store, 화면이 들고 있는 판 상태)·훅(hook, 화면 쪽 동작 묶음)을 씀 — `frontend-mobile/vite.config.js:19`가 `@`를 `frontend/src`로 이음. 그래서 화면 쪽 원인은 PC·모바일 같음.
- 확인 방법: 코드 읽기 + 시험 기대값 읽기 + 저장소 밖 임시 폴더에서 `node`로 스토어 액션(action, 상태 바꾸는 함수)만 불러 첫날 재판 → 둘째 날 재판 차례를 돌려 봄. 서버·DB·브라우저·시험 묶음은 안 띄움.

## 후보마다

이 장은 후보마다 코드에서 본 것 → 다시 겪는 차례 → 판정 까닭 순서로 적음.

### 1. 첫날 "재판 표 냈음" 표시가 둘째 날 재판까지 남음 — 맞음

코드에서 본 것 (사실)
- 표를 내면 서버가 그 사람에게만 `session_self_progress`(내 제출 상태 알림)를 보냄 — `be/socket/gameSession/handlers/tribunal.js:100`, `be/socket/gameSession/delivery/progress.js:45-50`.
  - 재판 중이면 이 알림에 `hasSubmittedTribunalVote: true`(재판 표 냈음)를 실음 — `be/game-core/snapshot/progress.js:76-81`.
- 화면은 이 칸을 판 상태의 본인 정보(`self`)에 덮어씀 — `fe/store/ingame/sessionActions.js:118-122`, 칸 목록 `fe/constants/store/ingameStore.js:17-24`.
- 이 칸을 지우는 곳이 없음
  - 재판 끝 → 밤: "이번 단계에 이미 함"(`hasActedThisPhase`)만 풂 — `fe/store/ingame/voteActions.js:83-94`, `fe/utils/store/selfActed.js:23-27`.
  - 밤 → 새 낮: 낮 투표 칸 4개만 지움, 재판 칸은 목록에 없음 — `fe/store/ingame/phaseActions.js:100-102`, `fe/utils/store/selfActed.js:5`.
  - 낮 → 재판: 피고만 새로 넣고 본인 정보의 재판 칸은 그대로 — `fe/store/ingame/voteActions.js:44-58`.
  - 둘째 날 낮에 오는 내 제출 알림엔 재판 칸이 아예 없어 덮지도 못함 — `be/game-core/snapshot/progress.js:63-75`.
  - 단계가 바뀔 때 서버가 모두에게 내 제출 상태를 다시 보내지도 않음 (보내는 곳은 표 낼 때·준비 누를 때·누가 나갈 때뿐) — `be/socket/gameSession/handlers/dayVote.js:62`, `handlers/ready.js:37`, `departure/apply.js:71`.
- 재판 투표 훅은 서버 칸이 참/거짓 값이면 그것을 먼저 믿음 — `fe/hooks/useInGameTribunalVoteSubmit.js:139-151`.
  - 그래서 둘째 날 재판에서 `hasSubmitted`가 참으로 나옴.
- 재판 창 문지기(gate, 창을 띄울지 정하는 곳)는 `hasSubmitted`가 참이면 단추를 숨기고 "투표가 완료되었습니다."를 띄움 — PC `fe/components/tribunalPresentation/InGameTribunalPresentationGate.jsx:60-79`, 모바일 `mo/components/overlays/tribunal/TribunalGate.jsx:44-55`, 문구 `fe/constants/actions/ingameActionPanel.js:67`.
- 서버는 둘째 날 재판 표 묶음을 새로 만들어 그 사람 표가 없음 → 마감 때 기권(`ABSTAIN`)으로 채움 — `be/game-core/phase/day/resolve.js:127-132`, `be/socket/gameSession/phase/tribunal.js:68-98`.
- 풀리는 길은 스냅샷(snapshot, 판 전체 모습 다시 받기)뿐: 본인 정보를 통째로 새로 만들어 옛 칸이 사라짐 — `fe/utils/snapshot/applySnapshot.js:77`, `fe/utils/snapshot/self.js:48-58`.
  - 스냅샷은 화면이 처음 뜰 때·다시 연결될 때만 물음 — `fe/hooks/useInGameSessionSnapshotSync.js:127-150`.
- 같은 꼴의 낮 투표 문제("둘째 날 기권 잠김")는 이미 고쳤음: 새 낮에 낮 표 칸을 지우고, 표 기록에 날짜를 붙여 지난 날 것은 안 믿음 — `fe/utils/store/selfActed.js:7-20`, 시험 `frontend/tests/domains/game/ingame/store/dayTwoVoteAndTribunalDeadline.test.js:47-82`. 재판 칸은 이때 빠진 것으로 보임(짐작).

node로 돌려 본 것 (사실)
- 스토어 액션만 불러 차례대로 부름: 1일 재판 들어감 → 내 제출 알림(재판 표 냈음) → 무죄 판정·밤 → 2일 낮 → 2일 투표 → 2일 재판 들어감.
- 결과: 밤·2일 낮·2일 재판 내내 `hasSubmittedTribunalVote`가 `true`로 남음. 2일 재판의 피고·날짜는 제대로 바뀜.

다시 겪는 차례 (운영 규칙 5명 판, 가장 짧게)
1. 1일 낮 투표로 재판이 열림. A(산 사람, 피고 아님)가 유죄나 무죄를 누름 → "투표가 완료되었습니다."
2. 재판이 무죄로 끝나 밤 → 2일 낮. A는 그사이 새로고침·끊김 없음.
3. 2일 낮 투표로 다시 재판이 열림 (피고는 A 아님).
4. A 화면: 유죄·무죄 단추 없이 "투표가 완료되었습니다."만 보임 → 서버엔 A 표 없음 → 재판 시간이 끝날 때까지 기다림 → A 표는 기권으로 셈.
- 1일이 유죄여도 같음 (5명이면 2일 재판 투표자가 2~3명뿐이라 한 사람만 걸려도 눈에 띔).

"한 사람만" 걸리는 까닭 (짐작 포함)
- 1일 재판에서 안 누른 사람은 안 걸림: 1일 피고였던 사람, 시간을 넘겨 기권된 사람.
- 그사이 스냅샷을 받은 사람은 안 걸림: 새로고침, 다시 연결(모바일 화면 꺼짐·앱 전환이면 다시 연결될 수 있음 — 짐작).
- 2일 재판 중 누가 나가면 서버가 모두에게 내 제출 상태를 다시 보내 풀림 — `be/socket/gameSession/departure/apply.js:71`.
- 그래서 "1일 재판에서 눌렀고, 그 뒤 한 번도 다시 붙지 않은 사람"만 걸림 → 판 안에서 한 사람만 겪는 일이 흔할 수 있음(짐작).

판정 까닭
- 둘째 날에만 생김, 첫날은 됨, 한 사람만, 마감까지 기다림 — 네 가지 다 맞음.
- 지우는 곳·다시 덮는 곳을 PC·모바일·서버 모두 찾아봤으나 없음.
- 단, 그 사람 화면에 "투표가 완료되었습니다."가 떴는지는 사용자 확인이 필요함 (아래 물어볼 것).

### 2. 연결이 끊긴 순간 누르면 아무 일도 안 일어남 — 그럴듯함 (낮음)

코드에서 본 것 (사실)
- 제출 컨트롤러(controller, 보내기 담당)는 소켓(socket, 서버와 이은 줄)이 안 붙어 있으면 아무 표시 없이 그냥 끝냄 — `fe/utils/createTribunalVoteSubmitController.js:205-206`.
- 단추 잠금의 "연결됨" 값은 그릴 때 한 번 읽는 값이라 끊김을 따라 다시 그려지지 않음 — `fe/hooks/useInGameActionPanel.js:108`, `fe/utils/actionPanelLocks.js:71`.
  - 끊기면 제출 상태를 처음으로 되돌리지만, 이미 처음 상태면 화면이 다시 안 그려짐(짐작) — `fe/hooks/useInGameTribunalVoteSubmit.js:121-128`.
- 다시 붙으면 스냅샷으로 풀림.

다시 겪는 차례 (짐작)
- 2일 재판 창이 뜬 뒤 그 사람 연결이 잠깐 끊김 → 단추는 켜져 보이나 눌러도 아무 일 없음 → 다시 붙기 전에 마감.

판정 까닭
- "눌러도 안 먹음"과 맞지만 둘째 날에만 생길 까닭은 없음.
- 끊기면 채팅도 같이 안 됐을 것 — 사용자 확인 필요.

### 3. 서버가 표를 거절해도 화면에 까닭이 안 나옴 — 그럴듯함 (낮음)

코드에서 본 것 (사실)
- 서버 거절 조건: 판 다름·날짜 다름(`STALE_DAY_INDEX`)·재판 아님(`INVALID_PHASE`)·재판 상태 없음·이미 판정(`TRIBUNAL_ALREADY_RESOLVED`)·낮 투표 결과와 피고 다름·피고 죽음·내가 죽음(`PLAYER_NOT_ALIVE`)·내가 피고(`DEFENDANT_CANNOT_VOTE`)·값 틀림·이미 냄(`TRIBUNAL_VOTE_ALREADY_SUBMITTED`) — `be/game-core/phase/tribunal/vote.js:18-65`.
- 거절되면 화면 제출 상태는 다시 "보낼 수 있음"이 되고 오류 글만 담김 — `fe/utils/voteSubmitPatch.js:53`.
- 그런데 오류 글(`tribunalVoteError`)을 그리는 곳이 PC·모바일 어디에도 없음 — `fe/hooks/useInGameActionPanel.js:178`에서 넘기기만 함, 문지기 `InGameTribunalPresentationGate.jsx:60-79`·`mo/.../TribunalGate.jsx:44-55`는 안 읽음.
- 둘째 날에만 거절될 길은 못 찾음
  - 화면 날짜가 서버보다 늦으면 낮 투표 결과 알림부터 거절돼 재판 창 자체가 안 뜸 — `fe/store/ingame/voteActions.js:30-31`.
  - 서버 재판 상태는 날마다 새로 만듦(후보 9).

판정 까닭
- 거절이 생기면 "눌러도 아무 말 없이 단추가 그대로" → 겪는 모습과 비슷함.
- 그러나 둘째 날 거절 원인을 못 찾아 원인보다는 "알아채기 어렵게 만드는 곳"으로 봄.

### 4. 모바일만 피고를 명단에서 못 찾으면 재판 창이 안 뜸 (B03-1) — 그럴듯함 (낮음)

코드에서 본 것 (사실)
- 모바일 문지기는 피고를 판 명단에서 못 찾으면 아무것도 안 그림 — `mo/components/overlays/tribunal/TribunalGate.jsx:37-42`. PC는 기본 그림으로 띄움 — `fe/components/tribunalPresentation/InGameTribunalPresentationGate.jsx:45-58`.
- 재판 중엔 아래 화면·채팅이 잠김 — `mo/hooks/overlays/useOverlayLayer.js:89-92`.
- 명단은 판 상태가 비면 마지막 정상 목록을 씀 — `fe/components/InGamePlayerSessionProvider.jsx` (명단에서 산 사람이 빠질 길은 못 찾음).

판정 까닭
- 겪는 모습이 "창이 아예 없음"이라 "선택이 안 됨"과 조금 다름.
- 둘째 날만의 까닭 없음. `00-버그-다시확인.md`의 B03-1처럼 겪는 차례를 코드로 못 만듦.

### 5. "낮/밤이 되었습니다" 안내 창이 덮음 — 아님

- 안내 창 열쇠는 낮·밤 단계에서만 생기고 재판 단계에선 비어 있음 — `fe/utils/overlayIdentity.js:31-36`, 단계 목록 `fe/constants/ingamePhaseEntrance.js:5`.
- 열쇠가 바뀌면 떠 있던 안내를 버림 → 재판이 열리는 순간 닫히고 조작 막음도 풀림 — `fe/utils/reduceInGamePhaseEntrance.js:22-24`, `fe/hooks/useInGameOverlayStack.js:26`.
- 2일 낮 안내를 안 닫은 사람도 재판이 되면 풀림.

### 6. 밤 개인 결과 창이 덮음 — 아님

- 밤 개인 결과(조사 결과 등)는 새 낮이 돼도 안 지워져 확인 전까지 남음 — `fe/store/ingame/nightResultActions.js:18-27`.
- 하지만 확인·바깥 누름·Esc 모두 닫힘 — `fe/components/nightPrivateResult/InGameNightPrivateResultOverlay.jsx:10,21`.
- 한 번 누르면 풀려 "시간이 지나야 넘어감"과 안 맞음.

### 7. 추방 영상 멈춤(알려진 문제 1-3) — 아님

- 추방 연출은 재판 판정 알림(`tribunal_vote_resolved`)을 받은 뒤에만 생김 — `fe/hooks/useInGameTribunalExpulsionPresentation.js:98-108`.
- 재판 투표 중엔 아직 없음. 1일 영상이 멈췄다면 2일 낮부터 이미 막혔을 것.

### 8. 첫날 무죄 피고가 둘째 날에도 피고로 남음 — 아님

- 화면: 재판에 들어갈 때 재판 칸을 `{ defendantUuid }`로 통째로 새로 씀 — `fe/store/ingame/voteActions.js:52`. 재판이 끝나 밤이 되면 재판 칸을 비움 — `fe/store/applyTribunalResolved.js:133-139`.
- 피고 여부는 "지금 재판 피고 = 나"로만 셈 — `fe/hooks/useInGameTribunalVoteSubmit.js:83`.
- 시험: 무죄 피고가 2일 낮 투표를 냄 `e2e/tests/ingame/a-day/tribunal.spec.js:255-266`.

### 9. 서버의 첫날 재판 상태·날짜·투표자 계산 — 아님

- 낮 투표 판정마다 재판 상태를 새로 만듦(날짜·피고·빈 표 묶음) — `be/game-core/phase/day/resolve.js:127-132`.
- 표 받을 때 오늘 날짜·재판 날짜·낮 투표 결과 날짜를 다 맞춰 봄 — `be/game-core/phase/tribunal/vote.js:25-46`.
- 투표자 = 산 사람 중 피고 뺀 전원, 날마다 지금 명단으로 셈 — `be/game-core/phase/tribunal/ballots.js:9-15`.
- 서버 스냅샷은 2일 재판에서 `hasSubmittedTribunalVote: false`를 바르게 줌 — `be/game-core/snapshot/progress.js:77-81`. 즉 서버 값은 맞고 화면만 옛 값을 들고 있음.

### 10. 낮 투표 표가 재판 표 표시로 넘어감 — 아님

- 낮 표 칸(`hasSubmittedDayVote` 등)과 재판 칸(`hasSubmittedTribunalVote`)은 이름이 따로임 — `fe/constants/store/ingameStore.js:17-24`.
- 재판 훅·문지기는 재판 칸만 읽음 — `fe/hooks/useInGameTribunalVoteSubmit.js:140`.
- 낮 칸은 새 낮마다 지움 — `fe/store/ingame/phaseActions.js:102`. (지우는 목록에 재판 칸이 없는 것이 후보 1.)

### 11. "재판 판정" 요청 상태가 남아 단추가 잠김 — 아님

- 판정 요청 상태가 "판정 중"이면 재판 단추도 잠김 — `fe/utils/actionPanelLocks.js:56-70`.
- 모바일은 "재판 판정" 단추가 늘 보여(구간 글 Q03-4) 첫날 누른 사람이 있을 수 있음.
- 그러나 판·날짜·단계·피고가 바뀌면 처음 상태로 되돌림 — `fe/hooks/useInGameTribunalVoteResolve.js:61-63`. 재판 표 제출 상태도 같음 — `fe/hooks/useInGameTribunalVoteSubmit.js:116-119`.

### 이미 있는 시험

- 화면 단위 시험(`frontend/tests`) 중 `hasSubmittedTribunalVote`를 쓰는 시험 없음 (검색 0건).
- 같은 꼴 낮 투표 문제 시험만 있음: "첫날 기권 기록은 둘째 날 낮이 되면 지워짐" — `frontend/tests/domains/game/ingame/store/dayTwoVoteAndTribunalDeadline.test.js:47-82`.
- e2e(브라우저로 돌리는 시험) 둘째 날 재판 시험 4개 — `e2e/tests/ingame/a-day/tribunal.spec.js`
  - `:255` 무죄 피고(봇)가 2일 낮 투표 냄.
  - `:309` 같은 봇 두 번 내면 둘째는 거절.
  - `:344` 1일 피고로 처형된 "나"가 2일 재판에서 "사망한 참가자…" 봄.
  - `:356` 1일 처형된 봇의 2일 재판 표 거절.
  - 어느 것도 "사람이 1일 재판에서 누르고 → 2일 재판에서 단추가 보이는지"를 안 봄. `:344`의 "나"는 1일 피고라 1일에 표를 안 냄.
- 서버 시험은 1일 재판에서 `hasSubmittedTribunalVote: true`가 나오는지만 봄 — `backend/tests/audit-2026-11-09/game-tribunal.test.js:97-100`.

- `fe/store/ingame/voteActions.js:44-58` — 재판에 들어갈 때 본인 정보의 `hasSubmittedTribunalVote` 지우기 (가장 직접).

## 사용자에게 물어볼 것

이 장은 원인을 좁히려고 알아야 할 것만 적음.

- 그 사람 재판 창에 무엇이 보였나
  - "투표가 완료되었습니다." 글 → 후보 1 거의 확정.
  - 단추는 보이는데 눌러도 아무 일 없음 → 후보 2·3.
  - 재판 창이 아예 없음 → 후보 4(모바일).
- 그 사람이 1일 재판에서 유죄·무죄를 직접 눌렀나 (1일 피고였거나 안 눌렀으면 후보 1 아님).
- PC였나 모바일이었나. 판 도중 새로고침·앱 전환·화면 꺼짐이 있었나 (있었으면 후보 1이 풀렸을 것).
- 2일 재판 때 다른 사람들은 정상이었나. 그 사람들은 1일 재판에서 눌렀나.
- 2일 재판 때 그 사람 채팅은 됐나 (안 됐으면 연결 끊김 쪽).
- 그 판에서 2일 재판 중 나간 사람이 있었나 (있었으면 후보 1이 풀렸을 것).

## 확인 못 한 것

- 화면을 실제로 띄워 보지 않음. 후보 1은 스토어 액션까지만 `node`로 돌림 — 훅·문지기 그리기는 코드로만 따라감(훅이 서버 칸을 먼저 믿는 줄 `useInGameTribunalVoteSubmit.js:149-151`은 한 줄짜리라 짐작 여지 적음).
- 모바일 화면 꺼짐·앱 전환 때 실제로 다시 연결(→ 스냅샷)되는지 못 봄. "모바일은 덜 걸린다"는 짐작.
- 후보 2의 "끊겨도 다시 안 그려짐"은 React(화면 그리기 틀)가 같은 값이면 안 그리는 규칙에 기댄 짐작.
- 서버에서 둘째 날에만 표를 거절할 다른 길은 못 찾음 (못 찾음 ≠ 없음).
- 시험 묶음은 안 돌림.
