# 대기방 — 의도와 지금 동작

방 만들기부터 시작 누르기(시작 조건 검사)까지, 대기방에서 일어나는 일이 어떻게 돌아가야 하고 지금 코드는 어떻게 도는지 적은 글.

- 기준: 운영 규칙(`NODE_ENV=production`). 개발 전용 규칙(정원 4·1~2명 시작 등)은 곧 지울 것이라 의도로 안 침 → 10에서 다룸.
- 판이 만들어진 뒤는 → 02, 판 끝나고 대기방으로 돌아오기는 → 06, 끊김·다시 들어오기는 → 07에서 다룸.
- 줄 번호는 지금 작업 폴더 기준. `backend/socket/matchmaking/`는 `mm/`로 줄여 씀.

## 1. 흐름

### 1-1. 방 만들기
1. 방 찾기 화면 "방 만들기" → 설정 화면(일반·회의&투표 두 탭)에서 값 고르고 "게임 만들기" 누름 (`frontend/src/domains/game/setup/constants/gameSetupOptions.js:6-122`).
2. 화면이 `create_room`(방 만들기 요청)을 답 받는 방식(ack)으로 보냄. 값은 `buildCreateRoomPayload` (`frontend/src/domains/game/setup/utils/buildCreateRoomPayload.js:8-49`).
3. 서버가 점검 중이면 거절 (`mm/registerEvents.js:59-62`, `mm/join/maintenanceGate.js:7-13`).
4. 서버가 차례로 거절 검사: 진행 중 판 있음 → 이미 방 있음 → 처리 중 요청 있음 → 자동 매칭 줄에 있음 (`mm/join/create.js:31-45`).
5. 설정 값 검사(허용 표 밖이면 거절) + 직업 구성 검사 (`mm/join/create.js:51-61`, `backend/validations/room/create.js:60-125`, `backend/game-core/core/rules/roleComposition.js:126-160`).
6. 처리 중 표시(잠금)를 걸고 계정·프로필 읽기 → 소켓 채널 넣기 → 6자리 방 코드 뽑기 → 방 장부에 등록 (`mm/join/create.js:68-128`, `:183-190`).
   - 방 이름은 "닉네임의 방", 방장 = 만든 사람, 방장도 준비 안 된 상태로 시작 (`mm/join/create.js:156-168`).
   - 코드는 헷갈리는 글자(I·O·0·1) 뺀 대문자·숫자 6자리 (`backend/utils/roomCode.js:6-16`).
7. 만든 사람에게 답 `{ ok: true, room }` → 화면이 대기방(`/game-matching`)으로 감. 모든 접속자에게 `public_rooms_updated`(공개 방 목록 바뀜) 방송, 0.5초에 한 번으로 묶음 (`mm/room/view.js:80`, `:105-129`).
8. 결과 화면에서 만든 방이면 끝난 판 사람들을 끌어다 넣음 → 06에서 다룸 (`mm/join/create.js:193-211`).

### 1-2. 방 코드로 들어가기 · 공개 방 고르기
1. "코드로 참가" 화면에서 6칸 입력, 소문자는 칸에서 대문자로 바뀜 (`frontend/src/domains/game/mode/hooks/useRoomCodeInput.js:26`, 모바일 `frontend-mobile/src/domains/game/mode/hooks/useCodeField.js:23`).
2. 화면이 `join_room_by_code`(코드 입장)를 보냄. 답은 ack가 아니라 `room_joined`(입장됨) / `room_join_failed`(입장 실패) 사건으로 옴 (`mm/registerEvents.js:41-58`, `mm/join/guards.js:9-11`).
3. 공개 방 목록에서 고르면 `join_public_room` → 공개(open) 방만 받고, 코드 방이면 "이 방은 입장 코드가 필요합니다" (`mm/join/publicRooms.js:11-54`). 통과하면 코드 입장 흐름 그대로 탐.
4. 서버 검사 차례: 게임 중 → 빈 코드 → 1분 20번 시도 제한 → 이미 방·처리 중·줄 (`mm/join/joinChecks.js:18-55`, `mm/join/entryLimits.js:7-8`).
5. 방 찾기: 코드로 찾고, 없으면 "시작된 방 / 끝난 판 / 코드 틀림" 중 이유 골라 알림 (`mm/join/joinChecks.js:111-128`, `mm/join/guards.js:80-87`). 그 방에서 3번 쫓겨난 사람이면 거절 (`mm/join/joinChecks.js:131-139`).
6. 프로필 읽기 → 채널 넣기 → 기다린 사이 바뀐 것 다시 봄(끊김·방 사라짐·자리 없음) (`mm/join/join.js:24-64`, `mm/join/joinRecheck.js:38-93`).
7. 명단에 넣음(준비 안 됨) → 나에게 `room_joined`, 방 사람들에게 `player_joined_room`(새 사람 들어옴, 시작 가능 여부 같이), 공개 목록 갱신 (`mm/join/joinCommit.js:42-76`).

### 1-3. 초대로 들어가기
1. 대기방 사람 누구나(방장만 아님) 친구 초대 창에서 친구에게 초대 보냄 → HTTP `POST /friends/invites` (`frontend/src/domains/game/matching/hooks/useMatchingFriendInvite.js:81-98`).
2. 서버 확인: 보낸 사람이 대기방에 있음·방이 안 가득 참, 받는 사람 활성 계정, 차단 아님, 친구 사이, 받는 사람이 판·방·줄·입장 중이 아님 (`backend/services/friend/gameInvite/create.js:33-64`, `:133-136`, `mm/admission/inviteRoomReaders.js:32-43`). 초대 유효 3분 (`backend/services/friend/gameInvite/constants.js:7`).
3. 받은 사람이 수락 → `accept_game_invite`(초대 수락, ack) (`mm/registerEvents.js:101-108`).
4. 서버: 초대 엿보기 → 방 같은 회차인지·강퇴 3번인지·자리 있는지 → **자리 미리 잡음**(최대 15초) → 수락 기록 → 프로필 → 채널 → 영수증 안에서 명단 넣기 (`mm/admission/accept.js:62-105`, `mm/admission/acceptSteps.js:19-70`, `mm/admission/acceptPublish.js:18-57`).
5. 성공이면 방 사람들에게 `player_joined_room`, 본인에게 ack로 방 정보 (`mm/admission/accept.js:18-32`).
6. 입장 중인 사람이 있는 동안엔 시작 못 함, 시작 가능 표시도 꺼짐 (`mm/admission/attempts.js:79-85`, `mm/room/view.js:24`).

### 1-4. 준비
1. 누구나(방장 포함) "준비완료" / "준비취소" 버튼 (`frontend/src/domains/game/matching/components/MatchingPopupPanel.jsx:102-136`).
2. 화면이 `set_ready`(준비 바꾸기)를 방 id·내가 본 설정 버전과 같이 보냄 (`frontend/src/domains/game/matching/hooks/room/useRoomRequests.js:119-152`).
3. 서버: 내 초대 입장 확정 전이면 거절, 옛 설정 버전이면 "방 설정이 변경되었습니다" 거절, 같은 값이면 안 바꾸고 지금 값만 답 (`mm/room/ready.js:34-71`).
4. 바뀌면 준비 순번 올리고 나 빼고 방 사람들에게 `player_ready_changed`(준비 바뀜), 나는 ack로 받음 (`mm/room/ready.js:74-95`).

### 1-5. 방 설정 바꾸기
1. 방장 화면에만 "방 설정 변경" 버튼 → 편집 창. 방 만든 뒤 못 바꾸는 칸(불 꺼진 무도회·영혼의 베팅·투표 공개)은 숨김 (`frontend/src/domains/game/setup/constants/roomSettingsForm.js:34`, `backend/validations/room/updateSettings.js:55`).
2. 화면이 `update_room_settings`(설정 저장, ack)를 요청 id·기대 버전과 같이 보냄.
3. 서버 검사: 모르는 칸 있으면 거절 → 허용 값 → 지금 소켓 → 같은 요청 id면 저장된 결과 재생 → 게임 중·입장 중 → 내 방·방장 → 기대 버전 → 정원이 지금 인원(입장 중 자리 포함)보다 작으면 거절 (`backend/validations/room/updateSettings.js:193-274`, `mm/settings/handlers.js:47-152`).
4. 내용이 같으면 버전 안 올리고 "안 바뀜"만 답, 준비도 그대로 (`mm/settings/handlers.js:161-171`).
5. 바뀌면 설정 넣고 **전원 준비 풀고** 버전 +1 → 확정된 사람 소켓마다 `room_settings_updated`(설정 바뀜, 명단·방장·설정 통째로), 공개 목록 갱신 (`mm/settings/handlers.js:174-201`, `:12-44`).
6. 저장 답을 잃으면 `get_room_settings_update_result`(저장 결과 다시 묻기)로 10분 동안 영수증 조회 (`mm/settings/handlers.js:205-271`, `mm/settings/receipts.js:15`).

### 1-6. 방장 넘기기
1. 따로 넘기는 버튼·사건 없음. 방장이 나가거나(뒤로 가기) 15초 끊김 유예가 끝나 빠지면 **남은 사람 중 먼저 들어온 사람**이 방장 (`mm/room/leave.js:89-93`).
2. 방 사람들에게 `host_changed`(방장 바뀜) → 그다음 `player_left_room`(나감) (`mm/room/leave.js:124-150`).
3. 새 방장 화면에 게임시작·방 삭제·방장 버튼이 생김 (e2e `e2e/tests/room/waiting-room.spec.js:107`, `:117`).

### 1-7. 내보내기(강퇴)
1. 방장 화면 "참가자 추방" → 창에서 대상 고르고 확인 (`frontend/src/domains/game/matching/components/MatchingHostActionButtons.jsx:55-75`).
2. `kick_room_player`(대기방 강퇴, ack): 요청 id·부팅 번호·방 id·방 회차·내 자리 번호·대상·대상 자리 번호 전부 필수 (`backend/socket/kickReceiptStore/constants.js:53-56`).
3. 서버 거절: 자기 강퇴, 내가 입장 중, 게임 중, 내 방 아님, 자리 번호 바뀜, 방장 아님, 대상 이미 나감, 대상 입장 중 (`mm/room/host.js:83-140`). 같은 요청 id는 10분 동안 같은 답 (`mm/room/host.js:51-60`).
4. 대상 빼고 그 방 강퇴 횟수 +1 (`mm/room/host.js:160-162`) → 방장 ack → 대상 소켓에 `room_kicked`(쫓겨남) → 방 사람들에게 `player_left_room` (`mm/room/host.js:179-187`).
5. 대상 화면은 방 비우고 방 목록(`/multiplay`)으로 감, 따로 안내 문구 없음 (`frontend/src/domains/game/ingame/hooks/sessionEvents/roomHandlers.js:33-41`).

### 1-8. 대기방 채팅
- 없음. 서버에 대기방 채팅 사건이 없고(채팅 사건은 판 안 `submit_game_chat_message`·`submit_joker_chat_message`뿐, `backend/socket/gameSession/handlers/register.js:48-49`), PC·모바일 대기방 화면에도 채팅 칸이 없음 → Q01-1.

### 1-9. 시작 누르기 (시작 조건 검사까지)
1. 방장 화면 "게임시작" 버튼은 시작 중일 때만 잠김, 조건이 안 맞아도 누를 수 있음 (`frontend/src/domains/game/matching/components/MatchingPopupPanel.jsx:110-115`).
2. 화면: 연결 없음·방 확인 전이면 안 보내고 안내 창 (`frontend/src/domains/game/matching/hooks/room/useRoomRequests.js:67-89`). 보내면 `start_game`(게임 시작, ack, 8초 기다림).
3. 서버: 점검 중 거절 → 지금 소켓 → 요청 모양 → 내 방·방장·설정 버전 → 시작 조건 (`mm/registerEvents.js:83-88`, `mm/room/start.js:119-170`).
4. 시작 조건 (`mm/room/start.js:153-170`):
   - 인원 5명 이상이고 광대 수보다 많음 → 아니면 `MIN_PLAYERS_NOT_MET` "게임을 시작하기 위한 인원 조건을 아직 충족하지 못했습니다."
   - 지금 인원으로 직업 구성이 맞음 → 아니면 `INVALID_ROLE_COMPOSITION` "설정한 역할 구성이 현재 인원과 맞지 않습니다. 인원을 더 모아주세요."
   - 전원(방장 포함) 준비 → 아니면 `PLAYERS_NOT_READY` "아직 준비하지 않은 참가자가 있습니다."
   - 초대로 입장 중인 사람 없음 → 아니면 `ADMISSION_IN_PROGRESS`.
5. 프로필·전적 읽는 사이 방장·명단·준비·설정 버전이 바뀌었으면 `ROOM_STATE_CHANGED` (`mm/room/start.js:15-28`, `:173-182`). 참가자 한 명이라도 받을 소켓이 없으면 `PARTICIPANT_UNAVAILABLE` (`mm/room/startLaunch.js:65-80`).
6. 실패 답은 방장 화면에 "게임을 시작할 수 없습니다" 양피지 창 + 서버 문구 (`frontend/src/domains/game/matching/components/GameStartBlockedModal.jsx:13-35`).
7. 통과하면 판 만들기·방 지우기·`game_started` → 02에서 다룸 (`mm/room/startLaunch.js:16-23`).

### 1-10. 나가기 · 방이 없어지는 때
1. 손님 "방 나가기", 방장은 뒤로 가기 → `leave_room`(나가기, 답 없음) 보내고 바로 방 목록으로 (`frontend/src/domains/game/matching/hooks/useMatchingPage.js:121-126`, `mm/registerEvents.js:94`).
2. 서버: 명단에서 빼고, 마지막 사람이면 방 없앰, 아니면 필요할 때 방장 넘기기 (`mm/room/leave.js:57-95`).
3. 방장 "방 삭제하기" → 확인 창 "방을 삭제하면 모든 참가자가 나가게 됩니다." → `delete_room` → 방 사람들에게 `room_deleted`(방 없어짐) → 전원 방 목록으로 (`frontend/src/domains/game/matching/hooks/room/useRoomRequests.js:42-64`, `mm/room/host.js:192-244`, `frontend/src/domains/game/matching/hooks/room/useRoomEvents.js:121-125`).
4. 방이 없어지는 때 전부 한 함수(`disposeRoom`)로 정리: 방·입장 시도·설정 영수증·다음 방 우편함·대기 초대 취소 (`mm/room/dispose.js:25-31`).
   - 마지막 사람 나감 (`mm/room/leave.js:83-86`), 방장 삭제 (`mm/room/host.js:228`), 게임 시작 (`mm/room/startLaunch.js:107`), 초대 입장 되돌린 뒤 빈 방 (`mm/admission/release.js:42-46`), 판 끝 정리 중 빈 방(→ 06), 점검 시작 시각 (`mm/room/maintenanceClose.js:13-22`).
5. 끊긴 사람은 15초 뒤 방에서 빠짐 → 07에서 다룸 (`mm/room/leave.js:31-54`).

### 1-11. 자동 매칭
- 일부러 잠금(`RANDOM_MATCH_ENABLED = false`, `mm/core/config.js:16`). `join_matchmaking`은 `matchmaking_disabled`로 거절. 이 글에서 더 안 다룸.

  1. **(추천) 지금 서버대로(접속 안 해도 초대 남김) 확정하고 결정 문서·화면 주석을 고침** — 들어오자마자 3분 안이면 수락 가능, 서버 바꿈 없음.

## 5. 버그로 보이는 곳

### B01-1 공개 방 목록 인원·"마감" 표시가 초대로 잡힌 자리를 안 셈
- 겪는 모습: 9/10 방에 친구가 초대 수락 중(자리 잡음)이면 목록엔 "9/10 대기"로 보여 누를 수 있는데, 눌러 보면 "방 정원이 가득 찼습니다."
- 왜: 목록은 명단 수만 셈(`mm/room/view.js:61`, `:65`). 입장 판정·초대 보내기 판정은 잡힌 자리까지 셈(`mm/admission/attempts.js:88-101`, `mm/join/joinRecheck.js:86-91`, `mm/admission/inviteRoomReaders.js:25-27`). 같은 방 "가득 참"을 두 기준으로 셈.
- 다시 겪는 차례(짐작): 정원 10 방에 9명 → 친구 초대 → 친구가 수락 누름(최대 15초 사이) → 다른 사람이 목록에서 그 방을 보고 입장하기.
- 크기: 보기만 이상함 (입장은 제대로 거절됨, 잡힌 자리는 15초 안에 풀리거나 채워짐).

### B01-2 모바일 "방 삭제하기" 버튼이 삭제 중에도 안 잠김
- 겪는 모습: 모바일에서 삭제를 누르고 답을 기다리는 동안 버튼이 그대로 눌리는 모양. PC는 잠김.
- 왜: PC는 `disabled={isDeleting}` (`frontend/src/domains/game/matching/components/MatchingPopupPanel.jsx:116-121`), 모바일은 빠짐 (`frontend-mobile/src/domains/game/matching/components/actions/ActionBar.jsx:73-79`). 모바일 파일 머리 주석은 "잠금은 데스크톱 … 아래 버튼 줄과 같음"이라 적음(`:2`).
- 다시 겪는 차례: 모바일 대기방 방장 → 방 삭제하기 → 확인 → 답 오기 전 버튼 다시 누름.
- 크기: 보기만 이상함 (훅의 보내는 중 표시가 두 번 보내기는 막음, `frontend/src/domains/game/matching/hooks/room/useRoomRequests.js:43`).
