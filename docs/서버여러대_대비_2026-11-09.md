# 서버 여러 대 대비 (2026-11-09)

게임 서버를 여러 대로 늘릴 때 깨지는 곳 목록, 개발자용.
지금 동작은 그대로 두고 조사만 함 (Redis 설치·socket.io Redis 어댑터 연결은 안 함, 나중).

- 기준 커밋: `39a88c99` (브랜치 `feature/mobile-ingame-talk`)
- socket.io 4.8.3 (`except`·`fetchSockets`·`io.local`·`socketsJoin`·`disconnectSockets` 전부 있음)
- 사용자 결정: "특정 사람에게 보내기"는 **그 사람 전용 채널(`user:<uuid>`)로 보내기** 한 가지로 맞춤 → 나중에 어댑터만 붙이면 여러 서버에서 그대로 됨

## 0. 전제 (이 문서 판단 기준)

- **판·대기방은 한 서버에 고정**: 방 사람 소켓은 전부 그 방이 사는 서버에 붙는다고 봄 (방 위치 기록·라우팅·로드밸런서 고정 연결로 보장, 4장 순서 2~3)
- 이 전제면 판·방 안 전송(소켓 객체 보고 자격 다시 확인하며 보내기)은 그대로 OK
- 판·방 **밖** 전송(친구·알림·초대·업적·전적 캐시·강제 끊기)은 받는 사람이 어느 서버에 붙었는지 모름 → 계정 채널로 보내야 함

## 1. 소켓 전송 분류

조사 범위: `backend/socket/**`, `services/{friend,notification,ops}/**`, `routes/internal.routes.js`, `game-core/**` + 거기서 불리는 `services/{achievement,game/record,auth/account}`·`utils/processLifecycle.js`.
`game-core/**`엔 소켓 전송 없음 (상태·판정만).

### 1-1. 계정 전용 채널 join 여부

- **없음**. `user:` 같은 계정 채널 join하는 곳 0곳 (`socket/socket.js` `registerConnectionHandlers`에도 없음)
- 지금 "한 사람에게 보내기"는 전부 `onlineUsers`(uuid → 소켓 id, `socket/emitter.js:3`) 또는 `io.sockets.sockets` 훑기로 소켓 찾아 보냄
- 소켓이 원래 드는 채널: 자기 소켓 id 채널(socket.io 기본) + 대기방 id + 판 채널 id
- 계정 채널 넣어도 영향 없음 확인: `socket.rooms` 크기·전체 훑기로 판정하는 곳 없음 (`channelMembership/detach.js` 연결 유지 판정은 장부 기준 `socketHasLiveMembership`)

## 4. 나중 할 일 순서

1. **Redis 어댑터 붙이기** (`@socket.io/redis-adapter`) — 3장 B0~B7 끝난 뒤면 판·방 밖 전송은 그대로 여러 서버에서 됨, `io.emit`(공개 방 목록)·종료 안내는 `io.local` 확인
2. **방 위치 기록·라우팅** — 방 id·방 코드·판 id → 서버 id를 Redis에 (2장 4·7·14·21번), 다른 서버로 온 코드 입장·초대는 그 서버로 보내기
3. **로드밸런서 고정 연결** — 같은 사람은 같은 서버(쿠키·uuid 해시), 방 들어갈 땐 방 서버로 다시 붙이기(화면이 받은 서버 주소로 재접속), socket.io 폴링 쓰면 고정 연결 필수
4. **접속 목록 공유** — `onlineUsers`를 Redis로 (2장 1·3번), 그 뒤 A3 옛 탭 끊기를 계정 채널로, 친구 목록 접속 상태(1-6)·공지 대상 맞추기
5. **방 코드 중복 막기** — Redis `SET NX` 예약 + 시작된 방 표시 같이 (2장 6·7번)
6. **요청 제한 옮기기** — `createRateLimiter`·비번 틀린 횟수·코드 입장 시도를 Redis 카운터로 (2장 10·24·25번)
7. 나머지 — 점검·금지어 다시 읽기 알림(27·28), 동시 접속 기록 서버 id(29), 지금 상황 합치기(30), 채팅 증거 읽기(26)
