# 관리자 페이지 기획 초안

## 한 줄 요약
관리자 서버를 따로 만들지 않고, 관리자 서버 기능 15개 전부를 게임 서버 안 팀원용 관리자 페이지로 넣고, 게임 안 문의 창도 만든다.

## 누가, 왜
- 누가: 관리자 대표·CTO(권한 나누기 없음) · 문의는 플레이어
- 왜: 관리자 쪽에서 관리자 서버 기능 15개가 많다고 함 → 기능은 안 줄이고, 그 부담을 게임 서버가 짐

## 쓰는 장면 (스토리의 뼈대)
1. 플레이어가 게임에서 신고 → 팀원이 채팅 증거 보고 정지
2. 플레이어가 게임 안 문의 창에 글 → 팀원이 답 → 플레이어 알림
3. 업데이트 전 → 점검 켜기 + 공지
4. 이상한 닉네임·채팅 → 금지어 추가

## 성공하면
- 팀원이 휴대폰으로도 신고 → 정지까지 몇 번 눌러 끝냄
- 정지한 사람이 바로 튕김, 문의 답이 플레이어 알림으로 뜸
- 관리자가 한 일이 전부 기록에 남음

## 제약
- PC·휴대폰 둘 다
- 보안: 클라우드플레어 Access(팀원 이메일만) + 우리 로그인(아이디·비번 + OTP 앱)
- Node 여러 개일 때 점검·금지어는 Node 전부에 반영

## 고른 방향 (버린 안과 이유)
- 게임 서버 안 관리자 페이지 ← 관리자 서버 따로(기능 많아 부담 · 밖에서 DB 직접 건드리는 위험: DB 문 밖에 열기, 장부·끊기·다시 읽기 규칙 두 번 지키기, 표 바뀌면 같이 깨짐, DB 비번 두 곳, 무거운 조회가 게임 느리게)
- 문 두 개 보안 ← 클라우드플레어만(설정 꺼지면 뚫림) · 우리 로그인만(로그인 페이지가 그대로 보임)
- 게임 안 문의 창 ← 디스코드 문의

## 숨은 가정 (확인할 것)
- 클라우드플레어 무료 Access로 팀원 수(50명 아래)가 충분함
- 관리자 주소는 게임과 다른 주소(예: admin.도메인)로 둠 — 설계 때 정함
- 문의를 담을 새 표가 필요함(DB 변경) — 설계 때 정함
- 이미 있는 표(신고·증거·금지어·점검·관리자 계정·관리자 기록)와 내부 API를 그대로 다시 씀

## 첫 버전 범위 (관리자 서버 15개 전부 + 문의)
- 팀원: 열기(로그인) · 첫 화면 · 신고 처리 · 문의 처리 · 회원 찾기·정지 풀기 · 점검 · 공지 · 금지어 · 관리자 기록 · 결제 관리·환불 · 상품 · 골드·다이아 주고 뺏기 · 쿠폰 · 통계 · 지난 판 결과 · 약관 버전 · 열린 방·판
- 플레이어: 문의 쓰기 · 답 보기

## 나중에
- 문의 사진 첨부

## 안 하는 것 (이유)
- 관리자 서버 따로: 그 부담을 게임 서버가 짐
- 디스코드 문의: 게임 안 문의 창으로 바꿈
- 권한 나누기: 팀원만 쓰니까 다 같은 권한
