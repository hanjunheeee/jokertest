# 관리자 페이지 경계 (단위 목록 · 단위끼리 약속)

- 단위 하나 = 스토리 한 단계를 실제로 쓸 수 있게 하는 서버 + 화면 + 시험 (세로로 자름)
- **에이전트 여럿이 동시에 만들게 파일이 안 겹치게** 나눔. 공용 파일(`backend/index.js`·`scripts/migrate-db.js`·`admin/index.js`·메뉴 표·`e2e/playwright.config.js`)은 뼈대가 미리 빈 자리까지 만들어 둠 → 다른 단위는 자기 파일만
- 만드는 순서는 unit-build 한 바퀴: 겉모양 → 시험 먼저(실패 확인) → 가장 작게 → 시험·경계 → 실제로 돌려 보기 → 설명·기록
- 시험 번호(AD-xxx) 뜻은 `테스트.md`, 상태는 `진행.md`

## 1. 순서와 묶음

```
0-1 DB·틀
 ├─ 0-2 인증·기록 ─┐
 └─ 0-3 화면 뼈대 ─┴─ 0-4 브라우저 시험 틀
                       │
       ┌───────────────┼───────────────┐            ← 묶음 1: 관리자 기본(요구사항 5개), 가장 먼저 끝냄
     꾸러미 1A        꾸러미 1B        꾸러미 1C
   1-1 회원 찾기     1-3 공지·결과     1-5 운영 현황
   1-2 제재          1-4 처리 이력
                       │
  ┌──────┬──────┬──────┼──────┬──────┬──────┬──────┐  ← 묶음 2: 나머지 병렬
  2A     2B     2C     2D     2E     2F     2G     2H
 신고    점검    점검   돈     보기   문의    문의   배포
 금지어  서버·   큰안내 (4)    (4)    서버·   창
        관리자  (플레이어)           관리자  (플레이어)
                       │
                     3-1 마무리 (전 경로 기록·막힘 검사)
```

| 꾸러미(에이전트 하나) | 단위 | 먼저 끝나야 할 것 |
|---|---|---|
| 0 (차례로) | 0-1 → 0-2·0-3(동시) → 0-4 | — |
| 1A 회원·제재 | 1-1 → 1-2 | 0 전부 |
| 1B 공지·이력 | 1-3 → 1-4 | 0 전부 |
| 1C 운영 현황 | 1-5 | 0 전부 |
| 2A 신고·금지어 | 2-1 · 2-5 | 묶음 1 (신고 처리가 1-2 정지 함수를 씀) |
| 2B 점검 서버·관리자 점검 화면 | 2-2 → 2-4 | 묶음 1 |
| 2C 점검 큰 안내(플레이어 화면) | 2-3 | 묶음 1 (약속만 보면 2B와 동시) |
| 2D 돈 | 2-6 · 2-7 · 2-8 · 2-9 | 묶음 1 (2-8은 1-1 회원 상세 자리에 붙음) |
| 2E 보기 | 2-10 · 2-11 · 2-12 · 2-13 | 묶음 1 |
| 2F 문의 서버·관리자 | 2-14 → 2-16 | 묶음 1 |
| 2G 문의 창(플레이어 화면) | 2-15 | 묶음 1 (약속만 보면 2F와 동시) |
| 2H 배포 | 2-17 | 0-3 (빌드 명령) — 묶음 1과 동시여도 됨 |
| 3 마무리 | 3-1 | 전부 |

## 2. 공통 약속 (모든 단위)

| 항목 | 약속 |
|---|---|
| 주소 | 서버 `/admin-api/<영역>` · 화면 `admin.<도메인>/<영역>` |
| 성공 응답 | `200 { ok: true, ...내용 }` (만들기는 `201`) |
| 실패 응답 | `{ ok: false, code, message }` — code는 대문자_밑줄, message는 쉬운 우리말(화면이 그대로 보여도 됨) |
| 공통 실패 | `404`(관리자 페이지 꺼짐) · `403 ADMIN_ACCESS_REQUIRED` · `503 ADMIN_ACCESS_UNAVAILABLE` · `401 ADMIN_LOGIN_REQUIRED` · `401 ADMIN_SESSION_EXPIRED` · `403 ADMIN_CSRF_FAILED` · `429 RATE_LIMITED` · `503 ADMIN_BUSY` · `503 ADMIN_QUERY_TIMEOUT` · `400 INVALID_INPUT { field }` · `500 ADMIN_INTERNAL` |
| 쓰기 머리글 | `X-Admin-Csrf: <csrfToken>` (adminClient가 붙임) |
| 백그라운드 | 자동 새로고침은 `X-Admin-Background: 1` |
| 시각 | ISO 글자, UTC (`2026-11-10T03:00:00.000Z`) → 화면이 한국 시각으로 |
| 목록 | `?before=<마지막 id>&limit=<1~50>` → `{ items, nextBefore }` (`nextBefore` null이면 끝), OFFSET 없음 |
| 요청 번호 | 돈·공지·문의 답 쓰기는 몸에 `requestId`(UUID) — 같은 번호 두 번이면 처음 결과 |
| 사유 | 정지·기간 바꾸기·해제·강제 종료·뺏기·환불은 `reason` 1~200자 필수 → 비면 `400 REASON_REQUIRED` |
| 기록 | 쓰기 서비스는 `audit.record({ req, action, targetType, targetId, before, after, reason }, { transaction })`를 같은 트랜잭션으로 |
| 조회 | 관리자 조회는 `queryQueue.run(fn)` 안에서, SQL에 `/*+ MAX_EXECUTION_TIME(3000) */` |
| 바깥 입력 검사 | 컨트롤러에서 한 번(모르는 칸 거절), 서비스는 다시 안 봄 |
| 바꿀 땐 더하기만 | 기존 응답·사건 모양은 안 바꾸고 칸만 더함 |
