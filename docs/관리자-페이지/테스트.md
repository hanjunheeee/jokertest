# 관리자 페이지 테스트

- 겉으로 보이는 결과만 시험: 응답·오류 code·DB에 남은 것·소켓으로 온 것·화면에 보이는 것
- 스토리 단계마다 **시험 코드(서버·화면) + 브라우저 시험**이 둘 다 있음. 확인 기준·잘못되면 줄마다 최소 하나
- 단위마다 "먼저 쓸 시험"을 먼저 쓰고 실패를 본 뒤 만듦(unit-build). 처음부터 통과하는 새 기능 시험은 고침
- 가짜만 보는 시험 금지: 서버 통합은 진짜 시험 DB, 클라우드플레어 확인은 진짜 서명 검증(가짜 키로 서명), Node 여러 개는 `memoryCluster`(진짜 bus·rpc 코드)

## 1. 종류와 돌리는 법

| 종류 | 무엇 | 어디·어떻게 |
|---|---|---|
| 서버 단위 | DB 없이 함수·경로(가짜 시계·메모리 클러스터) | `backend/tests/admin/**` · `cd backend && npm test` |
| 서버 통합 | 진짜 시험 DB(`.env.testdb`) + 경로 | `cd backend && npm run test:with-db -- tests/admin` |
| 화면 단위 | jsdom + Testing Library | `frontend/tests/admin/**`·`frontend/tests/domains/{maintenance,inquiry}/**` · `cd frontend && npm test` |
| 브라우저 | Playwright, 기존 `e2e/` 틀 | `cd e2e && npx playwright test --project=admin` (프로젝트: `admin` 1280×800 · `admin-phone` 375×812 · `desktop` · `mobile` · `serial`(서버 전체에 걸리는 것, 하나씩) · Node 2개는 `E2E_NODES=2`) |
| 설정 확인 | 빌드·nginx·도커 결과 검사 | `node frontend/scripts/verify-admin-split.mjs`, `bash deploy/scripts/nginx-nodes-check.sh 2` |
| 손 확인 | 운영 배포 뒤 클라우드플레어·계정 | `docs/배포_설정.md` 관리자 장 확인 줄 |

- 클라우드플레어 확인: 서버 시험은 시험 안에서 RSA 키를 만들어 공개키를 작은 서버로 주고 같은 키로 서명한 표를 머리글에 넣음(`ADMIN_ACCESS_CERTS_URL`). 브라우저 시험은 `serve-front.js admin`이 쿠키 `e2e_access_email`이 있을 때만 서명한 표를 붙임. 운영에선 시험 값 무시
- 관리자 계정: 서버 시험은 `adminTestApp`, 브라우저 시험은 `e2e/helpers/adminAccounts.js`(`createAdmin`·`otpNow`·`loginAsAdmin`)
- 돈 시험 공통 확인: 끝나고 **지갑 잔액 = 그 사람 장부 amount 합**, 장부 참조 id 겹침 없음

## 4. 돈 시험 (장부 일치)

| 확인 | 번호 |
