# 관리자 페이지 스토리

주인공: 관리자(대표·CTO, 관리자 페이지 쓰는 사람) · 플레이어(문의 쓰는 사람)
표시: [첫 버전] [나중에] [안 함]

## 팀원 쪽

### 1. 관리자 페이지 열기 [첫 버전]
- 사용자: 관리자 주소를 PC나 휴대폰으로 연다 → 클라우드플레어가 보낸 메일 번호 입력 → 아이디·비번 + OTP 앱 번호 입력
- 프로그램: 관리자(대표·CTO) 이메일만 통과시키고, 우리 로그인을 확인한다
- 확인 기준: 관리자 이메일이 아니면 페이지 자체가 안 열림 · 관리자 아닌 계정은 관리자 길(서버 주소) 전부 막힘 · 관리자는 두 번 로그인 뒤 첫 화면
- 잘못되면: 비번·OTP 여러 번 틀리면 잠깐 막힘 · 가만히 있으면 자동 로그아웃 · 실패도 기록
- 근거: 보안 A안(문 두 개) · 요구사항 1(대표·CTO 로그인, 관리자 외 접근 제한)

### 2. 첫 화면에서 할 일 보기 [첫 버전]
- 사용자: 첫 화면을 본다
- 프로그램: **전체 가입자 수 · 오늘 총 판 수 · 지금 진행 중 판 수** · 지금 접속 수 · 새 신고 수 · 새 문의 수 · 점검 켜짐 여부를 보여 준다
- 확인 기준: 처리 안 된 신고·문의가 바로 보임
- 잘못되면: 게임 서버 숫자를 못 받으면 "지금 숫자 못 받음"만 표시, 나머지는 그대로
- 근거: 첫 주 장면 — 신고·문의가 오면 연다 · 요구사항 2(운영 현황)

### 3. 신고 처리 [첫 버전]
- 사용자: 신고 목록 → 하나 누름 → 사유·메모·그 판 채팅 증거를 읽음 → "정지"(기간·사유) 또는 "기각"
- 프로그램: 정지면 정지 기록 넣고 그 사람을 바로 끊음 · 신고에 처리한 사람·시각 남김
- 확인 기준: 정지한 사람이 게임에서 바로 튕기고 다시 못 들어옴 · 신고가 "처리됨"으로 바뀜
- 잘못되면: 이미 다른 팀원이 처리한 신고면 "이미 처리됨" · 채팅 증거가 없으면 "증거 없음" 표시
- 근거: 신고는 게임에서 누르면 알아서 들어옴(사용자 결정)

### 4. 문의 처리 [첫 버전]
- 사용자: 문의 목록 → 하나 누름 → 내용 읽고 답 쓰기 → "답 보내기"
- 프로그램: 답을 저장하고, 플레이어에게 게임 알림(종)을 보냄 · 문의가 "답함"으로 바뀜
- 확인 기준: 플레이어의 "내 문의 목록"에 답이 보이고 알림이 뜸
- 잘못되면: 플레이어가 지금 접속 안 했으면 다음 접속 때 알림이 보임
- 근거: 문의는 게임 안 창으로(사용자 결정), 답은 내 문의 목록 + 알림(사용자 결정)

### 5. 회원 찾기·제재 [첫 버전]
- 사용자: **UUID나 닉네임**(또는 이메일)으로 찾기 → 회원 하나 누름 → "강제 접속 종료" / "기간 정지"(기간·사유) / "영구 정지"(사유) / "제재 해제"(사유)
- 프로그램: 가입일 · 상태(접속 중 여부 포함) · 정지 기록 · 받은 신고 · 최근 로그인 기록을 보여 줌 · 정지면 기록 넣고 바로 끊음 · 해제도 사유와 같이 기록
- 확인 기준: 강제 종료하면 바로 튕김 · 기간 정지는 기간 끝나면 다시 들어옴 · 영구 정지는 계속 못 들어옴 · 해제하면 바로 다시 들어옴 · 정지·해제 사유가 남음
- 잘못되면: 못 찾으면 "없음" · 탈퇴한 회원은 "탈퇴함" 표시 · 이미 정지된 사람 또 정지하면 "이미 정지 중"(기간 바꾸기로 안내) · 사유 비면 막음
- 근거: 신고 처리하다 그 사람 예전 기록을 봐야 함 · 요구사항 4(회원 관리 및 제재)

### 6. 점검 켜고 끄기 [첫 버전]
- 사용자: 안내 문구 · 시작 시각 · 끝 안내 시각 입력 → "점검 켜기" (끝나면 "점검 끄기")
- 프로그램: 점검 상태를 저장하고 게임 서버(Node 전부)에 다시 읽게 함
- 확인 기준: 시작 시각 뒤 새 방 만들기·입장이 막히고 안내 문구가 뜸 · **시작 시각이 되면 진행 중 판은 강제로 끝남(무효: 승패·보상·벌점 없음, 판 결과엔 "점검으로 끝남" 표시) · 대기방도 닫히고 로비로** · 플레이어에게 "점검으로 판이 끝났어요" 안내
- 잘못되면: Node 하나라도 못 받으면 "n2 반영 안 됨"처럼 알려 줌
- 근거: 첫 주 장면 — 업데이트 전에 점검

### 7. 공지 보내기 [첫 버전]
- 사용자: 제목·본문 입력 → "접속 중 전체" 또는 "고른 사람" → 보내기
- 프로그램: 알림으로 저장하고 접속 중이면 바로 보여 줌
- 확인 기준: 플레이어 알림(종)에 공지가 뜸 · **보낸 뒤 결과(받은 사람 수·실패 수·중복 수)가 화면에 보임**
- 잘못되면: 같은 공지를 두 번 눌러도 한 번만 감 · 고른 사람 중 없는 UUID는 실패 수로 보임
- 근거: 첫 주 장면 — 점검 전 공지 · 요구사항 3(전체·특정 회원 공지, 발송 결과 확인)

### 8. 금지어 넣기·빼기 [첫 버전]
- 사용자: 금지어 목록 → 단어 넣기 / 끄기
- 프로그램: 저장하고 게임 서버(Node 전부)에 다시 읽게 함
- 확인 기준: 그 단어가 채팅에서 `*`로 가려지고 닉네임으로 못 씀
- 잘못되면: 이미 있는 단어면 "이미 있음"
- 근거: 첫 주 장면 — 이상한 닉네임·채팅

### 9. 관리자 기록 보기 [첫 버전]
- 사용자: 기록 목록을 본다 · **"공지 발송 이력" / "제재·해제 이력"** 칸으로 골라 보기 · 회원으로 찾기
- 프로그램: 누가 · 언제 · 무엇을(정지·해제·공지·점검 등) · 사유 · 전후 값을 보여 줌
- 확인 기준: 3~8·10~16에서 한 일이 전부 남아 있음 · 공지 이력엔 제목·대상·결과 수 · 제재 이력엔 대상·종류(기간/영구/해제/강제 종료)·사유
- 근거: 보안 A안 — 관리자 행동 전부 기록 · 요구사항 5(관리자 처리 이력)

## 플레이어 쪽

### P1. 문의 쓰기 [첫 버전]
- 사용자: 게임 안 "문의" 창 → 종류(버그·계정·기타) · 제목 · 내용 → 보내기
- 프로그램: 저장하고 관리자 페이지 문의 목록에 넣음
- 확인 기준: 내 문의 목록에 "답 기다림"으로 보임
- 잘못되면: 너무 자주 쓰면 잠깐 막힘 · 금지어는 가려짐
- 근거: 문의는 게임 안 창으로(사용자 결정)

### P2. 답 보기 [첫 버전]
- 사용자: 알림(종)을 누르거나 내 문의 목록을 연다
- 프로그램: 팀원 답을 보여 줌
- 확인 기준: 답이 보이고 "답함"으로 바뀜
- 근거: 답은 내 문의 목록 + 알림(사용자 결정)

### 10. 결제 관리·환불 [첫 버전]
- 사용자: 충전 주문 목록 → 찾기(회원·기간·상태) → 주문 하나 → "환불"
- 프로그램: 주문을 환불 상태로 바꾸고 장부 규칙대로 다이아를 되돌림
- 확인 기준: 환불한 주문으로 다시 지급 안 됨 · 그 사람 다이아가 맞게 줄어듦
- 잘못되면: 이미 쓴 다이아라 모자라면 멈추고 알림(마이너스로 안 만듦) · 결제 회사 쪽 환불은 결제 회사 화면에서
- 근거: 관리자 서버 기능 전부 게임 서버로(사용자 결정)

### 11. 상품 관리 [첫 버전]
- 사용자: 다이아·골드 상품 목록 → 값·수량·판매 켜기/끄기 고침
- 프로그램: 저장하고 상점에 바로 반영
- 확인 기준: 상점 화면 값이 바뀜
- 잘못되면: 진행 중인 결제는 주문 때 값 그대로
- 근거: 같음

### 12. 골드·다이아 주고 뺏기 [첫 버전]
- 사용자: 회원 하나 → 금액·사유 입력 → 주기 / 뺏기
- 프로그램: 장부에 남기고 지갑 바꿈
- 확인 기준: 그 사람 지갑과 장부가 맞음
- 잘못되면: 뺏을 게 모자라면 멈춤
- 근거: 같음 (보상 문의 처리)

### 13. 쿠폰·이벤트 [첫 버전]
- 사용자: 쿠폰 코드 · 보상 · 횟수 · 기간 입력 → 만들기 / 끄기 · 쓴 사람 수 보기
- 프로그램: 저장 (플레이어 쿠폰 입력은 이미 있음)
- 확인 기준: 플레이어가 코드 넣으면 보상 받음
- 근거: 같음

### 14. 통계 [첫 버전]
- 사용자: 기간 고름
- 프로그램: 가입 수 · 접속 수 · 판 수 · 매출을 그래프로
- 확인 기준: 숫자가 DB와 맞음
- 근거: 같음

### 15. 지난 판 결과 보기 [첫 버전]
- 사용자: 판 찾기(회원·날짜) → 판 하나
- 프로그램: 참가자 · 직업 · 승패 · 시간 보여 줌
- 근거: 같음 (신고 처리 때도 씀)

### 16. 약관 버전 [첫 버전]
- 사용자: 새 약관 본문·시행일 넣기
- 프로그램: 새 버전 저장, 플레이어가 다음 접속 때 다시 동의
- 근거: 같음

### 17. 열린 방·판 보기 [첫 버전]
- 사용자: 목록을 본다
- 프로그램: 지금 대기방·진행 판(Node 전부 합침)을 보여 줌
- 근거: 같음

## 나중에
- 문의에 사진 붙이기

## 안 함
- 관리자 서버 따로 만들기 (게임 서버 안으로 함)
- 디스코드로 문의 받기 (게임 안 문의 창으로 함)
- 권한 나누기 (팀원만 쓰니까 다 같은 권한)
