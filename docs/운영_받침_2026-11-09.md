# 운영 받침 (게임 서버 쪽) — 2026-11-09

관리자 서버는 따로 운영하고 MySQL은 같이 씀. 게임 서버는 표 + 내부 API + 그걸 따르는 게임 동작만 제공함. 관리자 화면·고객 문의(디스코드)는 여기 없음.

## 1. 표 (마이그레이션 0024 · 0025)

| 표 | 쓰는 쪽 | 핵심 칸 |
|---|---|---|
| `reports` | 게임 서버 접수 · 관리자 서버 처리 | reporter_id, target_id, game_id, reason_code(ABUSE·SPAM·GRIEFING·CHEATING·NICKNAME·ETC), memo, status(OPEN→RESOLVED·DISMISSED), handled_by_admin_id, handled_at · 유일 (reporter_id, target_id, game_id) |
| `report_chat_evidence` | 게임 서버 저장 · 관리자 서버 읽기 | report_id, game_id, messages(JSON 원문 `[{at, channel, senderUuid, nickname, text}]`), saved_at(90일 정리 인덱스) |
| `banned_words` | 관리자 서버 쓰기 · 게임 서버 읽기 | word(유일), is_active |
| `maintenance_state` | 관리자 서버 쓰기 · 게임 서버 읽기 | id=1 한 줄: is_enabled, message, starts_at(지나야 막음), ends_at(안내용, 자동 꺼짐 없음) |
| `admin_users` | 관리자 서버만 | id(UUID, `user_bans.banned_by`에 그대로 넣기), login_id, password_hash, role(SUPER·OPERATOR·VIEWER), totp_secret(암호화해서), is_active |
| `admin_audit_logs` | 관리자 서버만 | admin_id, action, target_type/id, before_value/after_value(JSON), ip |
| `coupons` | 관리자 서버 쓰기 · 게임 서버 사용 | code(대문자·숫자·- 4~40자, 유일), reward_type(GOLD·DIAMOND), reward_amount, max_uses(null=무제한), used_count, starts_at, ends_at, is_active |
| `coupon_redemptions` | 게임 서버 | id(UUID = 장부 참조 `coupon:<id>`), coupon_id, user_id · 유일 (coupon_id, user_id) |

0025: `users.created_at` · `game_results.ended_at` · `economy_topup_orders.created_at` 기간 조회 인덱스.
충전 주문 상태에 `REFUNDED` 더함 (관리자 서버가 환불 때 넣음, 게임 서버는 다시 확인·지급 안 하고 `409 ORDER_REFUNDED`).
약관 버전·동의 표는 회원 기능 쪽(0026) 몫.

## 2. 내부 API (`/internal/*`)

- 머리글 `X-Internal-Key` = 환경값 `INTERNAL_API_KEY`(32자 이상). 없거나 짧으면 경로 전체 꺼짐(404). 틀리면 401.
- 해시 뒤 상수 시간 비교, IP마다 1분 120번(틀린 키도 셈), 응답 `Cache-Control: no-store`, 키는 로그에 안 남김.

| 경로 | 하는 일 | 응답 |
|---|---|---|
| `POST /internal/users/:uuid/disconnect` | 정지·비활성 반영 즉시 끊기. DB 다시 봐서 code 고름: 정지 `ACCOUNT_BANNED` · 상태 ACTIVE 아님 `ACCOUNT_INACTIVE`(둘 다 세션도 내림) · 그 밖 `ADMIN_DISCONNECT` | `{ uuid, code, disconnected }` |
| `POST /internal/announcements` | `{ announcementId, title(≤120), body(≤500), target: 'online' \| 'users', userUuids? }` → 시스템 알림 저장 + 접속 중이면 바로 보냄. 같은 announcementId는 한 사람 한 번 | `{ recipientCount, created, duplicated, failed }` |
| `POST /internal/maintenance/reload` | 점검 한 줄 다시 읽기 | `{ maintenance }` |
| `POST /internal/banned-words/reload` | 켜진 금지어 다시 읽기 | `{ count }` |
| `GET /internal/live` | 대기방(방 id·코드·공개 여부·인원·최대) · 진행 판(판·방 id·코드·인원·산 사람 수·단계·날짜·시작 시각) · 접속 수 · 점검 상태. 명단·닉네임 없음 | `{ onlineCount, roomCount, gameCount, rooms, games, maintenance }` |

## 3. 게임 동작

- **정지 즉시 반영**: 소켓 주기 검사(5초)·사건 검사·HTTP 요청마다 정지·계정 상태(ACTIVE 아님) 확인 → 세션 내리고 끊음. 소켓 `force_disconnect` code는 `ACCOUNT_BANNED`·`ACCOUNT_INACTIVE`(그 밖 `SESSION_EXPIRED`). refresh도 상태 ACTIVE 아니면 `403 ACCOUNT_INACTIVE`. 바로 끊으려면 위 disconnect API.
- **점검 모드**: 켜짐(+시작 시각 지남)이면 방 만들기·게임 시작·코드 입장·자동 매칭 거절 (`code: 'MAINTENANCE'`, `message`, `endsAt`). 진행 중 판·방 안 행동은 그대로. 서버 시작 때 한 번 + reload 때 읽음.
- **쿠폰** `POST /economy/coupons/redeem` `{ code }` (로그인, 1분 10번): 쿠폰 줄 잠금 → 사용 중지·기간·한 사람 한 번·횟수 → 사용 기록 + 쓴 횟수 + 장부 지급(`COUPON_REWARD`) 한 트랜잭션. 오류 code: `INVALID_COUPON_CODE` `COUPON_NOT_FOUND` `COUPON_INACTIVE` `COUPON_NOT_STARTED` `COUPON_EXPIRED` `COUPON_ALREADY_REDEEMED` `COUPON_EXHAUSTED` `COUPON_MISCONFIGURED`.
- **신고** `POST /reports` `{ targetUuid, gameId, reasonCode, memo? }` (로그인, 1분 5번): 자기 자신 `SELF_REPORT` · 둘이 같이 한 판 아니면 `GAME_NOT_FOUND`(진행 판 메모리 → 저장된 판 결과) · 같은 판 같은 대상 `DUPLICATE_REPORT`. 접수 때 그 판 채팅 원문을 `report_chat_evidence`에 저장(실패해도 신고는 남음).
- **판 채팅 보관**: 낮·재판·죽은 사람·밤 같은 직업 채팅 원문을 판마다 메모리에 (판 500줄·300판 상한, 판 끝 뒤 10분, 끝 표시 없이 3시간 조용하면 버림).
- **금지어**: 채팅은 받는 쪽에 같은 길이 `*`로 가려서 보냄(보관은 원문). 닉네임은 이메일 가입·소셜 가입·닉네임 바꾸기 때 `400 NICKNAME_BANNED_WORD`. 금지어 표가 비면 아무것도 안 막음.

## 4. 환경값

- `INTERNAL_API_KEY` (32자 이상 무작위, 게임 서버·관리자 서버 같은 값). `.env.example`엔 이름만.

## 5. 관리자 서버가 할 일

- 정지: `user_bans` 줄 넣기(`banned_by` = admin_users.id) → `POST /internal/users/:uuid/disconnect`. 비활성: `users.status` 바꾸기 → 같은 API.
- 점검: `maintenance_state` id 1 고치기 → `POST /internal/maintenance/reload`. 서버 여러 대면 대마다 부르기.
- 금지어: `banned_words` 고치기 → `POST /internal/banned-words/reload`.
- 공지: announcementId를 관리자 서버가 만들어 보냄(같은 id 다시 보내도 중복 안 생김).
- 신고 처리: `reports.status`·`handled_by_admin_id`·`handled_at` 고치기, 증거는 `report_chat_evidence` 읽기.
- 증거 90일 정리: `services/ops/evidenceRetention.js`의 `purgeExpiredChatEvidence()` 하루 한 번 (게임 서버 index.js엔 예약 안 붙임 — 관리자 서버 작업이나 cron으로).
- 쿠폰 만들기: `coupons` 줄 넣기(코드는 대문자). 환불: `economy_topup_orders.status = 'REFUNDED'` + 장부 되돌리기는 관리자 서버가 장부 규칙대로.
- 모든 관리자 행동은 `admin_audit_logs`에 남기기.
