## 2. 맥북에서 할 일 순서

이 장은 번호 순서대로 하나씩 하면 됨. 줄마다 "명령"과 "되면 보이는 것"이 있음. 막히면 8장(확인 필요)을 먼저 봄.

### 2-1. 코드 받기

```bash
git clone https://github.com/hanjunheeee/jokertest.git jokertest
cd jokertest
git checkout fix/scenario-2026-11-16
git log --oneline -3
```

- 되면 보이는 것: 맨 위 커밋이 이 글 커밋이거나 `387b57e0`
- 폴더 이름은 `jokertest`로 함: 시험 DB 컨테이너(Docker 안 작은 서버 상자) 이름이 `jokertest-db-1`이 되려면 폴더 이름이 `jokertest`여야 함 (도구가 이 이름을 씀)
- 다른 폴더 이름을 쓰면 `docker compose -p jokertest ...`로 이름을 맞춤 (맥에서 안 돌려 봄)
- **main에는 절대 안 합침** (사용자 결정). 이 브랜치만 씀

### 2-2. Node 깔기

- Node 22.12 이상 (`.nvmrc`는 22, `backend/package.json`의 engines는 `>=22.12`)
- 깔기 방법(nvm·공식 설치 파일 등)은 고름
- 되면 보이는 것: `node -v` → `v22.…`

### 2-3. 패키지 설치 (npm)

```bash
(cd backend && npm ci)
(cd frontend && npm ci)
(cd frontend-mobile && npm ci)
(cd e2e && npm ci)
```

- 네 폴더 모두 `package-lock.json`이 있음. `npm ci`가 안 맞으면 `npm install`로 바꿈 (`e2e/README.md`는 `npm install`로 적음)
- 순서 이유: e2e(브라우저로 누르는 시험 폴더) 도우미가 `backend/node_modules`(DB 연결·Redis 연결)를 빌려 쓰고, 화면 서버는 `frontend/node_modules`·`frontend-mobile/node_modules`의 vite(화면 빌드 도구)를 씀 → backend·frontend가 e2e보다 먼저
- 저장소 맨 위 `node_modules`는 이미 git에 올라가 있음(순수 JS 묶음) → 맨 위에서 따로 안 깔아도 됨. `frontend-mobile/package.json`이 `"mmc": "file:.."`(맨 위 폴더를 가리킴)를 가져서 설치가 막히면 맨 위에서 `npm install`을 먼저 함 (맥에서 안 돌려 봄)
- 되면 보이는 것: 네 폴더 모두 `node_modules`가 생기고 오류 없이 끝남

### 2-4. 환경값 파일(`.env`) 옮기기

이 줄은 비밀값이 든 파일이라 git에 없음. **값은 글·채팅에 적지 않음**. 눈 확인에 꼭 필요한 건 맨 위 `.env` 하나뿐임.

| 파일 | 눈 확인에 필요한가 | 얻는 법 |
|---|---|---|
| `.env` (맨 위) | **필요** (DB 상자를 켤 때 `MYSQL_*` 값을 읽음) | 윈도우 것을 옮기거나, 새 DB면 `cp .env.example .env`(본보기 값만 들어 있음, 눈 확인엔 이걸로 됨 — 맥에서 안 돌려 봄) |
| `e2e/.env.e2e` | 필요하나 **저절로 만들어짐** | 2-7의 `npm run db:setup`이 무작위로 만듦. 옮기지 않음 |
| `backend/.env` | 안 필요 (선택) | 시험 백엔드는 이 파일을 안 읽음. 단 `db:setup`이 여기서 토스 시험 키(`TOSS_TEST_*` 이름 셋)만 옮겨 적음 → 상점 장면(가-16·17)에 필요한지는 8장 |
| `backend/.env.testdb` | 안 필요 | 진짜 DB 시험을 돌릴 때만, `npm run test:db:setup`이 새로 만듦 |
| `backend/.env.test` | 이미 git에 있음 | 옮기지 않음 |
| `frontend/.env`·`frontend-mobile/.env` | 안 필요 | 눈 확인용 화면 빌드는 이 파일을 안 읽음(`envDir:false`). 맥에서 개발 서버(5173·5174)를 따로 쓸 때만 옮김 |

- 각 폴더 본보기는 `.env.example` (이름·설명만 들어 있음, git에 있음)
- 되면 보이는 것: `ls -a`에 맨 위 `.env`가 보임

### 2-5. DB 켜기 (Docker)

```bash

docker inspect -f '{{.State.Health.Status}}' jokertest-db-1
```

| 자리 | 지금 | 맥에서 바꿀 것 (제안, 맥에서 안 돌려 봄) |
|---|---|---|
| `run.sh:19` | CPU 재기를 PowerShell로 함 | `top -l 2 -n 0`의 마지막 `CPU usage` 줄에서 idle(놀고 있는 몫)을 빼 계산. CPU 기록이 필요 없으면 `echo "$(date +%H:%M:%S) 0"`로 대신 |

## 3. 눈 확인 도구 쓰는 법 (짧게)

## 7. 지켜야 하는 규칙

이 장은 맥북 쪽에서 일할 때도 같은 규칙을 지키라고 모음.

- git
  - **main에 합치지 않음**. force push(밀어 덮어쓰기)·기록 다시 쓰기·`git add .`·stash(임시 치우기)·reset(되돌리기) 안 함
  - 커밋은 내 경로만: `git commit -m "…" -- <경로>` (여럿이 일하면 남의 스테이징이 섞임)
  - 지울 땐 휴지통으로 (영구 삭제 안 함)
- DB·코드
  - 기존 마이그레이션 `0001`~`0034` 안 고침 (새 번호만)
  - `joker`·`joker_realgame` DB 안 건드림. 눈 확인·브라우저 시험은 `joker_e2e`만, 백엔드 DB 시험은 `npm run test:db:setup`이 만드는 전용 DB만
  - 진짜 메일·결제·바깥 요청 안 함 (브라우저 시험 쪽에서 광고·토스 주소는 막아 둠)
  - `.env` 값을 글·채팅·로그에 안 찍음
- 시험
  - 브라우저 시험과 DB 시험은 같이 안 돌림 (시간 초과남). 하나만 돌리고 잠금(`tools/시험도구/with-lock.sh e2e|testdb <명령>`)을 걸어 둠
  - 시험은 다 만든 뒤 한 번에 돌리고, 실패는 모아 적은 뒤 한 번에 고침
  - 손대지 않는 파일: 저장소 맨 위 점 폴더 안의 실행 설정 `launch.json`, `docs/known-issues.md`
- 말투·일하기
  - 채팅·문서 모두 한국어, 쉬운 말, 개조식(~함/~음/~기). 개발 용어는 지우지 말고 바로 뒤 괄호에 우리말
  - 일은 잘게 나눠 맡김. 한 단계 끝나면 결과를 알리고 다음으로 감
  - 의도된 것(버그 아님): 인원 5~10명, 자동(랜덤) 매칭은 일부러 잠가 둠

7. `frontend-mobile`의 `"mmc": "file:.."` 때문에 설치 순서가 필요한지 (맨 위 `node_modules`가 git에 올라와 있음)

9. 바-05·09·26·27을 한 판 줄로 엮을 수 있는지
10. 목록의 "들어가는 법 확인 필요" 11줄: 가-07·09·15·16·17, 나-04, 다-04, 라-05, 바-19·26·27
