## 2026-11-10 시간대 버그 — SQL에 날짜를 넘기면 9시간 어긋남

- 증상: 진짜 DB 시험에서 `sequelize.query` 자리 값(`?`·`:이름`)에 `Date`를 넣으면 9시간 어긋나게 저장·비교됨(관리자 0-1·1-5가 따로 봄). 소켓 세션 확인 묶음 질의(`repositories/user/sessionCheck.js`)도 같은 모양 → 한국 시간대 서버에선 정지 끝나기 전 마지막 9시간 동안 소켓 길이 정지를 못 막고, 9시간 안에 시작할 예약 정지는 미리 막음(http 길은 모델이라 맞음, 두 길 판정이 갈림)
- 원인: sequelize 6.37.8 raw 질의 `replacements`가 값 바꿀 때 시간대 설정을 안 넘김(`node_modules/sequelize/lib/utils/sql.js` `escape(값, undefined, …)`) → `Date`를 Node 프로세스 시간대(이 PC 한국) 글자로 바꿈. 모델 쓰기·읽기와 DB 연결(`SET time_zone='+00:00'`)은 sequelize 기본 `timezone: '+00:00'`(UTC)라 맞음. 처음으로 잘못된 결정 = 부르는 쪽이 raw 질의 replacements에 `Date`를 그대로 넘긴 것 (설정은 맞음)
  - 확인: 한국 시간대에서 `2026-11-10T01:00:00Z` → replacements `'2026-11-10 10:00:00'`, 모델 escape `'2026-11-10 01:00:00'`
  - 설정으로 안 고친 이유: `timezone: '+09:00'`로 바꾸면 모델 쓰기·연결 시간대가 바뀌어 이미 저장된 UTC 값 해석이 9시간 달라짐. `process.env.TZ='UTC'`는 로그·지역 시각 쓰는 곳 전부 바뀜
  - 운영 서버(Docker node 이미지, TZ 안 넣음 = UTC)에선 안 드러남, 이 PC·한국 시간대 서버에서만 드러남
- 고친 곳: `backend/repositories/user/sessionCheck.js` — `now: new Date()` → `now: toUtcSqlText(new Date())` (UTC 글자로 직접 넘김)

## 2026-11-10 다른 Node 소켓 정지 안내가 "세션 만료"로 뜸

- 증상: 관리자 1A 보고. 관리자 정지·비활성을 n1이 받고 플레이어가 n2에 붙어 있으면, 튕김·다시 로그인 막힘은 맞는데 플레이어 화면 첫 안내가 "정지된 계정" 대신 "세션이 만료되었습니다. 다시 로그인해주세요."
- 처음 짐작(안내 `force_disconnect`와 끊기가 어댑터 다른 길로 가서 순서 뒤집힘)은 아님
  - redis-adapter 8.3.0: 원격 소켓 `emit`은 방송 채널, `disconnect`는 요청 채널이지만 같은 보내기 연결·같은 받기 연결이라 Redis가 보낸 순서대로 줌, 받는 Node는 둘 다 받자마자 처리 → 순서 맞음
  - 확인: 진짜 Redis Node 둘에서 관리자 끊기(세션 안 내림) 5번 모두 첫 안내 ADMIN_DISCONNECT
