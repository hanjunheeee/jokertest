# F31 회원가입 이메일 인증

## 승인 및 기준
2026-09-13 사용자가 추가 구현 및 기존 배치 F28 이전 편성을 승인했다. 선행 F29 완료 후 F30→F31→F32 순서로 구현한다.

## 구현 요구사항

- 신규 이메일 회원가입은 메일 소유 확인 후 완료한다. 인증번호 발송→확인→일회용 가입 증명→가입 제출. 주소 변경 시 재인증한다.
- 기존 계정은 추가 인증 강제 없이 이용을 유지한다. 실제 미인증 계정을 email_verified=true로 허위 이관하지 않는다.
- Google/Discord는 서버가 신뢰할 수 있는 제공자 응답에서 이메일 인증을 확인하면 추가 메일 인증을 생략한다. 확인되지 않은 이메일/미제공 이메일은 자체 메일 인증을 적용한다. 클라이언트 주장으로 우회할 수 없다.
- 위임된 초깃값:6자리,10분 유효,재발송60초,오입력5회,재발송 시 이전 번호 무효. 이메일당5회/시간·10회/일,IP당30회/시간·100회/일. 가입 증명10분,서버 설정으로 운영 조절.
- 서버는 이메일·목적·만료·시도·소비 여부를 관리한다. 번호는 서버 비밀값을 이용한 검증값으로 저장하고 원문/증명은 로그에 노출하지 않는다. 가입 증명 소비·계정 생성·기본 지급은 같은 DB 트랜잭션으로 단일 처리한다.
- F29와 메일 전송 기반을 공유하되 비밀번호 재설정 증명과 가입 증명을 목적별로 격리한다. 기존 세션/소셜 연결 정책을 훼손하지 않는다.
- 인수: 실제 메일 발송·수신·Chrome 가입,직접 API 우회 거부,만료/오입력/재발송/주소 변경,동시 소비 단일 가입,기본 지급 회귀,기존 계정 로그인 및 소셜 정책. 메일 서비스·발신 주소·테스트 수신함 미준비는 명시하고 실제 발송 PASS를 만들지 않는다.

## 책임 경계
이 작업에 배정된 기능만 구현하며 기존 완료 기능과 데이터는 보존한다. docs/requirements/2026-09-13-additional-execution-approved.md의 사용자 확정이 이전 초안을 대체한다. 기존 UI 재사용,실제 서버 판정,계정 격리,멱등 처리 및 정상 계획·코드 심사를 유지한다. DB는 승인된 pluto_f01_20260909_al 및 _restore_check만 사용한다. 운영 DB/볼륨 초기화 금지.

## 완료 조건
배정된 모든 기능의 실제 변경·테스트·빌드·격리 DB·외부 Chrome 및 정상 독립 심사와 병합을 확인한다. 실제 메일/결제 설정·상품 정책이 없으면 독립 구현을 진행하고 해당 인수는 미완료로 남긴다. 모의 검증을 실제 외부 연동으로 바꾸지 않는다. F28 최종 통합 인수에 증거와 미검증을 넘긴다.
