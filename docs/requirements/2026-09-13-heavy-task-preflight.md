# F20 이후 재작업 감소를 위한 사전 점검

2026-09-13 사용자 요청에 따른 운영 보강. 기존 배치 순서·요구 범위·독립 심사·DB 보호·900초 전체 검증 제한을 유지한다. 이 문서는 새 자동 검사 엔진이 아니라 계획/구현 작업 지시와 운영자 확인 기준이다. 체크 표시나 ready 선언만으로 검증 완료를 인정하지 않는다.

## 구현 전 실제로 확정할 것

각 인수 조건을 다음 한 줄에 연결한다: 기존 실제 파일/함수 → 권한 및 상태의 서버 책임자 → 입력/저장/이벤트 → 실제 소비 화면 → 실패를 재현하는 시험 → Chrome 시나리오. 그래프 검색과 실제 소스를 대조하고, 미정 심볼·존재하지 않는 기능을 구현 위치로 단정하지 않는다.

조건별 상태 전이 표에 시작 상태, 입력, 최종 저장 상태, 허용 수신자, 다음 타이머, 재시도 결과를 적는다. 반드시 해당 기능에 관련되는 다음 교차 상황을 선택하고 구체적 재현 순서를 정한다:

- 오래된 조회 응답이 새 변경보다 늦게 도착함.
- 처리 중 계정 A→B→A, 새로고침, 연결 교체, 방 이동.
- 서버 커밋 후 응답 유실, 동일 요청 재시도, 종료 후 새로운 요청.
- 시작/퇴장/추방/강제 종료와 정상 종료의 경합.
- 실패/시간 초과 뒤 늦게 완료된 작업이 새 작업의 잠금·소속·타이머를 훼손함.

관련 없는 경우는 이유를 적고 불필요한 시험을 늘리지 않는다. 계획의 확정 정책과 구현에서 새로 고른 세부 동작을 구분한다. 모호한 연결은 공식 계획 단계에서 해소하고 이미 승인된 정상 구현/검증 작업은 별도 허가 대기로 돌리지 않는다.

## 구현과 검증 순서

1. 관련 실패를 재현하는 작고 의미 있는 회귀 시험을 먼저 만든다. 기존 코드에서 실제 실패한 이유와 새 구현에서 통과한 근거를 남긴다. 신기능이면 계약 시험의 검증 경계를 명시한다.
2. 권한·상태 전이 → 저장/이벤트 → 화면 순서로 연결한다. 각 묶음을 관련 시험으로 확인한다. 전체 기능을 모두 만든 뒤 처음 검증하지 않는다.
3. 중복 방지·응답 형식·상태 의미를 바꾸면 영향받는 기존 호출부와 테스트 fixture를 함께 대조한다. 예: 서로 다른 두 사건을 필요로 하는 시험은 실제 distinct ID를 확인한다. 단언 제거로 맞추지 않는다.
4. 관련 회귀 시험으로 보수한 후보의 범위를 감사하고 Claude/Codex 양쪽 독립 코드 심사를 먼저 수행한다. 반려되면 원인을 좁혀 보수하고 심사부터 다시 진행한다. 알려진 실패를 남겨 둔 채 전체 시험이나 UI 검증을 먼저 반복하지 않는다.
5. 양쪽 심사 통과 후 정식 전체 시험/빌드, 실제 외부 Chrome 인수, 정상 승인/병합 순으로 수행한다(2026-09-14 이후 사용자 확정 순서). 구현/공식 DB 검사와 QA를 겹치지 않는다. 앞선 후보의 PASS를 새 후보로 복사하지 않으며, 동일 후보의 이미 완료된 검증은 순서 전환만을 이유로 반복하지 않는다. 변경한 코드에 따라 재검증하고 근거의 한계를 보존한다.
6. 작업 지시 변경 후에는 실제 instruction.md에 최신 실패 근거가 들어갔는지 확인한다. 정상 병합 후 MCP는 실제 변경 심볼까지 확인한다.

## 작업별 가장 먼저 고정할 경계

| 작업 | 먼저 합의·검증할 경계 |
|---|---|
| F20 | 설정 저장과 게임 시작이 경합할 때 단일 설정 버전, 방장 변경, 인원 하한, 준비 해제 |
| F21–22 | 추방/자발 이탈/정상 종료/강제 종료의 최종 상태 책임자, 타이머 정리, 전적·보상의 단일 확정 |
| F23 | 외부 관전자 입장 금지와 기존 사망 참가자 관전 OR 나가기 구분. 잠정 피격은 최종 사망 아님. 명시적 나가기와 단절 복원 구분 |
| F24 | 현재 서버 설정만 복원하고 관전자 설정·오래된 방 상태를 다시 살리지 않음 |
| F25 | 광대→의사→경비원→마녀사냥꾼 상태표. 피격/치료 대기/최종 사망 구분. 치료 전 승패·기록 확정 금지. 자기 치료와 회복 후 같은 밤 행동 |
| F26 | F25 확정 사건을 기반으로 안정 사건 ID·수신자별 공개 필드·ACK 유효 세대. 대상자에게 조사자 신원/결과 노출 금지 |
| F27 | F25/26의 동일 사건과 서버 진행 상태를 소비. 영상 완료/건너뛰기/실패/상한 중 한 번만 다음 단계 해제. 늦은 ACK와 재접속이 다른 밤을 진행시키지 않음. 승인 MOV 내장음·mute 계약 유지 |
| F29 | 토큰 사용·비밀번호 변경·기존 세션 폐기의 일관된 확정, 동일 토큰 동시 제출, 메일 실패·미리보기·만료·원문 비노출 |
| F28 | 각 담당의 실제 증거와 미검증을 대조하고 여러 기능이 이어지는 시나리오 실행. 전체 기능을 처음부터 다시 구현하지 않음 |

F25 계획에서는 F26/27에 제공할 사건·상태·진행 해제 계약을 문서화하되 미래 영상 기능을 미리 구현하지 않는다. F26은 F25 병합 구현과 계약을 대조하고 F27은 둘을 대조한다. 계약 변경이 필요하면 기존 소비처와 회귀 시험을 함께 갱신한다. 실제 다중 사용자 Chrome에서는 정상 한 번뿐 아니라 해당 작업의 대표 실패/복원 경로도 확인한다.

## 증거와 한계

F19에서 실제 확인한 실패: 완료 후 발견된 계정/조회 경합, 실제 마우스 입력이 막히는 겹침, PENDING 중복 방지 변경 후 두 사건을 가정한 fixture 불일치, 계정 복원 때 생성 키 재사용. 반복 반려나 기능별 처리 시간 감소는 앞으로 측정할 항목이며, 이 문서 추가만으로 개선 완료 또는 무결함을 주장하지 않는다.
