# F-33 이모티콘 · F-34 플레이어 카드 메뉴 배치 (2026-09-22)

## E-1 이모티콘 카탈로그 23종·기본 지급·상점 구매 허용

### 승인 및 기준
2026-09-22 운영자가 F-33 이모티콘 설계도(`docs/design/F-33-emoticon.md`)와 이 배치 편성을 승인했다. 설계도의 경로·itemId·필드·담당은 계약이다. 이 조각은 설계도의 **E-1** 몫만 구현한다.

### 목표
디자이너 가이드의 이모티콘 23종(기본 지급 8, 상점 판매 15)을 서버 카탈로그와 상점 화면에 등록하고, 상점에서 실제로 구매·소유되게 한다. 자산 파일은 이미 커밋돼 있다(`frontend/public/shopItem/basic/emoji/*.png` 8개, `frontend/public/shopItem/emoji/*.png` 15개, `frontend/public/frame/emoji/*.png` 3개) — 옮기거나 이름을 바꾸지 않는다.

### 구현 요구사항
- `backend/economy/catalog.js`: 표시용 4종(`emoticon-웃음/울음/화남/박수`)을 삭제하고 설계도 §0의 itemId 23종을 등록한다. 기본 8종 `{type: EMOTICON, priceGold: 0, defaultGrant: true, purchasable: false}`, 상점 15종 `{type: EMOTICON, priceGold: 500, defaultGrant: false, purchasable: true}`. 가격은 **임시값**이며 상수 하나(`EMOTICON_PRICE_GOLD_PLACEHOLDER`)로 모은다 — 최종 상품표로 확정하지 않는다.
- 기본 8종의 기존·신규 계정 지급은 기존 `ensureDefaultEntitlements`(등록만 하면 다음 지갑 조회·가입·backfill 경로에서 지급) 로 한다. 새 지급 코드를 쓰지 않는다.
- `frontend/src/domains/store/constants/storeItems.js`: `EMOTICON_STORE_ITEMS`를 23종으로(id = itemId, `category:"이모티콘"`, `name`=한국어 제목, `icon`=설계도 §0 파일 경로, 기본 8종은 가격 0·`tag:"기본 지급"`, 상점 15종은 `priceAmount: 500`). `frontend/src/domains/store/components/panel/StorePanel.jsx`의 `NON_PURCHASABLE_CATEGORIES`에서 "이모티콘"을 빼고, `StoreSelectedItemDetail.jsx`의 이모티콘 "표시 전용 · 준비중" 분기를 없애 일반 구매 버튼·일괄 구매에 포함한다. 소유한 항목은 기존 "보유" 표시 규칙을 따른다.
- 서버 응답 형태(`getWalletSummary`·구매 API)는 바꾸지 않는다.

### 책임 경계
팔레트 저장(E-2)·인게임 표현(E-3)은 다루지 않는다. 기존 완료 기능과 데이터는 보존한다. DB 검증은 격리 테스트 DB(pluto_f01_20260909_al 및 _restore_check)만 사용한다. 기존 사용자 DB·Docker 볼륨을 삭제하거나 초기화하지 않는다. 필요한 프런트·백엔드·테스트 변경은 승인되었다. 기능 범위를 임의 축소하거나 테스트/심사 관문을 우회해 완료로 처리하지 않는다.

### 완료 조건
- `backend/tests/db/f09-store-purchases.integration.test.js`의 "표시용 이모티콘 개별 구매는 거부" · "이모티콘이 섞인 일괄 구매" 두 시험은 **계약 변경**으로 다시 쓴다: 상점 이모티콘 개별 구매 성공(골드 차감·소유 생성·원장 1건), 일괄 구매에 이모티콘 포함 성공, 기본 지급 이모티콘은 구매 불가(`purchasable:false`), 존재하지 않는 itemId 위조 요청 거부(무차감)는 유지.
- 기본 지급 시험: 신규 계정과 기존 계정(backfill 경로) 모두 기본 8종 소유, 재실행해도 중복 지급 없음.
- 상점 화면 시험: 이모티콘 탭에 23종이 보이고 상점 15종에 구매 버튼, 기본 8종에는 구매 버튼 없음.
- 프런트 `npm test`·`npm run build`, 격리 DB 백엔드 전체 실행기 통과.

완료 조건은 **시험이나 실행으로 확인할 수 있는 범위**로만 판정한다. "코드 어디에도 없다" 같은 부재 증명은 이 조각의 조건이 아니다. 성공 조건 문장에 경로를 적을 때는 저장소 루트 기준 실제 경로로 적는다. 실제 브라우저 확인은 운영자의 몫이며 이 조각은 test/build로 완결한다.

## E-2 이모티콘 팔레트 저장(테이블·API)과 마이페이지 이모티콘관리 화면

### 구현 요구사항

  - `PUT /user/me/emoji-palette` `{slots:[8], expectedRevision}` — 허용 필드 이 둘뿐(모르는 필드 400, 로드아웃 `/economy/equip`와 같은 규칙) → `{ok:true, slots, revision}` / `INVALID_SLOTS`(길이≠8·중복·형식) / `NOT_OWNED`(소유하지 않은 itemId) / `REVISION_MISMATCH`(409, 현재 값 동봉). 저장은 한 트랜잭션: 소유 검증 → revision CAS 조건부 UPDATE → 새 revision. 빈 슬롯(null) 허용.

API `frontend/src/domains/user/api/emojiPalette.api.js`, 상태 `frontend/src/domains/user/store/emojiPalette.store.js`(zustand, `identityGeneration` 경계는 economy.store와 같게).
- `frontend/src/domains/user/components/MyPageLayout/EmoticonEntryButton.jsx`는 `/mypage/emoticons`로 이동한다.

### 승인 및 기준

### 목표
인게임 플레이어 카드를 좌클릭하면 그 카드에 대한 행동 메뉴(투표 / 재판 찬반 / 밤 행동 대상)가 열리고, 기존 제어 패널과 같은 규칙으로 제출된다. 제어 패널은 이 조각에서 아직 없애지 않는다(V-2).

### 구현 요구사항
- `frontend/src/domains/game/ingame/components/board/InGamePlayerBoard.jsx`의 카드 래퍼에 좌클릭(`onClick`, `role="button"`, `tabIndex=0`, Enter/Space)을 달아 메뉴를 연다. **우클릭(`contextmenu`)은 F-33 팔레트 몫이므로 건드리지 않는다.**
- 메뉴 항목·보이는 조건·활성 조건·실행은 설계도 §2-1 표 그대로 — `useInGameActionPanel`의 기존 값(`dayVoteControlsEnabled`, `dayVoteTargets`, `tribunalVoteControlsEnabled`, `isNightTurnActor`, `nightActionsLocked`, `nightActionTargets`, `setSelected*`, `submitDayVote`, `submitTribunalVote`, `submitNightAction`)을 쓴다. 새 규칙을 만들지 않는다. 본인 카드는 투표·밤 행동 항목 없음. 대상이 아닌 카드는 항목을 비활성으로 보이고 이유 문구를 단다.
- 메뉴는 한 번에 하나. 다른 카드 클릭·바깥 클릭·Esc·단계 변화(`phase`/`dayPhase`/`nightTurnRole`)·게임 종료에 닫힌다. `interactionBlocked`면 열리지 않는다.

- 내 현재 투표·밤 대상 카드는 `InGamePlayerCard`의 기존 `voteHighlight` prop으로 강조한다.
- 신규 파일: `frontend/src/domains/game/ingame/hooks/useInGamePlayerCardMenu.js`, `frontend/src/domains/game/ingame/components/board/InGamePlayerCardMenu.jsx`.

## V-2 제어 패널 제거·단계 행동 줄·카드 메뉴 추방·투표 현황 실데이터
