# F32 외부 백엔드 등록 상품의 DB 조회 계약

2026-09-14 사용자 확정: 충전 가격과 상품은 다른 백엔드 서버가 DB에 등록한다. 게임 서버는 해당 DB를 조회하여 상품 표시와 구매에 반영한다. 이 문서는 기존 F32 문서의 상품 가격·지급량·교환비를 사용자에게 먼저 확정받아야 한다는 착수 조건을 대체한다.

## 책임과 범위

- 대상은 F32의 원화 결제 다이아 충전 상품과 다이아로 구매하는 골드 상품이다. 기존 스킨·테두리 등 전체 상점의 DB 이관으로 범위를 확대하지 않는다.
- 별도 백엔드가 합의된 테이블 계약에 따라 상품을 등록·수정·판매 중지한다. 이번 작업은 그 관리 서버나 관리자 화면을 만드는 일이 아니다.
- 게임 서버는 DB의 유효하고 판매 중인 상품을 조회해 API로 제공한다. 브라우저는 이 API 결과를 표시하고 상품 ID와 버전을 제출한다. 브라우저에서 DB에 직접 연결하지 않는다.
- 가격·기본 지급량·보너스·골드 구매 비용과 지급량은 DB 값으로 결정한다. 최종 숫자 확정은 구현 착수 조건이 아니다. 코드에 운영 상품표를 고정하거나 DB 오류 시 하드코딩 상품으로 대체하지 않는다.
- 현행 backend/economy/catalog.js는 코드 카탈로그이고 재화 패키지는 제외돼 있다. 요청 구조가 이미 구현됐다고 간주하지 말고 F32에서 필요한 저장소·조회·구매 연결을 구현한다.

## 저장 및 조회 계약

- 착수 시 실제 기존 스키마를 확인하고 재사용 여부를 결정한다. 외부 등록 서버가 사용할 정확한 테이블·컬럼·제약·등록 예시를 문서화한다. 현재 연결 정보나 외부 서버 구현이 확인됐다고 주장하지 않는다.
- 최소 계약: 안정적 상품 ID, 상품 종류, 표시 이름, 지불 통화와 금액, 지급 통화와 기본 수량 및 보너스, 판매 상태, 정렬 순서, 버전 또는 동등한 변경 식별자. 다이아 충전은 KRW→DIAMOND, 골드 구매는 DIAMOND→GOLD로 제한한다.
- 외부 작성자는 필수값·양수 정수 금액/수량·통화 조합·고유 ID를 만족해야 한다. 상품 수정은 관련 필드를 원자적으로 변경하고 버전도 갱신한다. 서버에서도 유효성을 검사한다.
- 상품 목록과 신규 주문은 요청 시 DB를 읽는다. 외부 등록·수정·판매 중지가 커밋된 뒤 다음 조회에 반영되고, 게임 서버 재시작이나 재배포를 요구하지 않는다. 실시간 푸시까지 요구하지 않으며 열린 화면은 재조회·새로고침으로 갱신한다.
- 상품이 없으면 빈 상품 안내, DB 조회 실패면 오류·재시도를 표시한다. 판매 중지·삭제·잘못된 상품은 신규 주문을 거부한다. 오래된 화면의 상품 가격이나 버전이 달라졌으면 갱신을 안내하고 새 가격을 확인받는다.

## 주문과 지급

- 게임 서버는 주문 생성 시 DB 상품의 유효성·판매 상태·버전을 확인하고 계정·상품 ID·버전·가격·지급량을 주문에 스냅샷으로 저장한다. 클라이언트가 제출한 금액·지급량은 신뢰하지 않는다.
- 이미 생성된 유효 주문은 이후 상품 수정·판매 중지·삭제로 금액이나 지급량이 바뀌지 않는다. 승인 대조·지급·응답 유실 복구는 주문 스냅샷을 사용한다. 주문 만료·취소 정책과 중복 지급 방지는 기존 F32 계약을 유지한다.
- 다이아로 골드를 구매할 때도 서버가 확인한 상품 조건으로 다이아 차감·골드 지급·원장을 하나의 트랜잭션으로 처리한다. 동일 구매 재시도는 저장된 결과를 재사용한다.
- 토스 테스트 키와 실제 테스트 결제 검증은 여전히 필요하다. 테스트 전용 DB 상품값은 시험 데이터로 명시하고 운영 가격으로 확정하지 않는다.

## 검증과 작업 순서

- 승인된 테스트 DB에 외부 작성자를 모사하는 별도 연결로 상품 등록 → 실제 게임 API 및 외부 Chrome에 표시 → 가격/수량 수정 → 재조회 반영 → 판매 중지 후 신규 주문 거부를 확인한다. 서버 재시작·재배포 없이 수행한다. 실제 외부 관리 서버와의 통합은 그 서버 연결이 있을 때 별도로 기록한다.
- 상품 버전 변경 시 오래된 화면의 주문 거부·갱신 안내, 주문 생성 후 상품 변경/삭제에도 원래 승인 금액·지급량 유지, 빈 목록·조회 실패·잘못된 값·중복 구매·동시 구매를 검증한다.
- 기존 배치 F32/BQ에 포함한다. F28/BN은 DB 상품 변경부터 결제·골드 구매까지 통합 확인한다. 순서와 총32개는 유지한다.
- BQ 착수 시 동결된 초기 요구사항과 이 최신 사용자 확정을 대조한다. 기존 AC를 보존하면서 누락된 DB 조회·변경 반영·주문 스냅샷 조건은 공식 acceptance/set 및 정상 계획 심사에 포함한다. 상태 파일 직접 수정·심사 우회는 금지한다.
- DB 보호 규칙은 유지한다. 이번 요구사항 정리에서는 DB나 실제 상품을 변경하지 않는다.
