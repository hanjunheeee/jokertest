# F32 다이아 충전과 골드 구매

## 승인 및 기준
2026-09-13 사용자가 추가 구현 및 기존 배치 F28 이전 편성을 승인했다. 선행 F29 완료 후 F30→F31→F32 순서로 구현한다.

## 구현 요구사항

- 토스페이먼츠 **테스트 모드로 다이아만 충전**한다. 테스트 승인에서 실제 금액은 결제되지 않는다. 골드는 다이아를 지불하는 기존 상점 상품으로 구매한다.
- 원화 직접 골드 충전과 골드→다이아 역교환은 추가하지 않는다. 실제 유료 운영/정기결제/운영 환불은 별도 범위다.
- 상품·가격·지급량·보너스·골드 구매 조건은 별도 백엔드가 DB에 등록하고 게임 서버가 조회한다. 서버 재시작 없이 다음 조회부터 반영한다. 숫자 확정은 구현 착수 조건이 아니다. [2026-09-14 DB 상품 계약](2026-09-14-f32-db-product-contract.md)을 적용한다.
- 서버 상품표로 주문자·상품 버전·가격·지급량을 고정하고 테스트 client/secret 키 세트를 사용한다. secret은 서버에만 보관한다. 테스트 구성의 live 키는 거부한다.
- 결제창 복귀만으로 지급하지 않는다. 서버가 paymentKey/orderId/amount/소유권을 확인하고 승인 결과를 확정한 뒤 다이아를 지급한다. 외부 승인 중 DB 잠금을 장시간 유지하지 않는다.
- 승인 성공·DB 지급 실패 또는 응답 유실은 확인 중/지급 대기 상태로 복구한다. 동일 주문 조회·멱등키·고유 결제키·고유 원장으로 한 번만 지급한다. 실패/취소는 미지급,다른 계정 주문 접근은 거부한다.
- 골드 구매는 다이아 차감·골드 지급·구매 원장을 같은 트랜잭션으로 처리한다. 잔액 부족·중복 클릭·동시 요청·응답 유실에서 부분 성공이나 이중 차감/지급이 없다.
- 인수: 외부 DB 상품 등록·수정·판매 중지의 다음 조회 반영, 주문 생성 후 상품 변경에도 주문 조건 보존, 실제 토스 테스트 결제창→서버 승인→다이아 증가→골드 구매→양쪽 잔액/원장→새로고침·재로그인,변조·타인 주문·잔액 부족·취소·실패·불명확한 승인·DB 장애·중복 요청. 실제 키나 테스트 상품 데이터가 없으면 해당 외부 검증은 미완료로 남긴다.

## 책임 경계
이 작업에 배정된 기능만 구현하며 기존 완료 기능과 데이터는 보존한다. docs/requirements/2026-09-13-additional-execution-approved.md의 사용자 확정이 이전 초안을 대체한다. 기존 UI 재사용,실제 서버 판정,계정 격리,멱등 처리 및 정상 계획·코드 심사를 유지한다. DB는 승인된 pluto_f01_20260909_al 및 _restore_check만 사용한다. 운영 DB/볼륨 초기화 금지.

## 완료 조건
배정된 모든 기능의 실제 변경·테스트·빌드·격리 DB·외부 Chrome 및 정상 독립 심사와 병합을 확인한다. 상품 수치 확정을 기다리지 않고 DB 계약과 테스트 전용 상품으로 구현·검증한다. 실제 결제 설정이 없으면 해당 외부 인수는 미완료로 남긴다. 모의 검증을 실제 외부 연동으로 바꾸지 않는다. F28 최종 통합 인수에 증거와 미검증을 넘긴다.
