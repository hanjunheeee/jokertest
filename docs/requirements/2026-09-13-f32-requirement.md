# F32 다이아 충전과 골드 구매

## 승인 및 기준
2026-09-13 사용자가 추가 구현 및 기존 배치 F28 이전 편성을 승인했다. 선행 F29 완료 후 F30→F31→F32 순서로 구현한다.

## 구현 요구사항

- 토스페이먼츠 **테스트 모드로 다이아만 충전**한다. 테스트 승인에서 실제 금액은 결제되지 않는다. 골드는 다이아를 지불하는 기존 상점 상품으로 구매한다.
- 원화 직접 골드 충전과 골드→다이아 역교환은 추가하지 않는다. 실제 유료 운영/정기결제/운영 환불은 별도 범위다.
- 상품 가격·다이아 지급량·다이아 대 골드 환산율·보너스는 아직 미정이다. 임의로 사업 정책을 확정하지 않는다. 독립 구현은 진행하되 최종 상품 활성화 전에 확정값이 필요하다. 자동 시험용 수치와 최종 상품표를 구분한다.
- 서버 상품표로 주문자·상품 버전·가격·지급량을 고정하고 테스트 client/secret 키 세트를 사용한다. secret은 서버에만 보관한다. 테스트 구성의 live 키는 거부한다.
- 결제창 복귀만으로 지급하지 않는다. 서버가 paymentKey/orderId/amount/소유권을 확인하고 승인 결과를 확정한 뒤 다이아를 지급한다. 외부 승인 중 DB 잠금을 장시간 유지하지 않는다.
- 승인 성공·DB 지급 실패 또는 응답 유실은 확인 중/지급 대기 상태로 복구한다. 동일 주문 조회·멱등키·고유 결제키·고유 원장으로 한 번만 지급한다. 실패/취소는 미지급,다른 계정 주문 접근은 거부한다.
- 골드 구매는 다이아 차감·골드 지급·구매 원장을 같은 트랜잭션으로 처리한다. 잔액 부족·중복 클릭·동시 요청·응답 유실에서 부분 성공이나 이중 차감/지급이 없다.
- 인수: 실제 토스 테스트 결제창→서버 승인→다이아 증가→골드 구매→양쪽 잔액/원장→새로고침·재로그인,변조·타인 주문·잔액 부족·취소·실패·불명확한 승인·DB 장애·중복 요청. 키/상품 정책이 없으면 해당 실제 검증은 미완료로 남긴다.
