## 복구 원칙

1. 이 배치만 점검하며 중복 배치를 등록하지 않는다. 예전 배치와 L·U를 재시도하거나 승인하지 않는다.
2. 데몬이 실제 종료됐고 같은 프로젝트의 중복 프로세스가 없으면 아래 CLI로 다시 시작한다. Windows 앱 실행은 숨김 창을 사용한다.
3. `error`·`human` 또는 제한 시간을 넘긴 정체는 최근 실패 근거부터 읽는다. 권한·프로세스·테스트 환경·설정·구현 오류 등 수정 가능한 원인을 해결한 뒤 해당 단계에 맞는 공식 RPC로 재시도한다. `retry`는 멈춘 단계와 실제 반송 코드가 있을 때만 사용하고, 병합 실패에는 `merge/retry`를 사용한다.
4. 사용량 제한은 제공자의 재개 시각을 확인해 재예약한다. 사용량 초기화 크레딧 사용·결제·무한 재시도로 우회하지 않는다.
5. 반복되는 동일 실패는 원인을 고치지 않은 채 재시도 횟수만 늘리지 않는다. 심사 실패 근거를 지우거나 수동 PASS로 바꾸거나 테스트를 약화하지 않는다. 데이터 삭제·초기화·강제 덮어쓰기 없이 복구한다.
6. 외부 OAuth 설정·Discord 지원 URL·사용자 제공 영상·검증된 효과음·실제 메일 수신 환경이 없으면 구현 가능한 부분을 진행하고 해당 인수 조건을 미검증으로 기록한다. 가짜 값이나 테스트 대역으로 실제 연동 완료를 선언하지 않는다.
7. 점검 시각·변화·실행한 복구·다음 확인 사항은 `.pluto/monitor/`에 기록한다. 매 점검마다 추적 파일을 수정해 원본 작업 트리를 더럽히지 않는다. 승인 문서 변경이 실제 필요한 경우 명시적으로 기록·커밋한다.
8. 상태 변화가 없으면 알리지 않는다. 의미 있는 완료·복구 실패·사용자 자료 필요를 알리고, 29개 전부 검증·병합 완료 여부와 미검증 목록을 확인한 뒤 자동화를 일시 중지한다.

