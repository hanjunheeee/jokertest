# F20·F24·F28 설정 검수 담당 조정 — 사용자 승인

2026-09-17 사용자는 현재 설정을 F20에서 검수하고 실제 다음 방 복원을 F24·최종 F28에서 필수 검수하는 제안에 **“해 그렇게”**라고 승인했다. 일반 작업 재개 승인과 별개의 완료 조건 담당 조정 승인이다.

원래 전체 요구사항은 그대로 보존한다: **“관전자 관련 설정 필드는 편집 UI·저장 요청·다음 방 복원 데이터 어디에도 포함되지 않는다.”** 아래 조정은 기능이나 검증을 삭제하지 않고 검수 담당을 나눈다. 기존 반려 기록은 당시 조건에 대한 기록이며 PASS로 바꾸지 않는다.

F24의 기존 모든 조건과 F28의 기존 모든 조건(추가 F30~F32 포함)을 보존한다. F24의 선행 작업 F20·F22, 기존 32개 큐 순서, F28 마지막 배치를 유지한다. F24 복원 기능이 아직 없다는 사실 자체는 조정된 F20의 실패 사유가 아니며, F20 통과가 F24 복원 검증 완료를 뜻하지 않는다.

공식 acceptance/plan API로 반영하고 독립 심사를 새로 받는다. F24·F28은 아직 REQ 단계이므로 등록한 추가 조건은 전체 조건 목록을 대신하지 않는다. 착수 시 원래 요구사항 전체로 AC를 생성하고 위 담당 조건도 반드시 포함한다. 자동 생성 과정에서 이 조건이 누락되면 구현 전에 공식 acceptance API로 보완하고 정상 계획 심사를 거친다.

순서는 관련 회귀 테스트 → Claude·Codex 독립 코드 심사 → 공식 전체 테스트·빌드·보호 DB → 실제 외부 Chrome → 정상 승인·병합이다. 수동 PASS, 테스트 생략, 상태파일 직접 변경, 가짜 복원 생산자 추가, 선행 F24 구현, 큐 재정렬은 하지 않는다.

승인 당시 BE 후보는 `a77d2a5dbeebf3d2cbef7895a74a352bb8bcde48`이며 관련 테스트 126 PASS는 전체 인수 완료와 구분한다. 과거 RESULT-8·CODEX-8의 AC-06 partial 및 실제 Chrome 미실행 기록을 보존한다.
