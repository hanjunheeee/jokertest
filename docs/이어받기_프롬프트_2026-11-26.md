## 2. 이미 정해진 원칙 (바꾸지 않는다)

1. **백엔드와 백엔드 시험은 내 것이 기준.** 화면을 백엔드에 맞춘다. 백엔드를 화면에 맞추지 않는다.
2. **PC 화면은 내 것이 기준.** 상대가 넣은 PC 고침(방 확인 다시 묻기 350ms×8, 끊김 20초 뒤 나가기, appConfirm, 입장 준비 덮개, 시간 막대 이름표+타이머 판 등)은 살렸고, 내 것과 겹치면 내 것이 이긴다.
3. **모바일 화면은 상대 것을 통째로 쓴다** (커밋 `d71ab651`). `frontend-mobile/src` 는 `baa5c898` 과 37개 파일만 다르고, 그 차이는 전부 "안 고치면 안 돌아가는 곳"이다.
   - 지금 서버에 없는 기능이라 걷어낸 것: 설정의 방관리 탭(다음 게임 설정 유지), 밤 성공 연출·밤 대기 창, 낮 집계·재판 판정·밤 종료 단추, MVP 칸
   - 백엔드에 맞춘 것: 로비 들어올 때 `enter_lobby` 보냄, `game_result_closed` 받음, 투표 결과 코드 글, 비밀번호 확인 칸, 밤 연출 자리를 낮 시작 연출(`DawnReportOverlay`)로 이음
   - 게임을 못 하게 하던 버그 둘: 확인·알림 창 겹 순서(z-140), 판이 바로 끝나도 방 목록으로 안 감
   - **내 화면 규칙을 모바일에 다시 얹지 않는다.** (예전에 얹었다가 사용자가 "통째로"로 정해서 뺐다.) 모바일 화면을 고치려면 먼저 사용자에게 묻는다.
4. **쿠폰 입력 단추는 기본 숨김.** 빌드 값 `VITE_STORE_COUPON_BUTTON=1` 이면 보인다 (`frontend/src/domains/store/constants/storeLayoutStyle.js`). e2e 빌드는 `e2e/scripts/serve-front.js` 가 알아서 켠다. 기능은 살아 있다.
5. 마이그레이션 `0013-f19-friends-invites.js` 는 내 것으로 되돌려 두었다. 상대가 이미 적용된 파일을 고쳤는데, 그 판으로 올라간 DB는 체크섬이 달라 서버가 멈춘다. **이미 적용된 마이그레이션 파일은 고치지 않는다.**

## 3. 절대 하지 않는 것

- 개발 DB와 진짜 `.env` 를 고치지 않는다. 환경 파일의 **값**을 출력하지 않는다. 시험은 시험 DB(`joker_e2e`, `.env.testdb`)와 시험 Redis(127.0.0.1:6380)만 쓴다.
- `git add .`, `git stash`, `git reset --hard`, force push, main 에 합치기를 하지 않는다. 커밋은 경로를 짚어서(`git commit -- <경로>`). push 는 사용자가 하라고 할 때만.
- 시험을 지우거나 skip 하거나 기대값을 느슨하게 해서 통과시키지 않는다. 없어진 기능만 보던 시험은 지우되 번호와 까닭을 남긴다. 실패가 코드 버그로 보이면 시험을 그대로 두고 보고한다.
- 사용자 이메일 등 개인 정보를 바깥 서비스에 보내지 않는다.

## 4. 시험 돌리는 법 (실제로 쓴 명령)

**CPU 규칙 (사용자가 꼭 지키라고 함)**: 무엇이든 돌리기 전에 CPU와 남은 메모리를 잰다. CPU 85%를 넘거나 남은 메모리가 4GB 아래면 내려갈 때까지 기다린다. Playwright 일꾼은 2까지, `node --test` 는 `--test-concurrency=2` 까지(DB 시험은 1). 단위 시험·빌드·브라우저 시험을 겹쳐 돌리지 않는다. 일꾼 4로 돌렸을 때 CPU 100%가 이어졌고 DB 연결이 끊겼다.

```powershell
(Get-CimInstance Win32_Processor).LoadPercentage; (Get-CimInstance Win32_OperatingSystem).FreePhysicalMemory/1MB
```

- 서버 (backend 폴더에서, 약 40분)
  - `npm run test:db:setup`
  - `REDIS_URL_TEST=redis://127.0.0.1:6380 node --env-file=.env.test --env-file=.env.testdb --test --test-concurrency=1`
  - `REDIS_URL_TEST` 가 없으면 Redis 시험 101개가 건너뛰어진다.
- PC 단위 (frontend 폴더): `node --experimental-test-module-mocks --test --test-concurrency=2 "tests/**/*.test.js"`
- 모바일 단위 (frontend-mobile 폴더): `node --test --test-concurrency=2`
- 브라우저 시험: `tools/시험도구/묶음돌리기/README.md` 대로. 빌드본 모드로 돌린다(개발 서버 모드는 느리고 흔들린다). 화면 코드를 고치면 다시 빌드해야 한다.
  - 켜기: `powershell -ExecutionPolicy Bypass -File tools/시험도구/묶음돌리기/start-servers.ps1 -Apps backend,desktop,mobile,mon`
  - 한 덩어리: `bash tools/시험도구/묶음돌리기/run.sh <이름> <1|2> --project=mobile <파일>`
  - 모바일 전체: `bash tools/시험도구/묶음돌리기/run-mobile.sh m1-` (약 3시간)
  - 실패만 다시: `failed.js --grep a.json b.json` 값을 `run.sh … --grep "<값>"` 에
  - 끄기: `powershell -ExecutionPolicy Bypass -File tools/시험도구/묶음돌리기/stop-servers.ps1`
  - 포트: 백엔드 4100, PC 5273, 모바일 5274, 관리자 5275

## 9. 할 일

사용자가 이어서 수정할 것을 말해 줄 것이다. 그 전에:

1. `git status` 와 `git log --oneline -12` 로 위 상태와 같은지 확인하고, 다르면 무엇이 다른지 먼저 말한다.
2. 수정을 받으면 고치기 전에 원인을 코드로 확인하고, 어느 원칙(2번)에 걸리는지 본다. 모바일 화면을 건드리는 일이면 먼저 묻는다.
3. 고친 뒤에는 걸린 단위 시험과 브라우저 시험을 돌려 숫자로 보고한다. 통과시키려고 시험을 고쳤으면 무엇을 왜 고쳤는지 적는다.
4. 확인하지 못한 것은 "확인 못 함"이라고 쓴다.
