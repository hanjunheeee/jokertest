## 2. 목표 (2026-09-08 확정: 병합이 아니라 이식)

1. **기준은 로컬 브랜치** `windows-handoff-20260808`이다. 기능(게임 규칙·소켓·store·훅)은 로컬이 최신이므로 그대로 둔다.
2. **원격 브랜치는 UI 소스 창고**다. `git merge`·`cherry-pick`은 하지 않는다. 슬라이스마다 필요한 컴포넌트·상수·에셋을 `git show origin/feature/ui-Phase1complete:<경로>`로 꺼내 로컬 로직에 붙인다.
3. 원격의 구버전 게임 로직(밤 턴 은닉 계산, 밤 개인 결과 병렬 필드, 방 코드 검증, 결과 종료 요청 등)은 한 줄도 가져오지 않는다. 신 UI가 필요로 하는 데이터는 로컬에 이미 있는 것(`colorIndex`, `winResult`, `night_action_result`)을 쓰고, 없으면 표시를 비활성화한 채 기록한다.
4. 백엔드는 변경하지 않는다.

## 3. 비목표

- 신버전 UI 자체의 디자인 수정.
- 원격 슬라이스(0822~0827)의 기능 병합. 이 브랜치의 게임 로직은 로컬이 대체한다.
- `origin/main` 병합·PR 생성.

## 4. 근거 조사 요약

- 원격 UI 커밋 두 개(d1bf4d2, 8a80b56)는 469파일이며 백엔드 변경은 `user_stats.title` 제거뿐이다. 신 UI는 서버 API를 새로 요구하지 않는다(프로필 편집·스킨·상점·설정·도서관·포디움 모두 프론트 상태·상수).
- 로컬은 서버가 배정한 `colorIndex`, 종료 시 `winResult`, 본인 전용 `night_action_result` 이벤트를 이미 갖고 있어 원격 오버레이·카드·결과 화면을 로컬 데이터로 구동할 수 있다.
- 양쪽이 모두 손댄 영역은 ingame(액션 패널·타임바·오버레이·store 유틸)과 mode/setup/matching(방 코드·역할 구성)이다. 이 영역은 "원격 레이아웃 + 로컬 훅"으로 붙이고 로컬 테스트를 수정 없이 통과시키는 것을 성공 조건으로 둔다.
- 참고로 실제 `git merge`를 임시 워크트리에서 시도하면 충돌 파일 27개·구간 71개가 난다. 이 방식은 채택하지 않는다.
