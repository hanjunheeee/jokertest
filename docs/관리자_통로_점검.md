# 관리자 통로 점검 (관리자 서버 ↔ 게임 서버)

- 관리자 서버 없이 게임 서버의 관리자 통로(`/internal/*`)가 살아 있는지 한 줄로 확인하기
- 도구: `backend/scripts/admin-call.js` (`npm run admin`), 열쇠는 `.env`의 `INTERNAL_API_KEY`만 읽고 화면에 안 찍음

## 준비 (처음 한 번)
- `backend/.env`에 `INTERNAL_API_KEY=` 32자 이상 무작위 값 (관리자 서버와 같은 값)
- 넣은 뒤 게임 서버 다시 켜기 (열쇠 없으면 통로 전체가 꺼져 404)

## 점검 (backend 폴더에서)
```bash
npm run admin -- check
```
- 줄 세 개가 다 `OK`면 통로 정상
  - 게임 서버 살아 있음 (`/health`)
  - 틀린 열쇠는 막힘 (401)
  - 맞는 열쇠로 지금 상황 읽힘 (200)

## 기능별 시험
| 명령 | 하는 일 |
| --- | --- |
| `npm run admin -- live` | 지금 접속 수·대기방·판 수 |
| `npm run admin -- announce "제목" "본문"` | 접속 중인 사람 전체에게 공지 (알림 창에 뜸) |
| `npm run admin -- announce "제목" "본문" <uuid,uuid>` | 고른 사람에게만 공지 |
| `npm run admin -- disconnect <uuid>` | 그 사람 바로 끊기 (정지·비활성 반영) |
| `npm run admin -- maintenance-reload` | 점검 상태 다시 읽기 (DB `maintenance_state` 바꾼 뒤) |
| `npm run admin -- banned-words-reload` | 금지어 다시 읽기 (DB `banned_words` 바꾼 뒤) |

- 실서버에서 부르기(권장): 서버 안에서 `docker compose -f docker-compose.yml -f docker-compose.prod.yml exec backend npm run admin -- check` (`ADMIN_CALL_BASE_URL` 비움 → 컨테이너 안 `localhost:4000`, nginx·클라우드플레어 안 거침)
- 같은 서버 docker 망의 관리자 서버: `ADMIN_CALL_BASE_URL=http://backend:4000`
- 바깥에서 꼭 부르면: `ADMIN_CALL_BASE_URL=https://api.도메인` + 부르는 곳 공인 ip를 `nginx/snippets/internal-allow.conf`에 `allow <ip>;` (기본 전부 403). 클라우드플레어를 거쳐도 진짜 ip로 검사함, 봇 확인(Bot Fight Mode)을 켜면 막힐 수 있음 → `docs/배포_설정.md` 6-7
- 공지 확인: 로그인한 화면 로비 왼쪽 아래 편지 아이콘 → 알림 창 맨 위 (2026-11-09 로컬에서 확인함, 화면 사진 `reports/관리자공지_시험_화면.jpg`)

## 결과 읽는 법
- `404`: 서버가 열쇠를 못 읽음 → `.env` 확인 후 서버 다시 켜기
- `401`: 열쇠가 서로 다름 → 관리자 서버와 게임 서버 값 맞추기
- `403`(nginx 화면): 부르는 곳 ip가 허용 목록에 없음 → `nginx/snippets/internal-allow.conf`
- `서버에 못 닿음`: 게임 서버가 꺼졌거나 주소 틀림
- 1분에 120번 넘게 부르면 잠깐 막힘 (요청 수 제한)
