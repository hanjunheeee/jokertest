# 프로젝트 흐름도 인덱스

프로젝트 전체 흐름은 한 문서에 몰아두지 않고, `LOGIN_FLOW.md`와 같은 형식의 파트별 문서로 나눕니다.

## 문서 목록

| 파트 | 문서 | 상태 |
| --- | --- | --- |
| 로그인 | `docs/LOGIN_FLOW.md` | 구현됨 |
| 공통 인프라 | `docs/COMMON_INFRA_FLOW.md` | 구현됨 |
| 회원가입 | `docs/SIGNUP_FLOW.md` | 구현됨 |
| 세션 확인 / 로그아웃 | `docs/SESSION_LOGOUT_FLOW.md` | 구현됨 |
| 사용자 / 계정 | `docs/USER_ACCOUNT_FLOW.md` | 구현됨 |
| 친구 | `docs/FRIEND_FLOW.md` | 구현됨 |
| 소켓 / 접속 상태 | `docs/SOCKET_PRESENCE_FLOW.md` | 구현됨 |
| 매칭 / 방 | `docs/MATCHING_ROOM_FLOW.md` | 부분 구현 |
| 인게임 / 기타 페이지 | `docs/INGAME_AND_MISC_FLOW.md` | 부분 구현 |

## 구현 차이 요약

| 영역 | 실제 상태 | 차이 |
| --- | --- | --- |
| 인증 | 대부분 구현됨 | 로그인/회원가입/세션 확인/로그아웃은 연결됨. 비밀번호 찾기/계정 찾기는 모델만 있고 라우트/컨트롤러 흐름 없음 |
| 사용자/계정 | 구현됨 | 프로필 조회, 닉네임 변경, 비밀번호 변경 모두 프론트 API에서 백엔드 컨트롤러까지 연결됨 |
| 친구 | 구현됨 | REST 처리와 소켓 알림이 함께 연결됨 |
| 소켓/접속 상태 | 구현됨 | 로그인 상태 기반 연결, 쿠키 JWT 인증, 단일 소켓 정책, 친구 상태 브로드캐스트 존재 |
| 랜덤 매칭 | 부분 구현 | 게임 찾기는 큐/방 생성까지 연결됨. 게임 만들기는 설정 후 매칭 화면으로 이동하지만 서버 방 생성 없음 |
| 방 코드 참여 | 부분 구현 | 6자리 입력 UI만 있고 참여 API/소켓 이벤트가 TODO 상태 |
| 인게임 | 부분 구현 | 화면 조합/더미 유틸 중심. 백엔드 게임 진행/소켓 이벤트 연결은 확인되지 않음 |
| 설정/상점/홈 | 프론트 전용 | 설정·상점은 로컬 UI/필터/영상 제어 중심, 홈은 정적 랜딩 |
| `traffic_log` | 미연결 | 모델은 있으나 기록/조회 호출 흐름을 찾지 못함 |
