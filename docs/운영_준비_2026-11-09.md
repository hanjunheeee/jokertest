# 운영 준비 (2026-11-09, 개발자용)

배포: 네이버 클라우드 예정. 업데이트 순서: **공지 → 점검 → 내림 → 업데이트 → 켬**.
판 상태는 서버 프로세스 메모리에 있음 → 서버가 죽거나 내리면 진행 중 판은 사라짐. 그래서 "바로 다시 서기"와 "내리기 전 공지·점검"이 중요.

## 1. 죽으면 바로 다시 켜기

### docker compose (기본)
- `db`·`backend`·`frontend` 모두 `restart: unless-stopped`: 죽으면 docker가 바로 다시 켬, 손으로 `docker compose stop` 한 것만 안 켬. 서버 재부팅 뒤에도 docker가 켜지면 같이 켜짐 (`sudo systemctl enable docker`)
- `backend` healthcheck: 30초마다 `/health`, 3번 연속 실패면 `unhealthy` 표시 (`docker ps`로 봄). 주의: compose는 unhealthy라고 다시 켜 주진 않음 — 프로세스가 죽어야 다시 켬. 멈춘 채 살아 있는 경우는 감시(아래 /health)로 잡기
- `stop_grace_period: 15s`: `docker compose stop`·업데이트 때 정리 시간
- 로그 크기 제한: `logging: max-size 10m, max-file 5` (화면 로그가 디스크 채우는 것 막기)

### Docker 없이 (pm2)
`backend/ecosystem.config.cjs` (pm2는 저장소에 안 넣음, 서버에만 설치)
```bash
npm i -g pm2
cd backend && pm2 start ecosystem.config.cjs
pm2 save && pm2 startup     # 서버 재부팅 뒤 자동으로 켜기
pm2 logs mmc-backend        # 화면 로그
pm2 reload mmc-backend      # 업데이트 뒤 다시 켜기 (판 사라짐, 점검 뒤에)
```
- 프로세스 1개만 (판 상태가 메모리에 있어서 여러 개면 판이 갈림)
- 10초 못 버티고 죽는 게 10번 이어지면 멈춤 (고장 난 채 무한 재시작 막기), 메모리 1GB 넘으면 다시 켬

### 프로세스 안 (backend/utils/processLifecycle.js, index.js가 직접 켤 때만)
- `SIGTERM`(docker stop·pm2)·`SIGINT`(Ctrl+C): 새 연결 막기 → 접속자에게 `server_shutdown` 안내 → 1.5초 → 소켓 닫기 → DB 닫기 → 종료 코드 0. 10초 넘으면 강제 종료
- 예상 못 한 오류(`uncaughtException`): 기록 → 위 순서로 종료 코드 1 → docker·pm2가 다시 켬 (상태 망가진 채 계속 도는 것보다 안전)
- 처리 안 된 Promise 거절(`unhandledRejection`): 기록만, 서버는 계속
- 화면은 아직 `server_shutdown`을 안 들음 (끊긴 뒤 자동 재접속으로 이어짐). 화면에 안내 띄우려면 프론트에서 이 사건 받기

## 2. 로그

- 위치: `backend/logs/app-YYYY-MM-DD.log` (compose는 `backend_logs` 볼륨의 `/app/logs`), 날짜 바뀌면 새 파일
- 보관: `LOG_RETENTION_DAYS`일 (오늘 포함, 기본 14), 지난 파일은 새 파일 열 때 지움
- 설정: `LOG_DIR` (비우면 `backend/logs`, `off`면 파일 안 남김)
- 내용: 요청 로그(방법·경로·상태·ms, 쿼리 문자열 빼고 비번 재설정·가입 경로는 가림) + console 출력 전부(INFO·WARN·ERROR)
- 비밀값 가림: 비번·토큰·쿠키·키 값, `Bearer …`, JWT 모양, 접속 주소 안 비번 → `[REDACTED]`
- compose에서 보기: `docker compose exec backend tail -f /app/logs/app-$(date +%F).log`

## 3. /health

- `GET /health` → DB `SELECT 1` 되면 `200 {ok:true}`, 안 되면 `503 {ok:false, code:"DB_UNAVAILABLE"}`. 로그인 필요 없음, 요청 로그엔 안 남김
- `X-Internal-Key: <INTERNAL_API_KEY>` 붙이면 `server` 칸 더함: 메모리(MB)·이벤트 루프 지연(지난 조회 뒤 평균/95%/최대 ms)·연결 수(접속자·소켓·진행 판)
- 네이버 클라우드 로드밸런서 상태 확인 경로·외부 감시(예: 1분마다)에 `/health` 사용
- 시작할 때 필수 환경값(`DATABASE_URL`·`JWT_SECRET`·`FRONTEND_URL`): 운영(`NODE_ENV=production`)은 비면 시작 거부, 개발은 경고만

## 5. 네이버 클라우드 DB 백업

### Cloud DB for MySQL을 쓰면 (권장)
- 만들 때 **백업 사용**: 매일 자동 전체 백업, 보관 기간 정함 (기본 1일 → **7일 이상**으로)
- 백업 시각은 사람 적은 새벽으로
- **시점 복구**(Point-in-time): 보관 기간 안 원하는 시각으로 새 DB를 만들어 되살림 (기존 DB를 덮지 않음 → 확인 뒤 앱 주소 바꿈)
- 백업 파일을 Object Storage로 내보내기 설정해 두면 DB를 지워도 남음
- 고가용(HA) 구성이면 주 DB가 죽어도 대기 DB로 넘어감

### 서버에 MySQL을 직접 띄우면 (compose의 db)
매일 `mysqldump` → 압축 → Object Storage(S3 호환) 올리기, 서버엔 7일만 남김.
```bash
# /etc/cron.d/mmc-backup  (매일 04:00)
0 4 * * * root /opt/mmc/backup.sh >> /var/log/mmc-backup.log 2>&1
```
```bash
#!/bin/sh
# /opt/mmc/backup.sh — 비번은 파일 안에 쓰지 않고 /root/.my.cnf(권한 600)나 compose 환경값에서
set -e
DAY=$(date +%F)
docker compose -f /opt/mmc/docker-compose.yml exec -T db \
  sh -c 'mysqldump --single-transaction --routines --triggers -uroot -p"$MYSQL_ROOT_PASSWORD" "$MYSQL_DATABASE"' \
  | gzip > /backup/mmc-$DAY.sql.gz
aws --endpoint-url=https://kr.object.ncloudstorage.com s3 cp /backup/mmc-$DAY.sql.gz s3://<버킷>/db/
find /backup -name 'mmc-*.sql.gz' -mtime +7 -delete
```
- Object Storage 버킷엔 수명 주기(예: 30일 뒤 지움) 걸기
- `--single-transaction`: 판 중에도 잠금 없이 한 시점 백업

### 복구 연습 (한 달에 한 번)
1. 어제 백업 파일 받기 (`aws s3 cp s3://<버킷>/db/mmc-<날짜>.sql.gz .`)
2. 시험용 빈 DB 하나 띄우기 (`docker run -d --name restore-test -e MYSQL_ROOT_PASSWORD=… mysql:8.4`)
3. 넣기: `gunzip -c mmc-<날짜>.sql.gz | docker exec -i restore-test mysql -uroot -p… <DB이름>`
4. 확인: 사용자 수·최근 판 기록 수가 운영과 비슷한지, `node scripts/migrate-db.js status`로 마이그레이션 이력 맞는지
5. 걸린 시간 적기 (실제 사고 때 얼마나 멈추는지 알게) → 시험 DB 지우기
Cloud DB면 2~3 대신 콘솔에서 "백업으로 새 DB 만들기"·시점 복구로 같은 확인.

## 6. 업데이트 순서 (공지 → 점검 → 내림 → 업데이트 → 켬)
1. 공지 (관리자 서버 공지 API)
2. 점검 켜기 → 새 방·시작·매칭 막힘, 진행 중 판은 끝날 때까지 기다림 (`/internal/live`로 판 수 0 확인)
3. 내림: `docker compose stop backend` (SIGTERM → 안내 → 정리 종료)
4. 업데이트: `git pull && docker compose build backend` (마이그레이션은 켤 때 자동)
5. 켬: `docker compose up -d backend` → `/health` 200 확인 → 점검 끄기
