# DB 변경 2026-11-09

DB 전수조사(reports/전수조사_2026-11-09/db) 뒷정리. 데이터 지우는 변경 없음.

## 바꾼 것

| 번호 | 무엇 | 왜 | 되돌리기 |
|---|---|---|---|
| D-01 | 서버 시작 때 `sequelize.sync` 뺌 → `db/schemaReadiness.js`가 마이그레이션 이력만 확인 | sync가 표를 모델 모양으로 먼저 만들면 마이그레이션이 "있으니 건너뜀"으로 넘어가 DB마다 모양이 갈림 | `index.js`에서 `ensureSchemaReady` 대신 `db.sequelize.sync({force:false})` 다시 부르기 |
| D-01 | 운영(`NODE_ENV=production`): 안 돌린·실패한·적용 뒤 바뀐 마이그레이션이 있으면 시작 거부, `[STARTUP] 실패 — DB 표 준비 안 됨: …` 한 줄 + 종료 코드 1 | 표 없는 채로 켜져 요청마다 500 나는 것보다 켜지기 전에 멈추는 게 원인 찾기 쉬움 | 위와 같음 |
| D-01 | 개발·시험: 같은 확인을 하되 경고 한 줄만 남기고 켬 (표는 안 만듦) | 여러 사람이 한 개발 DB를 같이 쓰는 중이라 남의 새 마이그레이션 때문에 서버가 안 켜지면 곤란 | — |
| D-01 | `backend/Dockerfile` 시작 명령: `migrate` 먼저, 성공하면 `exec node index.js` | 컨테이너는 늘 마이그레이션을 거친 뒤 켜짐. `exec`라 node가 PID 1 그대로 (SIGTERM 바로 닿음). 여러 대 동시 시작은 마이그레이션 잠금(GET_LOCK)으로 한 번에 하나 | `CMD ["node", "index.js"]`로 되돌리기 (그때는 손으로 migrate) |
| D-02 | 0020: `oauth_states.user_id → users.uuid` 외래키 (이름 `oauth_states_ibfk_1`, 규칙 NO ACTION) | 0005가 선언했지만 sync로 만든 DB엔 없음. 없는 계정을 가리키는 state를 DB가 못 막음 | `ALTER TABLE oauth_states DROP FOREIGN KEY oauth_states_ibfk_1` |
| D-02 | 0020: 고아 행 있으면 지우지 않고 멈춤, 모델에 `belongsTo(User)` 추가 | 지울지 말지는 사람이 봐야 함 | 모델 `associate` 빼기 |
| D-03 | 0021: `user_sessions.refresh_token_hash`·`refresh_previous_hash` 인덱스 (유일 아님) | 로그인 유지 갱신이 두 칸 OR + FOR UPDATE로 찾음 → 인덱스 없으면 표 전체 훑고 훑은 줄 다 잠금. 적용 뒤 실행 계획이 두 인덱스 합치기(index_merge union)로 바뀜 | `DROP INDEX user_sessions_refresh_token_hash`, `…_refresh_previous_hash` |
| 이름 차이 | 0022: sync식 인덱스 이름을 마이그레이션 이름으로 RENAME만 (oauth_states 2개, social_signup_intents, friendships, external_identities) | 나중 마이그레이션이 이름으로 인덱스를 다루면 한쪽 DB에서만 실패함 | `ALTER TABLE … RENAME INDEX 새이름 TO 옛이름` (옛 이름은 cmp_indexes.tsv의 d 칸) |
| D-08 | 0023: `online_presence.current_room_id`·`user_bans.banned_by` INT → CHAR(36) BINARY, NULL 허용 | 방 id는 `crypto.randomUUID()`, 정지한 사람은 `users.uuid` → INT엔 못 담음. 둘 다 넣는 코드 없고 값 전부 NULL이라 잃는 값 없음. 값이 하나라도 있으면 아무것도 안 바꾸고 멈춤 | `ALTER TABLE … MODIFY 칸 INT NULL` (값 비운 뒤) |
| D-11 | 모델 `friendships.created_at·updated_at` NOT NULL | 마이그레이션·DB와 맞춤 | 모델 `allowNull: false` 빼기 |
| 모델 | 인덱스 이름·새 인덱스를 모델에도 같게 적음 (oauthState, socialSignupIntent, friendShips, externalIdentity, userSession), `onlinePresence`·`userBan` 타입 UUID | 모델·마이그레이션·DB 세 곳이 같은 모양 | 모델 파일 되돌리기 |

같이 바꾼 시험: `tests/db/migrations/dbAudit20261109.migration.test.js`(0020~0023 모양, DB 없이), `tests/db/schemaReadiness.test.js`(시작 확인 + index.js 거부 길), `tests/helpers/schemaNotReady.preload.js`, `tests/models/schema.existingTables.test.js`(타입·인덱스 이름), index.js를 띄우는 시험 3개(`dbStartup`, `passwordReset.api`, `signupEmailVerification.api`)는 sync 대신 `ensureSchemaReady`를 바꿔 끼움.

## 적용 순서

1. 백업: `mysqldump --single-transaction --routines --triggers <DB>`
2. `cd backend && node -r dotenv/config scripts/migrate-db.js status` → 0020~0023만 pending인지
3. `node -r dotenv/config scripts/migrate-db.js migrate`
4. 다시 `status` → 다 applied
5. 서버 켜기 (Docker는 2~4를 시작 명령이 함)

미리 확인한 것 (2026-11-09):
- 로컬 개발 DB 백업 복원본과 빈 DB 두 곳에 0001~0023을 돌려 인덱스·외래키·칸 타입 전부 같게 나옴 (버리는 DB, 확인 뒤 지움)
- 로컬 개발 DB(`joker`): 0020~0023 적용됨
- `joker_realgame` DB도 0019까지 적용된 상태 → 이 DB로 서버 켜면 경고 나옴, 쓰는 사람이 migrate 해야 함 (안 건드림)

## 애매해서 안 한 것

| 번호 | 무엇 | 왜 안 했나 / 제안 |
|---|---|---|
| D-05 | 쌓이기만 하는 표 정리 (concurrent_snapshots 60초마다 1행·읽는 곳 없음, user_sessions, login_history, refresh_token_history, oauth_states, social_signup_intents, game_invites) | 지우는 일이라 안 함. 제안: 표마다 보관 기간 정하고 하루 한 번 예약 작업으로 `DELETE … WHERE 시각 < NOW() - INTERVAL n DAY LIMIT 1000`을 0행 될 때까지 반복. 예: oauth_states·social_signup_intents는 `expires_at` 지나고 1일, user_sessions는 `revoked_at` 또는 `refresh_token_expires_at` 지나고 30일(refresh_token_history는 그 세션 따라), login_history 90일, concurrent_snapshots는 쓸 곳 없으면 기록 자체를 끄거나 7일. 지우기 전 user_sessions에 `revoked_at` 인덱스 필요 |
| D-04 | user_stats 4칸 이중 저장 (쓰기만 함) | 표를 줄일지 화면에 보여 줄지 기획 결정 |
| D-06·D-15 | 정지 넣기·풀기, 권한·상태 바꾸기 관리 기능 없음, 정지 판정이 start_at 안 봄 | 기능 만들 때 같이 (banned_by 외래키도 그때) |
