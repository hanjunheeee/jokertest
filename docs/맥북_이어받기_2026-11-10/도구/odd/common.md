# 이상한 순서·여러 명 동시 시험 더 넣기 — 공통 규칙

사용자 말: "이상한 순서랑 여러명 동시도 체크 해줄래??? 이건 더 넣어서"

## 목표 (끝난 모습)
- 맡은 영역에서 **이상한 순서로 누르기**와 **여러 명이 동시에 하기** 상황 중, 지금 시험이 없는 것을 찾아 시험을 새로 넣음.
- 넣은 시험을 한 번 돌려서 통과 / 진짜 버그 의심 / 시험 실수를 나눠 기록함.

## 두 가지 뜻
- 이상한 순서: 단계가 아닌데 보내기, 같은 요청 두 번(따닥), 취소 뒤 다시, 끝난 뒤 보내기, 순서 뒤바꿔 보내기, 중간에 나갔다 들어와서 이어 하기, 이미 처리된 것 또 하기.
- 여러 명 동시: 둘 이상이 같은 순간에 같은 것을 함(마지막 자리 들어가기, 같은 대상 고르기, 같은 물건 사기, 한 계정 두 곳 로그인, 관리자 둘이 같은 사람 조작 등), 한 사람이 하는 중에 다른 사람이 상태를 바꿈.

## 어려운 시험도 넣음 (사용자 추가 말: "어려운 테스트도 추가해서 굴려")
쉬운 한 줄짜리만 넣지 말고, 맡은 영역에서 아래 같은 어려운 상황도 넣음.
- 여러 일이 겹침: 이상한 순서 + 동시 + 끊김이 한 번에(예: 투표 따닥 중에 다른 사람이 나가고 단계가 넘어감).
- 시간 경계: 타이머가 끝나는 바로 그 순간에 보내기, 끝난 직후 보내기, 단계 넘어가는 중에 보내기.
- 끊겼다 다시 붙기: 처리 도중 끊김, 다시 붙은 뒤 상태가 맞는지, 두 번 처리 안 되는지.
- 끝까지 가는 긴 흐름: 한 판을 처음부터 끝까지 가면서 중간중간 이상한 요청을 섞고, 마지막 상태(점수·재화·기록)가 맞는지.
- 사람 수 끝값: 가장 적은 수·가장 많은 수(5명·10명)에서 전원이 동시에.
- 중간에 실패: DB 저장이 중간에 실패했을 때 반만 저장되지 않는지, 같은 요청을 다시 보내면 한 번만 처리되는지.
어려운 시험은 시험 이름이나 주석에 무엇이 겹치는지 한 줄로 밝힘. 흔들리는 시험이 되지 않게 기다림은 시간(sleep)이 아니라 상태 확인으로 함.

## 일하는 순서
1. 먼저 읽기: `~/.claude/skills/test-run/SKILL.md`, 맡은 영역의 코드와 이미 있는 시험. **이미 있는 상황은 다시 쓰지 않음.** 개수 채우기 금지 — 빈 곳만.
2. 넣을 상황 목록을 진행 파일에 적음(아래 "진행 파일").
3. 시험을 **전부 쓴 뒤** 한 번에 돌림(사용자 규칙: 다 만든 뒤 한 번). 쓰는 중간에 돌리지 않음.
4. 실패를 나눔: 시험 실수 → 시험을 고침. 진짜 버그 의심 → **코드는 고치지 않고** 기록(시험은 그대로 둠). 흔들림 → 그 파일만 한 번 더 돌려 보고 기록.

## 파일 규칙
- **새 파일만 만듦.** 이미 있는 시험 파일·코드·도우미는 고치지 않음. 공용 도우미가 꼭 필요하면 내 파일 안에 넣음.
- 파일 이름에 `odd`를 넣음(예: `night-actions.odd.test.js`, `last-seat.odd.spec.js`). 그 폴더의 이름 규칙(진짜 DB는 `.integration.test.js`, Redis는 `.redis.integration.test.js` 등)은 그대로 따름.
- 맡은 폴더 밖은 손대지 않음. 다른 에이전트 셋이 다른 영역을 같이 함.
- 시험 서버를 띄울 땐 `tests/helpers/fetchablePort.js`를 씀(Windows에서 listen(0)이 막힌 포트를 받아 흔들림).
- 주석: 파일 머리 2줄(무엇 하는 파일 / 무엇을 봄), 끝맺음 ~함/~음/~기, 쉬운 우리말, 이유만. 시험 이름도 그 폴더의 기존 말투를 따름("~하면 → ~함").

## 브라우저 시험(e2e) 주의 — 꼭 지킴
- 지금 브라우저 전체 시험이 도는 중임. `e2e/tests` 아래에 새 파일을 만들면 도는 시험에 끼어듦.
- 그래서 **`<임시 폴더>/br/timeline.txt`에 "전체 끝" 줄이 생긴 뒤에만** e2e 파일을 만들고 돌림. 그 전에는 조사와 서버 쪽 시험(backend/tests)을 먼저 함.
- 서버 쪽 시험으로 볼 수 있는 것은 서버 쪽으로 씀(빠르고 덜 흔들림). 화면에서만 보이는 것(버튼 따닥, 창 두 개)만 e2e로.

## 돌리는 규칙
- 내가 만든 파일만 돌림. 전체 시험은 돌리지 않음.
- 무거운 일: `AGENT_NAME=<이름> bash <임시 폴더>/heavy.sh <명령>` (CPU 90% 넘으면 기다려 줌).
- 진짜 DB: `…/scratchpad/with-lock.sh testdb <명령>`. 브라우저: `…/scratchpad/with-lock.sh e2e <명령>` (한 번에 한 에이전트).
- `jokertest-db-1` 평소 쓰듯만. `joker_realgame` 금지. Docker Desktop 켜고 끄기 금지. 사용자 nodemon(포트 4000) 건드리지 않기. 내가 띄운 서버·브라우저·컨테이너는 끝나면 정리.

## 금지
- `git add .`, stash, reset, force push, main 합치기, 커밋(감독이 함). `.env` 값 읽어 적기. 영구 삭제. 이미 있는 마이그레이션 고치기. 하위 에이전트 띄우기.
- `.claude/launch.json`, `docs/known-issues.md`, `e2e/.tmp-check`, `frontend/tests/domains/game/ingame/store/participantDeparture.test.js` 손대지 않기.
