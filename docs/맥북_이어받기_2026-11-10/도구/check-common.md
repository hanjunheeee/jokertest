# ② 점검 1단계 — 공통 규칙 (돌리고 기록만)

- 기준 스킬: test-run(`~/.claude/skills/test-run/SKILL.md`) — 실패를 진짜 버그 / 시험이 낡음 / 환경 / 다른 사람 작업 중으로 나눔.
- **이번 단계는 고치지 않음.** (사용자: "실패 나오면 기록하고 한 번에 고쳐") 전부 돌리고 실패를 기록·분류만. 고치기는 2단계에서 감독이 묶어서 맡김.
- 기록 파일: `<저장소>/docs/점검_실패목록_2026-11-10.md` — 내 칸(제목 "## <내 이름>")에만 씀. 다른 에이전트도 같은 파일 자기 칸에 씀 → 쓰기 전 다시 읽고 내 칸만 고침(덮어쓰지 않기). 커밋은 감독이 함.
  - 표: 시험(파일:줄·이름) · 프로젝트/종류 · 오류 한 줄 · 분류 · 원인 짐작(근거) · 같은 원인 묶음 이름
  - 맨 위에 숫자: 전체·통과·실패·건너뜀·불안정(다시 돌려 통과), 걸린 시간, CPU 최고값
- 불안정(flaky) 판단: 실패한 것만 한 번 다시 돌려 봄(그 파일만). 다시 통과하면 "불안정"으로 적고 원인 짐작.
- **CPU 확인하며** (사용자 지시): 돌리기 전·중간에 `powershell -NoProfile -Command "[math]::Round((Get-CimInstance Win32_Processor | Measure-Object LoadPercentage -Average).Average)"`. 90% 넘게 오래 가면 workers 줄이기. 메모리 모자라 서버가 안 켜지면 workers 줄여 다시.
- 무거운 일: `AGENT_NAME=<이름> bash <임시 폴더>/heavy.sh <명령>`. 진짜 DB: `…/with-lock.sh testdb <명령>`. 브라우저: `…/with-lock.sh e2e <명령>`(한 번에 한 에이전트).
- 코드·시험 안 고침. 시험 환경(서버 켜기) 문제로 아예 못 돌면 원인을 기록하고, 시험 도우미 쪽 아주 작은 환경 고침(예: 포트·메모리 옵션)만 하고 그 내용 기록.
- `jokertest-db-1` 평소 쓰듯만, `joker_realgame` 금지, Docker Desktop 켜고 끄기 금지, 사용자 nodemon(4000) 건드리지 않기.
- 끝나면 내가 띄운 서버·브라우저·Redis 컨테이너 정리. 하위 에이전트 금지.
- 마지막 답(한국어, 짧게): 숫자 표 · 실패 묶음(원인별) 목록 · 못 돌린 것과 이유.
