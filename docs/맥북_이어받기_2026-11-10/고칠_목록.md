## 2. 공통 — 다시 돌리는 명령 모양

- 서버 단위(진짜 DB·Redis 없음): `cd backend && node --env-file=.env.test --test <파일>`
- 진짜 DB: `cd backend && node --env-file=.env.test --env-file=.env.testdb --test --test-concurrency=1 <파일>` (= `npm run test:with-db`의 명령. `.env.testdb`·진짜 MySQL 필요, 맥에 있는지 확인 못 함)
- 진짜 Redis: `cd backend && REDIS_URL_TEST=redis://127.0.0.1:6380 node --env-file=.env.test --test --test-concurrency=1 <파일>` (Redis 6380 필요, `npm run test:redis:setup` 참고)
- 시험 하나만: 위 명령에 `--test-name-pattern="<시험 이름 일부>"`
- 브라우저: `cd e2e && npx playwright test --retries=0 --no-deps --project=<프로젝트> tests/<파일>:<줄>`
  - `--no-deps` 꼭 붙이기. 안 붙이면 `serial` 프로젝트가 앞 프로젝트(desktop·mobile 등) 전부를 같이 돌림
  - 서버 2개: 앞에 `E2E_NODES=2`. serial 시험(Node 죽이기 등)은 다른 프로젝트와 한 번에 돌리지 않기
  - 브라우저 시험은 한 번에 하나만(포트가 같음, 둘이 동시에 돌면 서로 깨짐)

## 6. 고치는 순서 제안

- 서버 쪽(묶음 1~7·17)은 진짜 DB·Redis만 있으면 같이 돌릴 수 있음. 다만 진짜 DB 시험은 `--test-concurrency=1`이고 같은 DB를 씀 → DB 시험 돌리기는 한 번에 한 에이전트

| 조 | 같이 돌릴 묶음 | 까닭 |
|---|---|---|
| 1조 | 1 · 3 · 4 · 7 · 18 | 고칠 파일 안 겹침. 18만 브라우저 시험 |
| 2조 | 2 · 5 · 6 · 17 · 10 | 6은 3 뒤. 10만 브라우저 시험 |
| 3조 | 8 · 11 · 13 | 8은 서버 2개, 11·13은 서버 1개 → 시험은 차례로 |
| 4조 | 9 · 12 · 14 · 16 | 9는 8 뒤, 12는 10 뒤, 14·16 안 겹침 |
| 5조 | 15 · 19 | 15는 14 뒤, 19는 다 고친 뒤 CPU 낮을 때 |

- 꼭 지킬 순서: 3 → 6, 8 → 9, 10 → 11·12, 14 → 15, 19는 맨 끝
- 맨 끝에 한 번: backend `npm test`·`npm run test:with-db`·`npm run test:with-redis`, frontend·frontend-mobile `npm test`, e2e 전체(`--no-deps`로 프로젝트별)
