# 2일차 낮 투표 생존 판정 — 10인 수동 검증 절차 (AC-06)

서버상 생존한 계정이 2일차 낮에 실제로 투표를 수행할 수 있고, 사망한 계정은 투표 UI가 잠겨
있는지 실제 브라우저 10인 환경에서 확인한다. 매번 같은 판을 재현할 수 있도록 참가자 구성과
처형·사망 대상을 아래에 고정한다 — 즉흥으로 정하면 스크린샷이 무엇을 증명하는지 흐려진다.

## 무엇을 보는가

프론트의 낮 투표 게이트(`dayVoteControlsEnabled`)는 서버 canonical 생존 상태
(`state.players[].alive`)를 판정원으로 쓴다(`resolveInGameSelfAliveForControls`). 세션
컨텍스트의 표시 status가 아니라 서버 상태가 UI를 결정하는지가 이 검증의 대상이다.

## 사전 준비

1. 백엔드와 프론트를 각각 기동한다(`backend`: `npm start`, `frontend`: `npm run dev`).
2. 서로 다른 계정 10개로 로그인한 브라우저 컨텍스트 10개를 연다(창 분리 또는 프로필 분리 —
   같은 프로필의 탭만 쓰면 세션이 섞인다).
3. 계정에 P1~P10 번호를 붙이고, 어느 창이 어느 계정인지 창 제목이나 메모로 고정한다.
4. 한 방에 10명이 모두 입장한 뒤 게임을 시작한다.

## 시나리오 (고정)

| 단계 | 행동 | 기대 |
| --- | --- | --- |
| 1 | 전원 역할 확인(ROLE_REVEAL) 완료 | 1일차 낮(DAY_DISCUSSION) 진입 |
| 2 | 전원 준비 → 1일차 투표 개시 | DAY_VOTE 진입, 생존 10인 전원 투표 가능 |
| 3 | **P10에게 표를 몰아 재판 회부** | phase TRIBUNAL, 피고인 P10 |
| 4 | 유죄(GUILTY) 다수로 판정 | P10 처형, 밤 진입 |
| 5 | 밤 역할 턴 진행 — **조커는 P9를 지목** | P9 사망 |
| 6 | 밤 판정 반영 | 2일차 낮(dayIndex 2) 진입 |
| 7 | 전원 준비 → 2일차 투표 개시 | DAY_VOTE 진입 |

2일차 낮 기준 생존/사망:

- 생존(8인): P1 P2 P3 P4 P5 P6 P7 P8
- 사망(2인): P9(밤 사망) · P10(1일차 처형)

## 2일차 낮에서 확인할 것

1. **생존 계정(P1)** — 투표 대상 목록에서 P2를 고르고 `투표` 버튼을 누른다.
   - 대상 선택과 투표·기권 버튼이 활성화되어 있어야 한다.
   - 제출 후 오류 메시지 없이 제출 상태로 바뀌어야 한다(서버가 `ACTOR_NOT_ALIVE`로 거부하지
     않는다).
   - 투표 대상 목록에 P9·P10(사망자)이 보이지 않아야 한다.
2. **생존 계정(P5)** — P1과 같은 절차로 한 번 더 확인한다(한 계정만 우연히 열린 경우 배제).
3. **사망 계정(P10, 1일차 처형)** — 투표·기권 버튼과 대상 선택이 모두 비활성이어야 한다.
4. **사망 계정(P9, 밤 사망)** — P10과 같아야 한다.
5. **새로고침 후 재확인** — P1과 P10에서 각각 브라우저를 새로고침해 스냅샷 복원
   (`get_session_snapshot`) 경로로 들어온 뒤에도 3·4의 결과가 그대로여야 한다. 이벤트 경로와
   복원 경로의 판정이 같은지 보는 단계다.

판정이 화면과 어긋나 보이면 해당 창의 콘솔에서 아래 값을 함께 남긴다 — 서버 상태가 틀린
것인지 화면이 틀린 것인지 이 값으로 가른다.

```js
// 브라우저 콘솔
const s = window.__ingameStore?.getState?.() // 노출돼 있지 않으면 React DevTools로 store state 확인
// 확인할 값: state.players (uuid/alive), state.self.uuid, state.dayIndex, state.dayPhase, snapshotSeq
```
