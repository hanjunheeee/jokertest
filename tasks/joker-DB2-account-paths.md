# joker-DB2 · 계정 경로 수리 (가입 트랜잭션·닉네임 409·세션 검증)

## 배경 (전수조사 1.6·2.2·2.3)

① 회원가입이 createUser → createUserStats 별도 커밋이라 중간 실패 시 user_stats 없는 유저가 생긴다 (전적 기능이 붙으면 이 유저들이 터짐). ② 닉네임 변경(PATCH /user/me/nickname)에 중복 검사가 없어 unique 위반이 500 + 스택 노출로 샌다 — 회원가입 쪽은 409를 주는데 두 경로가 불일치. ③ JWT payload에 sessionId를 넣어놓고 아무도 검증하지 않아, 다른 기기 로그인·계정 정지가 REST에 반영되지 않는다 (토큰 만료 1일까지 유효).

## 요구

1. 회원가입의 createUser + createUserStats를 **하나의 트랜잭션**으로 묶는다 (실패 시 둘 다 롤백). 기존 user_stats 없는 유저가 이미 존재할 수 있으므로, 프로필 조회 등 user_stats를 읽는 경로가 부재 시에도 죽지 않는지 확인하고 방어한다 (없으면 생성 또는 기본값).
2. 닉네임 변경에 중복 검사를 추가한다 — 회원가입과 동일한 방식·동일한 409 응답. unique 제약 위반이 500으로 새지 않는다.
3. 인증 미들웨어가 JWT의 sessionId를 user_sessions와 대조한다: 세션이 is_online:false(다른 기기 로그인으로 무효화)면 401. 활성 밴 검사도 이 지점에 포함할지는 계획이 성능 영향(요청당 DB 조회)과 함께 1안 제시 — 캐시·조회 전략 포함.

## 성공 조건

- 가입 중간 실패를 강제하면 user도 user_stats도 남지 않는다 (트랜잭션 테스트)
- 중복 닉네임 변경 요청이 409로 응답한다 (500 아님)
- 무효화된 sessionId의 토큰으로 REST 요청 시 401
- 기존 로그인·로그아웃·프로필 조회 회귀 없음

## 성공 조건에 넣지 말 것 (범위 밖 — 수정 금지)

- refresh token·토큰 재발급 (미구현 유지)
- 탈퇴 기능
- 게임·소켓 로직
