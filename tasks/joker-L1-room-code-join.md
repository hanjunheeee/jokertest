# joker-L1 · 방 코드 입장 연결

## 확정 스펙 (전제)

- 방 코드 입력 UI는 프론트에 이미 존재한다 — 이 슬라이스는 신규 설계가 아니라 **기존 UI와 백엔드의 배선**이다. 코드 형식·생성 방식은 기존 UI·기존 방 데이터의 현황을 계획 단계에서 확인하고 그에 맞춘다 (기존 형식이 있으면 따르고, 없으면 1안 제시)
- 비밀방은 방 목록에서 숨기지 않는다 — **목록에 보이되 자물쇠 아이콘으로 표시**, 입장 시 코드를 요구한다
- 공개방의 기존 입장 방식(목록 클릭)은 그대로 유지한다

## 요구

1. 방 생성 시 비밀방 여부를 설정할 수 있고, 비밀방에는 입장 코드가 부여된다 (기존 UI에 해당 입력이 있으면 그걸 연결, 코드 자동 생성이면 방장에게 표시). 현황 확인 후 계획이 확정.
2. 방 목록에서 비밀방은 자물쇠 아이콘과 함께 표시된다. 방 이름·인원 등 기본 정보는 공개방과 동일하게 보인다.
3. 비밀방 입장 시 코드 입력을 요구하고 백엔드가 검증한다. 거부 사유를 구분해 응답한다: 코드 불일치 / 방 없음 / 이미 시작된 게임 / 정원 초과.
4. 코드 검증은 백엔드에서 강제한다 — 프론트 우회(소켓 직접 호출)로 코드 없이 비밀방에 입장할 수 없어야 한다.
5. 공개방은 코드 없이 기존대로 입장된다 (회귀 확인).

## 성공 조건

- 비밀방 생성 → 목록에 자물쇠 표시 → 올바른 코드로 입장 성공
- 틀린 코드 입장이 거부되고 사유가 표시된다
- 소켓 레벨에서 코드 없이 비밀방 입장 시도가 거부된다
- 공개방 입장이 기존과 동일하게 동작한다

## 성공 조건에 넣지 말 것 (범위 밖 — 수정 금지)

- 게임 내(인게임) 로직 전부
- 초대 링크·친구 시스템
- 접속 끊김 처리 (S3)

## 자잘한 규칙

- gameSession.js 인게임 로직과 독립적일 가능성이 높지만, 안전하게 다른 슬라이스와 직렬로 돌린다
