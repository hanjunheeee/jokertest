# joker-S1-1 · 서버 밤 턴 엔진

## 확정 스펙 (전제)

- 밤 턴 순서: **광대 → 의사 → 경비원 → WITCH_HUNTER** (고정)
- 서버 상태 모델: NIGHT를 NIGHT_TURN(role) 시퀀스로 세분화. 턴별 상태: 대기 / 제출완료 / 시간초과
- 이벤트 계약: `night_turn_started(role, deadline)` / `night_turn_ended(role)` — 죽은(전멸 포함) 직업의 턴도 동일 이벤트로 방송한다 (은폐)
- 타이머 소유권: 서버 단일. 이 슬라이스에서는 타이머 미구현(S1-2)이지만 이벤트에 deadline 필드는 지금부터 포함한다 (임시값 허용)
- 턴 진행: 해당 직업 생존자 **전원 제출(건너뛰기 제출 포함) 시 즉시** 다음 턴
- 죽은 직업 턴: **무작위 지연(해당 턴 제한시간의 20~60% 사이) 후 종료** — 산 턴이 빨리 끝나는 세계에서 죽은 턴만 풀타임이면 그게 전멸 신호가 되기 때문

## 요구

1. 위 상태 모델·이벤트 계약대로 턴 시퀀스를 구현한다. 각 턴에는 해당 직업의 행동 제출만 허용하고, 다른 직업의 제출은 거부한다.
2. 죽은 직업의 턴도 동일한 이벤트로 방송한다. 이벤트 payload만으로 해당 직업의 생존 여부를 구별할 수 없어야 한다 (필드 구성·값 형태 동일).
3. "건너뛰기"는 정식 제출로 취급한다 — 전원 제출 판정에 포함된다.
4. 이 슬라이스에서 시간 만료 처리(미제출 기권)는 구현하지 않는다 (S1-2). 산 직업 턴의 종료 조건은 전원 제출뿐이다.

## 성공 조건

- 밤 동안 night_turn_started가 광대→의사→경비원→WH 순서대로 방송된다 (죽은 직업 포함)
- 자기 턴이 아닌 직업의 행동 제출이 거부된다
- 죽은 직업 턴이 제한시간의 20~60% 범위 내 무작위 시점에 종료된다
- 이벤트 payload만 보고 어느 직업이 전멸했는지 알 수 없다 (5.2 / 11.6의 서버 측)

## 성공 조건에 넣지 말 것 (범위 밖 — 수정 금지)

- 프론트 수정 (S1-3)
- 시간 만료·타이머 소비 (S1-2)
- 접속 끊김 처리 (S3)
