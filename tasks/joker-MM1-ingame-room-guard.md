# joker-MM1 · 게임 중 대기방 중복 소속 차단

## 배경 (Codex 전수조사 3장)

게임 시작 시 playerRoom이 삭제된 뒤, 방 생성·참가 코드가 활성 playerSession을 검사하지 않는다 — 진행 중인 게임의 참가자가 새 대기방을 만들거나 참가할 수 있다 (matchmaking.js:367, :884, :972 일대).

## 요구

1. 방 생성·방 참가·매칭 진입 전에 활성 playerSession(uuid → gameId)을 검사하고, 진행 중인 게임이 있으면 거부한다. 거부 사유 코드를 구분한다 (예: ALREADY_IN_GAME).
2. 거부 응답에 현재 게임으로 돌아갈 수 있는 정보(gameId 또는 재동기화 안내)를 포함할지는 계획이 1안 제시.
3. 기존 재접속 경로(resyncSessionRouting)는 그대로 동작한다 — 이 차단은 "새 방"만 막고 "자기 게임 복귀"는 막지 않는다.

## 성공 조건

- 게임 중인 계정의 방 생성·참가·매칭 요청이 ALREADY_IN_GAME으로 거부된다
- 같은 계정의 게임 복귀(재동기화)는 정상 동작한다 (회귀 확인)
- 게임에 없는 계정의 방 생성·참가는 기존과 동일하다

## 성공 조건에 넣지 말 것 (범위 밖 — 수정 금지)

- 인게임 로직, 끊김 처리(S3), 방 코드 입장(L1)
