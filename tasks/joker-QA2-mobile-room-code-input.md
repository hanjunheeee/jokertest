# Joker QA2 — 모바일 영숫자 방 코드 입력 계약 복구

## 배경

QA1에서 서버가 생성하는 영문 대문자·숫자 6자리 방 코드를 훅이 보존하도록 수정했다. 그러나 실제 입력 컴포넌트는 아직 숫자 키패드와 숫자 전용 pattern을 선언해 모바일에서 영문 코드를 입력하기 어렵다.

## 재현

1. 모바일 viewport에서 `코드로 참가` 화면을 연다.
2. 여섯 입력칸의 `inputMode`, `pattern`, 자동 대문자화 속성과 표시되는 키보드 유형을 확인한다.
3. 영문과 숫자가 섞인 실제 서버 코드의 타이핑·붙여넣기·삭제·재입력을 수행한다.

## 요구사항

- 입력 UI의 힌트와 validation 속성은 서버 코드 형식 `[A-Z0-9]{6}`과 일치해야 한다.
- 모바일에서도 영문과 숫자를 모두 입력할 수 있어야 하며, 소문자는 대문자로 정규화되어야 한다.
- 여섯 칸 타이핑, 전체 코드 붙여넣기, Backspace, 좌우 이동, 자동 포커스, 중간 칸 재입력이 회귀하지 않아야 한다.
- 허용되지 않은 문자와 공백은 서버로 전송하지 않는다.
- 기존 공유 모달의 읽기 전용 코드 표시·복사 동작은 변경하지 않는다.
- backend schema/migration과 방 코드 생성 형식은 변경하지 않는다.

## 성공 조건

- 컴포넌트 DOM 속성이 숫자 전용 입력을 강제하지 않고 `[A-Z0-9]` 계약을 표현한다.
- 모바일 viewport의 실제 브라우저에서 영문+숫자 6자리를 타이핑하거나 붙여넣어 참가 요청까지 보낼 수 있다.
- 관련 훅/컴포넌트 단위 테스트, frontend 전체 테스트, production build가 통과한다.
