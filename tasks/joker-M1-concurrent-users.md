# joker-M1 · 실시간 동접자 집계·저장

## 확정 스펙 (전제)

- 범위: 서버 전체 접속자 (로비 + 게임중 합산)
- 이 슬라이스는 **집계와 DB 저장까지만** — 표시 UI 없음. 추후 다른 백엔드가 소켓으로 구독하는 것은 범위 밖 (단, 그때 쓸 수 있게 "현재값 조회" 내부 함수/이벤트 훅은 남겨둔다)
- 카운트 기준 권장: 고유 플레이어 기준 (같은 계정의 다중 소켓·탭은 1로) — 계획이 현황 보고 1안 확정
- 선행 조건: DB·계정 전수조사 완료 (R1과 동일 — 스키마 추가 방법을 조사 결과에 따름)

## 요구

1. 서버가 현재 접속자 수를 상시 추적한다: 소켓 연결·해제 시점에 갱신되는 인메모리 카운터. 로비·게임중 구분 값도 함께 유지한다 (합산이 전체).
2. 주기적으로 DB에 스냅샷을 저장한다: 시각, 전체 접속자, 로비 인원, 게임중 인원, 진행 중인 방 수. 주기는 설정 가능(기본값은 계획이 1안 제시 — 예: 1분).
3. 저장 실패가 게임·로비 동작에 영향을 주지 않는다 (R1과 같은 원칙 — 분리·실패 허용·로그).
4. 현재값을 코드에서 조회할 수 있는 내부 인터페이스 1개 (추후 소켓 중계의 연결점). 외부 노출 API·소켓 방송은 만들지 않는다.
5. 서버 재시작 시 카운터가 0에서 정확히 다시 시작한다 (유령 카운트 없음).

## 성공 조건

- 접속·해제를 반복해도 카운터가 실제 연결 상태와 일치한다 (다중 탭 처리 포함, 확정된 기준대로)
- 스냅샷 레코드가 주기대로 쌓이고 필드가 정확하다
- DB를 강제로 실패시켜도 로비·게임이 정상 동작한다
- 서버 재시작 후 유령 카운트가 없다

## 성공 조건에 넣지 말 것 (범위 밖 — 수정 금지)

- 표시 UI (프론트 무변경)
- 외부 백엔드로의 소켓 중계·외부 API
- 게임 로직

## 자잘한 규칙

- 변경 범위: backend 소켓 연결 수명 주기 일대 + 저장 계층
- 실행 순서: [DB 전수조사] 뒤, R1 앞뒤 무관 (같은 저장 계층 위라 직렬 유지)
